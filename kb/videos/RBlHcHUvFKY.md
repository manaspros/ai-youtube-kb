> Hands-on walkthrough of OpenAI's new drag-and-drop Agent Builder, used to build a GitHub PR code-review agent; covers guardrails, structured outputs, MCP, widgets and evals, with bugs noted and a verdict that it does not yet replace n8n.

## Summary
The host builds a GitHub pull-request code-review agent in OpenAI's new Agent Builder, a visual drag-and-drop workflow editor on the OpenAI platform, and walks through each node. The workflow runs a guardrails check on input, extracts owner, repo and pull number as structured JSON, gates on an if/else check, reshapes data with transform nodes, fetches the diff through a GitHub MCP server, runs a review agent with file search and web search, and ends with a final agent that returns an interactive widget. The host calls out guardrails with configurable moderation and jailbreak checks, JSON-schema outputs, an AI-assisted widget builder and a trace-based evaluate tab with graders as the most useful features. He also reports several first-week problems: a required-field toggle that breaks the workflow, a GitHub MCP call that stopped working mid-demo so he substituted a fake diff server, and an Agents SDK that does not yet run workflows containing MCP nodes. His verdict is that n8n is not yet threatened, since n8n offers non-AI flows, non-MCP integrations, sharing and self-hosting, while the Agent Builder mainly targets OpenAI models and so creates model lock-in. The evidence is one person's single demo with no metrics, costs or latency figures.

## Key ideas
- **Agent Builder is a visual workflow editor on the OpenAI platform, positioned against n8n and Zapier, with six starter templates.** — Nodes are Start (text input plus typed variables), Agent (model plus prompt), tools (file search, guardrails, MCP) and logic nodes for multi-step flows. The host loaded a PR review workflow he had built earlier. ([0:00](https://youtu.be/RBlHcHUvFKY?t=0))
- **A workflow can return a widget instead of text, giving an interactive component inside the chat.** — The final agent in the demo picks a meme from the code review and renders it as a widget. Widgets are part of ChatKit. ([1:09](https://youtu.be/RBlHcHUvFKY?t=69))
- **The guardrails node runs checks on user input or model output, and each check is configurable.** — Options include moderation, jailbreak, personal-information and hallucination checks. The jailbreak check lets you choose the checking model and a confidence threshold. A failed check routes to a short agent that sends a warning message and ends the flow. ([2:30](https://youtu.be/RBlHcHUvFKY?t=150))
- **Structured extraction uses a JSON output format with a schema, and the required toggle is buggy.** — The extraction agent pulls owner and repo as strings and pull number as a number from the chat, and the schema fields carry descriptions. Unticking required breaks the whole workflow, so every field stays required. An AI button can generate the schema. ([3:48](https://youtu.be/RBlHcHUvFKY?t=228))
- **Transform-data nodes are needed to flatten nested outputs into the exact input schema an MCP tool expects.** — Hovering the connector path shows the target input schema. The upstream output was a nested object, so a select-based mapping pulled the pull number out to the flat field the MCP tool requires. ([4:43](https://youtu.be/RBlHcHUvFKY?t=283))
- **MCP nodes can reach OpenAI-curated and third-party servers, or any server that speaks streamable HTTP, but a live dependency is fragile.** — Setting require approval to never makes the step fully automated. The GitHub MCP server stopped working during recording, so the host built a fake diff server that returned the diff he already knew. ([5:44](https://youtu.be/RBlHcHUvFKY?t=344))
- **Context control matters for a reviewer agent: the review agent has include-chat-history turned off, so it only sees the prompt and the diff.** — The agent uses multiple instruction steps with user or assistant roles. Tools are a Context7 MCP server, a file-search vector store holding code best practices, and web search. The host says the aim is to keep irrelevant context out of the review. ([6:53](https://youtu.be/RBlHcHUvFKY?t=413))
- **The Evaluate tab shows traces of recent runs, and graders written as plain-language prompts run across all of them for pass/fail.** — Example graders are whether the agent performed a code review and whether it was polite. Publish pushes the draft to the production API. The Code button offers ChatKit or the Agents SDK, and the Agents SDK does not yet support workflows with MCP nodes. ([9:10](https://youtu.be/RBlHcHUvFKY?t=550))
- **The bigger risk is lock-in: the Agent Builder is built around OpenAI models, so switching to another provider's model is harder than in n8n.** — The host expects people to combine n8n or Zapier with the Agent Builder, since n8n has non-AI flows, non-MCP integrations, shareable workflows and self-hosting. ([10:02](https://youtu.be/RBlHcHUvFKY?t=602))

## Techniques
- **Input guardrail with a fail branch** — In the guardrails node, enable moderation and jailbreak checks on the user input, choose the jailbreak model and confidence threshold in each check's settings, then route the fail path to a small agent (GPT-4.1 in the demo) that returns a friendly warning and ends the workflow. *When:* Any user-facing agent that accepts untrusted text and must block abusive or injected prompts before tools run.
- **Structured extraction gate before tool calls** — Set the agent's output format to JSON and define a schema with typed fields (owner string, repo string, pull number number), each with a description. Follow it with an if/else node whose CEL expression checks for empty strings and a zero number, and only continue to tool nodes when the check passes. *When:* Pipelines where a tool needs validated parameters extracted from free-form user text, and missing values should stop the flow early with a clear message.
- **Transform node to flatten nested outputs for a tool** — Click the connector path between two nodes to see the target input schema. Add a transform-data node and map each required flat key (e.g. pull number) from the nested upstream object using the select picker. *When:* The upstream output is nested, but the downstream MCP or function tool needs flat named parameters.
- **Isolated reviewer context** — On the review agent, turn off include chat history, put the fixed review instructions in a user message, and add the diff as a separate user message. Use multiple instruction steps for ordering. Keep unrelated tool output out of the reviewer context. *When:* A reviewer or critic agent should judge only the artifact (diff, document, plan) and not inherit the whole conversation or prior tool dumps.
- **Natural-language graders over traces** — Run the workflow a few times, open Evaluate to see the traces, then add a grader with a plain-language criterion such as whether the agent performed a code review or stayed polite. Run it across all traces and read the pass/fail result. *When:* Quick regression checks on a no-code or low-code workflow before a deeper eval harness exists.
- **Widget output from a final agent** — Set the final agent's output format to widget. Open the widget builder, describe the component in a prompt (the AI generates it), then preview the widget JSON. The output renders as an interactive card in chat. *When:* The end result is better shown as a card (a status, a chart, a choice) than as plain text.
- **Adding a custom MCP server** — In the MCP node, choose Add for the curated list, or Server to enter a URL and auth for any server that supports streamable HTTP. Pick the tools to expose and set require approval to never for unattended steps. *When:* Connecting a remote tool server to a visual workflow without writing a client, if the server supports streamable HTTP.

## Hot takes
- Agent Builder is not an n8n killer for now: it is focused on OpenAI models, with no non-MCP integrations, no sharing or self-hosting, and no non-AI flows [9:10].
- The bigger risk is model lock-in to OpenAI, which matters more than the missing features [10:02].
- Early-stage bugs (the required-field toggle breaking the flow, the MCP call failing live, the Agents SDK missing MCP support) should be expected to be fixed within about a week [3:48] [5:44] [9:10].
- Evidence is one hands-on demo with no metrics; treat the verdict as a single practitioner's first impression.
