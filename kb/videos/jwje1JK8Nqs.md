> AI Labs walks through 24 tactics for stretching Claude Code and Codex usage limits, from habits (clear, compact, rewind, one big prompt) to settings (model and effort, skill and CLAUDE.md size, memory, bundled skills, output caps, advisor).

## Summary
The speaker argues that every message resends the whole conversation, so context length and idle time both drive token cost, and that $20 plans need stricter habits because the five-hour and shared weekly limits run out quickly. Level 1 covers habits: run clear between unrelated tasks, compact only when needed and before breaks (since the prompt cache expires), rewind instead of stacking corrections, batch work into one prompt, and turn off automatic recaps in Claude Code. Level 2 covers configuration: pick the cheapest model that can do the task, keep effort at medium by default, and keep always-loaded context small by keeping CLAUDE.md and SKILL.md under about 200 lines and moving detail into per-folder files and reference files. The speaker prefers a CLI over an MCP server when the CLI can do the job, because MCP tool schemas stay loaded in context. Level 3 covers defaults that quietly cost tokens: auto-memory, bundled skills, sub-agent workflows, unfiltered command output (cap at 10,000 characters and filter passing tests with a hook), and the built-in advisor, which the speaker replaces with a custom agent that runs only on request. Most numbers are the speaker's own and unmeasured; the video is a practitioner checklist with a community plug.

## Key ideas
- **Every message resends the whole conversation, so the same prompt costs more later in a session.** — Models keep no memory between turns; the full history plus the new prompt is sent each time, and tool reads and command runs also add to what is sent. Context windows are cited as Opus 1M tokens and GPT-5.6 Sol 272,000 tokens. ([1:17](https://youtu.be/jwje1JK8Nqs?t=77))
- **Limits are a five-hour rolling window plus a weekly cap shared across all models.** — The five-hour clock starts with the first message. Switching models does not restore weekly usage. The speaker says $20 plans (Claude Pro, ChatGPT Plus) need the strictest habits. ([2:45](https://youtu.be/jwje1JK8Nqs?t=165))
- **Compacting is expensive and lossy, and prompt-cache timing decides when to do it.** — Compaction reads the whole conversation (costing usage) and loses detail. Cached reads are said to cost about a tenth of normal, but the cache is discarded after an idle period, so compact before a break, not after returning. Always tell compact what to keep. ([3:44](https://youtu.be/jwje1JK8Nqs?t=224))
- **Rewind removes a bad turn instead of layering a correction on top of it.** — A correction in the next prompt leaves the mistake in context for every later message. Rewind (command in Claude Code, double-Esc in both tools) drops the turn entirely. ([3:44](https://youtu.be/jwje1JK8Nqs?t=224))
- **One consolidated prompt beats several small ones.** — Each tool read or command re-sends the conversation, so splitting work across prompts multiplies context. Bundling a set of website design fixes into one prompt cost noticeably fewer tokens than doing them one at a time (no figure given). ([5:12](https://youtu.be/jwje1JK8Nqs?t=312))
- **Model and effort should match task difficulty; medium is the default.** — Opus is for hard work; Sonnet is the day-to-day choice (Opus is recommended as the daily driver on the $100 plan). Codex effort levels are low, medium, high and extra high. Raise effort per task rather than globally. ([7:47](https://youtu.be/jwje1JK8Nqs?t=467))
- **Always-loaded context is the hidden recurring cost: keep CLAUDE.md and skills short and split them.** — CLAUDE.md and SKILL.md should stay under about 200 lines. Only skill names and descriptions load by default; detail goes in reference files pulled on demand. Specialized rules belong in skills, and large projects get per-folder CLAUDE.md files. An MCP server's tool schemas stay in context all session, while a CLI loads only when used. ([9:14](https://youtu.be/jwje1JK8Nqs?t=554))
- **Turn off or replace the default-on features that burn tokens.** — Auto-memory, bundled skills, sub-agent workflows and the built-in advisor all add cost. The speaker disables memory and bundled skills, turns workflows off or caps them, and replaces the advisor with a custom agent (same name) that runs only when asked, since the built-in one sends the full conversation to a stronger model with no cache. ([14:54](https://youtu.be/jwje1JK8Nqs?t=894))
- **Command output is a silent context sink: filter it and cap it.** — A hook keeps only failing test output so passing tests stop filling context. Claude Code's bash max output length is lowered from 30,000 to 10,000 characters. Codex has a tool output token limit covering all tools. ([16:21](https://youtu.be/jwje1JK8Nqs?t=981))

## Techniques
- **Clear between unrelated tasks** — Run the clear command (same in Claude Code and Codex) before starting a task that has nothing to do with the previous one, so the new prompt does not carry old context. *When:* Every task switch.
- **Compact with explicit keep-instructions, before breaks** — Run compact, and in the same command tell it which details must survive the summary. Run it before stepping away, because the cached copy of the conversation expires during idle time. *When:* Context is filling up and you need to continue the same task; avoid compacting repeatedly.
- **Rewind instead of correcting** — In Claude Code, run rewind or double-tap Escape; in Codex, double-tap Escape (no command). Then send the corrected instruction as the next prompt. *When:* The agent did something wrong and you want the bad turn gone from context.
- **Batch changes into one prompt** — Combine related edits (the speaker's example: remove gradients, remove glow, fix alignment) into a single prompt rather than queuing several. *When:* Several related changes to the same codebase.
- **Turn off automatic session recaps (Claude Code only)** — Open config, search for session recap, and switch it off; run the recap command manually when wanted. Codex has no equivalent. *When:* Running several sessions and you do not need recaps on every return.
- **Set model per task with /model and effort with /effort** — Run the model command (both tools) to switch models. In Codex, pick effort from low, medium, high or extra high after choosing the model. In Claude Code, run the effort command. Put the keyword ultrathink in a prompt to raise thinking for one task. *When:* Default to Sonnet (or GPT-5.6 Terra for Codex) and medium effort; escalate for hard problems.
- **Pin sub-agent model in the prompt, or route automatically with a skill** — Name the model in the prompt and the agent spawns a sub-agent on that model. For automatic routing, the speaker uses a custom Model Router skill that runs on every prompt; a CLAUDE.md rule is rejected because early instructions drift out of attention in long sessions. *When:* Mixed-difficulty work where you do not want to pick the model for each task.
- **Keep skills small with reference files** — Keep SKILL.md under about 200 lines. Put long detail in separate reference files next to it; the agent loads only what it needs. Skills load only when the task matches, so design rules do not load during database work. *When:* Authoring any skill that is more than a few paragraphs.
- **Write a lean CLAUDE.md and per-folder CLAUDE.md files** — Keep CLAUDE.md under about 200 lines and include only what the agent does not already know; do not let the agent auto-generate it (it adds things like how to run the app). Give each large folder its own CLAUDE.md, which loads only when a file in that folder is opened. Move specialized rules into skills. *When:* Large projects with many folders, or any project where CLAUDE.md is growing.
- **Check spend with the usage command** — Run the usage command to see 5-hour and weekly consumption and which skills, MCP servers and habits consume the most. *When:* Periodically, or when limits are hit sooner than expected.
- **Use a CLI instead of an MCP server when the CLI is enough (Supabase example)** — Install the Supabase CLI, log in with its login command, and let the Supabase skills teach the agent how to call it. The speaker's reasoning: MCP tool names and descriptions stay in context permanently, while the CLI runs through the terminal only when needed. *When:* A service offers both a CLI and an MCP server, and you do not need the MCP's always-on tool listing.
- **Turn off memory and bundled skills** — Run the memory command in Claude Code or Codex to stop saving and loading memories. For bundled skills, set the disable-bundled-skills setting to true in settings (exact key name not clearly spoken; check settings.json). *When:* Work is focused and past memories or review skills are not useful.
- **Disable or cap sub-agent workflows** — Run config, find workflows, and turn them off; if kept, set a maximum size (smaller on a $20 plan). *When:* Any Claude Code setup on a low-tier plan.
- **Filter passing tests out of tool output with a hook** — Ask Claude Code to write a hook that filters passing test results so only failures reach context. The hook is registered in settings.json inside the .claude folder, with its script in the hooks folder. *When:* Test suites where the agent only needs failing cases.
- **Cap bash output length** — In the .claude/settings.json file, reduce the bash max output length from 30,000 to 10,000 characters (spoken key name; verify). Codex equivalent: Tool Output Token Limit, which counts tokens across all tools. *When:* Commands with large logs or verbose output.
- **Replace the built-in advisor with a custom on-demand agent** — Disable the built-in advisor. Create your own agent with the same name so it replaces the built-in one; it calls a stronger model only when the main agent or user decides. For Codex, the speaker configures GPT-5.6 in its config file with reasoning set high (transcript wording garbled at this point; verify at 17:49). *When:* You want a stronger second opinion without paying for it on every call.
- **Message between Claude Code sessions with only the relevant part** — Name each open session and have one message another with only the necessary excerpt instead of the whole context. *When:* Running several sessions on related parts of a project.
