> AI LABS walks through about 19 Hermes agent config settings (context limits, compression, sub-agents, auxiliary models, quick commands, checkpoints, YOLO, isolation mode) that they changed to fix workflow problems, with defaults and new values.

## Summary
The presenters say they hit recurring problems with their Hermes agent setup and found most fixes were existing config options rather than new tools. Hermes keeps each profile's settings in its own config.yaml under the .hermes folder, and changes made with the Hermes config command land in the active profile. The first group covers context and output limits: the tool-output cap (default 50,000 characters, raised for monitoring test runs), the file-read line limit (raised to 5,000 for large policy documents), and the per-line character limit (default 2,000). The second group covers compression: the default 50% threshold compressed too early on a 200k-context model, so they moved it to 0.75, and they kept the 20% target ratio that controls how much uncompressed tail survives. Sub-agent settings follow: max concurrent children raised from 3 to 5, max spawn depth (default 1) raised so sub-agents can spawn sub-agents, and auto-approve turned on so sub-agents are not stalled by permission prompts. The cost group recommends configuring cheaper auxiliary models for background subtasks and lowering the effort level or disabling thinking. The workflow group covers quick commands (exec and alias types), file checkpoints with rollback (off by default), background notifications, an ephemeral system-prompt variable, YOLO mode, an isolation mode that ignores user config, and a personality command. The video is a practical settings tour with concrete defaults and values, but it gives no benchmarks, and the one sponsored segment is excluded from the substance.

## Key ideas
- **Hermes settings live in one config.yaml per profile, and the config command edits the active profile, so the profile must be checked before changing anything.** — Multi-profile setups give each profile its own .hermes subfolder and config.yaml. The Hermes config command writes to whichever profile is active. ([0:00](https://youtu.be/nN6DZi_fiSo?t=0))
- **The default 50,000-character cap on tool output hides long test-run failures, so raise it.** — Tool output beyond the cap is cut off. The presenters raised it while using Hermes to monitor test runs, where failures appeared past the limit. ([1:09](https://youtu.be/nN6DZi_fiSo?t=69))
- **Compression at 50% of the context window fires too early for 200k-context models; they set the threshold to 0.75.** — On a 1M-context model, a 50% threshold means compression at about 500k tokens, which is fine. On a 200k model it fires at about 100k, which breaks long runs. The speaker says Codex and Claude Code use about 75%, which is not verified in the video. ([2:37](https://youtu.be/nN6DZi_fiSo?t=157))
- **The target ratio sets how much recent conversation stays uncompressed as the tail after compression, and the presenters kept the 20% default.** — With a 1M window the tail is about 100k tokens. With 200k it is about 20k. Suggested range is 10% to 80%, where a higher value keeps more context but leaves less room to work. ([4:04](https://youtu.be/nN6DZi_fiSo?t=244))
- **Sub-agent concurrency and nesting are capped by defaults the presenters changed: max concurrent children 3 to 5, and max spawn depth 1 to a higher value.** — Spawn depth 1 blocks any sub-agent from creating its own sub-agents, which blocks nested-repo exploration. Concurrency is token-heavy, so the speaker warns about cost. ([4:30](https://youtu.be/nN6DZi_fiSo?t=270))
- **Sub-agents only inherit the parent's permissions by default, so they stall on prompts unless auto-approve is set to true.** — Auto-approve defaults to false. The video does not discuss the safety trade-off beyond the general YOLO advice. ([5:17](https://youtu.be/nN6DZi_fiSo?t=317))
- **Auxiliary models handle background subtasks such as web search and compression, and the presenters set them to cheap models so the main model is not spent on trivial work.** — When auxiliary models are left empty, Hermes falls back to the cheapest model in the config. In their OpenRouter setup that was Gemini Flash. Sub-agents can also be pointed at smaller models, including from another provider via the Hermes auth command. ([6:45](https://youtu.be/nN6DZi_fiSo?t=405))
- **Effort level is a token lever: lower effort or disabled thinking reduces token use at the cost of output quality.** — The presenters suggest low or minimum effort, or turning thinking off, for cost savings. They do not quantify the trade-off. ([7:53](https://youtu.be/nN6DZi_fiSo?t=473))
- **Quick commands and checkpoints are the workflow fixes: exec commands run a shell sequence, aliases shorten built-in commands, and checkpoints allow rollback after a failed experiment.** — Quick commands are defined in config.yaml. Checkpointing is off by default and is enabled in config, then used via the rollback command. Background process notifications can be set to all. ([9:00](https://youtu.be/nN6DZi_fiSo?t=540))
- **YOLO mode and an isolation mode that ignores the user config are the escape hatches for debugging and speed.** — YOLO can be enabled via a command or a launch flag and is described as the same as Claude Code's dangerously-skip-permissions. Isolation mode strips all .hermes configs so a user can tell whether the error comes from Hermes or from their own config. ([10:28](https://youtu.be/nN6DZi_fiSo?t=628))

## Techniques
- **Per-profile config tuning** — Open the active profile's config.yaml under the .hermes folder, or use the Hermes config command to write the same keys. Check which profile is active first, because the command writes only there. Set the tool-output cap, file-read line limit and per-line character limit for large documents. *When:* When the agent misses details in long test output, long files or long markdown lines.
- **Compression threshold and tail tuning** — Set the compression threshold to 0.75 for models with about 200k context, leaving the default for 1M-context models. Keep the target ratio at 0.2 (20%) and move it toward 10% to 80% depending on how much recent history you want kept after compression. Memory and user memory files have character limits that can also be raised. *When:* On long-running sessions where compression fires too early and drops the thread of the task.
- **Sub-agent concurrency, depth and permission settings** — Raise max concurrent children from 3 to 5. Raise max spawn depth above 1 only if nested sub-agents are needed. Set auto-approve to true for sub-agents so they do not stall on prompts. Change a sub-agent's model to a smaller one, and add other providers with the Hermes auth command. *When:* For broad, parallel tasks such as searching multiple nested repos or doing web searches, where the default limits slow the run.
- **Cheap auxiliary models and effort control** — Configure auxiliary models for background subtasks such as web search and compression, using a cheaper model than the main one. Lower effort to low or minimum, or turn thinking off, for routine work. *When:* When the main model is expensive, such as an Opus-class model, and most of the work is routine.
- **Exec and alias quick commands** — Define an exec quick command in config.yaml to run a shell sequence (for example a git routine) and place its output in context. Define an alias to rename a built-in command, such as a single-letter alias for compress. Aliases must be set in config.yaml, not via a simple command. *When:* For repeatable multi-step shell routines, or for shortening frequently used commands.
- **File checkpoints and rollback** — Enable checkpointing in config (it is off by default). Use the rollback command to restore the saved file state after an experiment breaks something. *When:* Before risky automated edits, so an experiment can be reverted quickly.
- **Ephemeral system-prompt variable** — Set the Hermes ephemeral system prompt environment variable in the terminal session to add instructions to the system prompt. The value applies only to that terminal session and is not persisted. The exact variable name is garbled in the captions, so check the Hermes docs. *When:* For one-off instructions that should not persist across sessions.
- **Isolation mode for config debugging** — Launch Hermes in ignore-user-config mode. It strips all .hermes configs and runs the agent in isolation. If the error disappears, the cause is in your config, and you can bisect from there. *When:* When an error might come from Hermes itself or from a local config change.
