## Summary
The host argues that single-prompt "one-shot" landing pages are misleading and shows a multi-tool workflow for building an animated product landing page. Google's Whisk (Nano Banana image generation with Gemini 3 expanding short edits into detailed prompts) produces a matched first and last keyframe. Google Flow's frame-to-video mode (VO 3.1) then animates between those two frames, and the host notes that prompts must describe the path from start to end and that first attempts can get direction wrong. The Flow MP4 is converted to animated WebP so it can be scroll-mapped as a hero image in a Next.js project. Claude is then prompted with XML-tagged sections (context, requirements, animation behavior, constraints, output) to wire up the scroll animation. The host swaps generic components for HeroUI pieces (Tailwind plus framer-motion), uses Motion.dev for scroll and parallax effects, and copies a 21st.dev component prompt into Claude, which adapted the footer to the project. The video is a tool tour with one anecdotal project and only a single cost figure, with no evals or measured results.

## Techniques
- **Two-keyframe hero animation** — 1) In Whisk, write a subject, scene and style prompt for the first frame (camera, lens reflections, resolution, depth), then iterate with short plain-language edits such as 'only show the lens layering'. 2) Generate the last frame as a related shot, e.g. a technical cutaway. 3) In Google Flow, use frame-to-video with both frames and a prompt that states how the start transitions to the end, the animation style, and the spin or motion direction. 4) If the motion is wrong, re-prompt with just the needed correction. *When:* A scroll-driven hero section that needs a consistent camera or object animation, where a single generated video is unlikely to be right first time.
- **MP4 to animated WebP for scroll mapping** — Upload the Flow MP4 to a free online converter, set it to best quality animated WebP, download, and place the file in the Next.js public/ directory. Reference it as an image. *When:* Short looping animation that must be scroll-scrubbed on a web page and kept light. The host notes that WebP avoids the media-player wrapper MP4 needs.
- **XML-sectioned prompt for an AI coding agent** — Wrap prompt parts in tags: <context> (goal and what is being built), asset locations, <requirements>, <animation_behavior> (e.g. how scrolling drives the animation), <implementation> details, <constraints>, and the required output format. Send the whole prompt to Claude. *When:* Multi-part UI or feature tasks where the agent needs to keep requirements, behaviour and constraints separate.
- **Install individual UI components instead of the whole library** — Choose a library whose visual style fits the target (HeroUI for an Apple-like look). Install only the needed components with the library's per-component install command, not the project-wide install, then ask the agent to replace existing components with them. *When:* Adding a polished visual style to an existing Next.js or Tailwind project without restyling the whole codebase.
- **Copy-paste component prompts from 21st.dev** — On 21st.dev, open a component and copy its agent prompt. The prompt includes project requirements (ShadCN, TypeScript), code and destination paths in the components directory, dependency code, required npm packages, and integration steps. Paste it into the coding agent, which will also tailor the component to the project, e.g. dropping unused social icons from a footer. *When:* Adding a ready-made section (CTA, footer) to a landing page quickly, with the agent handling imports, dependencies and adaptation.
