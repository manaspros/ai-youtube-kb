## Summary
AI LABS walks through six GitHub repos aimed at Claude Code and MCP users, each covered with a short pitch or demo. The first two are resource and workflow picks: awesome-claude-code, a curated list of hooks, workflows and tools (including Claude Squad for running several sessions and a usage monitor), and the BMAD method, an agile workflow where role-specific agents work from a PRD and sprint-sized stories. Next come UI component libraries (shadcn/ui and an awesome-ui-component-library list), which the host suggests the agent can pick from. The second half is about MCP: GitMCP turns any GitHub repo into a remote MCP server for context, FastAPI-MCP exposes existing FastAPI endpoints as MCP tools (demoed on a to-do app driven from Cursor), and mcp-use connects any LLM to MCP servers directly in Python code (Airbnb search example). A Mobbin sponsor segment takes roughly a minute in the first half. No benchmarks or measured results are given; the value is in the pointers.

## Techniques
- **Repo to remote MCP server via GitMCP** — Open the GitMCP site (linked from the GitMCP repo's README). Paste the GitHub repo URL into the prompt box to get a remote MCP server URL, which needs no local docs. Copy the config snippet for your client (the host uses Cursor, and the page also offers Claude Code and Claude Desktop) and paste it into the client's MCP settings. Check that the server shows as active. The site also has a chat mode for one-off questions about a repo without creating a server. *When:* An agent needs a repo's docs or workflows as context and you do not want to read or store them yourself, for example a complex method repo like BMAD.
- **Expose FastAPI endpoints as MCP tools (fastapi_mcp)** — Add the FastAPI-MCP library to an existing FastAPI app. Its endpoints become MCP tools. Connect the resulting MCP server to a client (Cursor in the demo). The host says setup is 'one import' and points to the project's docs; no code is shown in the video. *When:* You have a CRUD-style app with an API and want an LLM to drive it through the same endpoints, as in the to-do-list demo. Access control for the exposed endpoints is not discussed.
- **Use an MCP server from code with mcp-use** — In a Python file, import an LLM client and the mcp_use library. Define the MCP server(s) in a JSON config file (the Airbnb example uses one). Run the script: the library starts the MCP server and the LLM calls its tools, with no MCP client. The host's YouTube example combines a transcript-extraction MCP server with an LLM to summarize a video. The exact code is not shown. *When:* You want an application backend to call external MCP tools directly, instead of using Claude Desktop or Claude Code as the client.
- **Repo dump into markdown as Claude Code context** — Run GitMCP or git ingest on a repo to produce a markdown file of its content. Give that file to Claude Code as context before asking it to build against the repo. *When:* You are working with a framework or repo you do not know well, and you want a single static context file rather than a live MCP server.
- **BMAD staged agile agents** — Work through the method's stages in order: write a PRD, then an architecture doc, then break the project into stories. Each story holds its task and context. Run the dev agent on one story at a time, then test. The host notes the full workflow guide is long and does not show the commands. *When:* A multi-session app build where a single prompt would break down, and you want role agents (PM, architect, dev, UI/UX) with explicit handoffs.
- **Pick UI components with the agent** — Tell the agent which component you need (for example a shadcn/ui component). Browse a framework-specific list such as awesome-ui-component-library, choose components, then let the agent install and wire them in. The host pairs this with the BMAD UI/UX agent. *When:* Building the UI of a web app (React, Vue, Next.js) without designing every component from scratch.
- **Parallel Claude Code sessions and usage monitoring** — Use Claude Squad to manage several Claude Code sessions at once and a Claude Code usage monitor to track instance usage. Both are found through awesome-claude-code. Setup details are not shown. *When:* Running several coding agents in parallel and needing to watch how much of your usage they consume.
