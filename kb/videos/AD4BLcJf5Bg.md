> Side-by-side walkthrough of Windsurf (Codeium) and Cursor, both VS Code forks: inline edits and tab completion are about even, while Windsurf's Cascade agent felt more context-aware and cheaper on paper.

## Summary
The presenter opens the same small React project in Windsurf and Cursor and compares them feature by feature. Inline completion, inline edit (Cmd+I in Windsurf, Cmd+K in Cursor) and terminal command prompts behave almost identically, and the presenter says the chosen model matters more than the IDE. The main difference is Windsurf's Cascade agent, which builds a project from a vague prompt, runs terminal commands with per-step accept, and corrects its own output. Cursor's Composer, in the same test, has less project context: it reached for Tailwind in a plain-CSS project. Cascade also picks up manual edits when asked to "continue my work". The pricing comparison favours Windsurf on both free and Pro tiers, with Cascade capped at 1,000 steps per month. The evidence is one presenter, one project and one run per task, so it is anecdotal, and the prices may have changed since the video's date.

## Key ideas
- **Windsurf and Cursor are both VS Code forks, and the presenter found their core completion, inline-edit and terminal features nearly identical. Output differences came mostly from the model selected.** — Windsurf's Super Complete and Cursor's Tab both do next-edit prediction. Windsurf's first suggestion was wrong (it proposed replacing the URL input), and the presenter says experience varies run to run. Inline edits (Cmd+I vs Cmd+K) produced the same layout change with a different gap value. The presenter says model choice matters more than the editor. ([0:00](https://youtu.be/AD4BLcJf5Bg?t=0))
- **Windsurf positions Cascade as its differentiator: it combines chat, inline edit and an agent that can create files and run terminal commands.** — Cascade has a chat-only mode for developers who don't want AI editing their code. Its write mode, which the presenter calls 'agentic', can scaffold a project from a vague prompt. The presenter says Cursor's Composer can't create a project or run commands in the same way. ([4:34](https://youtu.be/AD4BLcJf5Bg?t=274))
- **Cascade checks its own output against the original request and can be redirected mid-run without losing context.** — It caught that its first output didn't match the goal and fixed it. When it started create-react-app, the presenter stopped the run and asked for Vite, and it carried on with the same task context. ([5:47](https://youtu.be/AD4BLcJf5Bg?t=347))
- **The presenter's main complaint is that Cascade's terminal is unclear. Stopping a step doesn't stop a dev server the agent started, and the terminal isn't the integrated VS Code terminal, so Ctrl+C and history don't work.** — This points to a general problem with agent-run processes: a step's stop control may not terminate the process it spawned. Any harness that runs long-lived processes needs an explicit kill path. ([5:47](https://youtu.be/AD4BLcJf5Bg?t=347))
- **Project context matters more than the model in the presenter's test. Cursor's Composer used Tailwind to fix a styling bug in a plain-CSS project, and Cascade read the project's conventions without being told.** — This is one anecdotal run, not a benchmark. The presenter attributes Composer's mistake to having 'less context of what our project was'. ([8:09](https://youtu.be/AD4BLcJf5Bg?t=489))
- **Cascade's 'continue my work' picks up edits the user made by hand and propagates them: it found the new date field in app.jsx and updated the item component to match. Cursor needed a prompt before it did the same.** — The continuation prompt is a plain-language request that relies on the agent reading the diff or the files the user changed. ([8:09](https://youtu.be/AD4BLcJf5Bg?t=489))
- **Pricing favours Windsurf in the presenter's comparison, but Cascade's 1,000-step monthly limit counts terminal commands as steps, so it is a real budget.** — Figures quoted in the video: Windsurf Pro at $10 a month (described as half Cursor's price), 1,000 Cascade steps per month, unlimited autocomplete and chat on the free tier. Cursor free: 2,000 completions and 50 slow premium requests. ## Techniques
- **Inline edit with a model picker** — Select the code to change, press Cmd+I (Windsurf) or Cmd+K (Cursor), describe the change in the prompt box, and choose the model in the dropdown. Review the proposed diff and click Accept, then save. In Windsurf the default model in this test was a 'Codium Fast' model, and Claude or GPT can be selected from the same dropdown. In Cursor the test used Claude 3.5 Sonnet. *When:* Small, targeted edits to a selection, such as making two buttons sit side by side. The presenter found no meaningful quality gap between the two editors for this.
- **Terminal command prompt with undo context** — Open the terminal's AI prompt (Cmd+I in Windsurf, Cmd+K in Cursor), describe the command in plain language (e.g. resetting the last commit), choose a model, and submit. The command is pasted in for you to run. Then send a follow-up like 'undo that' in the same prompt. Windsurf kept the earlier command in context and reversed it. *When:* Git and shell operations where you don't remember the exact syntax, and when you want to chain a follow-up instruction that depends on the previous command.
- **Agentic scaffold with per-step accept and mid-run redirect** — In Cascade's write mode, give a deliberately vague prompt (the presenter used 'create me a to-do app using React'). Accept each proposed terminal command and file change as it appears. If the agent picks the wrong tool (here create-react-app), press Stop and ask for the one you want (here Vite). The agent keeps its context and proposes new commands. Use 'Accept all' at the end and run the dev server it started (localhost:5173 in the demo). *When:* Bootstrapping small projects where you want the agent to decide the file layout. Keep a close eye on terminal steps, because the stop control may not kill processes the agent started (see the terminal pain point in the video).
- **Continue-my-work after manual edits** — Make a change yourself (e.g. add a Date.now() field in app.jsx). Then open the agent panel and send 'continue my work'. The agent reports which files you changed and proposes the matching edit in related files (e.g. the to-do item component to display the new field). *When:* Iterating on a codebase where you edit some files by hand and want the agent to propagate the change to dependent code without restating the context.
- **Chat-only mode for AI suggestions without edits** — Use Cascade's chat mode (not write mode), select a model, and ask for suggestions. The agent doesn't modify files, so you apply changes yourself. *When:* Developers who want AI suggestions in the editor but don't trust agents to write to the repo, and who want to avoid copy-pasting from a separate chat app.

## Hot takes
- Windsurf's Cascade gives a better user experience and a better understanding of the project than Cursor's Composer, without needing file references (presenter's personal experience).
- The editors are nearly identical, so the choice of AI model matters more than which IDE you use.
- Windsurf is the better value on both free and Pro tiers, but Cascade's 1,000-step limit makes it less 'unlimited' than advertised.
- Windsurf calls itself the first agentic IDE; the presenter repeats this without testing it against other tools.
- Pricing and tier details are as quoted on the video's date (2025-11-02) and may be out of date.
