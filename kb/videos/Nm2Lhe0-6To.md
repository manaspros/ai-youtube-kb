> Walkthrough of Desktop Commander, a free MCP server that gives Claude Desktop file, terminal and edit tools, demoed by building a Next.js and FastAPI image editor from one prompt.

## Summary
The host argues that paid Cursor or Windsurf seats, or open-source editors that need per-token API keys, limit which models a developer can use and how much they can build. He proposes running Desktop Commander, a free MCP server built on the file system MCP server, inside an existing Claude Desktop subscription instead. Installation is a config paste into Claude Desktop, with no extra arguments. He shows the server's configuration tools (blocked commands, default shell, allowed directories, telemetry), changing the shell to zsh through a set tool, and terminal tools that run commands, read output, list and terminate sessions. He also covers a search-and-replace edit tool that avoids rewriting whole files. The main demo prompts for a Next.js frontend with a FastAPI and Python backend for an image editor; the agent also produces run instructions and Docker support. The app is basic, and the one bug he hit (edits not applying back to back, needing two Apply clicks) was fixed by asking the agent in chat. The video is a single run with no failure rates or comparison against Cursor output.

## Techniques
- **Replace an AI IDE with an MCP server in an existing chat client** — Paste the Desktop Commander config into Claude Desktop's MCP configuration (the 'edit configuration' button in settings), then confirm the tools appear under Tools. The transcript does not show the JSON, so take it from the project's README. *When:* You already pay for Claude Desktop and want file, terminal and edit tools without a separate IDE subscription. Expect the agent's tool-permission prompts.
- **One prompt with a target path and an objective** — Give the agent a directory (for example a folder under the home developer directory) and a PRD-style description of the app. Include the stack (Next.js frontend, FastAPI and Python backend) and ask for run instructions and Docker support. *When:* Greenfield project generation where you want a full scaffold from a single prompt.
- **Search-and-replace edits instead of full-file rewrites** — Use the edit tool with the exact old text and the new text. The pattern is optional, but a clear description of the search and replace target still works. *When:* Small changes in large files, where rewriting the whole file wastes tokens and risks clobbering unrelated code.
- **Read and change the MCP server's config through its own tools** — Ask the agent to return the server configuration, then set individual values such as the default shell (he changed it to zsh) using the built-in set tools. *When:* Adjusting allowed directories, blocked commands or the shell, especially for a remote server where you cannot edit a local file.
- **Run-and-verify loop with bug reports in chat** — Start the generated app yourself, run each feature, and describe any bug to the agent in the same chat. Ask it to fix the defect in the code and retest. *When:* Validating agent-generated apps where the UI is basic but the logic must work, such as chained edits.
- **Side-by-side IDE view with agent edits** — Open the project in VS Code while the agent works on the same files, then inspect the diffs and make manual changes. *When:* You want to read and hand-edit code without a Cursor-style IDE agent.
