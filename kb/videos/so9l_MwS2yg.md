> Zack Proser (WorkOS) argues human attention, not agent capacity, is the bottleneck, and shares remote Claude Code from a phone, verification gates, and session-log mining to protect focus.

## Summary
Zack Proser, on WorkOS's Applied AI team, says agents now scale almost without limit, but the developer's attention degrades under load and is the real constraint. He gives a concrete example: he asked Claude Code, which had Slack and Linear access, to fix a sentence-case bug, and it reproduced the issue, fixed it, and verified the result without him steering it. He describes a stack of "signal layers" (cheap monitoring of Slack and tickets), voice-first input, and remote control, where a session started at the desk can be driven from a phone while walking away. He lays out three verification gates (lint/build/unit tests via hooks, a browser click-through, and a separate reviewing agent checked against a written constitution), and says speed requires safety. He recommends a scheduled pass over saved Claude Code JSONL conversation logs to find struggle, extra thinking, and missing skills, and notes the built-in skill-creation tool. The Q&A covers early-career skill building (don't delegate what you can't already do), overnight agent loops on tickets tagged "agent ready", voice use, and parallel work with git worktrees and agent teams.

## Key ideas
- **Human attention is the hard constraint, not agent throughput** — Agents can loop until they meet the criteria they are given, but judgment, taste, and knowing a problem is truly solved stay with the human. Linear scaling of what you take on will burn you out fast. ([3:35](https://youtu.be/so9l_MwS2yg?t=215))
- **Closed-loop bug fixing via MCP access plus explicit verification criteria** — Giving Claude Code Slack and Linear access and an instruction to verify its own work and not stop until done let it reproduce, fix, and confirm a bug end to end. The speaker came back to a finished loop without a follow-up prompt. ([0:59](https://youtu.be/so9l_MwS2yg?t=59))
- **Signal layers filter the noise of many tools** — An agent reads Slack mentions, DMs and tickets on a loop, deduplicates asks against Linear, and surfaces only the high-priority items. This protects focus from the constant context switches that agents make worse. ([5:02](https://youtu.be/so9l_MwS2yg?t=302))
- **Remote control turns walk-away time into work time** — A Claude Code session started at the desk runs on the dev machine with full file access. It can be reached from a phone on another network, so the developer can send new design ideas and review PRs while away from the desk. ([9:41](https://youtu.be/so9l_MwS2yg?t=581))
- **Verification gates scale from cheap checks to independent review** — Gate 1 is lint, build and unit tests run via hooks on every change. Gate 2 requires a browser click-through to confirm nothing broke, such as login. Gate 3 is a separate agent that checks the work against a written set of rules, similar to a constitution. Speed requires safety. ([10:47](https://youtu.be/so9l_MwS2yg?t=647))
- **Mine your own saved agent sessions for the harness to improve** — Claude Code saves conversations locally as JSONL. A scheduled pass, or a session-end hook that writes key points to a markdown store, can find where you spent extra thinking, went back and forth on ambiguity, or lacked a skill. The fixes then go back into skills or tools. ([13:02](https://youtu.be/so9l_MwS2yg?t=782))
- **Use the built-in skill tooling to build, evaluate and improve skills** — The speaker notes Claude Code has a built-in skill that creates, evaluates and improves skills from a natural-language prompt. He recommends using it to close the gaps that session review finds. ([14:15](https://youtu.be/so9l_MwS2yg?t=855))
- **Scale bigger work with worktrees, agent teams and CI, not chat alone** — For large cross-stack features, use git worktrees so agents run in parallel without touching each other's files, give each team clear prompts, and rely on unit tests and continuous integration against a spec. Humans then supply the review and correction. ([24:03](https://youtu.be/so9l_MwS2yg?t=1443))
- **Learn the hard way first, then delegate** — His advice for early-career engineers is not to use AI for something they cannot already do. Build battle-tested skills, then use the tools to speed up work in areas where you already have the judgment to catch bad output. ([16:55](https://youtu.be/so9l_MwS2yg?t=1015))

## Techniques
- **Three-tier verification ladder for agent output** — Gate 1: hooks run lint, build and unit tests on every change. Gate 2: the prompt requires a browser click-through of key flows such as login (Claude Code can be started with a --chrome flag for its own browser). Gate 3: a separate reviewing agent checks the diff against a written rules document and returns feedback to act on. *When:* When agent-written code must ship without line-by-line human review, and you want the agent to prove it is done before reporting success.
- **Closed-loop ticket fixing with explicit done criteria** — Connect the agent to Slack and the issue tracker through MCP. Give it the bug, the acceptance criteria, and an instruction to verify and not stop until verified. It reads the ticket, reproduces, fixes, and confirms the outcome in the same session. *When:* For bounded bugs with a checkable outcome, to save developer attention on triage and follow-up.
- **Remote-controlled session from a phone** — Start a Claude Code session with the remote-control flag or config setting on the dev machine. Continue it from a phone on any network, send messages, and review PRs there. Leave natural-language PR comments that tag the coding agent. *When:* When you want agents to keep working while away from the desk, and design ideas that come up on walks can be applied without a return trip.
- **Scheduled session-log retrospective** — Either run a weekly or daily agent pass over saved Claude Code JSONL logs with a prompt that looks for churn, excess thinking tokens, back-and-forth clarification, and missing skills or tools. Or use a session-end hook to save key points and struggles to Markdown, then analyse that store on a schedule. *When:* When you want the agent harness and skills to improve from routine work without relying on memory to review it.
- **Ticket-tagged overnight agent loop** — Create linear tickets with subtasks for bugs and features, tag ready ones 'agent ready', and run a loop every 15 minutes that picks up tagged work. Review the output in the morning and merge the small share that passes. *When:* When backlog work is well-specified and you accept a low merge rate in exchange for unattended throughput.
- **Parallel large features with worktrees and agent teams** — Give each agent its own git worktree so runs do not conflict. Assign each team a clearly scoped prompt. Lean on unit tests and continuous integration as the shared check against a spec, and keep a human in the loop for correction. *When:* For features that touch the whole stack, where one agent on one branch would be too slow or would collide with other work.
- **Voice-first brainstorm, then written artifact** — Brain-dump ideas by voice (the speaker uses ChatGPT advanced voice mode on walks, and a local open-source speech tool), then ask the model to turn the discussion into a succinct transcript or architecture note to paste into the coding agent. *When:* When you think best away from the keyboard, and want the result to feed a coding session.

## Hot takes
- The agents are not the bottleneck anymore; we are.
- Speed requires safety: without verification gates, faster agents just ship more breakage.
- Don't use AI to do something you don't already know how to do. You need the scar tissue to catch hallucinations.
- Burnout will arrive faster with LLMs unless you deliberately protect yourself, so intentional pacing is the real productivity skill.
