## Techniques
- **CLAUDE.md verification loop for long autonomous runs** — Put instructions in CLAUDE.md telling the agent to test after every implementation and to confirm the feature works before moving on. Use a visual check (Claude Chrome extension) for UI work. The speaker does not show the file contents, so the exact wording is not in the talk. *When:* Autonomous or long-running tasks where the agent must show that each step works before the next one starts.
- **Commit each verified unit, with decisions in the message** — After tests and visual checks pass, commit with a descriptive message. Ask the agent to record the decisions it made in the commit message so commits are clean and reviewable. Use git to roll back changes to code or tests the agent should not have touched. *When:* Any multi-step agent run where you need rollback and an audit trail of what changed and why.
- **Split work into small independent units and run agents in parallel** — Ask the agent to break a task into small units that do not depend on each other, then assign each unit to a separate agent running at the same time. *When:* Tasks that can be divided without shared state, such as separate features, modules or review passes.
- **Custom specialist subagents with chosen models and instructions** — Define subagents for specific jobs, each with its own instructions and model chosen for the task's difficulty. Subagents get their own context window, which keeps the orchestrator's context from bloating. *When:* Mixed-difficulty workloads where cheaper models can handle some subtasks and the orchestrator needs to stay focused.
- **Plan mode with agent questions before building** — Turn on plan mode and let the agent ask questions about the app. Answer them, let it produce a plan, then have it build from the plan. The speaker used this to build a backend in an unfamiliar language. *When:* Working in a stack or language you do not know well, or starting a feature from scratch.
- **Agent first-pass review with human review of exceptions** — Have agents review output for security, architecture consistency and quality. Human reviewers look only at flagged exceptions or high-risk areas instead of every change. *When:* When agent output volume is greater than what humans can read.
- **Layered security agents plus an external scanner** — Run dedicated agents for code review, testing and server-side access control, then add an external tool such as CodeRabbit to catch known vulnerability patterns early. The talk does not give configuration details. *When:* Applications built with agent assistance, especially when non-security engineers are doing the building.
