> Practical habits for managing Claude Code's context window (compaction, clear, rewind, sub-agents, recaps) to limit context rot and goal drift in long runs; mostly attributed advice with a sponsored segment.

## Summary
The speaker argues that the 1M-token context window does not solve degradation in Claude Code, because "context rot" (performance dropping as the window fills with information) can begin well before the window is full, with a figure of roughly 300-400k tokens attributed to the Claude Code creator. He names four failure modes for long-running agents: context pollution, goal drift, memory corruption, and decision inaccuracy. The core advice is to choose deliberately after each task between continuing, compacting, clearing, a structured save-then-clear handoff, and rewinding. He recommends controlling compaction yourself with an explicit instruction rather than letting auto-compact fire mid-task, and clearing when switching to an unrelated task. He also suggests periodic recaps to push goals back into recent context, delegating research, refactoring, summarization and doc generation to sub-agents that return only final output, and rewinding (Esc twice or the rewind command) instead of correcting forward. Much of the framing is secondhand (an article by a Claude Code engineer and the creator's remarks), and the video includes a sponsor segment for Verdant.

## Key ideas
- **A 1M-token window does not remove degradation. Context rot can start well before the window is half full.** — The speaker says the creator of Claude Code puts the onset around 300-400k tokens, and that a bloated window gives more distractors to interfere with reasoning. This is a secondhand, single-source figure. ([0:00](https://youtu.be/O1XLCh-uA_E?t=0))
- **Four failure modes for agents that manage context badly: context pollution, goal drift, memory corruption, decision inaccuracy.** — Memory corruption example: the agent writes a file, a sub-agent outside its context modifies it, and the agent keeps acting on the stale version. Decision inaccuracy: inconsistent choices in near-identical situations, such as two different error-handling patterns. ([2:28](https://youtu.be/O1XLCh-uA_E?t=148))
- **After a task finishes, pick the next move on purpose: continue, compact, clear, clear-plus-structured-save, or rewind.** — Continuing is the default, but the speaker argues the choice should depend on whether the next prompt is part of the same flow. ([3:55](https://youtu.be/O1XLCh-uA_E?t=235))
- **Auto-compaction is lossy and least reliable mid-task. Compact yourself at a chosen point and give it explicit instructions.** — Compaction is a summary that drops details the model judges unimportant. Recency bias keeps recent work and can lose older mistakes or warnings. Tool-call history is not fully preserved. The speaker advises triggering compaction around 300-400k and listing decisions, constraints and discovered issues to carry forward. ([4:30](https://youtu.be/O1XLCh-uA_E?t=270))
- **Clear to start fresh when switching to an unrelated task, so the earlier task does not bias the new one.** — Example: after generating test cases, start a new session for debugging so the test-generation reasoning does not shape the debugging. ([6:50](https://youtu.be/O1XLCh-uA_E?t=410))
- **Combine clear and compaction through a structured JSON state file.** — A custom command has the agent write task, current state, constraints and discovered issues into a file in a fixed schema. Then clear the context and start a new session that reads the file. The speaker says a schema is stricter than prose, so the agent represents important state more consistently. ([8:17](https://youtu.be/O1XLCh-uA_E?t=497))
- **Pause periodically to have the agent recap its work, constraints and goals, which moves them back into recent context.** — This targets goal drift and decision inconsistency, since the recap sits in the recent part of the window that survives compaction better. ([8:17](https://youtu.be/O1XLCh-uA_E?t=497))
- **Use sub-agents to keep raw intermediate work out of the main context. Only the final output comes back.** — Each sub-agent has its own context window and tools. The test is whether you will need the intermediate steps again. Research (many pages, many sources) is the clearest case. The speaker says Claude Code can spawn sub-agents itself, but you can also ask for delegation explicitly. ([9:43](https://youtu.be/O1XLCh-uA_E?t=583))
- **Rewind instead of correcting forward, so wrong turns leave the context entirely.** — Rewinding removes the bad attempt, and summarizing from that point keeps only the correct state. This also gives sub-agents a cleaner starting context and avoids carrying the wrong approach into a later compaction. ([11:07](https://youtu.be/O1XLCh-uA_E?t=667))

## Techniques
- **Manual compaction with an explicit instruction** — Do not wait for auto-compact. At a reasonable point (the speaker suggests around 300-400k tokens), compact on purpose and give an instruction that lists the decisions, constraints and discovered issues to carry forward. The speaker says flags exist to control when auto-compaction fires but does not name them in the video. *When:* A long session where you want the previous task's context to carry into the next window, not a fresh start.
- **Clear on task switch** — Run the clear command when the next task is unrelated to the current one. Start a new session and give only the context the new task needs. *When:* Switching from generating tests to debugging, or any change of task where old reasoning would bias the new one. Not as a reflex when the window is only getting full mid-task.
- **Structured state handoff (save, clear, reload)** — Create a custom command that asks the agent to analyze the conversation and current application state, then write a JSON file with the full task, current state, constraints, discovered issues, and other relevant fields. After the file is saved, run clear. In the new session, tell the agent to read that file and continue from it. The speaker gives the field categories but not a full schema. *When:* Long-running work that must resume in a new session. Stricter than prose compaction because the structure is enforced.
- **Periodic recap to reinforce goals** — Stop during a long task and ask the agent to recap what it has done, the constraints, and the important factors before continuing. *When:* Long runs where the agent starts to drift or contradict earlier decisions.
- **Sub-agent isolation for raw-heavy subtasks** — Explicitly tell Claude Code to delegate the subtask to a sub-agent. The sub-agent works in its own context and returns only the final output to the parent. Decide by asking whether you will need the intermediate steps again. *When:* Research across many pages or sources, refactoring, summarization, or document generation, where only the synthesis matters.
- **Rewind, then re-prompt** — When the agent makes a mistake, rewind with the rewind command or by pressing Esc twice. Optionally summarize from that point so the correct earlier work is kept. Then give the corrected direction in a new prompt, instead of correcting forward. *When:* Any time the agent goes wrong. Prefer this to repeated corrections, which leave the failed attempt in context.
