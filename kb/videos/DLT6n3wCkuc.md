- **Temporal reached stage 4 in March after about nine years in development, and is the largest of the confirmed features.** — Speaker says it is ready to ship and that Firefox, Chrome, Node.js and Deno already have it. Bun is 'coming soon' and Safari 'needs to catch up' (per the speaker). ([0:00](https://youtu.be/DLT6n3wCkuc?t=0))
- **Temporal replaces one Date object with separate types that each do one job: PlainDate, PlainTime, Instant, ZonedDateTime and Duration.** — Instant is a point in time as nanoseconds since the Unix epoch. ZonedDateTime is a full date-time in a real zone that understands DST. Duration gives date math without ad hoc millisecond arithmetic. ([1:04](https://youtu.be/DLT6n3wCkuc?t=64))
- **Temporal handles DST across a flight example. A 8pm New York departure plus a 7-hour flight should land at 8am London by naive math, but Temporal gives 7am, which the speaker says is correct because the London clocks change that night.** — The speaker uses get time zone transition (spoken form) to confirm the London change happened at 1am London time. ([1:04](https://youtu.be/DLT6n3wCkuc?t=64))
- **Temporal's day-based arithmetic keeps wall-clock intent: pushing an 11am meeting back one day stays at 11am across a clock change instead of shifting to 10am.** — Temporal treats the operation as days, not 24-hour spans. Immutability is the second advantage the speaker names: every operation returns a new object, so an original date is never mutated behind your back. ([2:07](https://youtu.be/DLT6n3wCkuc?t=127))
- **Explicit resource management (the using keyword) reached stage 4 in May. A variable declared with using has its Symbol.dispose method called when it goes out of scope, including at the end of a block, on an early return or on an exception.** — Targets file handles, database connections and streams that otherwise need try/finally blocks or leak. The speaker says it has been available in Firefox, Chrome, Node and Deno for some time. ([2:07](https://youtu.be/DLT6n3wCkuc?t=127))
- **Async cleanup uses an async dispose method, and DisposableStack composes several resources so they are torn down in reverse order.** — The speaker frames this as helpers for cleaning up the try/finally code, with no further detail on syntax. ([3:19](https://youtu.be/DLT6n3wCkuc?t=199))
- **iterator.zip iterates several iterables in parallel and yields an array per step. zipKeyed does the same but yields named objects. Mode controls unequal lengths: shortest (default), longest (with optional padding values) or strict (throws a TypeError).** — The speaker says zip is currently only usable in Firefox, and that it extends the ES2025 iterator helpers (map, filter, take, drop) with stage 3 proposals for chunking, includes and join. ([3:19](https://youtu.be/DLT6n3wCkuc?t=199))
- **Atomics.pause is a low-level hint for spin-waiting on shared memory. It is for library authors, shown with a spin lock on a SharedArrayBuffer built on Atomics.compareExchange.** — Without a hint, a tight spin loop can hammer the CPU; the speaker says Atomics.pause lets the runtime and CPU handle the spin more efficiently. - **Stage 3 items include import defer (the module is loaded but its top-level code runs on first use, which is lazy execution rather than lazy loading), Promise.all keyed (named results in an object), and standard decorators (stage 3 since 2022, shipped by Bun in February).** — The speaker argues import defer targets startup time for apps with large dependency graphs and is distinct from dynamic import. - **Signals (stage 1) would add a built-in reactive primitive with writable values, computed values and automatic dependency tracking, so frameworks such as Angular, Vue, Svelte and Solid could share one low-level core.** — The speaker calls this the most exciting proposal but says it may take a long time to land. It is the least certain item in the video. ([5:35](https://youtu.be/DLT6n3wCkuc?t=335))

## Techniques
- **Replace Date with Temporal types by job** — Use PlainDate for calendar dates with no time or zone, PlainTime for wall-clock times, Instant for a unique point in time, ZonedDateTime for a real zone with DST handling, and Duration for arithmetic. Do date-level math in days rather than adding milliseconds. Remember every operation returns a new immutable object. *When:* Scheduling or recurring events, cross-timezone flights and meetings, and anywhere a codebase currently adds milliseconds or mutates Date objects.
- **Check DST transitions with getTimeZoneTransition** — The speaker uses the method (spoken as 'get time zone transition') on a ZonedDateTime to find when a zone's offset changes, here the 1am London change. *When:* Debugging or verifying time-zone logic around a clock change, and confirming Temporal results.
- **Scope-bound cleanup with using and Symbol.dispose** — Declare the resource with the using keyword. The object implements a Symbol.dispose method, which the runtime calls automatically at block end, on early return or on exception. Use the async dispose variant (Symbol.asyncDispose) when cleanup is asynchronous. *When:* File handles, database connections, streams, or any resource that today needs try/finally or is easy to leak.
- **Compose resources with DisposableStack** — Register several disposable resources in a DisposableStack so they are torn down in reverse order when the stack is disposed. *When:* A function that opens multiple resources that must be released in dependency order.
- **Parallel iteration with iterator.zip and zipKeyed** — Pass several iterables to iterator.zip to get an array of the next value from each input per step. Use zipKeyed for named objects. Choose mode: shortest (default), longest with optional padding values, or strict to throw a TypeError on unequal lengths. *When:* Combining parallel arrays such as names, ages and cities into records. Note the speaker says it is currently only available in Firefox.
- **Spin-wait hint with Atomics.pause** — Inside a spin loop on a shared Int32Array in a SharedArrayBuffer, which uses Atomics.compareExchange to acquire a lock, call Atomics.pause on each iteration to tell the runtime and CPU that the wait is intentional. *When:* Multi-threaded code with workers and shared memory, such as a library's lock implementation, where a tight spin would waste CPU.
- **Named results with Promise.all keyed** — Pass Promise.all an object of promises instead of an array. The result is an object with the same keys, so the code destructures by name rather than by position. *When:* Several independent async calls whose positional order is hard to track. Stage 3, so verify runtime support first.
- **Lazy execution with import defer** — Mark an import as deferred. The module is fetched at load time, but its top-level code runs only on first use. The speaker contrasts this with dynamic import, which defers the fetch itself. *When:* Apps with large dependency graphs where startup time is the problem. Stage 3, so check runtime support first.
