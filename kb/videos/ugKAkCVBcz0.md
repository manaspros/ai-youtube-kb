> Local model picks for 8 to 24 GB VRAM. The GGUF file (quant method and uploader) matters more than the model name, MoE models survive RAM spill while dense ones collapse, and thinking tokens often dominate wall time.

## Summary
The host opens with a failed local setup (a dense 27B model on an 8 GB RTX 4060 took 2.5 hours for one page at 4.2 tok/s) and argues that the wrong file, not the wrong model, was the real mistake. Decode speed is memory-bound: each generated token reads the full weights, so tokens/s is capped by memory bandwidth divided by bytes read per token. Dense models that spill out of VRAM fall to system-RAM bandwidth and crawl, while Qwen 3.6 35B-A3B (MoE, about 3B active) can keep most experts in RAM and run far faster on small cards. The video then goes card by card (8, 12, 16, 24 GB). On 12 GB and 16 GB, the same model at the same bit width differs a lot by uploader and by how bits are allocated, with ISTA's searched-bit builds winning on self-reported benchmarks. On 16 GB the default Q4 file silently spills because of desktop VRAM use. The host also argues that KV cache squeezing, reasoning-token count, and GPU thermals (3090 Founders Edition memory at 112 C) change real results, and recommends checking local outputs against frontier models on five of your own prompts. A sponsored segment for Chat LLM by Abacus AI sits in the middle.

## Key ideas
- **The file matters more than the model name. Same model, same 2-bit level, two uploaders: one fixed 16 of 20 real Python bugs, the other fixed 7. The bigger file (8.98 GB) was the worse one, because how bits are assigned across layers matters more than total size.** — ISTA's build runs a search that gives more precision to sensitive parts of the model under a fixed size budget. Most other builds use a fixed bit count per layer. Check who made the file before checking its bit count. ([8:12](https://youtu.be/ugKAkCVBcz0?t=492))
- **Decode is memory-bound. Each generated token reads the full active weights, so the ceiling is bandwidth divided by bytes read per token. A 16.46 GB file on a 936 GB/s RTX 3090 gives about 57 tok/s; one user measured 41.** — If the model spills into dual-channel DDR4 (about 51 GB/s), throughput drops about 18x. DDR5 is still roughly 10x slower than GPU memory. Every token waits on the slowest memory holding any part of the model. ([2:17](https://youtu.be/ugKAkCVBcz0?t=137))
- **Dense and MoE models follow different rules when VRAM is short. Dense models want to live fully in VRAM and crawl when they spill. MoE models with a small active set can keep most experts in system RAM and stay usable.** — Qwen 3.6 35B-A3B has 35B total parameters with about 3B active per token, so each token reads under 2 GB, roughly a ninth of a dense 27B model's per-token reads. On an RTX 2060 (6 GB) with 32 GB DDR4, one llama.cpp flag that keeps experts in RAM gave about 23 tok/s, against 4.2 tok/s for the dense model on an 8 GB 4060. ([3:38](https://youtu.be/ugKAkCVBcz0?t=218))
- **On 8 GB cards, system RAM is the real spec. 32 GB of RAM is the floor for running the 35B-A3B file with experts offloaded, and the host says that beats most 8 GB recommendations.** — Without that much RAM, a small dense model such as Gemma 12B at Q3 (about 5.7 GB) fits fully on the card for chat, but the host does not expect it to handle agent workflows. ([4:36](https://youtu.be/ugKAkCVBcz0?t=276))
- **On 16 GB the default Q4 file silently spills. The card's 17.18 GB leaves 0.72 GB of headroom, and Windows desktop and browser already use 1 to 2.3 GB of VRAM, so the default 16.46 GB Qwen file runs over and speed collapses without an error. The fix is a 3.5-bit ISTA build (11.77 GB), about 14.4 GB with the speculative decoding head and a 64k context.** — The host notes that the 16 GB tier also depends on context cache size, not only the model file. ([9:26](https://youtu.be/ugKAkCVBcz0?t=566))
- **Tokens per second is not time to answer. Reasoning models spend many thinking tokens before the answer. Qwen 27B used about 20,000 thinking tokens on one moderate prompt: over an hour at 4.2 tok/s on the 8 GB card, about 8 minutes on a 3090.** — A fast model that rambles can lose to a slower one that answers directly. The host recommends measuring total time to a finished task. ([13:17](https://youtu.be/ugKAkCVBcz0?t=797))
- **For 16 to 24 GB, spend memory on the model file first and on the KV cache second for Qwen. Across 189 benchmarks of 27B builds, one person found a bigger file with the cache squeezed to 4-bit beat a smaller file with a full-size cache. The host warns that Gemma models want full-size cache, so the rule is model-specific.** — Qwen 3.6 27B keeps growing cache in 16 of its 64 layers. At 24 GB, Q4 with a 128k context and an 8-bit cache sits around 21 GB and runs about 41 tok/s on a 3090. ([10:47](https://youtu.be/ugKAkCVBcz0?t=647))
- **Validate local models against frontier models on your own work. Take five prompts from your real workload, run them locally and on large hosted models side by side, and see whether the local output is good enough before buying hardware.** — The host frames this as the only way the benchmark numbers in the video mean anything for a specific use case. This is a practitioner recommendation, not a measured result. ([5:57](https://youtu.be/ugKAkCVBcz0?t=357))
- **Thermals and power limits change the numbers. On a 3090 Founders Edition, memory hit 112 C within seconds of heavy generation on the stock fan curve. Capping at 270 W with fans at 100% brought it in spec but cost about 30% of speed (41 tok/s down to about 29).** — The host says to plan around sustained speed, not the peak number. ([14:22](https://youtu.be/ugKAkCVBcz0?t=862))

## Techniques
- **Back-of-envelope decode ceiling** — Estimate the ceiling as memory bandwidth divided by bytes read per token. For dense models, bytes per token is roughly the whole file. For MoE, use total active parameters times bits per weight. Example: a 16.46 GB file on 936 GB/s gives about 57 tok/s. Compare with a measured number to sanity-check the setup (about 41 measured on a 3090). *When:* Before downloading a model or buying hardware, to see whether a model will be usable at all, and to tell whether a slow run is a spill problem or a config problem.
- **Fit check with desktop headroom** — Require file size + context KV cache + speculative decoding head + roughly 1 to 2.3 GB for Windows desktop and browser to fit inside VRAM. Keep a margin: the 16 GB card's 17.18 GB is not enough for a 16.46 GB Q4 file. *When:* Choosing a quant file for a fixed VRAM budget, especially on Windows, where a spill is silent.
- **MoE expert offload to system RAM** — Load a MoE model in llama.cpp with the flag that keeps most expert weights in system RAM (the flag name is not spoken in the video; the host only says 'one flag in llama.cpp'). Keep attention and the active path on the GPU. Pair with enough system RAM (32 GB cited as the floor for the 35B-A3B file). *When:* A small-VRAM card (6 to 8 GB) with a lot of system RAM, running a MoE model with a small active set.
- **Pick the quant by builder, then bit width** — Compare files of the same model and the same nominal bit width from different uploaders. Prefer builds that allocate bits per layer under a size budget (ISTA's searched builds) over fixed per-layer bit counts. Check task-specific results (the video cites a 20-bug Python repo test) before picking. *When:* A 12 GB or 16 GB card where two 2-bit or 3-bit files of similar size behave very differently.
- **Quantize the KV cache for Qwen, not Gemma** — For Qwen 3.6 27B at 16 to 24 GB, set the cache to 4-bit (or 8-bit at a 128k context on 24 GB) and spend the saved memory on a larger model file. For Gemma, keep the cache at full size, per the host. *When:* A model file and a long context compete for VRAM, and the model family is known.
- **Time-to-answer measurement** — Time the full task (thinking plus output) rather than reading tokens/s. Count reasoning tokens in the output; the host gives 20,000 thinking tokens on one prompt for Qwen 27B and 12,577 for the Bolt model before code output. *When:* Comparing a fast small-active model with a slower dense one for a real coding or agent task.
- **Power-cap for sustained speed on a 3090 Founders Edition** — Cap the card at 270 W and set fans to 100% to bring memory temperature back in spec. The host measured about 30% speed loss under the cap. *When:* Long generation sessions on a 3090 Founders Edition where memory temperature exceeds spec on the stock fan curve.
- **Side-by-side local vs frontier check** — Pick 5 prompts from the real workload. Run them on the local model and on large hosted models, then compare outputs side by side. *When:* Deciding whether a local model is good enough, or whether to send specific jobs to hosted models.

## Hot takes
- The right file matters more than the right model: 'the bits decide whether a model fits, but the file maker decides whether it works.'
- A dense model on a small card is worse than a larger MoE model with experts in RAM; tier lists that rank by model size miss this.
- Tokens per second is misleading for reasoning models; time-to-answer including thinking tokens is the real metric.
- The ISTA numbers are self-reported by the builder, and the host says so. The independent 20-bug test is the stronger evidence.
- NVIDIA's Bolt chart compares it to Qwen 3.6 35B-A3B but omits the dense Qwen 27B that many 24 GB users run; the host calls the Bolt win premature and suggests waiting for real-world reports.
- Sponsored segment at about 7:02 (Chat LLM by Abacus AI, $10/month) is pitched as a way to compare local and hosted outputs. The rest of the video is substantive. Auto-captions mis-spell several model names (for example 'Quen', 'Lama CPP', 'Onslaught', 'DeepSig'); the notes use the corrected names where the context makes them clear.
