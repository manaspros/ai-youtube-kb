> A host walks through a multi-agent Claude Code workflow for building an app: specialized sub-agents run in sequence, each writing its output to docs, with checkpoints for rollback and a generated agent-workflow setup.

## Summary
The host argues that Claude Code sub-agents are more than custom slash-command helpers. Each sub-agent gets its own context window, so a main session can act as controller and hand specialized work to agents that return only essential results. He builds a YouTube production manager app with a chain of agents: a UX researcher, a sprint prioritizer, a UI designer, a whimsy injector, a rapid prototyper, a front-end developer, a test runner and a performance benchmarker. Each phase's output is written to documentation files so later agents can use it. He reports that his first run produced a cluttered, poor-looking UI because planning lacked review, and fixed it by planning features in a separate chat before constraining the UX agent to UX only. He also covers Claude Code's checkpoint rewind (double Escape), a gitingest-based way to generate an agent workflow from a repo of agent definitions, and the token cost, which pushed him from the $20 plan to a $100 plan. The evidence is one personal project shown by narration, with a few token and time figures and no baseline comparison.

## Key ideas
- **Sub-agents are chainable and parallelizable, which slash commands cannot do** — The host says each sub-agent gets its own context window and that agents can be chained (one identifies issues, another fixes them) or run in parallel. In a demo, five agents each wrote a line to a shared hello.md file at the same time. ([1:03](https://youtu.be/7Sx0o-41r2k?t=63))
- **Main session as controller, specialized agents as workers** — The host describes the main session distributing work to specialized agents. Each agent keeps the context for its own task and returns only essential information, so the main session's context stays lean. This is a claim he presents as the reason the output is better; he does not measure it. ([1:03](https://youtu.be/7Sx0o-41r2k?t=63))
- **Build the context and plan before any code** — He starts by creating a documentation structure. A UX researcher agent then defines navigation and user experience (not visuals), and a sprint prioritizer splits the work into small sprints, all triggered by one prompt through prompt chaining. Planning output stays in documentation, which he calls critical because thorough planning makes implementation straightforward. ([3:24](https://youtu.be/7Sx0o-41r2k?t=204))
- **Planning failures show up as bad UI, and the fix is review plus scoping** — The first prototype looked cluttered, with widgets that looked bad further down the page. He traced it to insufficient planning and planning that had no review. His fix: have a separate chat assistant break down the features from the raw idea, then limit the UX researcher to UX decisions and not feature scope. ([8:23](https://youtu.be/7Sx0o-41r2k?t=503))
- **Checkpoints give per-prompt rollback in Claude Code** — Pressing Escape twice opens a menu of earlier prompt states (branches) that you can switch back to. The host says checkpoints are created automatically at each prompt, and he notes Cursor had this first. ([5:49](https://youtu.be/7Sx0o-41r2k?t=349))
- **Generate the agent workflow from a repo of agent definitions** — He pulls a public repo of Claude Code sub-agents organized by department and converts it to LLM-readable text with gitingest.com. He pastes that text into Claude Code with an example of agent chaining from the Claude Code docs and asks for a coding workflow with connections between agents. He says the agent context must be recorded in markdown files because it is too large to pass between agents directly. ([5:49](https://youtu.be/7Sx0o-41r2k?t=349))
- **Sub-agents are expensive, and the host upgraded plans because of it** — He says sub-agent runs take a long time and use many tokens. He exhausted the $20 Pro plan and moved to the $100 plan, which he recommends with Claude Opus, even without sub-agents. ([10:31](https://youtu.be/7Sx0o-41r2k?t=631))

## Techniques
- **Phased sub-agent chain driven by one prompt** — Define one agent per phase (UX research, sprint planning, UI design, whimsy/micro-interaction design, rapid prototype, front-end build, test runner, performance benchmark). Ask Claude to run them in sequence with a single prompt, so each agent's output (written to docs/MD files) feeds the next. Each agent is a separate file whose content is copied into the Claude agents folder. *When:* Greenfield app builds where planning, design, implementation and QA are separate stages and each needs a clean context window.
- **Parallel sub-agent fan-out** — Ask Claude to use every sub-agent on the same small task (the demo had each agent write a greeting into hello.md). Claude can run them in parallel, e.g. several UI design options at once. *When:* Independent subtasks such as generating several design options or reviewing separate modules at the same time.
- **Docs-first planning with scoped agents** — Before coding, set up a documentation structure, then run UX research and sprint breakdown into docs. Restrict the UX agent to user experience and navigation, not feature decisions, and keep design agents documentation-only so they do not implement. *When:* When an early prototype looks cluttered or off-scope, because planning is the stage that determines the final UI.
- **Two-stage requirements before agent planning** — Give the raw app idea to a separate chat assistant (the host used Claude Desktop) to decompose it into features and refined agent prompts. Review the output, then feed it into the agent workflow as the scope source. *When:* Before running a multi-agent build, to stop the agents from inventing features or pages.
- **Rewind with double-Escape checkpoints** — Press Escape twice in Claude Code to open the list of prompt checkpoints, then switch to an earlier one. Checkpoints are created automatically per prompt. *When:* When a long agent run goes wrong at one phase and you want to return to the state before that prompt.
- **Generate an agent workflow from a repo** — Run the agent repo through gitingest.com to get one text dump. Paste it into Claude Code along with an example of chained-agent workflows from the Claude Code docs, and ask for a workflow with connections between agents. Remove unneeded agents (he dropped marketing agents and extra test agents for a simple Next.js app) and ask Claude to save the workflow files. *When:* To bootstrap a custom multi-agent workflow from an existing library of agent definitions instead of writing agents from scratch.
- **Verbose view of sub-agent activity** — Start Claude Code with the verbose option to see what each sub-agent is doing while it runs. The exact flag name is not spelled out in the captions. *When:* When you need to watch background sub-agent work that is otherwise hidden.
