> Walkthrough of Netflix's open-source VOID model, which removes an object from video and also rewrites the physical consequences of its removal, plus a self-built web UI and the setup gotchas the speaker hit.

## Summary
Better Stack presents VOID (Video Object and Interaction Deletion), an open-source video inpainting model from Netflix and a partner the captions render as "Insight". The speaker's core claim is that standard AI erasers remove an object's pixels but not its effects, so a bowling ball removed from a scene leaves the pins falling for no reason. VOID runs in two passes: a reasoning pass (a vision-language model plus SAM2 segmentation) that asks what else would change if the object were gone and encodes that as a quad mask, then a video diffusion pass that generates the counterfactual footage, with an optional second pass using Flow Warp Noise to keep remaining objects stable. Training data came from paired physics simulations (with and without the object), not real footage. The official repo is hard to run: the speaker says it needs SAM3 access (a gated model), expects quad masks named exactly quad_mask_0.mp4, and ships a Gradio demo with no UI for creating masks. He built a web app to cover segmentation, inference and both passes, then ran it on a RunPod H100 on three clips (Matrix, La La Land, Titanic). Results were strong on La La Land, mixed on the Matrix (hand artifacts, a dreamy look), and weakest on Titanic, where a leftover hand appeared because he had not segmented that point. He concludes the model works on some scenes and not others, and that the project-page examples look better than his tests.

## Key ideas
- **Erasing an object is solved; erasing its consequences is not** — Standard video erasers are content-aware fill that patches the pixels where the object was. Removing a person from a scene with a running blender leaves the blender spinning, because the physics of other objects is ignored. ([0:01](https://youtu.be/1yj46x45-QI?t=1))
- **VOID reasons about a counterfactual version of the scene** — The model generates the video as it would look if the object had never existed, so dependent objects (other dominoes, pins, a churning blender) change accordingly. ([1:09](https://youtu.be/1yj46x45-QI?t=69))
- **Two-pass pipeline: reason first, then generate** — Pass one uses a vision-language model with SAM2 tracking to ask what else changes when the object is removed, and writes this into a quad mask. The mask says both where to erase and where the surrounding physics should be rewritten. Pass two is video diffusion generation. ([2:16](https://youtu.be/1yj46x45-QI?t=136))
- **Optional refinement pass locks shapes in place** — Diffusion output can morph or lose object shape. A second pass using Flow Warp Noise keeps remaining objects solid while the physics around them changes. ([2:16](https://youtu.be/1yj46x45-QI?t=136))
- **Training data is synthetic counterfactual pairs** — Real footage cannot show a crash and its uncrashed version, so the team ran thousands of physics simulations (the speaker names Kubrick, likely the Kubric simulator) and trained on before/after pairs, one with the collision and one where the object was never there. ([3:19](https://youtu.be/1yj46x45-QI?t=199))
- **The official repo has undocumented setup failures** — The speaker reports the inference command fails without the SAM3 model, which the docs never mention. Quad masks must be named exactly quad_mask_0.mp4, and the Gradio demo needs an existing SAM2 mask because it has no mask-creation UI. ([4:26](https://youtu.be/1yj46x45-QI?t=266))
- **Results are scene-dependent; the best example is not the obvious one** — La La Land (Emma Stone removal) looked almost flawless, Matrix (Neo removal) was usable with hand artifacts, and Titanic had a leftover hand plus face morphing, which the speaker blames on incomplete point segmentation. He says the model works on some scenes and not others. ([9:05](https://youtu.be/1yj46x45-QI?t=545))

## Techniques
- **Two-stage video object removal with an intermediate mask** — Stage 1: track the target with SAM2 (pixel-accurate mask), then run a vision-language model asking which other objects would change if it were removed. Encode the answer as a quad mask covering both the erase region and the region to be re-rendered. Stage 2: run a video diffusion model conditioned on the mask and a prompt. Optional stage 3: a flow-warp-noise pass to stabilize shapes that drift. *When:* Removing an actor or object whose presence drives physical interactions (collisions, fluids, dominoes) that a plain inpainting model would leave behind.
- **Counterfactual training data from paired simulations** — Render the same physics scenario twice in a simulator (for example Kubric): once with the object, once with it removed. Train on the (with, without) pairs so the model learns how an object's presence changes its environment. *When:* You need supervision for 'what would have happened without X' that cannot be captured on real footage.
- **Running VOID on RunPod (speaker's setup)** — 1) Spin up an H100 pod. 2) In the template section, raise the container size to 100 GB. 3) Expose port 8998 in the port section. 4) SSH in, clone the speaker's repo, cd into it, and run run.sh. It asks for a Hugging Face token; request access to the gated SAM3 repo. 5) Provide a Gemini API key, which the segmentation step uses for pose estimation when building the quad mask. 6) Launch the web app with the command shown in the repo and open the pod's port 8998 from the RunPod page. The exact launch command is not in the transcript. *When:* You want to try VOID without a local GPU, and you are willing to use the speaker's wrapper repo instead of the official Gradio demo.
- **Web UI workflow, tab by tab** — Tab 1: enter a removal instruction (for example 'remove the fighter in the white kimono from the scene'), click several points on the target for SAM2, and choose an output folder name. This folder name is the ID used in every later tab. Tab 2: run segmentation. Tab 3: enter the folder name again, plus a prompt describing the desired scene WITHOUT the removed object (for example 'a fighter in a dark kimono standing inside a gym'), then run inference. Tab 4: run the optional second pass. Results tab: load the video by folder name. *When:* Driving the pipeline manually, or building your own UI around a model whose official demo expects pre-made masks.
- **Prompting for the counterfactual background** — In the inference prompt, describe what the scene should look like after removal and do not name the removed object. The speaker says the authors recommend this. *When:* Writing the generation prompt for any object-removal inpainting run.
- **Segment every part of the target** — Add a click point for each part of the target person or object during segmentation. The speaker's Titanic artifact (a leftover hand) came from a point he did not segment. *When:* Any removal where a body part or limb is near other people or objects, since missed points leave ghost fragments.

## Hot takes
- Standard AI erasers are 'content-aware fill on steroids' and cannot handle physical consequences of removal.
- The official VOID GitHub docs have holes and misleading information; the speaker found several undocumented requirements.
- Results depend heavily on the scene: 'it does not work for every scene', and the project-page examples look much better than his tests.
- Netflix could use this for interactive or personalized video narratives, drawing a comparison to Black Mirror: Bandersnatch (speculation).
