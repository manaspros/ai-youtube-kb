## Key ideas
- **A paywall has two parts: get users to it after they have experienced value, then convert them. Converting them is the part that matters most.** — The host frames paywall success as a funnel problem split into reaching the paywall and converting once there. ([0:00](https://youtu.be/Y2oK0nubq9A?t=0))
- **Content and education apps should deliver instant value before any payment request. Gate by progress rather than by hiding the core experience.** — Babbel-style example: starter languages are free, later course sections are locked by progress. Users hit the paywall after finishing the first lesson. The host says lesser-known apps must prove value up front, unlike Netflix, which already has trust. ([2:07](https://youtu.be/Y2oK0nubq9A?t=127))
- **Pricing anchoring: put a much more expensive option beside the yearly plan and show the yearly plan as a large monthly figure.** — The example shows a $299.99 lifetime plan beside a yearly plan displayed as $9/month in much larger text, with a savings badge. The true annual total is $107.99. Monthly plans are hidden behind a 'show all plans' button. The host says the goal is to sell the most affordable option that is still profitable for the app. ([5:22](https://youtu.be/Y2oK0nubq9A?t=322))
- **Habit apps use progress as the hook: give a taste of visible progress first, then gate.** — Two gating styles: a time-boxed free week, or a feature cap such as a few free habits before the paywall. The host argues progress naturally wants to expand, so limiting expansion pushes users to upgrade. Sleep Cycle-style onboarding walks users through benefits and shows extra features after sign-up. ([8:45](https://youtu.be/Y2oK0nubq9A?t=525))
- **Utility ('creative friction') apps gate the output at the moment of need: page limits, export resolution, or export quality.** — Examples: a PDF converter that allows one free page; a video editor (CapCut was named) that exports 720p free and locks 1080p until the export step, after the user has invested in editing. ([10:11](https://youtu.be/Y2oK0nubq9A?t=611))
- **A paywall ladder: three tiers, where the middle plan is marked most popular and the top tier holds the features that are missing from the middle one.** — PhotoRoom-style example: basic paid tier with HD export, a Pro tier tagged most popular, and a Max tier with the remaining features. The host compares this to Apple's hardware upsell path. ([11:30](https://youtu.be/Y2oK0nubq9A?t=690))
- **Design workflow for vibe-coded paywalls: a slash command that runs a design prompt file, plus screenshot-to-clone from a reference library.** — The host built a Claude Code slash command 'design' that reads design.md, a prompt file adapted from SuperDesign's open-source design prompt and stripped down for quick implementation. Output is HTML styled with Flowbite rather than raw CSS. For references, he points to the Paywall Screens site and suggests passing a screenshot to the agent to clone. He says the Babbel paywall was built in one shot with a rule file and design agent, without details shown. ([6:47](https://youtu.be/Y2oK0nubq9A?t=407))

## Techniques
- **Progress-gated free tier for education apps** — Make the first lesson or course free and fully functional. Lock later sections by progress (sequential unlock), not by a hidden paywall. Show the paywall after the user completes the first lesson and tries to reach the second. *When:* Content or education apps that lack brand trust and need to prove value immediately.
- **Anchored yearly pricing** — Show a very expensive lifetime option next to the yearly plan. Render the yearly plan as a large monthly figure (annual total divided by 12). Add a savings badge. Hide monthly and other plans behind a 'show all plans' control so the choice stays on two options. *When:* Subscription paywalls where recurring revenue is the goal and the yearly plan should be the default choice.
- **Progress hook with time or feature gating** — Option A: a free trial period (the host cites a free week) during which the user builds habits and sees progress. Option B: a feature cap, such as a few free habits, with unlimited habits behind the upgrade. Show the paywall once the user is invested. *When:* Habit, tracking, or progress apps where the value of the product grows as the user invests.
- **Usage cap at point of need** — Set a small free allowance for the core action, such as one free PDF page or a 720p export. Lock the higher-value output (more pages, 1080p) so the paywall appears at the final step after the user has invested effort. *When:* Utility or creative apps (PDF converters, video editors) where users hit the limit at the moment of need.
- **Three-tier ladder with a highlighted middle** — Create basic, pro, and max tiers. Feature each feature only in the tier that needs it, so the upgrade path is continuous. Tag the pro tier as most popular. *When:* Apps with a feature set that naturally splits into tiers, so users feel they are stepping up rather than facing one large jump.
- **Slash-command design pass for prototypes** — Save a Claude Code custom slash command (the host names it 'design') that reads a design.md prompt file. The prompt should set the design rules and target HTML with a component library (Flowbite). Provide the app context in the command so the agent builds the screen in one pass. The host says this is adapted from SuperDesign's open-source prompt, stripped for quick implementation rather than iterative refinement. *When:* You have the app structure and design inspiration ready and want a single-pass prototype of a screen such as a paywall, not an iterative design exploration.
- **Screenshot-to-clone reference** — Find a paywall in a reference library (the host cites Paywall Screens, which lists thousands of paywalls with evolution history). Take a screenshot and give it to the coding agent with an instruction to clone it. *When:* You need a concrete visual reference for a paywall or onboarding screen before writing the markup.
