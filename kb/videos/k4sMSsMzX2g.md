> AI LABS walks through Google's Open Knowledge Format (OKF), a folder, index.md and YAML-frontmatter convention for markdown knowledge bases, and reports a small team test with lower token use and faster lookups.

## Summary
The narrator says personal "second brains" built on Claude Code are hard to share and navigate because each person structures them differently. Google's Open Knowledge Format (OKF) is presented as a standard layout for these markdown knowledge bases, built on Karpathy's LLM-wiki pattern as an alternative to RAG. In OKF each topic is a folder with an index.md that agents read first, and each concept document carries YAML frontmatter with a name and description. OKF ships with a BigQuery-only enrichment agent and an HTML graph visualizer, so the team wrote its own "Markdown to OKF" skill, script-first with evals, and tested it on a branch of their team's Git-tracked second brain. Claude ignored the new structure until a CLAUDE.md section explained it, after which it navigated via index.md and loaded YAML metadata before opening files. The speaker's conclusion is that OKF is an optimization for now, not a necessity, until agents support it natively. The video also contains a sponsored Mobbin segment and no measured token or latency figures.

## Key ideas
- **Second brains built on Claude Code are personal and unstandardized, so they are hard for others to navigate or share.** — The speaker's team keeps a Git-versioned second brain guided by a CLAUDE.md file, with per-folder CLAUDE.md files. Claude still misfiles content and creates duplicate folders because it only finds files by searching and does not know what already exists. ([0:00](https://youtu.be/k4sMSsMzX2g?t=0))
- **OKF is pitched as a standard for knowledge, in the way MCP and skills became standards for tools and instructions.** — It is based on Karpathy's LLM-wiki pattern: markdown files the agent can navigate, instead of RAG that rebuilds answers from scratch on every query and accumulates no knowledge. The speaker notes that the format itself adds nothing new technically. ([2:45](https://youtu.be/k4sMSsMzX2g?t=165))
- **An OKF bundle is a folder tree of markdown concept documents, each with YAML frontmatter describing it.** — The frontmatter tells the agent what a file holds before it opens the file. The format is meant to be readable by humans as well as agents, and it is independent of any specific platform. ([4:12](https://youtu.be/k4sMSsMzX2g?t=252))
- **The core OKF rules are one topic per folder, an index.md in every folder read first, and one concept per document.** — Each concept has a short YAML block with name and description, and a type field that says what the concept is. The speaker stresses minimalism: mixing topics in one concept stops the agent from loading just the part it needs. ([5:12](https://youtu.be/k4sMSsMzX2g?t=312))
- **OKF ships with a BigQuery enrichment agent, an HTML visualizer and examples, but the team had to build its own converter for markdown.** — The team's skill was script-first: code does most of the conversion and the agent only handles judgment calls, which the speaker says saves tokens. Evals are prompts that the agent runs against the output to check the conversion. ([8:04](https://youtu.be/k4sMSsMzX2g?t=484))
- **Claude did not use OKF until CLAUDE.md documented the structure; after that it searched index files first and used fewer tokens.** — Without the CLAUDE.md section it fell back to keyword and filename matching. With it, it read index.md files and YAML metadata before deciding which files to open. The speaker reports faster retrieval and fewer tokens, with no numbers shown. ([9:32](https://youtu.be/k4sMSsMzX2g?t=572))
- **The speaker's own verdict is that OKF is an optimization for now, and it becomes essential only once agents support it out of the box.** — The speaker also speculates that websites could publish OKF bundles alongside llms.txt. That is speculation, not something Google has announced. ([10:59](https://youtu.be/k4sMSsMzX2g?t=659))

## Techniques
- **Index.md per folder as the agent's entry point** — Put an index.md at the root and in every subfolder. Each one lists the folder's contents with links to subfolders, so the agent reads the index before opening documents. The speaker says this is the same linking idea Obsidian uses for its graph view. *When:* A large, nested markdown knowledge base where agents waste tool calls and tokens on filename guessing.
- **YAML frontmatter with name, description and type on every concept document** — Each concept file starts with a small YAML block holding name and description, plus a type field. Keep one concept per file, so the agent can decide from the frontmatter whether to load the file. *When:* You want cheap relevance checks before loading content, and want the knowledge base readable without the agent.
- **Script-first markdown-to-OKF conversion with evals** — Write a conversion script that turns a folder of markdown into the OKF layout (index.md files plus frontmatter). Use the agent only for judgment calls. Test the output with evals: prompts the agent runs against the converted bundle to check it. The speaker did not show the script or its name. *When:* Converting an existing markdown knowledge base, where code is cheaper and more reliable than agent edits.
- **CLAUDE.md navigation section that documents the bundle** — Add a section to CLAUDE.md that explains the layout, what each file role is, and that the agent should read index.md files first before searching. The speaker says Claude ignored OKF until this was added. The exact wording was not shown. *When:* Any non-standard knowledge layout that the agent does not know about by default.
- **Trial on a Git branch and visualize the bundle** — Make the conversion on a separate branch so main is untouched. Run the OKF visualize command in the terminal to produce an HTML graph of the bundle and open it in a browser to check links. The command and flags were only described, not shown. *When:* Evaluating a restructuring of a shared knowledge base before committing to it.
