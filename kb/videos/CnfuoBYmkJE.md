## Summary
The host argues that plain RAG can return confident, wrong answers because chunking and fuzzy vector search break the structure of a source document, using a refund-window example (30 days from RAG versus 14 days from a curated file). He presents Google Cloud's Open Knowledge Format (OKF), which he says shipped in June 2026, as a bundle of markdown files with YAML front matter, one concept per file, and links between concepts, where retrieval is deterministic and every change is a Git diff. He then recommends a hybrid: a router sends canonical, high-stakes questions to OKF and open-ended ones to RAG, with OKF acting as ground truth over retrieved chunks. He also covers the economics (OKF is just text, while RAG pays for embedding and a vector database that always runs) and two myths (OKF does not replace RAG, and a huge context window does not replace selective retrieval). The video has no code, benchmarks or eval results; the central example is a single illustrative anecdote, and the 80/20 split is a heuristic.

## Techniques
- **Curated-first hybrid routing** — Put a thin router in front of two sources. Canonical, high-stakes questions (for example, policy values or exact prices) go to a curated markdown bundle that returns a cited answer. Open-ended questions go to vector RAG over the full archive. When a curated concept exists for a question, trust it over any retrieved chunk. The speaker does not describe how to classify queries. *When:* A mixed corpus where a small set of facts must be exact and auditable, and the rest is too large or messy to hand-curate.
- **OKF-style concept files** — One concept per markdown file. YAML front matter with a required type field and optional title, description, tags, timestamp, and resource (a link to the real underlying asset). Express relationships as ordinary markdown links, for example a table linking to its dataset, or a playbook linking to the table it repairs. Add index files that list what knowledge exists so the agent can drill down progressively. *When:* Authoring a small, high-trust knowledge base that a human owns, where facts need owners and reviewable history.
- **Governing knowledge in Git** — Store the curated bundle in a repository. Review changes in pull requests, assign an owner to each fact, and roll back a bad edit with a single revert. *When:* Any knowledge base that must be auditable and changed by a process people already trust.
- **Single retrieval facade** — Expose both the curated bundle and the vector index behind one retrieval interface (the speaker suggests a single MCP server), and index the bundle inside the vector store so semantic search can also reach it. *When:* You want the model to ask for knowledge without knowing which store answered.
- **Baseline RAG ingestion** — Split documents into chunks of a few hundred tokens with small overlap. Embed each chunk, and store it with metadata such as source document, page, and title so answers can cite their source. At query time, embed the question, run approximate nearest-neighbour search (cosine similarity or dot product), and inject the top chunks into the prompt. *When:* Open-ended search over a large, changing corpus where fuzzy matching by meaning is acceptable.
