> Hands-on test of open-weight GLM 5.2 against Kimi K2.7 Code and Claude Opus 4.8 on web design, one-shot apps and cost; strong and cheap per task, but token-hungry, and prompt steering drove most results.

## Summary
The presenter reviews GLM 5.2 from Z.ai, an MIT-licensed open-weight model (744B total, 40B active parameters, same size as GLM 5.1) that scores 51 on Artificial Analysis's intelligence index, the top open model by his account. He cites Design Arena, where GLM 5.2 ranks first on single-turn HTML web design (second on game dev, dataviz and 3D, fourth on UI components), and says it beats Claude Opus 4.7 on DeepSWE at medium effort, with the caveat that the harness was Claude Code pointed at Z.ai's API. In hands-on single-prompt tests (a Linear clone from a text-only prompt, a fictional SaaS landing page, a Three.js Silverstone racing game, and a full-stack finance dashboard), he finds GLM 5.2 competitive with Kimi K2.7 Code and Opus 4.8, with Opus most playable in the game and GLM arguably best in the dashboard. He reports GLM uses more tokens per task (about 43k average) but costs about $0.50 per task on Artificial Analysis, and that it is slower than most open peers and behind frontier models on speed. His main takeaway is that prompt steering matters as much as the model, and that GLM is good enough to swap in for simpler tasks. The evidence is one run per prompt and mostly subjective judgments.

## Techniques
- **Text prompt via a multimodal model for a text-only target** — Send the screenshot to a vision-capable model (Claude in the video) and ask for a detailed recreation prompt. Give that text prompt to the text-only model (GLM 5.2) to build the page from scratch. *When:* The target model has no image input, but you want a visual recreation of an existing UI.
- **Section-and-style design brief for a one-shot landing page** — Ask for a single-page site for a named fictional product. List the required sections (hero, social proof, pricing and so on) and style directives (clean premium SaaS aesthetic, soft gradient, strong typography, rounded cards). Run one version with no direction, to see the model's default look. *When:* Comparing models on front-end generation. The direction section controls the outcome more than the model does.
- **Single-prompt full-stack app as a stack-choice and integration probe** — Give a feature list for a full app (e.g. personal finance dashboard: accounts, transactions, pages) with no stack instructions. Check: what stack it picks, whether it persists to a real database or an in-memory store, whether the front end and back end connect, and whether the pages are navigable and work. *When:* Judging how a model handles a greenfield app from one prompt. Stack defaults vary by model and prompt.
- **Console-error loop as a pass or fail check** — Open the generated app in a browser and watch the console. If errors repeat, paste them into a follow-up prompt and count how many prompts it takes to get a working build. *When:* Scoring one-shot generation. Count prompts needed as well as tokens and cost.
- **Cost per task from token counts and per-million prices** — Multiply tokens per task by the provider's input and output prices, or use a published per-task figure (Artificial Analysis gave about $0.50 for GLM 5.2). Compare against the intelligence score on a cost-vs-intelligence chart. *When:* Choosing a cheaper model for routine tasks. Cheapest per token is not always cheapest per task, because GLM used more tokens.
- **Use a cheaper open model for simpler tasks** — Route routine tasks to the open model and keep Sonnet or Opus for hard ones. The presenter's claim is that the difference is hard to notice on simpler tasks; he did not measure this. *When:* Trying to cut spend on coding-agent work without much quality loss. Verify on your own tasks first.
- **Claude Code harness on a non-Anthropic API endpoint** — Point the Claude Code CLI at Z.ai's API instead of Anthropic's (the presenter's 'API trickery'). The video does not show the exact configuration. *When:* Benchmarking an alternative model inside an agent harness you already use. Note that results then measure model plus harness.

## Hot takes
- Presenter says GLM 5.2 may be swapped in for Sonnet or Opus on simpler tasks without him noticing, based on a few days of use and no measurement.
- Design Arena's first-place claim may reflect template training that favors clean outputs, but in the presenter's no-direction test GLM still produced heavy purple gradients, which contradicts the 'avoids AI anti-patterns' framing.
- Results are one run per prompt. A single failed Kimi run may reflect run variance, and rankings of the generated apps are subjective.
- The DeepSWE win uses Claude Code as the harness, so it measures model plus harness, not the model alone.
- The prompt, not the model, drove most differences (the stack choice and the database), which weakens any model-to-model ranking from one-shot tests.
- The 'open models are 4 to 6 months behind' view and the Z.ai frontier-model-by-Q1 promise are opinion or second-hand claims, not verified.
