> Vite creator Evan You explains why the Vite toolchain is moving to Rust (Rolldown, OXC), the unified Vite+ CLI, guardrails for agent-written code, and his skepticism about React Server Components.

## Summary
Evan You (creator of Vue and Vite, now running VoidZero) walks through why Vite's split toolchain (esbuild for dev, Rollup for production) led to a Rust rewrite: Rollup cannot be made fast from JavaScript because data passing between Rust and JS eats the gains, and plugin chains repeat parsing per plugin. The result is Rolldown (Rollup's API with esbuild-style built-in features) on top of the OXC Rust toolchain, with a single config and one transform pipeline for bundling, linting, formatting and testing. He covers Vite+ as a zero-setup entry point that also pins Node and package manager versions, and the decision to ship AGENTS.md and skills inside packages because models lag behind new releases. On AI he argues agents take shortcuts (invented config options, disabled rules to pass type checks) and accumulate tech debt faster, so they need guardrails and periodic cleanup. He is skeptical of React Server Components as over-hyped, with DX friction and server cost, and he says Next.js was effectively the only real path to it. Much of the substance is the speaker's own company's roadmap and self-reported benchmarks.

## Key ideas
- **Vite's split toolchain was the root problem** — Vite used esbuild to pre-bundle dependencies in dev and Rollup for production. The two tools diverge on plugin behavior, mixed ESM/CJS handling and tree shaking, and the team patched around the inconsistencies. The goal was one bundler for both. ([4:04](https://youtu.be/LSGZtHafiM4?t=244))
- **Rollup cannot be made fast from inside JavaScript** — Worker-thread plugins and an SWC-based Rust plugin inside Rollup gave little gain because passing large strings between Rust and JS, and cloning memory, cancels the speedup. A real fix means a native rewrite. ([6:52](https://youtu.be/LSGZtHafiM4?t=412))
- **Rolldown = Rollup's API shape with esbuild's built-in scope** — Rollup's core is lean, so a production preset needs many plugins (node resolve, CommonJS, define, inject, replace). Each JS plugin re-parses, transforms, regenerates code and merges source maps. Rolldown builds these features in, so plugins do not repeat that work. ([9:46](https://youtu.be/LSGZtHafiM4?t=586))
- **OXC supplies the composable Rust toolchain underneath** — OXC provides parser, resolver, transformer and minifier as separately usable crates. The speaker says its parser is about 3x faster than SWC's when both are in Rust. An arena allocator puts the AST in one contiguous block, which makes dropping it cheap and lets the whole buffer go to JS without cloning (used for fast JS plugins in oxlint). ([11:11](https://youtu.be/LSGZtHafiM4?t=671))
- **One vertical stack with one config and one resolver** — The plan is to cover parsing, bundling, dev server, linting, formatting and testing with a single config, all on the same transform pipeline and resolver. The aim is that tools agree on module resolution, which has to be configured separately in webpack and similar tools. ([14:04](https://youtu.be/LSGZtHafiM4?t=844))
- **Unbundled ESM only scales to a limit, then bundling wins** — Under roughly 1,000 modules the graph loads in a few hundred milliseconds. Around 3,000 modules the browser chokes, and each import is a separate HTTP request traversed eagerly. Bundling helps once you cross that threshold, which is why Rolldown is adding a full-bundled dev mode. ([16:49](https://youtu.be/LSGZtHafiM4?t=1009))
- **Vite+ targets zero-setup onboarding and removes version juggling** — One install script provides a global vp binary and commands such as vp new, vp dev, vp build and vp run. vp run caches tasks in dependency order, like Nx. Vite+ reads the .node-version file and the packageManager field to pick Node and pnpm versions, so nvm and Corepack become unnecessary. Everything is opt-in, and the company says it will not paywall features. ([23:54](https://youtu.be/LSGZtHafiM4?t=1434))
- **Ship AGENTS.md and skills inside the package to fix stale AI output** — Models lag behind new releases, so AI-scaffolded apps still use Vite 6. Vite+ plans to ship its own AGENTS.md and skills in the npm package, patch the relevant section on upgrade, and provide an upgrade prompt for agents. ([28:06](https://youtu.be/LSGZtHafiM4?t=1686))
- **Agents need guardrails: they invent options and disable rules** — In reviewing OpenClaw PRs, the team saw hallucinated linter options and rules switched off just to get type checks to pass. Their argument is that agents take shortcuts without guardrails, and that agents speed up tech debt, so cleanup has to be scheduled too. ([29:29](https://youtu.be/LSGZtHafiM4?t=1769))
- **React Server Components are over-hyped; Next.js was the only real path** — The speaker's objections are the network round trip for interactions, hydration costs that are not fully avoided, more server compute, and paper-cut DX from use server and use client boundaries. Frameworks other than Next.js struggled because the React team iterated mainly with Vercel. ([48:24](https://youtu.be/LSGZtHafiM4?t=2904))

## Techniques
- **Pre-bundle dependencies in dev, serve source as native ESM** — Serve application source unbundled with native ESM. Pre-bundle node_modules once with a fast bundler (esbuild in Vite's original design) so large dependency trees do not produce thousands of requests. *When:* Development server for apps where the module count stays under a few thousand. Above that, switch to a bundled dev mode.
- **Bundle for production when module count crosses a threshold** — Measure the module graph. Around 1,000 modules, unbundled load is still acceptable. Past roughly 3,000 modules, bundling gives a large win (the speaker cites about 100 ms bundled versus seconds unbundled over the network). *When:* Deciding whether a large app can stay on unbundled dev or needs a bundled path, especially for production over slow networks.
- **Built-in transforms instead of plugin chains** — Implement common transforms such as define, inject, replace and the node resolver in the bundler core. A JS plugin chain re-parses, transforms, regenerates code and merges source maps for every plugin, and that cost grows with plugin count. *When:* Building or choosing a build tool where per-plugin AST round trips dominate build time.
- **Check the data-boundary cost before offloading to native code** — Before rewriting part of a JS pipeline in Rust, measure the cost of passing strings and AST data across the boundary. The speaker's Rollup experiments show that a Rust plugin inside a JS core can end up no faster. *When:* Any hybrid runtime (JS to native, Python to Rust, Node to WASM) where the hot path passes large payloads.
- **Arena-allocate ASTs in one contiguous buffer** — Allocate all AST nodes for a file in one contiguous arena. Drop the arena in one step, and pass the raw buffer to another runtime without cloning, then deserialize on that side. *When:* Writing a parser or transformer where allocation and drop dominate, or where zero-copy handoff to JS is needed.
- **One config, one resolver for the whole toolchain** — Put parser, bundler, linter, formatter and test runner behind one config file, all sharing the same resolver and transform pipeline, so module resolution cannot disagree between tools. *When:* Setting up a new JS monorepo, or when tools drift because each one resolves modules differently.
- **Vite+ commands and version pinning** — Install with the vplus.dev install script (curl piped to bash, as described). Then run vp new to scaffold, vp dev to run, vp run <task> for cached, dependency-ordered tasks, and vp install to install the package manager named in the packageManager field. Pin Node in .node-version. The transcript auto-caption says 'patch.json' here, which is most likely package.json. *When:* Onboarding a fresh machine or repo where you want Node and pnpm versions pinned without nvm or Corepack setup. Note the Vite+ is still in transition and its commands may change.
- **Ship AGENTS.md and skills with the package, patched on upgrade** — Include AGENTS.md and skill files inside the npm package. On upgrade, the tool patches the relevant section of the project's AGENTS.md and links to the updated skills. Also provide an upgrade prompt that tells an agent how to move between two versions. *When:* Maintaining a library or framework that AI agents will use, where the model's training data lags the latest release.
- **Guardrails against agent shortcuts in PR review** — Review agent PRs for invented config options and for rules disabled to make checks pass. Enforce lint and type checks in CI so the agent cannot silence them. The speaker frames these as the tool authors' job to point out where AI falls short. *When:* Reviewing agent-written PRs in a codebase where the agent is not an expert in the toolchain it is changing.
- **Schedule debt-paydown passes between feature pushes** — Alternate periods of shipping features with deliberate cleanup, using AI to pay down debt that the agents themselves generated. *When:* Teams merging many agent PRs per day where code health drifts.
- **Plan mode, then write AGENTS.md, and run agents in parallel** — Use plan mode before implementation, have the agent write or update AGENTS.md, and run several agents in parallel on separate tasks. The speaker reports one engineer shipping about 60 PRs in a week this way. *When:* Large Rust or low-level codebases where the speaker says steering skill matters more than raw model capability.
- **Run downstream ecosystem CI before a major release** — Run the tool against a large set of real downstream projects (the speaker cites SvelteKit, auto-caption 'spell kits') and make sure their tests pass on the beta before stabilizing. The speaker describes this as the main concern before shipping Vite 8. *When:* Shipping a replacement for core infrastructure that many projects depend on.

## Hot takes
- Vendor interest: the speaker runs VoidZero, which sells Vite+; the performance multiples are self-reported social-media figures, not benchmarks shown in the video. Not sponsored, so quality is not capped, but treat numbers as marketing-grade.
- AI agents take shortcuts without guardrails (invented options, disabled rules to pass type checks), and they accumulate tech debt faster than humans, so AI must also be used to pay debt down.
- The harness layer for coding agents is converging like JavaScript frameworks; each new practice (plan mode, AGENTS.md) spreads within months.
- React Server Components were oversold; Next.js was effectively the only real path, and the use server/use client DX is a persistent cost.
- Rust over Go for the toolchain: Go's WebAssembly is poor (large binaries, slower), and the Rust parser ecosystem is more composable.
- Steering skill matters more than raw model capability: someone with no Rust expertise will not be productive in the OXC codebase even with AI.
