> Browserbase and Microsoft researchers on why LLM judges confidently mis-grade web agents, and their rubric-and-evidence "universal verifier" that agrees with humans far better, plus its use for filtering training data.

## Summary
The speakers argue that LLM-as-judge verifiers for web agents are confidently wrong: on one 7B browser agent, the WebVoyager GPT-4o judge reported 74% success while their verifier, which agrees well with humans, gave 38%. Their fix is a verifier that first writes a per-task rubric, then ranks the trajectory screenshots by relevance to each criterion, judges each criterion on only the top-K evidence, and outputs both a partial-credit process score and a boolean outcome with an explanation. They lay out four design principles: grade only what was asked, stop errors cascading between criteria, always check ground-truth screenshots, and separate agent-controllable failures from environment-blocked ones. They validated it with human expert labels, reporting false positives falling from almost half to zero and agreement with humans roughly equal to human-human agreement (Cohen's kappa 0.58). Training SFT on trajectories filtered by the better verifier gave a stronger model at 3K and 9K examples. In a side experiment, an auto-research loop rebuilt the verifier in about a day versus three weeks by hand, but reached only about 70% of the human-tuned agreement, so the speakers still recommend human involvement. The work is open source, with a held-out label split and a new benchmark.

## Key ideas
- **Existing LLM judge verifiers for web agents are confidently wrong, so using them as RL rewards or filters trains a more confident liar.** — On one 7B browser agent, the WebVoyager GPT-4o judge gave 74% success; the speakers' verifier, which agrees with humans, gave 38%. Human annotators caught the errors the judge missed. ([3:07](https://youtu.be/xLxhT2ZI7UM?t=187))
- **Common verifier weaknesses: weak judge models, no rubrics, screenshot overflow, and ignoring the final answer or action history.** — Judges were GPT-4o or o4-mini, with no per-criterion credit assignment. Feeding every screenshot overflows the context window, and some judges skip the final answer entirely. ([4:11](https://youtu.be/xLxhT2ZI7UM?t=251))
- **Universal verifier pipeline: rubric first, then per-criterion evidence, then a scored rubric and a boolean outcome.** — For a task it writes a rubric of criteria, ranks the trajectory screenshots by relevance to each criterion, and judges each criterion on the top-K evidence. It flags contradictions between what the agent claimed and what the screenshots show. Output is a partial-credit process score plus an outcome boolean with a reasoned explanation. ([5:28](https://youtu.be/xLxhT2ZI7UM?t=328))
- **Four design principles: grade only what was asked, isolate errors, always look at ground-truth screenshots, and separate controllable from uncontrollable failures.** — Naive rubrics add extraneous criteria (like total hotel price when not asked), which deflates scores. Subtasks that build on each other should not cascade a single arithmetic slip into every later criterion. ([6:51](https://youtu.be/xLxhT2ZI7UM?t=411))
- **Hallucinated success is the main failure to catch, and it is subtle enough that humans miss it.** — Example: the agent claimed a CIDEr score of 6.2% where the paper's abstract said 2.8%. Agents also overclaim actions they never did, so the verifier checks the screenshots rather than the agent's narration. ([8:20](https://youtu.be/xLxhT2ZI7UM?t=500))
- **Credit is assigned from an enumerated schema of failure modes, so environment blockers do not count against the agent.** — If an item is out of stock after a good-faith search, the agent gets full marks for effort but the outcome is still false. Finding a reasonable alternative still counts as success, while controllable mistakes and hallucinations are penalized. ([9:47](https://youtu.be/xLxhT2ZI7UM?t=587))
- **Validate the verifier against human labels, not just against itself, and hold out data.** — Humans first label, then see the verifier verdict and say whether they agree. The verifier sometimes caught things humans missed. Of 150 trajectories, about 50 were used for tuning and about 100 were held out with two annotators each, so the reported numbers are on untouched data. ([11:11](https://youtu.be/xLxhT2ZI7UM?t=671))
- **A better verifier yields better training data: filter SFT trajectories by verifier pass and train on the successes.** — At matched sample counts (3K and 9K trajectories), filtering with the universal verifier produced a stronger model than filtering with the speakers' weaker baseline verifier. ([12:12](https://youtu.be/xLxhT2ZI7UM?t=732))

## Techniques
- **Rubric-first LLM verification** — Before reading the trajectory, generate a list of criteria for what success looks like on this specific task. Grade only what the task asked for, so no extraneous criteria. *When:* Any open-ended task with no deterministic ground truth, such as web or desktop agent runs.
- **Per-criterion top-K screenshot evidence** — For each rubric criterion, rank trajectory screenshots by relevance and judge the criterion only on the top-K. Check the final answer and the action history alongside. *When:* Long agent trajectories where feeding every screenshot overflows the judge's context window.
- **Dual verdict: partial-credit score plus boolean outcome** — Output a per-criterion scored rubric for diagnosis (process score), and a true/false outcome with an explanation of what a reasonable user would expect. *When:* When you need both fine-grained credit for RL or analysis and a pass/fail gate.
- **Controllable vs uncontrollable failure schema** — Enumerate failure scenarios ahead of time (blocked by environment, similar alternative found, controllable mistake, hallucination). Assign credit per scenario rather than per raw outcome. *When:* Environments the agent cannot fully control, such as live websites with out-of-stock items or changed pages.
- **Error isolation across dependent criteria** — Judge each downstream criterion on its own logic, so an upstream mistake is penalized once and does not cascade into later checks. *When:* Multi-step tasks where later steps depend on earlier outputs.
- **Human-agreement validation with held-out labels** — Have humans label trajectories first, then show them the verifier verdict to agree or disagree. Compute Cohen's kappa against human-human agreement. Tune on one subset and report on a held-out set labelled by at least two humans. *When:* Before trusting any LLM judge as a reward, metric or data filter.
- **Verifier as data filter for SFT** — Run the verifier over generated trajectories and keep only those marked successful for supervised fine-tuning. *When:* When you can generate many agent trajectories but need only the good ones for training.
- **Auto-research loop to build a verifier, primed with human findings** — Let an automated experiment loop iterate on prompts and code for a verifier, seeded with the notes from earlier human-led experiments. *When:* To speed up building metrics or verifiers, with human review still needed; they say it reached about 70% of the human-tuned agreement alone.

## Numbers
- Same 7B web agent scored 74% success with the WebVoyager GPT-4o judge versus 38% with the universal verifier. ([3:07](https://youtu.be/xLxhT2ZI7UM?t=187))
- Universal verifier reduced false positives from almost half to zero on the golden labels. ([11:11](https://youtu.be/xLxhT2ZI7UM?t=671))
- Verifier-to-human Cohen's kappa of 0.58, matching the agreement between two human annotators on the same tasks. ([11:11](https://youtu.be/xLxhT2ZI7UM?t=671))
- SFT training on verifier-filtered trajectories was tested at 3K and 9K trajectories; the better verifier gave a higher-quality model at both sizes. ([12:12](https://youtu.be/xLxhT2ZI7UM?t=732))
- Building the verifier took about 3 weeks and about 30 experiments by hand; an auto-research loop ran the same number of experiments in about 1 day and reached about 70% of the agreement. ([13:13](https://youtu.be/xLxhT2ZI7UM?t=793))
- Label split: about 150 trajectories total; about 50 used for tuning, about 100 held out with 2x human overlap. ([18:15](https://youtu.be/xLxhT2ZI7UM?t=1095))

## Hot takes
- Using an LLM judge as an RL reward without checking it against humans trains a more confident liar, not a better agent.
- Open web benchmarks are saturating, so verifier quality is now the bottleneck for measuring progress.
- Building verifiers is as important as building the models themselves.
- Auto-research can build a verifier in a day, but human intervention is still needed to reach the top agreement.
