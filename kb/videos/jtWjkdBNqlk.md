> Kai Explains reviews LangChain's open-source DeepAgent, a model-agnostic take on Claude Code's harness, arguing it wins for shipping agents to users while Claude Code still wins for personal terminal coding.

## Summary
The video defines an agent "harness" as everything around the model: planning loop, to-do tracking, file and shell tools, context compression, subagents, and human-in-the-loop interrupts. It argues that Claude Code's harness is tied to Anthropic's API, so the memory and learned behavior it accumulates are locked in. It presents LangChain's DeepAgent as an open (MIT-licensed) reimplementation of the same architecture, where swapping the model is a small code change and memory can live in the user's own PostgreSQL or a repo-level agents.md file. The speaker then gives the trade-offs: Claude Code, paired with Opus 4.8 by the speaker's cited benchmark numbers, is stronger at raw terminal coding, and DeepAgent is only as good as the model plugged into it. He also flags the costs of DeepAgent: it is built on LangGraph, carries about 8% prompt-scaffolding overhead per call, and its managed multi-tenant runtime is a paid LangSmith product. The closing thesis is that the harness, not the model, is where the lock-in and leverage sit. Most of the benchmark and adoption figures are given without a source link in the video.

## Key ideas
- **A coding agent is a model plus a harness. The harness is the planning loop, to-do tracking, file and shell tools, context compression, subagents and human approval interrupts, and the video argues it matters as much as the model.** — Speaker lists five harness components and calls the harness the thing that matters more than the model. Claude Code's harness is said to be about 512,000 lines, a figure the speaker attributes to reports rather than verifying. ([0:00](https://youtu.be/jtWjkdBNqlk?t=0))
- **Claude Code's harness is inseparable from Claude, so the agent's memory and learned behavior flow through Anthropic's API and cannot be moved or exported.** — Speaker quotes Letta's CTO that plugging memory into a harness is like plugging driving into a car. He ranks lock-in in three tiers: stateful APIs (mild), closed harness with undocumented memory (bad), and harness-as-a-service (worst). He places Claude Code in the second tier and Claude Managed Agents in the third, citing a LangChain analysis from April 2026. ([2:52](https://youtu.be/jtWjkdBNqlk?t=172))
- **DeepAgent copies Claude Code's architecture (plan with to-dos, read/write files, run code in a sandbox, spawn subagents) but swaps the model behind it, so the model is a plug-in.** — The subagent gets an isolated context window, does a narrow task, and returns one summary; the parent never sees the raw transcript. Speaker says two lines of code swap the model, and any tool-calling model works, including OpenAI, Anthropic, Google, and open-weight models on Base10 or Ollama. ([4:18](https://youtu.be/jtWjkdBNqlk?t=258))
- **Memory can be owned by the user: it lives in your own PostgreSQL (via LangSmith deployment) or in a plain agents.md file in the repo for lighter setups.** — Speaker says self-hosting means you are the only one with access. This is the central argument for DeepAgent over Claude Code when building agents that ship to users. ([4:18](https://youtu.be/jtWjkdBNqlk?t=258))
- **Claude Code still wins on raw terminal coding; the split is personal coding workflow (Claude Code) versus agent infrastructure shipped to users (DeepAgent).** — Speaker cites Claude Code with Opus 4.8 at 78.9% on Terminal Bench 2.1 and 69.2% on SWE-Bench Pro. He says the model and harness were tuned together, while DeepAgent is 'only as good as the model you plug into it'; GPT 5.5 is competitive, a 7B local model is not. ([5:32](https://youtu.be/jtWjkdBNqlk?t=332))
- **The 'open' stack has hidden costs: DeepAgent is built on LangGraph, adds framework prompt overhead to every call, and its multi-tenant, sandboxing and session features are a paid runtime.** — LangChain 1.0 (GA October 2025) has about 8% framework-injected scaffolding overhead per call, down from 14%. Speaker says LangChain's own docs offer lighter options (create_agent, bare LangGraph) for simple bounded agents, and that some features have no released source. ([6:53](https://youtu.be/jtWjkdBNqlk?t=413))
- **Track record is the main gap: DeepAgent launched in March 2026, while Claude Code has been in production since 2024.** — Speaker says DeepAgent is production-tested at OpenSWE and LangSmith Fleet according to LangChain's docs, and that Claude Code is responsible for over 10% of public GitHub commits (a claim he does not source). ([8:13](https://youtu.be/jtWjkdBNqlk?t=493))
- **The closing thesis is that the harness, not the model, is the moat, and the real question is whether an agent's memory belongs to the user or to whoever runs the container it lives in.** — Speaker frames DeepAgent as 'not better than Claude Code at writing code' but better at keeping the agent's state yours. ([8:13](https://youtu.be/jtWjkdBNqlk?t=493))

## Techniques
- **Audit your harness against the five-part checklist** — List the planning/to-do mechanism, file and shell tools, sandboxed execution, context compression, subagent spawning with isolated context, and human approval interrupts. Mark which ones your agent gets from a vendor's CLI and which you own. The speaker's point is that the owned parts are where lock-in lives. *When:* Before choosing an agent stack or deciding what to build in-house versus rent from a CLI vendor.
- **Subagents with isolated context returning one summary** — Give a narrow subtask its own context window; the child does the work and returns one clean summary. The parent agent never sees the child's raw transcript, which keeps the parent's context small. *When:* When a task is too large for one context window or when sub-steps generate lots of intermediate output (file reads, test logs).
- **Keep agent memory in a store you control** — Persist cross-session memory in your own Postgres, or in a plain agents.md file in the repo for light use, so it is readable, portable and queryable without the vendor's API. Speaker presents this as the reason to use an open harness. *When:* When the agent learns preferences or facts across sessions and you may change model or vendor later.
- **Swap the model behind a fixed harness** — Use any tool-calling model as the brain behind the same planning, file and subagent wiring. Speaker says the swap is about two lines of code, but shows no code, so the exact API is not covered. *When:* When you want to compare models on the same agent loop or move to a cheaper or local model for privacy-constrained work.
- **Use a lighter agent abstraction for bounded tasks** — For simple, single-purpose agents, use the lighter create_agent option or bare LangGraph instead of the full deep-agent harness, to avoid the per-call scaffolding overhead the speaker describes. *When:* When the task is narrow and the full planning, subagent and memory stack is more architecture than the job needs.

## Hot takes
- The lock-in framing is editorial: the speaker's claim that memory 'belongs to Anthropic' is strongest only if the memory is stored server-side, which he does not check for Claude Code.
- The benchmark numbers for Claude Code with Opus 4.8 come with no link or methodology, and the video does not run DeepAgent on either benchmark, so the 'Claude Code wins at coding' claim is untested here.
- 'Open' is partly marketing: the speaker concedes multi-tenancy, sandboxing and session management are a paid LangSmith runtime, and that some features have no released source.
- The 'harness is the moat' thesis is presented as settled, but the video only shows one side (open harness vs closed CLI) and does not compare other open harnesses.
