> Walkthrough of eight Claude Code add-ons, mostly from one vendor, that put an LLM yes/no judge at decision points: action gating, rule checks, stop gates, message routing, compaction, file shortlisting and SEO audits.

## Summary
The video, from the AI LABS channel, presents eight Claude Code add-ons that each use a "Jev" decision model to answer yes/no questions at a point in the agent loop: before an action, before finishing, on the rules, during a browser test, on incoming messages, on compaction timing, on file search, and for site SEO. Almost all of them come from the same vendor ecosystem (TypeSafe's API key is the default for most), and the channel pitches its own community and earlier video. Install steps are described verbally ("copy this install command") and the commands are not shown in the transcript, so the setup is not reproducible from the notes alone. Single anecdotal test results are given for each tool (a 77% destructive-risk score, 49 rules with 33 needing judgment, a 37-file search that avoided about 67k tokens, an SEO score of about 76). The most reusable idea is the pattern itself: a small judge model at a decision point with a confidence threshold, which can block, re-prompt or redirect the agent. A sponsored Dakota segment sits in the middle and is unrelated to the tools.

## Key ideas
- **A single small decision model is placed at several points in the Claude Code loop: pre-action, stop, incoming messages, compaction, and file search. Each answers yes/no or picks one of a few options, and acts only above a confidence threshold.** — Stated design across the tools: Toolgate asks the judge before each action; Belay checks at stop; Steer/Queue picks Steer, Queue or Interrupt and acts only at 90% or more; Compact Advisor advises when to compact; Quicksilver shortlists files. The thresholds are the main control knob. ([0:00](https://youtu.be/jlEMo6Dsh9E?t=0))
- **Toolgate is a pre-action gate that is stricter than Claude Code's auto mode. It blocks irreversible changes, prompt injection, downloaded tools that send data out, use of permissions never granted (such as admin mode), and off-task actions, and it hands real decisions back to the user.** — In the test, Claude began deleting a folder without copying it first; Toolgate scored the action 77% destructive. Normally that means a confirm prompt, but in a no-permission-prompt mode it blocked the action, and Claude copied the files somewhere safe and finished. The speaker notes the downside: it also blocks deletions that are actually needed. ([1:24](https://youtu.be/jlEMo6Dsh9E?t=84))
- **Abide turns agents.md / CLAUDE.md rules into a rubric of yes/no questions, checks every edit against it, and forces the agent to fix every flagged violation before it can finish.** — The rubric in the test had 49 rules; 33 needed the judge to decide. The compile step and its log live in a .abide folder. The speaker's stated reason is that agents keep breaking project rules. ([2:52](https://youtu.be/jlEMo6Dsh9E?t=172))
- **Jev Browser has Claude drive a browser and the judge makes the yes/no calls on what is on screen. It is exposed as an MCP server, and the test ran in about 2 minutes and returned a bug list.** — The one-line installer installed an outdated version, so the speaker asked Claude to install the latest release. By default it works only with the TypeSafe key, and the speaker suggests asking Claude to adapt it for another provider. ([5:01](https://youtu.be/jlEMo6Dsh9E?t=301))
- **Jev Belay is a stop gate. When Claude says it is done, the judge reads the whole conversation for proof of completion and re-prompts Claude to prove the task if the proof is missing. The speaker compares it to Ralph loops, with the difference that the judge decides completion.** — Setup asks for the install scope, a provider key, and a confidence threshold, which was set to 75. Options include a decision log and a counterfactual log showing what would have happened without the gate. ([6:25](https://youtu.be/jlEMo6Dsh9E?t=385))
- **Steer/Queue/Interrupt routes a new user message sent while Claude is working. Default behavior (deliver after the current step) is kept unless the judge is at least 90% confident the message is urgent (Interrupt) or belongs to a different task (Queue).** — Works with both Codex and Claude Code. Example from the test: a colour-theme change during a landing-page build was judged urgent and sent through immediately. ([8:56](https://youtu.be/jlEMo6Dsh9E?t=536))
- **Compact Advisor advises after each reply whether to compact, based on session depth and whether the context can be compacted without losing needed details. The speaker's rule of thumb in the test is roughly 100k tokens with no open question.** — The speaker reports that compaction done at the advised time kept more of the session details than compaction at a random time. ([10:24](https://youtu.be/jlEMo6Dsh9E?t=624))
- **Quicksilver has the judge shortlist files for a query before Claude reads any of them, so Claude reads only the shortlist. This keeps the context window clean.** — Test: the judge checked 37 files in about 2 seconds, and Claude avoided reading about 67,000 tokens of files. This is a single run on the speaker's own app. ([11:35](https://youtu.be/jlEMo6Dsh9E?t=695))
- **Jev SEO crawls a site by following links, runs a fixed set of technical checks (broken links, sitemap problems), asks the judge the same content questions for every page (helpfulness, title fit), and outputs a PDF with per-area scores plus an Excel to-do tracker.** — Invoked as the /jevseo slash command with a URL. The tested site scored about 76 overall. The report also says whether the site is ready for AI search. ([12:59](https://youtu.be/jlEMo6Dsh9E?t=779))

## Techniques
- **Judge-gated pre-action hook (Toolgate pattern)** — Install the gate, store the provider key (the speaker uses the key command; the exact name is not shown) and any provider name from the repo, then run `toolgate init` (per the speaker) so the gate attaches to Claude Code and stores its rules and key in a folder. Before each tool action, the judge returns allow or block, and risky actions escalate to the user when the agent has confirm permissions. *When:* When running Claude Code with auto-approved permissions and you need a stricter gate than auto mode, and you accept that some legitimate destructive actions will be blocked.
- **Rules-to-rubric compilation (Abide pattern)** — Run the install command, pick the key provider and the scope (all projects or one project), then run the init command. In a Claude Code session, ask Claude to create the rubric. The result is a .abide folder with the rubric (one yes/no question per rule), a compile skill that records how the rubric was built, and a step log. Every edit is then checked, and Claude must fix every flag before finishing. *When:* When CLAUDE.md or AGENTS.md has many project rules that agents keep breaking, and some rules need judgment that a regex or linter can't check.
- **Completion gate with a confidence threshold (Belay pattern)** — Add the marketplace (this also reloads plugins), install the plugin, answer the setup questions (scope, provider key, threshold such as 75), and optionally enable the decision log and the counterfactual log. On each stop, the judge reads the whole conversation for proof; if it is below threshold, Claude is re-prompted to prove the task. *When:* When agents say they are done when they are not, and you want an automatic check before they are allowed to stop; the same logic applies to long unattended loops.
- **Three-way routing of mid-run messages (Steer/Queue/Interrupt)** — Install the plugin and add the provider key. For each new message sent during a run, the judge chooses Steer (deliver after the current step, the default), Queue (hold until all work is done, then send as a new request), or Interrupt (stop now). The plugin acts only at 90% or more confidence. *When:* When you often send follow-up messages during a long run and need to avoid tasks being mixed or an urgent change being delayed.
- **Advised compaction timing** — Install from the GitHub repo commands, start a new session, and answer the first-run questions (provider key, minimum context). After each reply, check the advice. The example trigger is about 100k tokens used with no pending question and nothing new to continue from. *When:* For long Claude Code sessions where compacting at a bad moment drops details the agent still needs.
- **Shortlist-then-read file retrieval (Quicksilver pattern)** — Run the install command once. Ask Claude to use Quicksilver for a search task (the speaker's example: find files that do not follow a shared colour setting). The judge screens the files and returns a shortlist, and Claude reads only the shortlisted files. *When:* When a task requires scanning many files to find a few, and reading every file would burn context and tokens.
- **Browser-driven test pass with judge verdicts** — Ask Claude to install the latest Jev Browser release, since the one-line installer may be outdated, and check that the browser tools are exposed as an MCP. In the prompt, name the Jev Browser tools explicitly, then ask for the test. Claude uses the tools several times and returns a bug list. *When:* For end-to-end checks of a web app where you want a bug report rather than just a pass or fail.
- **Site audit with a fixed checklist plus per-page judgment** — Install the SEO skill from the on-screen commands. Run `/jevseo <url>`. The skill crawls by following links, runs fixed technical checks, asks a fixed set of content questions for each page, and writes a PDF with per-area scores and an Excel to-do tracker. Re-run after fixes. *When:* When you need a repeatable audit of a site's SEO and AI-search readiness, with a task list.
