> Better Stack walkthrough of Alpic's SkyBridge 1.0, a TypeScript/React framework for building MCP apps (interactive widgets inside chatbots), shown by building and testing a camera-lens store app with its local dev dashboard, tunnel and Beacon Audit.

## Summary
The host argues that chatbot users increasingly expect interactive widgets instead of JSON or markdown output, and that an MCP app is effectively built for two users at once: the human and the LLM, which share one interface and state. He presents SkyBridge, an open-source TypeScript framework from Alpic that handles protocol bridging, state sync and security rules so developers can write standard React. SkyBridge 1.0's local dev server opens an emulator dashboard with three tools: the Alpic Playground (sandboxed testing with hot module replacement, no LLM needed), a one-click public tunnel, and Beacon Audit, which checks metadata, tools and security policies for common store-rejection triggers. The demo installs the SkyBridge agent skill into a repo, asks Claude to build a lens-shopping MCP app for an existing React store, and tests its search, compare and checkout flows in the dashboard. It then adds the tunnel URL as a custom connector in Claude's settings, where per-tool permissions can be set to auto-run or require approval, and confirms the widget opens inside a real chat. The video is a product walkthrough with no code or commands shown, and it presents the app as production-ready after a few minutes of generation, which the demo itself undercuts with a CSS white-space bug.

## Key ideas
- **MCP apps replace plain JSON or markdown answers in chatbots with interactive widgets.** — The premise is that users increasingly do routine searches and research through chatbots, so apps are switching to in-chat UI. The host presents this as a broad shift rather than backing it with data. ([0:00](https://youtu.be/9X8GRGcl5oA?t=0))
- **An MCP app is built for two users, the human and the LLM, who share one interface and state.** — Clicks and inputs from the human are visible to the LLM, and the LLM can update the data in the background so the UI changes live. This shared state is the core design difference from a traditional single-user web app. ([0:58](https://youtu.be/9X8GRGcl5oA?t=58))
- **SkyBridge is pitched as a framework that hides the protocol, state-sync and security plumbing.** — Developers write standard React components and the framework handles the bridging between the MCP protocol and the UI. The host describes it as open source TypeScript. ([0:58](https://youtu.be/9X8GRGcl5oA?t=58))
- **SkyBridge 1.0's dev server opens an emulator dashboard that removes the usual tunnel and restart loop.** — Previously, testing needed manual public tunnels, copy-pasted config and restarting chat sessions to fix small CSS issues. The dashboard offers a Playground with hot module replacement, a one-click tunnel, and Beacon Audit. ([0:58](https://youtu.be/9X8GRGcl5oA?t=58))
- **Beacon Audit is meant to catch store rejection triggers before submission.** — It scans app metadata, tools and security policies. The host says this matters only if the app will be submitted to public stores, and he does not show the audit output. ([2:11](https://youtu.be/9X8GRGcl5oA?t=131))
- **The app is generated by an agent that first asks intent questions, guided by the installed SkyBridge skill.** — The skill sits in a repo-level .agents directory. Claude asked follow-up questions about the app's intent before building, and the demo app took a few minutes to generate. The host notes it is easier to install the skill globally or per repo, and he chose per repo. ([3:07](https://youtu.be/9X8GRGcl5oA?t=187))
- **Connecting a local MCP app to a real chat is a settings flow with per-tool permissions.** — The tunnel URL is pasted as a custom connector in Claude's settings, then connected. Each tool can be set to run automatically or to require user approval. The host shows the widget opening in a fresh chat with a portrait-lens query. ([5:42](https://youtu.be/9X8GRGcl5oA?t=342))

## Techniques
- **Install the SkyBridge skill into the repo, then prompt the agent to build the app** — Install the SkyBridge skill (the video says it can be installed globally or per repo) so a .agents directory with the skill appears in the repo. Ask Claude to build an MCP app for the existing e-commerce shop, answer its intent follow-up questions (here: search lenses by criteria, select and compare side by side, add to cart, quick checkout), then let it generate the app. The exact install command is not shown in the video. *When:* Starting an MCP app from an existing React storefront when you want the agent to scaffold the widget and tool definitions.
- **Test tools and widget state in the SkyBridge dashboard before involving a chatbot** — Run the local dev server, which opens the emulator dashboard. Call each tool (here: search lenses with a max price and a result limit, and place order), check the desktop, mobile, dark and light views, and inspect the tool output and state panel while selecting items. Use the Playground for live hot-module-replacement edits to React widgets. *When:* Iterating on widget UI and tool logic quickly, since the video says this avoids touching a real LLM for every change.
- **Expose a local MCP server with the dashboard tunnel and attach it as a Claude custom connector** — Activate the tunnel in the dashboard to get a public URL. In Claude, open Settings, then Connectors, click Customize, add a custom connector with a name and the tunnel URL, click Add, then Connect. Set each tool's permission to automatic or to require approval. *When:* Trying the app inside a real chat client without deploying it first.
- **Run Beacon Audit before submitting to an app store** — Open the audit from the developer dashboard. It checks metadata, tools and security policies for common rejection causes. The video does not show the rules or the output format. *When:* Preparing an MCP app for public submission, such as to an AI app store.
