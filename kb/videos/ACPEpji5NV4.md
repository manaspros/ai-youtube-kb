> DoorDash's search and personalization lead on using LLMs offline to create graded relevance labels, semantic IDs, and memory, then serving those through small, fast models.

## Summary
Raghav Saboo (DoorDash, staff ML engineer on search and personalization) argues that marketplace discovery is mainly a semantic-understanding problem, and that engagement-only ranking surfaces popular but wrong items. He describes four primitives: supervision, catalog semantics, consumer memory, and steerable content generation. The core pattern is to spend expensive LLM reasoning once, offline, to produce graded relevance labels, then distill those labels into small models that serve retrieval and ranking cheaply. Labels are built from a human seed set, audited by a stronger LLM where human labels disagree with strong behavioral signals, and used to fine-tune a lightweight labeler that covers the full catalog. Semantic IDs (learned hierarchical codes) and three-timescale consumer memory feed the same downstream models. Reported results include about +2.3% relevance NDCG for retrieval, +4 to 5% MRR for the ranker from semantic IDs, and about 1% order-rate lift in the pets vertical. The talk is a practitioner overview with some metrics, not a detailed method paper.

## Key ideas
- **Discovery is a semantic-understanding problem, not only an engagement problem** — Engagement-only ranking keeps surfacing popular items that fail the user's constraint (e.g. regular spaghetti for a gluten-free pasta query). LLMs give a way to reason about item meaning and shopper intent. ([0:08](https://youtu.be/ACPEpji5NV4?t=8))
- **Use LLMs offline to create graded supervision, then distill** — Human seed labels (0/1/2 relevance) are expensive and go stale, and behavioral signals are biased by exposure, position and price. So an LLM produces the labels. Expensive reasoning runs once offline, then a lightweight labeler is fine-tuned and run across the full catalog. The resulting labels are a shared target for retrieval and ranking. ([3:39](https://youtu.be/ACPEpji5NV4?t=219))
- **Audit labels by disagreement with behavior** — When a human label says irrelevant but the item converts well, the case goes to a stronger LLM with more granular prompts. Labels are also reconciled with query-to-taxonomy models. This gives a high-precision golden set. ([5:02](https://youtu.be/ACPEpji5NV4?t=302))
- **Standard embeddings blur exact matches, substitutes and complements** — The fix is a two-stage contrastive retrieval model on the graded labels. Stage one shapes global geometry with two-tower multi-level supervised contrastive loss, then mines hard negatives. Stage two runs curriculum training on those relabeled hard negatives. Stage two is where the relevance separation appears. ([5:56](https://youtu.be/ACPEpji5NV4?t=356))
- **Add a relevance tower next to engagement towers instead of replacing the ranker** — An ordinal relevance tower trained on LLM graded labels sits beside click, add-to-cart and conversion towers and shares the bottom layers. A value function blends engagement and relevance per surface. The LLM is distilled into the production ranker, not used in its place. ([8:16](https://youtu.be/ACPEpji5NV4?t=496))
- **Semantic IDs give a learned hierarchy with no labels** — Each catalog item gets a short hierarchical code. Shared prefixes capture broad neighborhoods, later tokens capture fine splits (e.g. Mexican vs Caribbean vs Korean hot sauces). The code helps cross-category links, cold start (via n-gram/BPE tokens as sparse features), tail coverage, and auditing human labels. ([9:47](https://youtu.be/ACPEpji5NV4?t=587))
- **Consumer memory in three timescales, stored in three forms** — Long-term durable preferences (orders, search, browsing, support), real-time in-session context, and stated preferences from agentic chat. Each user's memory is kept as readable text, latent vectors and a graph, so both LLMs and retrieval/ranking models can use it without re-interpreting it. ([14:05](https://youtu.be/ACPEpji5NV4?t=845))
- **Batch-generate personalized content offline and serve it with the existing stack** — An offline LLM builds consumer-level collections (title, subtitle, items) from memory and semantic IDs. At serving time the existing retrieval and ranking handle item hydration and collection ranking, so there is no online LLM call. ([18:28](https://youtu.be/ACPEpji5NV4?t=1108))
- **Takeaway: the online LLM call is often not the architecture you need** — Capture reasoning as offline artifacts (labels, semantic IDs, memory) and let small, fast models serve them. Once the primitives exist, they support retrieval, ranking and content generation. ([20:59](https://youtu.be/ACPEpji5NV4?t=1259))

## Techniques
- **Offline LLM labeling with a distilled labeler** — Build a small human seed set of query-item pairs on a 0/1/2 graded scale. Send suspicious cases (human says irrelevant, behavior says strong) to a stronger LLM with finer prompts. Reconcile with taxonomy models. Fine-tune a lightweight LLM on the golden set and run it over the full catalog. *When:* Relevance labels are needed at catalog scale, human labels are too slow or stale, and behavioral logs are biased by exposure.
- **Label-audit by disagreement** — Flag cases where human labels conflict with strong conversion or add-to-cart signals. Re-evaluate those with a stronger model and adjust labels when category models agree. *When:* Building a high-precision gold set from mixed human, LLM and behavioral sources.
- **Two-stage contrastive retrieval with hard-negative curriculum** — Stage one: two-tower encoder with multi-level supervised contrastive loss for global geometry. Mine hard negatives, meaning items ranked too high or positives ranked too low. Stage two: curriculum training on relabeled hard negatives. *When:* Plain embeddings collapse exact matches, substitutes and complements together in a large catalog.
- **Auxiliary ordinal relevance tower with value-function blend** — Add a tower trained on LLM graded labels that shares bottom layers with the engagement towers. Predict relevance level probabilities in the same backward pass. Blend engagement and relevance scores with a per-surface value function. *When:* Adding relevance to an existing engagement-optimized ranker without giving up business metrics.
- **Hierarchical learned semantic IDs as sparse features** — Learn short hierarchical codes from data with no labels. Prefix sharing gives neighborhoods. Tokenize IDs with n-gram or BPE and use them as sparse ID features for new or tail items. *When:* Catalog is huge and changing, taxonomy is too coarse, and new items need signal before they have exposure.
- **Multi-form consumer memory blocks** — Store each memory block as text (human-readable), embedding (for retrieval/ranking features) and graph or hierarchy (for multi-hop relations). Keep it decoupled so downstream systems read it without reinterpreting. *When:* LLM agents and traditional ML models both need the same user context, and it must be inspectable.
- **Batch generation of personalized content with the existing ranking stack** — Generate content (titles, subtitles, item sets) offline with an LLM from memory and IDs. Serve by reusing retrieval and ranking for hydration and ordering. *When:* Per-user content variety is wanted without adding online LLM latency or cost.

## Numbers
- Graded relevance seed set on a 0/1/2 scale for query-item pairs, later used as the basis for LLM-labeled golden data ([3:39](https://youtu.be/ACPEpji5NV4?t=219))
- Retrieval relevance NDCG improved by about 2.3% after the two-stage contrastive approach, and downstream business metrics also improved ([6:54](https://youtu.be/ACPEpji5NV4?t=414))
- Semantic IDs improved the ranker's MRR by about 4 to 5%, which translated into conversion wins ([12:40](https://youtu.be/ACPEpji5NV4?t=760))
- Store-item catalog is a few billion items across international stores ([9:47](https://youtu.be/ACPEpji5NV4?t=587))
- Pets vertical: close to 1% order-rate increase and 0.6% increase in active users from personalized collections ([19:49](https://youtu.be/ACPEpji5NV4?t=1189))

## Hot takes
- The online LLM call is often not the product architecture you need; capture the reasoning offline and serve it through small models.
- Discovery is a semantic understanding problem, not an engagement optimization problem.
