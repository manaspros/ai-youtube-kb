## Summary
The host installs Roo Code, a bring-your-own-key VS Code extension, and routes it through OpenRouter. He builds a Hacker News clone in Architect mode, then switches to Code mode, using the Enhance Prompt button and auto-approve settings to reduce confirmations. The agent runs npm commands, recovers from its own command errors, and uses a browser it launches itself to screenshot the app, compare it with a reference image, and test form validation. The video then covers cost (about $0.50 for one task on Claude Sonnet versus an estimated $0.02 on Gemini 2 Flash), settings, per-mode API assignment, custom modes defined in JSON with file-regex edit limits, support-prompt customization, and creating MCP servers from a prompt. It is a product tour with few benchmarks; most of the value is in the configuration surface shown on screen. The title is hype and the host's claims about cost ratios and model behavior are not verified in the video.

## Techniques
- **Architect-then-code split** — Start the task in Architect mode so the agent writes a plan (and any files it proposes), review and approve, then let it switch to Code mode to implement. Run the plan step in Ask or Architect when you want read-only exploration. *When:* Multi-file greenfield tasks, where a written plan reduces wasted edits and makes the approval step meaningful.
- **Enhance Prompt before sending** — Type a short request, click the Enhance Prompt button to expand it with features, layout and styling detail, then review the expanded text before pressing enter. *When:* One-line requests that would otherwise leave the agent guessing about scope and styling.
- **Category-scoped auto-approve** — In the auto-approve settings, enable file edits first. Keep command execution and browser actions manual until you trust the repo. Enabling all of them turns the extension into an unattended agent. *When:* Throwaway or sandboxed projects, where you accept that the agent runs commands without review.
- **Browser self-check loop for UI work** — After the dev server starts (for example localhost:3000), ask the agent to open its own browser and compare the page with an attached reference screenshot. Set the browser viewport and screenshot quality in the settings. Then have it iterate on the differences and check again. Also ask it to try invalid input and confirm error messages appear. *When:* Frontend tasks where there is a visual reference or testable form behavior, and where compile success alone is not enough.
- **Per-mode model assignment** — Open the prompts settings (book icon), pick a mode, and set its API configuration: a cheaper model for documentation or planning modes, and a stronger coding model for Code mode. Type 'free' in the model field to list free models, which have rate limits. *When:* Mixed workloads where cost differs by task type, or where you want to test model cost against task quality.
- **Custom mode via prompt, then scope with file regex** — Ask the agent to create a new mode (for example a documentation writer). It writes the role definition, tool groups and custom instructions to a project-level modes file. Edit the JSON to set the edit tool's file regex to the file types the mode should change, such as .md only. *When:* Recurring roles that need a narrow write scope. The file regex enforces the limit, not just the prompt text.
- **Edit support prompts and attach diagnostics** — In the prompt settings, change the template for Enhance Prompt, explain code or fix issues, and select a different API for each. Use the @problems mention to feed workspace diagnostics into the prompt, or right-click a problem in the Problems tab and ask Roo to fix it. *When:* Tailoring the editor-side helper actions to your team's conventions, or fixing lint and type errors that the editor already reports.

## Hot takes
- Title says AMAZING and 'better than Cursor?', but the video is a feature tour with one small demo and no comparative benchmark against Cursor.
- The 37x cheaper claim does not match the host's own per-token prices (about 150x on input, 7.5x on output), and the 2-cent figure is an estimate.
- The host says Gemini lacks computer use and prompt caching, and suggests caching may not matter given the price. These are unverified claims made without a test.
- The auto-model-selection feature the host calls his 'dream feature' is described from settings but not demonstrated.
- The fork-origin story is hearsay from the host ('from what I can tell'). The video does not verify it.
- Hype caveat: the title and tone are promotional, with no sponsor shown. The substance is a useful configuration walkthrough, but the video does not test failure modes such as auto-approved destructive commands.
