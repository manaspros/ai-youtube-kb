> Walkthrough of Claude Routines (cloud-run scheduled, GitHub-event and API-triggered Claude Code tasks), covering setup gotchas, daily run caps and why the presenter finds them too expensive for most automation.

## Summary
The presenter tests Claude Routines, a cloud-hosted upgrade to Claude Code scheduling that runs a prompt on Anthropic infrastructure on a cron-style schedule, a GitHub event, or an API POST. He builds two examples: a daily 9am newsletter digest sent to Slack, and an automated PR reviewer. Routines are created with the /schedule slash command or in the web/desktop app, and the CLI only supports schedules, so GitHub and API triggers require the app. The main setup gotchas are an auto-attached GitHub repo he removed, a default environment that blocks Bash network calls (fixed with a custom environment that allows listed domains, or by using WebFetch), and cloud instances that lack local skills, settings and hooks, which must be shipped through a repo's .claude folder. Routines draw from subscription usage like interactive sessions and have a daily run cap (5 per day on Pro, 15 on the 20x Max plan by his account), while manual test runs did not count toward it in his observation. He concludes they are too expensive for most automation, prefers webhook-driven self-hosted agents on cheaper models, and sees Anthropic's cloud features as a larger direction.

## Key ideas
- **Claude Code now has three ways to run tasks: in-session loops, local or remote schedules, and routines, which add GitHub event triggers and API POST triggers on top of remote schedules.** — Routines run the prompt on Anthropic cloud infrastructure with chosen connectors and environments. The presenter frames this as part of a wider push toward cloud features such as managed agents and the ultra plan. ([0:00](https://youtu.be/yVnsU-xqng4?t=0))
- **A routine is created by typing /schedule followed by a plain-English prompt that includes the cadence and sources; Claude then drafts the environment, time zone and prompt.** — The example was a daily 9am trigger that fetches three newsletter RSS feeds, picks 10 articles and posts them to Slack. The default result is a remote routine, viewable in the browser or app. ([1:01](https://youtu.be/yVnsU-xqng4?t=61))
- **Default routine setup has traps: an unneeded GitHub repo gets attached, the prompt needs to forbid horizontal rules (Slack block validation fails on them), and connectors must already exist.** — Because a routine runs unattended, the prompt must not ask for permissions or clarification. ([2:26](https://youtu.be/yVnsU-xqng4?t=146))
- **The default environment blocks Bash network access, so curl to RSS feeds fails. A custom environment with an allowlist of domains fixes it, and WebFetch works without that allowlist because it goes through Anthropic's infrastructure.** — The presenter saw DNS failures on the Bash path and a fallback to WebFetch, and one feed failed even though it worked in an earlier test. ([3:35](https://youtu.be/yVnsU-xqng4?t=215))
- **Routine pricing: research preview, available on Pro, Max, Team and Enterprise; runs consume subscription usage like an interactive session and count against a daily routine cap (5 per 24 hours on Pro).** — Manual test runs did not count toward the daily cap in his test, while scheduled and triggered runs did. He notes 15 runs per day on the 20x Max plan. ([5:03](https://youtu.be/yVnsU-xqng4?t=303))
- **Cloud routines start from a fresh Claude Code instance with no access to local skills, settings or hooks, so those must be shipped in a repo's .claude folder, for example a settings.json hook that copies skills into the cloud skills directory.** — He also adds prompt guardrails that verify the skill was actually loaded before running it. ([6:23](https://youtu.be/yVnsU-xqng4?t=383))
- **A PR review routine on a GitHub event trigger cloned two repos, loaded the custom PR review skill, fell back to the GitHub MCP tool when no token was supplied, and posted an approval comment, using up one of the five daily runs.** — The presenter's verdict: it is too costly for everyday use, though far easier than building an equivalent setup from scratch. ([7:52](https://youtu.be/yVnsU-xqng4?t=472))
- **The presenter's conclusion is that routines are not a fit for every automation. A single prompt per routine is the model, and chaining prompts through a repo still costs a lot, so he prefers webhooks into a self-hosted agent such as Hermes Agent, or Multica with Hermes, on a cheaper model.** — He names GLM 5.1 and a GPT coding model as cheaper options and expects Anthropic to be heading toward something bigger with these cloud features. ([9:11](https://youtu.be/yVnsU-xqng4?t=551))

## Techniques
- **Schedule a remote routine from the CLI** — Run /schedule with a natural-language prompt that states the cadence, sources and output channel (e.g. 'create a daily 9 a.m. trigger that fetches RSS from <feeds>, picks 10 articles and sends them to me via Slack'). Review the generated time zone, environment and prompt in the web or desktop app, and remove any auto-attached repo you do not need. *When:* Recurring briefings or digests where a hosted run is acceptable and the local machine should not need to stay on.
- **Write prompts for unattended runs** — Tell the routine not to ask permission or clarifying questions. Add formatting constraints for the destination, such as no horizontal-rule dividers for Slack, and state the required connectors up front. *When:* Any routine, because nobody is present to answer prompts during a run.
- **Work around the Bash network block with a custom environment** — Create a custom environment instead of the default, set network access to custom, and list the required domains (e.g. the RSS feed hosts). Alternatively, have the prompt use WebFetch, which bypasses the Bash restriction. *When:* The routine must fetch external URLs and the default environment blocks outbound requests from Bash.
- **Ship skills and hooks to the cloud instance through a repo** — Commit a .claude folder to a repo the routine clones. Include settings.json with a hook that copies the bundled skills into the cloud instance's skills directory, and add a prompt check that confirms the skill loaded before the task runs. Keep the GitHub token in the environment if the skill expects one. *When:* A routine needs local Claude Code skills, settings or hooks, which the cloud instance does not inherit.
- **Trigger PR reviews from GitHub events** — Create a remote routine in the desktop or web app, attach the target repo, choose the GitHub event trigger, and put the PR review skill and prompt in the routine. The CLI cannot create GitHub or API triggers. *When:* Automatically reviewing new PRs with a custom review skill without running your own webhook server.
- **Compare routine cost with a self-hosted webhook agent** — Count daily runs against the routine cap and subscription usage. Compare that with a webhook that calls a self-hosted agent (Hermes Agent, or Multica with Hermes) on a cheaper model. Use the cloud routine only for the cases that justify the cost. *When:* Deciding whether recurring automations belong on Claude routines or on cheaper self-hosted infrastructure.

## Hot takes
- Routines are very expensive for what they do. The presenter says he would not use them regularly, and that for most people a webhook into a self-hosted agent on a cheaper model is better.
- Routines are not for every automation. A single prompt per routine cannot cover complex workflows, and chaining prompts through a repo still costs a lot.
- The default routine setup adds unnecessary repos and blocks network access. Users should review and edit the generated configuration before relying on it.
- Anthropic seems to be heading toward something bigger with its cloud features. The speaker is curious, but offers no evidence beyond the product trend.
- The title promises hidden costs, but the video gives no dollar figures. Its cost argument rests on the daily caps and subscription usage burn.
