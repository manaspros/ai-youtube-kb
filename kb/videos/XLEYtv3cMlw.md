> Sina Shahandeh (Radicait) on why coding-agent research loops stall on open-ended science, and how decomposing a codebase into linked component docs plus cross-model critique gets better hypotheses.

## Summary
The speaker starts from Karpathy's auto-research loop, where a coding agent hill-climbs a metric, and says it works for well-defined tasks but saturates on open-ended, long-horizon scientific work. In his view the learning and implementation parts are largely solved, and the real bottleneck is generating good hypotheses, or "research taste". His running example is Radicait's work on synthesizing PET scans from CT with an image-translation model, where the agent got stuck on a 2.5D model and only moved when a person prompted it toward a 3D idea. His fix is to have the coding agent decompose the whole project into a hierarchy of linked markdown documents (problem, data, architecture, loss, metrics, scripts, down to the code), viewed in Obsidian. A reasoning model then reviews each component and proposes changes, which he says lets the system generate on the order of 100 candidates and reach more radical changes. He extends the loop with image registration, where he adds a multimodal model as a qualitative critic (lung masks, cropping) and a stronger reasoning model (GPT-5.5 Pro via a packing CLI) for hypotheses and outcome review. He closes by saying current models cannot read small scientific image details, so they need fine-tuning on scientific data. He also argues the hierarchy trick is like chain-of-thought: a stopgap that newer, better post-trained models may make unnecessary. The talk is a practitioner account with no benchmark results.

## Key ideas
- **Coding-agent research loops saturate on open-ended science because they run out of ideas, not because they cannot implement or learn from errors.** — Hill-climbing a metric works for well-defined tasks. Long-horizon scientific problems hit a plateau when the agent stops producing new hypotheses. Implementation and memory of past mistakes are seen as largely solved. ([0:00](https://youtu.be/XLEYtv3cMlw?t=0))
- **Hypothesis generation is the hard part; a human had to prompt the agent to try a 3D idea it never proposed on its own.** — The initial model was 2.5D (CT slices fed as channels to 2D convolutions). Ordinary tuning never led to a radical change like 3D convolutions or reframing the problem. The speaker had to inject ideas mid-loop. ([5:21](https://youtu.be/XLEYtv3cMlw?t=321))
- **Decompose the whole project into a hierarchy of linked component documents before asking for ideas.** — A prompt tells the coding agent to read the codebase and write a level-1 README with the problem statement, then linked level-2 and level-3 docs for data, architecture, loss, metrics and scripts. Each doc is kept short and ends at the actual code. ([6:42](https://youtu.be/XLEYtv3cMlw?t=402))
- **With the hierarchy in place, a reasoning model can propose and review changes to each component, which broadens the search.** — Every component is a place to make a change, so the search covers more of the space. The speaker says this can yield around 100 candidate solutions, and it surfaced a 3D change that the plain loop would have missed. ([9:28](https://youtu.be/XLEYtv3cMlw?t=568))
- **Turn qualitative QC into a loop step by having a multimodal model judge outputs as a metric.** — For image registration, the metrics are partly qualitative, such as whether a lung mask sits on the lungs or whether the scan is cropped right. A vision model can review the image and return an opinion. This is packaged as a reusable skill. ([13:55](https://youtu.be/XLEYtv3cMlw?t=835))
- **Use a stronger reasoning model for hypothesis and critique, and send it the full context.** — Hypothesis generation and critique of past changes go to a larger reasoning model. A packing CLI bundles the code and data and sends them to a GPT-5.5 Pro API call. Each loop asks whether the change worked and what to do next. ([15:19](https://youtu.be/XLEYtv3cMlw?t=919))
- **Current multimodal models cannot see fine scientific detail, so the next bottleneck is observation, not reasoning.** — The speaker says models cannot reliably spot small findings such as a lung nodule, because they were not trained on scientific images. He suggests fine-tuning models so they can observe the way a trained scientist does. ([16:32](https://youtu.be/XLEYtv3cMlw?t=992))
- **The hierarchy trick is a stopgap, similar to chain-of-thought, and better post-trained models may make it unnecessary.** — Chain-of-thought was added on top of base models before models learned to reason natively. The speaker expects models post-trained to split problems up to need less of this scaffolding, but until then manual decomposition scales test-time compute in a structured way. ([17:45](https://youtu.be/XLEYtv3cMlw?t=1065))

## Techniques
- **Hierarchical component docs as a scaffold** — Prompt the coding agent to walk the codebase and write a linked tree of markdown docs, starting from a level-1 problem README and descending to data, architecture, loss, metrics and scripts. Keep each doc short and link them, such as in Obsidian. *When:* A coding-agent loop has plateaued on an open-ended problem and needs a structured view of the whole system to find new ideas.
- **Hypothesis generation over each component** — Give a reasoning model the component tree plus the objective and ask for changes to every component, optionally with an adversarial or collaborative review pass. Gather many candidates and pick among them. *When:* Plain 'optimize this metric' prompts saturate, and radical changes such as changing dimensionality or the problem framing are needed.
- **Multimodal model as a qualitative metric** — Wrap a vision-capable model in a skill that takes a generated image or overlay and returns a judgment, such as mask placement or alignment quality. Call it inside the loop next to quantitative metrics. *When:* Some success criteria are visual or hard to measure numerically, as with image registration, masks and crops.
- **Split roles across models in the loop** — Use a fast or vision model for observation and a larger reasoning model for hypothesis generation and critique of past iterations. Send the reasoning model a packed bundle of code and data through a CLI wrapper. *When:* Hypothesis quality matters more than cost, and the reasoning model needs the full project context.
- **Per-iteration outcome review** — After each implementation, ask the model whether the change was effective and what should happen next, and feed the answer into the next hypothesis step. *When:* You want the loop to learn from each experiment instead of only logging metric values.

## Numbers
- The hierarchy-driven hypothesis step is described as able to produce about 100 candidate solutions. This is the speaker's framing, and no measured results are shown. ([9:28](https://youtu.be/XLEYtv3cMlw?t=568))
- Example pipeline: synthesize PET from CT with a GAN-style encoder-decoder. The first model was 2.5D and the idea that moved it was a 3D change. No metric values are given. ([4:01](https://youtu.be/XLEYtv3cMlw?t=241))
- Speaker's example horizon for a full research process is two to ten years, broken into loops. This is illustrative, not measured. ([4:01](https://youtu.be/XLEYtv3cMlw?t=241))

## Hot takes
- Implementation and learning from mistakes are largely solved for coding agents. Hypothesis generation, or research taste, is the real bottleneck for autonomous science.
- Multimodal models today lack the understanding of scientific images needed to close the loop, so better scientific observation is the biggest gap.
- Manual problem decomposition is a temporary trick, like chain-of-thought, and newer models should make it unnecessary.
