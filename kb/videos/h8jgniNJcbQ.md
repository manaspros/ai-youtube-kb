> Tim Tyler (Gravitee) argues AI agents should be governed like employees: a unique identity, a named human sponsor, a scoped role and authority, and tiered recourse, with rules as a deterministic floor and intents judged probabilistically.

## Summary
Tim Tyler of Gravitee presents an "agent accountability" framework that treats AI agents as a digital workforce and borrows enterprise HR and access-control practices for them. The framework has three stages: assignment (identity, a named sponsor, role), alignment (scope and authority bounded down the delegation chain), and administration (oversight, scorecards, and recourse). He separates deterministic rules (hard limits such as spend caps or never approving a payment) from probabilistic intents (judged with confidence scores), and proposes thresholds that map confidence to actions like redact, escalate to a human, or block. He treats inherited alignment (the base model, incoming context, outside agents) as something the enterprise cannot control, and says a delegated agent's scope must never exceed its parent's. The talk is conceptual: it has no benchmarks or data, and the framework's controls are published as an auditable document rather than shown in a working system. Roughly the first and last minutes are a hiring pitch and company plug.

## Key ideas
- **Govern agents as a digital workforce, borrowing from HR** — Enterprises already govern human employees (ID badges, supervisors, MDM, reviews). The speaker argues agents should get the same treatment, and that software-only framing misses the point. He says a CTO, HR and an AI head each framed the agent differently, and HR's view is the one that fits. ([1:10](https://youtu.be/h8jgniNJcbQ?t=70))
- **Every agent needs one unique identity in a shared registry** — The identity is the single point of truth that every other control references. Agents are given distinct IDs (he uses Agent 203 vs Agent 49) so actions can be traced to a specific agent, not a user's clone. ([2:38](https://youtu.be/h8jgniNJcbQ?t=158))
- **A teammate, not a digital clone** — An agent acting on your behalf is not you. It should receive team context (goals, decisions, history) and return context (what it did, what it learned) so humans and other agents can follow its work. ([3:56](https://youtu.be/h8jgniNJcbQ?t=236))
- **A named human sponsor is accountable for each agent** — The sponsor defines the agent's purpose, owns its cost and spend, and gets the call when something goes wrong. He compares the handoff to a pool-supervision rule: an explicit 'I have the kids' acknowledgement, so someone always owns the agent. ([5:05](https://youtu.be/h8jgniNJcbQ?t=305))
- **Role (onboarding scope) vs mission (runtime)** — The role is a job description: purpose, responsibilities, budget and what success looks like, set once and changed rarely. Mission is what the agent is doing right now, such as each MCP tool call, and it changes constantly. ([6:23](https://youtu.be/h8jgniNJcbQ?t=383))
- **Authority scope never grows along a delegation chain** — The sponsor hands out access (which data, which tools). When agent 203 delegates to agent 409, 409 can use only the intersection of what the chain allows, and results return only through the scope everyone shares. Agents should be given the lowest scope that works. ([7:51](https://youtu.be/h8jgniNJcbQ?t=471))
- **Rules are checked, intents are judged, and recourse is tiered** — Deterministic rules form a floor (like fine-grained authorization policies). Probabilistic intents are scored as a weighted scorecard and tied to confidence, with actions at each level. Recourse escalates from correction to restricted authority to suspension, and starts strict before relaxing with repeated success. Guardian agents or an AI gateway enforce this at machine speed, and the sponsor tunes the role and authority. ([12:56](https://youtu.be/h8jgniNJcbQ?t=776))
- **Inherited alignment cannot be controlled, so treat it as untrusted** — The base model's alignment, incoming context and outside agents are not under the enterprise's control and can change. Outside agents are treated like contractors who get an identity and limited authorization. Only the defined alignment (the role and authority contract) is in the enterprise's hands. ([8:55](https://youtu.be/h8jgniNJcbQ?t=535))

## Techniques
- **Three-stage agent accountability model** — Assignment: give each agent a unique ID in a registry, a named sponsor, and a role (purpose, responsibilities, budget, success criteria). Alignment: define authority as an explicit scope and bound every action to it. Administration: monitor outcomes against a scorecard, apply recourse, and let the sponsor adjust the role. The speaker says the framework has published controls that can be audited. *When:* When designing governance for a fleet of agents in an enterprise, or deciding what an agent registry must store.
- **Scope-lineage delegation check** — Model delegation as a chain (A to B to C). Each delegated call is limited to the intersection of the scopes along the chain. A sub-agent only returns data that the caller already holds. Scope never widens during delegation. *When:* When agents call other agents or tools on a user's behalf, and you need to stop privilege escalation through delegation.
- **Deterministic floor plus probabilistic scorecard** — Hard rules are enforced exactly as policy (for example, an invoice approval cap, never approve a payment, write-only access to a ledger). Quality goals are scored as weighted metrics such as invoice match accuracy or reconciliation cycle time, and intent judgments carry a confidence value. *When:* When some agent behaviors must be binary and others can only be judged, such as an agent's output quality.
- **Confidence-tiered action ladder** — Map confidence bands to actions. The speaker's example: at about 90% confidence, redact out-of-alignment content; below 50%, escalate to a human in the loop; below 20%, block. For rule breaches, use a graduated response: correction, then restricted authority, then suspension. Start with tight limits and relax as the agent builds a successful record. *When:* When an automated control has to act on a probabilistic judgment, and you need a predictable response to low-confidence actions.
- **Guardian agents at machine speed** — Run monitoring agents or an AI gateway with guardrails that apply the restriction, prohibition, and suspension decisions in real time, while humans review and tune the role and authority definitions after the fact. *When:* When quarterly human review is far too slow for the number of agent decisions being made.

## Hot takes
- Governance should be a 'digital workforce' model: each agent needs an identity, a named accountable owner, and a scoped role, the same as an employee.
- Agents need micromanagers. Oversight should be machine-speed guardian agents, not quarterly human reviews.
- Never assume inherited alignment. The speaker says frontier models 'have said they're misaligned', which is an unsourced claim.
- Behaving within authority is not the same as succeeding at the role. Monitor both separately.
- Caveat: the framework is conceptual, with no benchmarks or production data. The thresholds (90/50/20) and the five-violation rule are illustrative examples. The opening hiring pitch and the closing company plug are promotional.
