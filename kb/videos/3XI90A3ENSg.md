> Automattic's two-week, in-person AI enablement cohorts (50% facilitated workshops, 50% real project work) and how they scale learning through alumni champions, meetups and a shared MCP and skills hub.

## Summary
Em Shreve from Automattic (WordPress.com, Tumblr, WooCommerce) describes how the company upskills a distributed workforce of about 1,400 people in 82 countries on AI tools. The core format is a two-week immersive, in-person cohort split 50% facilitated learning and 50% real project work, with demos at the end of each day. The engineering curriculum moves from basics (skills, MCPs, responsible use) to building MCPs, extending the Claude Code and Codex hook systems, and running background autonomous agents and routines. The curriculum has to be rewritten constantly because the top model changes from week to week. The company runs an internal MCP server called Context Automattic to add tool sets quickly and to layer governance and observability on top. Alumni are turned into multipliers through a guides or champions program, regional AI get-togethers (about 10 so far), ride-along sessions and an always-on help channel. The speaker reports engagement growth from surveys at 72 hours, 30 days and 90 days, and gives examples of projects that came out of cohorts. The talk is a program-design account with no outcome benchmarks.

## Key ideas
- **Handing people AI tools does not change how they work; they need protected time to learn and experiment.** — The speaker's central claim is that good quality output comes from giving people real time to learn, not from tool access alone. The program is built around that time. ([0:12](https://youtu.be/3XI90A3ENSg?t=12))
- **The two-week cohort is split 50% facilitated workshops and 50% real work.** — Participants bring work they actually need to do, or a tool or dashboard that would help their daily work, or a new skill or MCP. Peer sharing of workflows is part of the format, and each day ends with project demos. ([1:34](https://youtu.be/3XI90A3ENSg?t=94))
- **The engineering curriculum runs from foundations to autonomous background agents.** — It starts with skills, MCPs and responsible use, then moves to building MCPs and using the Codex and Claude hook systems to extend the harness, then to autonomous agents and routines running in the background, and ends with applied WordPress AI and personal assistants. ([3:00](https://youtu.be/3XI90A3ENSg?t=180))
- **The curriculum has to be rewritten continuously because the best model changes week to week.** — A curriculum written once goes out of date quickly. The team keeps updating it so that they do not teach material that is six months old. ([3:58](https://youtu.be/3XI90A3ENSg?t=238))
- **A shared internal MCP server lets the company add tool sets quickly and add governance and observability.** — Context Automattic is used both to wrap providers that have no native MCP server and to add observability. Capabilities built in cohorts accumulate in it, so each cohort adds to what the company can do. ([5:27](https://youtu.be/3XI90A3ENSg?t=327))
- **Alumni are expected to multiply the training to people the team cannot reach directly.** — Cohorts are about 45 people each. Mechanisms include a guides or champions program, regional AI get-togethers run by alumni, ride-along sessions where someone watches a peer in a similar role use a tool, and an always-on help Slack channel. ([5:27](https://youtu.be/3XI90A3ENSg?t=327))
- **The team measures intentionality, flow and sharing, plus individual lift, through surveys at 72 hours, 30 days and 90 days.** — The speaker says people keep gaining confidence after the program ends. Early on, some participants were using AI only as a chatbot, and the program aims to shift them toward deliberate, agentic use. ([9:46](https://youtu.be/3XI90A3ENSg?t=586))
- **Projects from cohorts show non-engineers and cross-functional teams building useful tools.** — Examples include an agentic analytics system for WooCommerce stores, a Zendesk connector on Context Automattic that other teams adopted, a shared skills directory that works across Codex, Claude and open code, and a guided-admin-support tool built by a support staffer. ([11:11](https://youtu.be/3XI90A3ENSg?t=671))

## Techniques
- **Two-week immersive cohort with a 50/50 split** — Run in-person cohorts where half the time is facilitated workshops and half is participants' own real work, with a demo at the end of each day. Hosts come from L&D and an AI enablement team and from inside the company. *When:* Use when the goal is changing how a team works with AI, not just giving them access to tools.
- **Living curriculum** — Review and update the training content on a regular cadence, because the best model and tooling change week to week. *When:* Use for any internal AI training that will run more than once.
- **Internal MCP server as a shared hub** — Host one internal MCP server where new tool sets are added quickly. Add governance and observability layers in front of providers that lack a native MCP server. Cohort projects are contributed back to it. *When:* Use when several teams need the same integrations and you want one place to control access and logging.
- **Tool-agnostic shared skills directory** — Store skills in a single directory that works with several coding agents (Codex, Claude, open code) rather than tying them to one tool. *When:* Use when the organization does not standardize on one coding agent.
- **Champions, regional meetups and ride-alongs** — Name top practitioners as guides who support other teams. Let alumni run local get-togethers. Run ride-along sessions where someone shows a peer in a similar role how they use a tool. Keep an always-on help channel staffed by alumni. *When:* Use when the training cannot reach everyone directly, such as a distributed company, and when people learn better by watching a peer in a similar role.
- **Staged post-program surveys** — Survey participants at 72 hours, 30 days and 90 days after the program, measuring intentionality, flow, sharing, and comfort with skills, custom commands, MCPs and context management. *When:* Use to track whether adoption keeps growing after the program ends, rather than measuring only at the end.

## Hot takes
- You cannot just write this curriculum once; AI changes so fast that a curriculum goes stale within weeks.
- Make learning the star of your education program rather than a side activity.
- Seeing someone in a similar role use a tool is easier to grasp than talking about the concept.
