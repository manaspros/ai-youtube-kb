> Setup and demo of Archon, a beta self-hosted tool that gives Claude Code or Cursor project docs, a task backlog, and on-demand RAG over crawled docs via MCP. Includes a sponsor segment and an oversold title.

## Summary
The host presents Archon, an open-source, self-hosted context hub for coding agents. Each project has a Docs tab (templated architecture and PRD documents) and a Tasks tab (a backlog the agent manages and remembers across sessions). Documentation sites are ingested by a crawler, and the agent is connected through an MCP server plus a rules file that tells it when to query the knowledge base. The walkthrough covers installing Archon with Docker Compose and a free Supabase project, adding an OpenAI or Gemini key for embeddings, and building a small SwiftUI app whose Liquid Glass styling was not in the model's training data. The speaker's evidence is one anecdotal build, with no retrieval benchmarks. The video also admits the tool is beta, needs a manual Xcode step, and is not yet beginner-friendly. The title "RAG Just Got Updated" oversells what is mostly a setup and workflow demo. A sponsor segment (Logs.so) appears mid-video.

## Key ideas
- **Static up-front context breaks down when a coding task changes midway, so you need a project knowledge base the agent can query on demand.** — The speaker frames context engineering as filling the window with only what a task needs, but says real work diverges (errors, new features, missing context), so the context has to be updated constantly. Archon's answer is a per-project store the agent pulls from. ([0:00](https://youtu.be/EgXOaH-ZqfU?t=0))
- **Archon organizes each project into a Docs tab and a Tasks tab.** — Docs are created from templates (e.g. architecture docs, feature PRDs) so the agent does not invent its own documentation layout. The Tasks backlog fills from the project scope, and the agent updates tasks and keeps task memory. Two example projects are shown, one with 1 backlog task and 13 in progress. ([1:11](https://youtu.be/EgXOaH-ZqfU?t=71))
- **The knowledge base ingests any documentation site through a crawler, and the speaker's example is the full SwiftUI docs.** — Vendor docs are added as URLs. The crawler follows links, navigates menus, and extracts each page. The speaker imported 505 pages (over 126,000 words) of SwiftUI docs because Liquid Glass was too new for the model to know. ([1:11](https://youtu.be/EgXOaH-ZqfU?t=71))
- **The agent decides when to query the knowledge base because of a rules file, not because the user asks it to.** — Archon supplies a rules file (a Claude Code version and a universal one) that tells the agent how to use the Archon MCP connector. The speaker says the agent runs a RAG query before writing PRDs or tasks, whenever it is uncertain, and throughout the build. ([9:22](https://youtu.be/EgXOaH-ZqfU?t=562))
- **RAG needs an embedding model, which is a separate API key from the coding agent's.** — During onboarding the user picks OpenAI or Google Gemini. The speaker uses OpenAI and says Archon's docs call Gemini's free rate-limited models sufficient for normal use. The RAG settings let you change the model and options. The speaker does not test or compare these choices. ([8:01](https://youtu.be/EgXOaH-ZqfU?t=481))
- **The one worked example of an uncertain query is a single anecdote: the RAG search found little, so the agent fell back to code examples.** — For glassmorphism in the polish cycle, the agent's knowledge-base query returned little. It then pulled code examples and found a working implementation. This is the only evidence for the claim that the agent reliably fills gaps. ([10:38](https://youtu.be/EgXOaH-ZqfU?t=638))
- **Work is split into cycles, and the MCP server's manage-tasks tool executes the backlog.** — The user asks for two cycles of tasks. The agent generates the backlog, runs the tasks through the manage-tasks tool, and adds bugs and extra requests as new tasks. Finished tasks wait in a review state. ([9:22](https://youtu.be/EgXOaH-ZqfU?t=562))
- **The speaker's own caveats: the tool is beta, a widget needed a manual Xcode step, and the flow is not beginner-friendly.** — The speaker compares Archon to the BMAD method, which he says has a clearer Agile flow. He says users will need to experiment to find a workable process, and says a final release is scheduled. ([11:52](https://youtu.be/EgXOaH-ZqfU?t=712))

## Techniques
- **Local Archon stack setup** — 1) Clone the Archon GitHub repo into your projects directory. 2) Run the command from the repo README that creates .env from .env.example (the speaker calls it a cp of .env.example). 3) Create a free Supabase project. 4) Open the Archon repo in Cursor, open the migration folder, copy the whole setup.sql, paste it into the Supabase SQL editor and run it; success with no rows returned means the tables exist. 5) In Supabase, copy the Project URL from Settings > Data API and reveal the service_role key under Settings > API Keys. Put both in .env. 6) Start Docker, then run `docker compose up` (first build is slow). Four containers start: Archon Agents, Archon Server, Archon MCP, and the frontend. 7) Open localhost:3737 and finish onboarding with an OpenAI or Google Gemini key for embeddings. *When:* First-time install of Archon as a local, self-hosted knowledge and task service for coding agents. Exact command names other than docker compose up and cp are not shown on screen; check the repo README.
- **Project docs and backlog from a feature description** — Create a project in the Archon UI. In Claude Code, ask it to find the project via the Archon MCP and describe the app: stack, constraints (e.g. local storage only, SwiftUI), and the features you want, as a PRD-style discussion. Archon fills the Docs tab from its templates. Then ask the agent to split the work into a fixed number of cycles; the backlog fills, and the agent executes it through the manage-tasks tool. *When:* Greenfield builds where you want the agent to keep its own task state across long sessions instead of relying on one large prompt.
- **Rules-file-driven on-demand RAG** — Copy Archon's rules file from its settings (Claude Code version or universal version) into the agent's instructions. The rules tell the agent to query the knowledge base before creating PRDs or tasks, to query whenever it is uncertain, and to fall back to code examples when docs are thin. *When:* When a library or platform is newer than the model's training data (speaker's example: Liquid Glass in SwiftUI). Untested beyond this one example.
- **Crawl vendor docs into a knowledge base** — In the knowledge base section, add the docs root URL. Set crawl depth to 2 (the speaker's stated optimum). Let the crawler follow links and index pages. *When:* You need current vendor documentation that the model does not know. Depth 2 is the speaker's judgment; no comparison is shown.

## Hot takes
- The title 'RAG Just Got Updated' oversells the video. It is mainly a setup and workflow walkthrough, and it gives no retrieval quality data or RAG change.
- Sponsored segment (Logs.so) at 3:40, which caps quality at 2.
- The claims that Archon 'completely solves' context loss and that the agent 'never relies on web search' rest on one SwiftUI glassmorphism example.
- The speaker says the tool is beta, not beginner-friendly, needs a manual Xcode step for widgets, and needs experimentation to find a workable flow.
- Recommends free-tier Gemini as an embedding option based on the docs, without testing it.
