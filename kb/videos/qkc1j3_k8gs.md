> Walkthrough of DeepSec, a regex-prefilter plus batched Claude Code/Codex agent harness for repo security scans. Strong on code-local bugs, weak on runtime and logic flaws.

## Summary
The video introduces DeepSec, a security scanning harness released by Vercel (captioned as "Versal"), aimed at AI-generated code in large repositories. Its pipeline runs a cheap regex scan to pick security-sensitive files, then sends batches of about five files to Claude Code or Codex agents with read-only tools, then optionally revalidates findings, attributes them to owners via git metadata, and exports per-issue Markdown or JSON. The presenters ran it on a deliberately vulnerable web app with 10 planted issues. A first run reported only 3 findings because their info.md context file listed the known vulnerabilities, which DeepSec was told to skip. On a second app, DeepSec reported 9 issues, while an unscoped Claude review reported 39 and a scoped one reported 13. The gap was in runtime, concurrency, logic and architecture issues, which a regex-filtered, code-local approach does not target. The workflow is expensive because it runs top models (Opus 4.7 at max effort, GPT 5.5 at x-high) in parallel. The closing section pitches a DeepSec skill that automates the whole flow, available through the channel's paid tier.

## Key ideas
- **Scanning is split into a cheap regex pass and an expensive agent pass. Regex patterns for security-sensitive code shrink thousands of files to a candidate pool before any model runs.** — Only the filtered pool goes to the agents, which is the main token-saving design choice. Regex only surfaces code-local signals, which later limits recall. ([1:27](https://youtu.be/qkc1j3_k8gs?t=87))
- **Agents review fixed-size batches, not the whole repo. Each batch gets a fresh prompt built from the detected framework and project info, then merged, deduplicated and normalized, with a final coverage check.** — Batches are about five files each and run in parallel. Agent tools are read-only. An optional revalidation pass cross-checks findings to cut false positives. ([2:36](https://youtu.be/qkc1j3_k8gs?t=156))
- **Cost is high by design. The default models are the strongest available (Opus 4.7 at max effort, GPT 5.5 at x-high), and running them in parallel makes token use grow quickly.** — The presenters say it is not built for cost-effectiveness. Each batch reports token use and estimated cost, which is informative even on a subscription. ([0:00](https://youtu.be/qkc1j3_k8gs?t=0))
- **A project context file (info.md), generated by an agent from inside the .deepsec folder, carries the codebase overview, auth flow, threat models, project-specific patterns and known false positives.** — The agent reads the parent project to write it. The file's content steers the scan, so it is the main lever for accuracy. ([3:40](https://youtu.be/qkc1j3_k8gs?t=220))
- **Listing known vulnerabilities in info.md makes DeepSec skip them. On the planted-vulnerability app, the first run produced only 3 findings out of 10.** — DeepSec was told the issues were already known, so it looked for other patterns. For a full audit, the context file should describe the app and leave out known bugs. ([6:36](https://youtu.be/qkc1j3_k8gs?t=396))
- **Processing is resumable. After an error it continues from the failing batch instead of restarting, and the subscription is the default auth when no API key is set.** — This matters for large repos. Per-batch token and cost estimates are printed even when the subscription bears the real cost. ([5:08](https://youtu.be/qkc1j3_k8gs?t=308))
- **Head-to-head on a second app: DeepSec found 9 issues. An unscoped Claude review found 39, and a review scoped to DeepSec's scope found 13, with a few DeepSec missed.** — The missed items were runtime-dependent, such as concurrency, logic and architecture problems. DeepSec works from regex-filtered, code-local context, so it does not look for them. ([7:54](https://youtu.be/qkc1j3_k8gs?t=474))
- **Each finding is written as its own file, in folders ordered by priority. It includes source file and lines, severity, confidence, the introducing commit and its author, the recommended fix, revalidation results and reproduction steps.** — Output goes to Markdown and JSON, so it can be turned into tickets for humans or into tasks for coding agents. ([5:08](https://youtu.be/qkc1j3_k8gs?t=308))
- **The whole pipeline is packaged as a Claude skill that reads a natural-language request, chooses the model and runs every step. It bundles evals, references and scripts.** — This is presented as the easier way to run the scan. The skill is distributed through the channel's paid tier, so it is a sales pitch for that tier. ([9:15](https://youtu.be/qkc1j3_k8gs?t=555))

## Techniques
- **Regex prefilter before agent review** — Run a regex-only scan over all files for security-sensitive patterns (auth, endpoints, input handling). Keep only matching files as the candidate pool, then send just those to agents. Their scan ran in seconds on a large repo. *When:* Large codebases with thousands of files, where a full agent review is slow and token-heavy. Expect code-local findings only.
- **Batched parallel agent investigation with merge and coverage check** — Split candidate files into batches of about 5. For each batch, build a fresh prompt from the detected framework and project context. Run Claude Agent SDK or Codex Agent SDK with read-only tools. Merge outputs into one deduplicated, normalized file. Run a follow-up pass to check coverage. Revalidation is optional. *When:* Repeatable, structured reviews of large repos where you need consistent output rather than one free-form report.
- **Project context file for the scanner (info.md)** — Create .deepsec, then paste the generated prompt into a coding agent from inside .deepsec. The agent reads the parent project and writes info.md with: codebase overview, auth flow, threat models, project-specific patterns, and known false positives. Do not list known real vulnerabilities if you want them found. *When:* Before any scan, to reduce false positives. Leave out known bugs when you want a full audit; include them only to focus the scan on new issues.
- **DeepSec command sequence** — 1) deepsec init (installs dependencies and creates the .deepsec folder), then install dependencies inside .deepsec. 2) Run the generated prompt in a coding agent from .deepsec to create info.md. 3) deepsec scan (regex matcher; lists candidate files and endpoints). 4) deepsec process (agent batches; set an API key in .env.local, or it falls back to the Claude Code subscription). 5) deepsec report (JSON and Markdown, grouped by severity). 6) Optional revalidation step, which marks false positives. 7) deepsec export (writes the findings folder). The exact revalidation command name is not shown in the video. *When:* Running a DeepSec audit on an existing codebase. Use process again after a failure, since it resumes from the failed batch.
- **Resumable batch processing** — If a batch fails during processing, restart from that point instead of rerunning the whole scan. Each batch also prints tokens used and estimated cost. *When:* Long agent runs over large repos where a single transient error should not cost the full run.
- **Per-finding output with ownership and repro** — For each finding, record the exact file and lines, severity, model confidence, the introducing commit and its author from git metadata, the recommended fix, revalidation status, and reproduction steps. Store one file per finding in a priority-ordered folder. *When:* Turning scanner output into tickets for humans or tasks for coding agents with an owner attached.
- **Scoping an unscoped agent review** — Ask the agent to produce a diff against the tool's findings, then restrict the report to the defined scope. The video cut a 39-issue review down to 13 this way. *When:* Comparing a general agent review with a structured tool, so the comparison is on the same scope.

## Hot takes
- The title ('One command fixed the biggest problem') overstates the result. The flow is several steps plus a context file, and the skill wrapper is a separate add-on.
- The presenters' own comparison shows the tool's limit. The unscoped Claude review found 39 issues to DeepSec's 9, and DeepSec missed runtime, concurrency, logic and architecture issues. Its value is systematic coverage of a defined scope, not overall recall.
- Telling the scanner which bugs are already known suppresses them. The 3-of-10 result on the planted-bug app shows that context-file content directly changes the scan's output.
- Cost is presented as a side note. The subscription default hides real spend, and the video never gives a total token or dollar figure for a run.
- The closing section sells the reusable skill through the channel's paid tier. Treat that as promotion, not evidence.
