> Walkthrough of leaked system prompts from Cursor, Windsurf, Replit, Manus and others, with the host's takeaways on tool design, background execution, memory, sandboxing and a repo-to-text trick. Useful as prompt-design evidence, but the verdicts are overreaching.

## Summary
The host reads leaked system prompts and tool lists from several AI coding and agent products (Cursor, Windsurf, Replit, Manus, Lovable, Devin, plus open-source Bolt and Roo Code) and summarizes what they reveal. For Windsurf's Cascade he argues it has a richer built-in toolset, persistent cross-session memory with semantic retrieval, and background command execution that Cursor's step-by-step loop lacks. For Manus he describes a full Ubuntu sandbox with port exposure and deployment, a six-layer agent loop, and a browser handled through native click, type, scroll and JavaScript functions rather than Selenium. He notes guardrails that keep the agent inside its sandbox and fallback behavior of asking the user or re-prompting itself when stuck. For Replit he describes a bespoke environment that forbids Docker, 17 specialized tools including a VNC-based GUI feedback tool, auto-prompts for missing API keys, and a mandatory post-edit error check. He also shows a trick for turning a GitHub subfolder into LLM-readable text. Most of the "winner" framing is his inference from prompt text, not measured product behavior.

## Techniques
- **Repo subfolder to LLM-readable text** — Take a GitHub URL for a single folder and replace 'hub' in the domain with the converter's domain (the host does not name the service). Copy the returned text, which includes the directory tree and file contents, and paste it into any LLM to ask questions about that folder. Scope it to a folder, because a whole large repo costs many tokens. *When:* Studying a competitor's or open-source agent's prompts or tool code without reading every file by hand. Expect roughly 7k tokens for a prompt-sized folder.
- **Post-edit verification loop** — After each code change, require the agent to check for errors (build, lint or run) before it moves on. The host describes this as Replit's built-in feedback loop and attributes its front-end quality to it. This is his interpretation, not a measured result. *When:* Agent-written code where broken iterations compound. Apply the check after every edit, not only at the end.
- **Background command execution with process status checks** — Let the agent start long-running commands in the background and keep editing files while they run. The agent then checks process status on its own rather than blocking and waiting after each edit. This is the Cascade pattern as the host describes it. *When:* Long test suites, dev servers or builds where the agent would otherwise sit idle between edits.
- **Persistent memory with semantic auto-retrieval** — Give the agent create, read, update and delete operations over stored memories covering preferences, snippets, API-key references and project milestones. On session start, retrieve memories that semantically match the current work. This is the Cascade memory design as described. *When:* Projects resumed after long gaps, where re-explaining context each session is costly.
- **Ask-for-secrets and stuck-fallback behavior** — When a required API key or input is missing, ask the user before continuing. When the agent is stuck, either ask for input or re-prompt itself, instead of looping. Both behaviors are written into the Replit and Manus prompts as the host describes them. *When:* Autonomous runs that would otherwise fail deep into a task on a missing credential or a repeated dead end.
- **Sandbox-scoped guardrails in the system prompt** — State explicitly that the agent works only inside its sandbox, does not use external accounts, and does not reach outside its environment. Manus's prompt is the example the host gives. *When:* Agents with shell or deploy access, to keep side effects inside a bounded environment.

## Hot takes
- Calling Windsurf the 'clear winner' over Cursor from reading system prompts overreaches. Prompt text shows intended features, not performance or reliability.
- The '$10B' in the title has no basis in the video.
- Calling the leaked material 'authentic' is asserted, not shown. Leaked prompts may be partial, outdated or from a different build.
- Attributing Replit's front-end quality to the verification loop is speculation, offered without evidence.
- Quality is capped at 2 because the title is hype-driven and the substance is mostly the host's read of prompts, with little verification. The prompt-level details are still worth checking against the raw text.
