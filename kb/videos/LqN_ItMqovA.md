> A team's walkthrough of MCP context bloat and a runtime MCP-to-CLI converter (MCP2CLI), plus CLAUDE.md and skills rules that keep large tool outputs out of the context window.

## Summary
The video argues that MCP tool definitions and tool outputs both bloat the agent's context window, and that existing fixes (Docker Code Mode, TypeScript-per-tool conversion, build-time CLI converters such as CLI Hub) each leave gaps. The host presents MCP2CLI, which converts MCP servers (and OpenAPI/REST APIs) into bash-callable CLI tools at call time, caches the converted tools for one hour by default, and runs on the MCP Python SDK. They wired a Supabase, GitHub, Puppeteer and Context7 MCP into Claude Code (78 tools total) to build a Next.js chat app, and report that the agent ignored Context7 until a CLAUDE.md rule forced it to consult docs first. Skills replaced CLAUDE.md for per-MCP guidance because skill descriptions load into context. For browser testing, the Puppeteer MCP lost session state between calls and was slow (about 7 minutes wasted), so they preferred Claude's browser extension. The closing technique is the most useful one: a CLAUDE.md rule that redirects large MCP output to a file and greps it, which they say was impossible while MCPs were handled natively by the agent. The video shows the workflow in one run and gives no token or cost measurements.

## Key ideas
- **MCP context bloat has two sources: tool definitions loaded up front, and tool outputs that stay in the window.** — Docker Code Mode, Anthropic's paper and TypeScript-per-tool conversion each address part of this. Claude Code's CLI flag loads tools on demand but does not stop large outputs from staying in context. ([0:00](https://youtu.be/LqN_ItMqovA?t=0))
- **MCP2CLI converts MCP servers into bash CLI tools at runtime, not at build time.** — The conversion happens when a tool is called, so upstream MCP changes show up automatically. Build-time converters such as CLI Hub need manual refresh. It also covers OpenAPI and REST APIs through the same CLI interface. ([1:27](https://youtu.be/LqN_ItMqovA?t=87))
- **Runtime conversion is kept fast by a one-hour cache of converted tools.** — Frequently used tools stay cached for one hour by default. The host says the design keeps runtime flexibility without making repeated calls slow. ([2:29](https://youtu.be/LqN_ItMqovA?t=149))
- **Tool output only enters the context window when the agent asks for it.** — The tool runs MCP calls as bash commands and returns results to the agent on request, which reduces context use compared with native MCP handling. ([2:29](https://youtu.be/LqN_ItMqovA?t=149))
- **Connecting MCPs does not make the agent use them; instructions have to force it.** — Claude ignored a deprecated Next.js middleware pattern. The team added a CLAUDE.md rule to consult Context7 before writing code, then converted per-MCP guidance into skills because skill descriptions are loaded into context. ([7:31](https://youtu.be/LqN_ItMqovA?t=451))
- **Puppeteer MCP is a poor fit for multi-step browser testing; a persistent browser is better.** — Each Puppeteer call started a new browser, so sessions were lost. The team says MCPs run as persistent processes, but the Puppeteer MCP still lost session state. They preferred Claude's own browser extension for end-to-end tests that need session persistence. ([8:58](https://youtu.be/LqN_ItMqovA?t=538))
- **Large MCP outputs can be redirected to a file and searched with grep, which the video calls the biggest unlock.** — Because MCP calls are now bash commands, a CLAUDE.md rule can send big output to a file path and have the agent grep the result. The agent then completed a feature from progress.json this way without dumping the output into context. ([10:26](https://youtu.be/LqN_ItMqovA?t=626))

## Techniques
- **Run MCP2CLI without installing it** — The host chose to run the tool without a global install (via pip or a no-install run) to keep the environment clean. A bundled skill lays out the core workflow and bash command examples for auth and caching. The exact command name is not shown in the video. *When:* When you want MCP servers available to the agent without polluting the system Python environment.
- **Give the agent the MCP access tokens through environment or file references** — Get the access token from the service first, then give it to Claude to add. Credentials are passed through environment variables, a file path, or a secret manager that injects them at runtime, not as command-line arguments. The host showed the agent referring to .env.local at project level. *When:* Any time an MCP is converted into a shell command, because CLI arguments can show up in process listings.
- **Verify MCP connections by asking the agent to count the tools** — After connecting the MCPs, ask Claude to confirm which MCPs are connected and how many tools they expose (78 across four servers in the video). *When:* After setup, to confirm every server actually loaded before building on them.
- **CLAUDE.md rule to consult docs before coding** — Add a rule that says to use the Context7 MCP before writing any code. The host reports the agent still needed a correction after the first attempt. *When:* When the agent keeps using outdated APIs or deprecated patterns from training data.
- **Move per-MCP guidance from CLAUDE.md into one skill per MCP** — Ask Claude to create a skill for each connected MCP describing its tools, how to use them and when to use them. The host argues skill descriptions are always in context, so the agent knows what is available without a full instruction dump. *When:* When CLAUDE.md is getting long with tool-usage instructions, or the agent does not read them reliably.
- **Ask for TOON output for verbose documentation MCPs** — A CLAUDE.md rule says to request TOON format whenever Context7 is called. The host describes TOON as indentation plus CSV-style lists that are smaller than JSON or YAML. The video does not show the exact flag or config key. *When:* When documentation or API MCP results are large and you want a smaller token footprint.
- **Redirect large MCP output to a file and grep it** — Add a CLAUDE.md instruction: when any MCP tool output is large, write it to a specified file path instead of the context window, then use grep to extract what is needed. The host applied this to Context7 and a progress.json tracker. The Claude.md file with the full rules is said to be in the AI Labs Pro community, which is not shown. *When:* For MCP results that can be large, such as documentation or query results, where only a few lines are needed for the task.
- **Use Claude's browser extension for stateful browser testing** — The host had Claude test the chat flow in a browser it controlled, having it click and scroll the UI. Puppeteer MCP spun up a new browser per call and lost sessions, so the host preferred the extension for end-to-end tests. *When:* For end-to-end UI tests that need login state or multi-step sessions across several tool calls.

## Hot takes
- The biggest claim, that MCP-as-bash redirection solves output bloat, is shown in one feature run with no before/after token counts.
- The video says the MCP2CLI token-efficiency tests had numbers behind them, but none appear on screen.
- The Orchids sponsor segment (around 3:57) is separate from the technical content. The technical content has enough substance that the sponsorship does not cap quality.
- The host's own experience is that connecting tools is not enough, and that CLAUDE.md rules and skills were needed to make the agent use them. This is more useful than the tool pitch itself.
- The title, 'I Didn't Know This Was Possible Until Now', overstates the content. Redirecting output to files was already covered in the channel's earlier Cursor video, which the host cites.
