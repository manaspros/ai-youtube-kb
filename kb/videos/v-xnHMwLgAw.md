> Kai Explains puts Meta's unannounced Muse Glimmer 30B through 48 hours of agent work on dual RTX 3090s: fast at 50-60 tok/s, but it fails instruction following, context depth and synthesis.

## Summary
The creator downloaded Meta's Muse Glimmer 30B within about 20 minutes of its unannounced August 10 release and ran it locally on dual RTX 3090s (48 GB VRAM). The setup was an Unsloth Q8_0 GGUF, a BF16 vision projector file, a DFlash drafter for speculative decoding, and llama.cpp built from source. Generation speed (50-60 tok/s, about 1,500 tok/s prefill) is strong and is the one area where the model clearly wins. The real test used his custom agent framework, which stays constant while the model varies, and he compared against DeepSeek V4 Flash and Qwen 3.6 27B on the same tasks. Muse Glimmer showed six failures: it ignored a detach-long-commands-in-tmux rule, treated "move" as "copy", produced code that did not run, hit its 131k context ceiling early, dropped all citations, and gave shallow, repeat-only analysis. His conclusion is that it behaves closer to Qwen 3.5 35B MoE than the Qwen 3.6 27B it is compared against, and that benchmark pages are marketing, so you should evaluate on your own workload. The evidence is one operator, one custom framework, and mostly single runs, so treat the failure list as a useful probe set rather than a general verdict.

## Techniques
- **Constant-harness model A/B test** — Keep the agent framework, system prompts and task set fixed. Run the same tasks on each candidate model and treat failures as model failures only when other models pass the same tasks. *When:* Comparing a new model against incumbents for agent use, before trusting any benchmark.
- **Three-question model vetting probe** — Test (1) unusual but explicit system-prompt rules, such as 'start long commands in detached tmux' or 'always keep source links', (2) a task whose context accumulates over many tool calls, and (3) a multi-source research task that checks whether the model synthesizes or only restates results. *When:* Screening any new model for agentic workloads. Turn these into regression probes in an eval suite.
- **Compaction threshold relative to window size** — The creator's framework auto-compacts at 50% of the available context window. This leaves runway for further tool results. He says a 131k model compacting at about 65k runs out of room on research workflows. *When:* Choosing context-management thresholds for agents on models with different window sizes.
- **Local llama.cpp serving recipe (as described, not as flags)** — Download the Unsloth Q8_0 GGUF of the model plus the BF16 vision projector file. Build llama.cpp from source for the local GPUs. Run the server with the DFlash drafter for speculative decoding. The transcript does not show exact command-line flags or config keys. *When:* Reproducing his dual-3090 setup. Check the flags and drafter wiring in the llama.cpp docs and the model card, since the video omits them.
- **Long-command detachment rule** — Add a system-prompt rule that any task over about 30 seconds starts in a new detached tmux session, so the agent session is not blocked by long transfers. Then test whether the model follows it. *When:* Running agents on servers where a long-running command can block the session.

## Hot takes
- Benchmark pages are advertisements: controlled tests on tasks the lab optimized for, so the user's own workload is the real measure.
- Muse Glimmer 30B performs closer to Qwen 3.5 35B MoE than the Qwen 3.6 27B it is marketed against, and its only real edge is speed.
- A model that accurately repeats search results without synthesis is a 'parrot', not a useful research agent.
