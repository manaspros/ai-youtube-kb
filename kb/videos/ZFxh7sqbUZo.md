> David Brumley (CMU, Bugcrowd) on designing RL environments for vulnerability discovery and exploitation, using deterministic oracles, an open-world "audit" task scored by precision and recall, and a 16-rung capability ladder run against V8.

## Summary
Brumley argues that cybersecurity is a good fit for RL because tasks form a ladder with deterministic pass/fail oracles. Benchmarks that ask a model to find one bug let it reward-hack the easiest bug, and naming the bug (for example with a backtrace) removes the need to reason. His fix is an "audit" task: the model is not told how many bugs exist, submits proof-of-vulnerability inputs for each one it finds, and a deterministic grader deduplicates them by stack backtrace (the same method crash-reporting systems use). Scoring is precision and recall over a set that includes bugs the authors did not know about, which allows open-world evaluation on real open-source code. He rejects LLM-as-judge for this domain because models always claim success. For harder targets he measures a 16-rung ladder on V8 (Chrome's JS engine), from triggering a bug up to arbitrary code execution. On 41 hand-verified V8 bugs, models that look equal on crash-only benchmarks separate sharply at the top of the ladder. He reports that the Mythos model reached full code execution on 73% of the bugs, GPT on 68%, and Gemini and Kimi on 0%. He also says the model found exploit routes that experts had not published. He says his group produces up to 10,000 RL environments per month from zero-days it mines from open-source code. ## Key ideas
- **Cyber tasks suit RL because they form a ladder with deterministic oracles** — A vulnerable program runs in a container, and the grader is code, not an LLM judge. Brumley says LLM judges always claim success on hacking tasks. The model must produce a witness input (for example, a crash input), and the oracle checks whether the program misbehaved. ([0:12](https://youtu.be/ZFxh7sqbUZo?t=12))
- **Single-bug task framing causes reward hacking** — Asking 'find the vulnerability' lets the model return the easiest bug. Benchmarks that give a backtrace or name the function remove the need to reason. The model also learns to repeat its first answer. Even DARPA's hand-curated challenges had unknown bugs: about 50% of them, per the speaker, and 18 unintended bugs at AIxCC. ([9:30](https://youtu.be/ZFxh7sqbUZo?t=570))
- **The audit task: don't tell the model how many bugs exist** — The model is asked to find all vulnerabilities and submit a proof input for each. The grader deduplicates crashes by stack backtrace, which is how crash-reporting pipelines triage bugs. This works without an LLM judge and lets the model find bugs the authors did not know about. ([13:10](https://youtu.be/ZFxh7sqbUZo?t=790))
- **Score open-world results with precision and recall** — Recall is the share of known-plus-discovered bugs that the model found. Precision is the share of submissions that are real. Precision stops the model from spamming bogus proofs, and recall rewards finding unknown bugs. Both are normalised and multiplied to give one score, so the model cannot just keep finding the same easy bug. ([14:22](https://youtu.be/ZFxh7sqbUZo?t=862))
- **Hardened targets need a capability ladder, not a pass/fail** — On V8, a hard target where most attempts fail, Brumley defines 16 rungs: trigger the bug, crash an in-sandbox object, get in-sandbox read/write primitives, get out-of-sandbox primitives, then arbitrary code execution. Graded this way, the signal stays informative when the top rungs are hard to reach. ([19:45](https://youtu.be/ZFxh7sqbUZo?t=1185))
- **Crash-only benchmarks overstate hacking ability** — On the 41 V8 bugs, GPT, GPT 5.5, and Mythos each triggered 39 of 41 (95%). Lower-tier models such as Gemini, Kimi, Minimax and GLM triggered about 50%. Yet only the top models reached code execution, so crash-only scoring hides the real gap between models. ([21:02](https://youtu.be/ZFxh7sqbUZo?t=1262))
- **Evidence that the results are not memorised** — Brumley reports that Mythos produced exploit routes that the Chrome security community had not published, such as forging a pointer by reversing JavaScript's Math.random. On one CVE he says even an internal expert did not believe the bug was exploitable on x86, and Mythos succeeded. He says these were not public exploits, but he gives no independent verification. ([22:25](https://youtu.be/ZFxh7sqbUZo?t=1345))
- **Expert-built oracles are the real work** — Brumley's closing point is that the hard part is building oracles that check whether the model was memorising, reward-hacking, or finding new bugs. The environments are Docker images with an MCP interface. Public release is limited: the Mythos transcripts are withheld under NDA. ([25:53](https://youtu.be/ZFxh7sqbUZo?t=1553))

## Techniques
- **Deterministic witness-based grading** — Require the model to submit a concrete input (a PoC) that the oracle replays. The oracle checks program behaviour (crash, control-flow hijack, unauthorised process launch) with no LLM in the loop. *When:* Any agent task where success can be checked by running code, and an LLM judge would be fooled by plausible-sounding claims.
- **Open-world audit task with dedup and precision/recall** — Ask for all issues without stating the count. Dedup submitted witnesses by stack-backtrace signature. Score recall over known plus discovered issues and precision over submissions. Combine them into one normalised score. *When:* Evaluating search or discovery agents on real code where the ground truth is incomplete, and where spam or repeated answers must be penalised.
- **Capability ladder for hard targets** — Break the goal into ordered milestones (trigger, primitive, chained primitive, full escape, arbitrary execution). Report how far each model gets rather than a single success rate. *When:* When top-tier tasks are mostly failed and a pass/fail score gives almost no signal.
- **Withhold the answer key and the most dangerous artifacts** — Publish environments and transcripts, but hold back transcripts where the model produced weaponised, previously unknown exploits. *When:* When a public benchmark would give attackers a usable artifact, or when licensing rules out release.

## Hot takes
- LLM-as-judge is unreliable for cybersecurity because models always claim they succeeded.
- Crash-only benchmarks are not evidence of hacking; they mostly measure whether a model can crash a program.
- Single-bug benchmarks teach reward hacking, and any hand-curated single-bug environment will contain extra bugs.
