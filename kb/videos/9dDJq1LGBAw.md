> Better Stack demos Universal Modder, an open-source Claude Code plugin that builds GTA 5 mods from games you own via recon, hot reload, in-game testing and shared field notes; ~$68 API cost.

## Summary
The video is a showcase of Universal Modder, an open-source Claude Code plugin by Rayhan made of skills, a CLI tool and a knowledge base of notes from earlier mods. The host asked Opus 5.5 in Claude Code to add Black Ops 3 Zombies elements (Vinewood sign arena, rounds, ray gun, Juggernog, mystery box, one custom perk) into GTA 5 Story Mode, with Black Ops 3 set as a read-only guest install. The agent fingerprinted the game, backed up saves, wrote a plan to a modlog, ran three parallel research sub-agents, wrote a converter for Black Ops 3 sound banks, and produced about 4,000 lines of C++. The mod draws new models itself through ReShade using the game camera and depth buffer, and it splits gameplay code so it hot-reloads in about 5 seconds. Playtesting shows a working but rough result: generated lookalike models, some wrong text, and guns that swap to GTA guns on pickup. The video reports about 210M tokens (99% cache reads), roughly $68 at API prices plus a few dollars of FAL art. The host describes the loop as recon, back up, read code, build one slice, verify in game, record, and write a field note that can be proposed to the shared KB by PR.

## Key ideas
- **Agent modding loop: search the KB, recon the game, back up saves, read the real code, build one working slice, check it in the running game, record results, then write a field note.** — The host calls this the mod-any-game skill loop. Recon uses the CLI to fingerprint the engine, anti-cheat and save locations. Each run starts from the closest existing game note (the GTA 5 Minecraft mod note, same GTA version, loader and ReShade trick). ([5:10](https://youtu.be/9dDJq1LGBAw?t=310))
- **Hot reload by splitting the mod so gameplay code reloads inside the running game in about 5 seconds, instead of waiting on GTA's slow boot.** — Claude noticed GTA 5 loads slowly and split the mods so gameplay code could reload in the live process. The agent used this hot reload nearly 50 times and checked each feature with screenshots. ([1:15](https://youtu.be/9dDJq1LGBAw?t=75))
- **New models cannot be loaded through GTA's archives, so the mod draws them itself as a post-process layer through ReShade using the game camera and depth buffer.** — This is the rendering workaround the host credits for making the custom props appear in the scene. ([1:15](https://youtu.be/9dDJq1LGBAw?t=75))
- **Asset gaps are filled with fallbacks: real Black Ops 3 sounds via a converter, lookalike models generated from concept art.** — The agent opened Black Ops 3 sound banks, worked out how they are stored and wrote a converter, so the round, Juggernog and kaboom sounds are real. The model extractor needs Black Ops 3 running, which the host had ruled out, so the machines are FAL-generated lookalikes. The host says he would allow launching the game next time. ([1:15](https://youtu.be/9dDJq1LGBAw?t=75))
- **Read-only guest games: the host game is run with anti-cheat off, and the second game is marked read-only so the agent reads its files but never launches or edits it.** — The host chose GTA 5 Story Mode as the host and Black Ops 3 as the read-only guest, and warned that anti-cheat games are out of scope. ([0:00](https://youtu.be/9dDJq1LGBAw?t=0))
- **The knowledge base works as shared memory: each run ends with a note on gotchas, cause and fix, which can be proposed back as a PR.** — The KB holds 117 game notes and 65 technique notes, mostly written by Claude Code and OpenCode. Contributing is an explicit step the user asks for, not automatic. ([5:10](https://youtu.be/9dDJq1LGBAw?t=310))
- **Cost profile: about 210M tokens, almost all cache reads, which the host says keeps the cost low.** — At API prices the build comes to about $68 plus a few dollars of FAL art. The host was on a Claude Max plan, so usage was barely dented. ([3:47](https://youtu.be/9dDJq1LGBAw?t=227))
- **The one-shot result is rough: the agent's trailer was judged poor and playtesting showed visible defects.** — Generated machines have garbled Juggernog text and do not match the real Black Ops 3 models. Guns are real Black Ops 3 models while spinning but convert to GTA guns on pickup. Police shoot zombies (and the mod stops the player being shot by them). The host sees value in the speed of the result rather than in playability. ([2:41](https://youtu.be/9dDJq1LGBAw?t=161))

## Techniques
- **Back up and log before touching user state** — First, back up the user's save files, then write the plan to a modlog file. Keep the plan on disk so the work can be audited and resumed. *When:* Any agent that edits user data or installs or changes a running app that the user can't easily restore.
- **Fingerprint before coding** — Run a recon CLI pass to identify the engine version, anti-cheat, and the location of save and asset files. In this case it compared the GTA 5 version with Script Hook 5 before writing any code. *When:* Targeting an unfamiliar binary or game, where the loader, version or protection decides what is possible.
- **Parallel narrow research sub-agents** — Start three sub-agents at once, each with one bounded question: game stats from decompiled scripts or a wiki, asset naming or storage format from the sound banks, and finding a finished reference save. Merge their findings before building. *When:* Early research where the questions are independent and the answers feed one implementation.
- **Write a converter for proprietary asset formats** — Inspect how the sound banks are stored, then write a small converter that pulls real assets from the user's installed game. Use real assets where licensing and install state allow, and fall back to generated substitutes otherwise. *When:* Reusing assets from a game the user owns, where the engine has no public loader.
- **Hot-reload the logic, not the host** — Split the mod so gameplay code is a separate module that can be reloaded into the running process (about 5 seconds here), and keep the heavy host and engine load out of the loop. *When:* The host app has a slow boot but the logic under development changes often.
- **Screenshot check after each reload** — After each hot reload, take a screenshot and check the feature in the running app before moving on. *When:* UI or rendering changes where unit tests cannot show the result.
- **Draw new content as a post-process overlay** — When the engine will not load new assets, render them in a post-process layer (ReShade here) using the camera and depth buffer to place them in the scene. *When:* The engine's asset pipeline is closed but a post-process or shader hook is available.
- **Field note plus shared KB PR** — After a build, the agent writes a note with gotchas, the cause and the fix. The user can ask the agent to open a PR that adds the note to the shared knowledge base. *When:* Any agent-driven build where other agents would hit the same problems on the same target.
