> Pinterest's Drasko Profirovic on Medic, an agentic Spark failure-diagnosis tool, and how its prototype became a multi-agent system with record/playback testing, log and metrics handling, and sub-agents.

## Summary
Pinterest's Medic for Apache Spark is an agent that answers "why did this Spark job fail?" with a research-style report, root cause evidence, and suggested fixes grounded in the job. The team started with MCP tools and one ReAct agent, but one large prompt became impossible to tune and produced shallow or verbose, inconsistent answers. Testing was manual against production runs, which had retention limits, so they built a record/playback harness: real tool responses are captured as checked-in fixtures, then graded by offline evals (for example, a cap of three suggested fixes). Raw logs were too noisy, so they learned which exceptions appear in successful jobs and filter those out as red herrings, exposing only top-K truncated exceptions through MCP. Time-series metrics are rendered as a collage of annotated graphs analysed by a quarantined sub-agent, which keeps token use fixed regardless of job length and returns only a summary to the parent. The harness moved to a LangGraph DeepAgent-based supervisor with specialised triage, parallel hypothesis researchers, and a healer agent that uses runbooks in a vector DB. The speaker says LangGraph deterministic workflows were brittle compared with the reasoning-and-acting approach, and that adding the SQL optimisation feature was just a new prompt.

## Key ideas
- **Start with the problem: support load for distributed-system jobs is heavy, and an agent can scale that knowledge on demand.** — The goal was one question, 'why did this job fail?', returning an evidence-backed deep research report with fixes tied to the job's context, available in Slack and the Airflow UI. ([0:01](https://youtu.be/0RNNfxpdbQk?t=1))
- **A single giant prompt does not scale. Adding detail in one area degrades another, and output quality swings between shallow and verbose.** — The speaker names the prompt-tuning trap and context-window blowups from large log tool outputs as the reasons to split the agent into roles. ([2:33](https://youtu.be/0RNNfxpdbQk?t=153))
- **Replace manual production-only testing with a record/playback harness and offline evals.** — In record mode, real downstream calls are captured as fixtures and checked in as code. In playback mode, the agent runs on fixtures, and the suite grades the report, so changes can be checked for regressions. ([3:38](https://youtu.be/0RNNfxpdbQk?t=218))
- **Learn which exceptions are benign from successful jobs instead of writing regex filters.** — The pipeline fingerprints and clusters exceptions, treats those common in successful jobs as red herrings, and ranks the rest by content relevance and timing relative to job termination. The agent calls only two MCP tools: top-K truncated exceptions, or full detail for one. ([5:43](https://youtu.be/0RNNfxpdbQk?t=343))
- **Analyse metrics in a quarantined sub-agent by rendering them as images, not raw time series.** — Time series are plotted as annotated graphs (min and max called out), collaged into one image, and attached to the model. The speaker says the image gives a predictable token cost regardless of job duration. ([7:05](https://youtu.be/0RNNfxpdbQk?t=425))
- **Sub-agents return summaries, not raw output, which keeps the parent's context window healthy.** — Each agent gets its own prompt and a subset of MCP tools. The framework's built-in to-do list and virtual file system help keep the agent on track, which the speaker compares with how Claude Code and Codex work. ([8:06](https://youtu.be/0RNNfxpdbQk?t=486))
- **A supervisor fans out parallel hypothesis research and picks the highest-confidence root cause.** — Triage checks the job's lifecycle state and generates failure hypotheses. Researchers validate each in parallel and return a score and root cause. A healer agent then proposes remediations from runbooks in a vector DB, and the supervisor assembles the report. ([9:07](https://youtu.be/0RNNfxpdbQk?t=547))
- **Extending scope is cheap in a multi-agent design, and LangGraph deterministic workflows were less reliable than the agent loop.** — Adding Spark SQL optimisation meant adding a new prompt. The speaker tried LangGraph workflows for determinism, found them brittle, and is now testing user feedback from past sessions for self-improvement and applying the pattern to Flink and Trino. ([10:09](https://youtu.be/0RNNfxpdbQk?t=609))

## Techniques
- **Record/playback end-to-end agent harness** — Record mode runs the agent against real downstream systems and saves each tool response as a fixture file checked into the repo. Playback mode runs the agent against those fixtures, then an offline eval suite grades the output (e.g. max three fixes). *When:* When production state is not retained and manual end-to-end checks cannot show whether earlier wins still hold after a prompt change.
- **Learned red-herring filtering for logs** — Learn which exceptions occur in successful runs, fingerprint and cluster exceptions, filter the common benign ones, and rank the rest by relevance and timing relative to job termination. Expose through MCP as top-K truncated results plus a drill-down call. *When:* When regex filters stop scaling and noisy exceptions push an agent toward the wrong root cause.
- **Metrics as a collaged graph image in a quarantined sub-agent** — Turn time series into annotated plots (min/max labelled, Grafana-like), collage them into one image, send it to a sub-agent that reasons about patterns, and return only its summary to the parent. *When:* When raw metric series are too long or token-costly, and the input size must stay fixed no matter how long the run is.
- **Supervisor with parallel hypothesis researchers** — Triage the state, produce a list of hypotheses, run one researcher per hypothesis in parallel, each returning a score and root cause, then have the supervisor pick the top-confidence result and call a remediation agent. *When:* When a diagnosis has several plausible causes that can be checked independently.
- **Per-agent prompt plus MCP tool subset** — Give each specialised agent its own prompt and only the MCP tools it needs, built on a deep-agent library with planning and virtual file system tools. *When:* When a single prompt has become too large to tune, and each role needs focused tests.
- **OpenTelemetry traces as step waterfalls** — Emit OTel spans for each agent step, send them to Langfuse, and read the waterfall to see where lower-quality answers came from. *When:* When you need to find which step of an agent run caused a bad output.

## Hot takes
- Deterministic LangGraph workflows were brittle for this task, and the reasoning-and-acting agent approach worked better.
- Rendering metrics as images gives a predictable token budget, which is better than feeding raw time series to the model.
