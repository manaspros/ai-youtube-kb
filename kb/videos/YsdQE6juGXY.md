## Summary
The AI LABS host says their team ran out of Claude Code limits much faster over recent weeks, and claims the 1M-token context window made this worse. He explains the plan model: a rolling 5-hour message window that starts at the first message, keeps running while idle, and is shared across devices and interfaces. He then gives a list of token-saving practices: clearing or compacting context, using a side-question command, rewinding instead of re-prompting, writing a short CLAUDE.md with path-scoped and linked docs, using session-only system prompt flags, routing models and effort levels, disabling unused MCP servers, filtering test output with a hook, and changing several settings. A sponsor segment (Twin) sits in the middle. Some claims are unverified, including a leaked-source account of retry and skill-listing token waste. Most of the advice is generic and reasonable, with few measurements behind it.

## Key ideas
- **The usage limit is a rolling 5-hour window that starts with your first message, not with active use.** — Idle time inside the window still counts. The window is tied to the account, not the device, so usage from several devices or interfaces (desktop, web) draws from the same limit. Speaker says Pro gets about 45 messages per window, Max about 225, and the 20x Max tier about 900. ([0:00](https://youtu.be/YsdQE6juGXY?t=0))
- **Model choice and task type change how fast the window burns.** — Opus is said to use roughly 3x the tokens of Sonnet for the same request. Compute-heavy tasks and multi-tool tasks burn the window faster than the nominal message count implies. The speaker also claims Anthropic reduces session limits faster during peak hours; no source is given. ([1:16](https://youtu.be/YsdQE6juGXY?t=76))
- **The leaked-source claims (unverified) say retries and skill listings waste tokens.** — The speaker says that after a rate-limit error the client keeps the partial error-filled response in context and retries on top of it. He also says skill listings are injected eagerly even though the skill tool already loads them on demand. He presents this as what people found in the leaked Claude Code source; he shows no code. ([2:44](https://youtu.be/YsdQE6juGXY?t=164))
- **Each message resends the full conversation, so context growth is cost growth.** — Every request includes system prompts, tool definitions and all prior turns. Clearing or compacting between tasks, and asking side questions in a separate context, keep the per-message cost from compounding. ([4:03](https://youtu.be/YsdQE6juGXY?t=243))
- **Rewind beats corrective re-prompting when Claude goes off track.** — Restoring conversation and code to a point before the misaligned message removes the bad turn from context. A correction stacked on top leaves the wrong attempt in the context. Double-tapping Escape is given as an alternative trigger. ([5:16](https://youtu.be/YsdQE6juGXY?t=316))
- **Spend tokens on upfront planning to avoid expensive course corrections.** — The speaker's argument is that planning up front costs fewer tokens than correcting an implementation that drifted from the spec later. ([5:16](https://youtu.be/YsdQE6juGXY?t=316))
- **Keep CLAUDE.md short and limited to what Claude does not already know.** — The init-generated file tends to list things Claude can infer, such as standard dev-server commands and directory structure. The speaker recommends under 300 lines, with what Claude should not do, team practices, and non-default conventions. Long CLAUDE.md content loads every session and costs tokens every turn. ([6:43](https://youtu.be/YsdQE6juGXY?t=403))
- **Load context progressively through linked docs, path-scoped rules, and skills.** — Move schema and area-specific rules into separate files linked from CLAUDE.md, and use path-specific rules so only relevant guidance is loaded. Put repetitive workflows into skills with bundled scripts, so deterministic work runs in code instead of tokens. ([8:11](https://youtu.be/YsdQE6juGXY?t=491))
- **Pass one-off instructions at session start instead of persisting them in CLAUDE.md.** — The append-system-prompt flag adds instructions for a single session only. The speaker argues this is cheaper than a permanent CLAUDE.md line, which stays in context every turn. ([8:11](https://youtu.be/YsdQE6juGXY?t=491))
- **Route effort and model to the task, and disable MCP servers you are not using.** — Set effort to low for simple work; the default is auto. ## Techniques
- **Clear or compact between tasks** — Run /clear when a task is finished and the old context is not needed. Run /compact when some context should survive; it summarizes the session and frees space. Both shrink the history that is resent on every message. *When:* At task boundaries, such as moving from implementation to testing, or whenever the context has grown large and turns are getting expensive.
- **Side questions in a separate context via the by-the-way command** — Ask quick side questions with the by-the-way command (named as such in the video; it is presumably the /btw slash command). It answers in a separate session context that is not carried into the next message. *When:* When you need an answer that is unrelated to the main task and should not bloat the main context.
- **Rewind to before a misaligned turn instead of re-prompting** — Use the rewind command to restore conversation and code to a point before the message where Claude went wrong, then reword the prompt there. Double-tapping Escape does the same. *When:* When Claude ignores or misreads an instruction, and a corrective follow-up would leave the bad attempt in the context.
- **Lean CLAUDE.md with linked, progressively loaded docs** — Keep CLAUDE.md under about 300 lines. Include only non-default instructions: what Claude must not do, team dev practices, and project conventions it cannot infer. Remove the dev-server commands and architecture summaries the init command adds. Move schema and area-specific guidance into separate files and link them from CLAUDE.md. *When:* At project setup, and whenever CLAUDE.md has accumulated content that Claude could infer from the file tree.
- **Path-scoped rules files** — Put area-specific logic in rules files that apply only to matching paths, so Claude loads them only when it works in those paths. *When:* When different parts of a repo follow different rules, such as frontend versus database code.
- **Skills with bundled scripts for repetitive workflows** — Put repeated workflows in skills and bundle scripts for the deterministic steps, so the model runs code instead of reasoning through each step in tokens. *When:* When the same multi-step workflow recurs and some steps are mechanical.
- **Session-only instructions via the append-system-prompt flag** — Pass one-off instructions with the append-system-prompt flag at launch. They apply to that session only and are not written to CLAUDE.md. *When:* For a temporary instruction needed in one session, so it does not stay in the context permanently.
- **Task-based model and effort routing** — Set effort to low for simple tasks (the default is auto). Use Haiku for straightforward tasks, Sonnet for tasks that need moderate reasoning, and Opus for the hardest work. *When:* Whenever a task does not need deep reasoning; default to a cheaper model and lower effort, then escalate.
- **Disable unused MCP servers per project** — Turn off MCP servers that a given project does not use, so their tool definitions do not sit in the context. *When:* When a project has several MCP servers configured and only some are needed.
- **Hook that keeps only failing tests in context** — Configure a hook that runs a script over test output and forwards only the failed tests to the context, dropping the passing ones. The video shows one test-runner example; other hooks can filter output the same way. *When:* When test or tool output is large and mostly noise, and Claude only needs the failures to act.
- **Settings toggles for token use** — Set disable prompt caching to false, so prefixes are cached. Disable auto memory and the disable-background-task flag if you want fewer background token costs. Disable extended thinking entirely for tasks that need no reasoning. Set an explicit max output tokens value. The video does not show the exact config keys or file location. *When:* When optimizing a Claude Code setup for token cost and you accept the trade-offs (for example, losing auto memory).
