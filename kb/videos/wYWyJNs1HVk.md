## Summary
The host argues that Claude Code wastes tokens and loses accuracy when it reads whole files or whole CLAUDE.md documents to find what a task needs, and that semantic (retrieval-style) search over the codebase returns only relevant pieces. He uses Context7 as an example of semantic doc retrieval, then installs Serena, an MCP server that indexes a project's code and exposes symbol-level lookup to the agent. The install is per project directory, and the video shows the Serena dashboard for logs and clean shutdown. Indexing runs once per project through the server's CLI; the host notes a deprecation warning but says the command still works, and that indexing only supports certain languages. After indexing, he has Claude read Serena's instructions so it knows which tools exist, then gives it an edit task that spans Python and UI files. He also recommends a terminal-based Claude Code usage monitor that tracks the 5-hour plan window, message usage and model distribution. The evidence is anecdotal: no before/after token counts or accuracy measurements are shown.

## Techniques
- **Per-project Serena MCP install** — Copy the Claude Code install command (the second of two shown) from Serena's GitHub README. Run it inside each project directory; it adds the MCP server to Claude Code's settings for that directory. Verify in Claude Code's MCP panel that Serena shows as connected. *When:* When you want symbol-level code retrieval in a specific repo. The MCP is directory-scoped, so new projects need their own install.
- **Index the project before using Serena** — Exit Claude Code, go to the folder where the MCP server was installed with uv, and run the indexing command from Serena's README against your project path. The host says the first of two listed commands applies to uv installs; it warns about deprecation, but the command still works. The exact command string is not spelled out in the transcript, so read it from the README. *When:* Once per project, before the first use. Only useful for languages Serena supports (the host cites TypeScript and Python), not HTML-only projects.
- **Prime Claude with Serena's instructions** — After indexing, start Claude Code in the project and have it read Serena's instructions or onboarding so it learns the available tools and the principles for using them. Then give normal edit requests; the agent should query the index and load only the needed parts. *When:* Immediately after indexing, before any real task. Without this step the host says the agent does not know how to use the tools.
- **Use the Serena dashboard for logs and clean shutdown** — Serena starts a web dashboard alongside the MCP. Use it to read server logs and press its shutdown button to stop the server cleanly. Restart by exiting Claude Code and launching it again in the same directory. *When:* When you need to debug the MCP server or stop it cleanly without killing the process.
- **Track plan-window usage in a terminal tab** — Install the Claude Code usage monitor from its GitHub repo with the one-line command in the README (the transcript says it needs one prerequisite installed first; it is not named). Launch it in a separate terminal tab to see the 5-hour window, time to reset, token, cost and message usage, and model distribution. *When:* On subscription plans with rolling usage windows, to pace heavy sessions and avoid hitting the limit mid-task.
