> AI LABS shows seven ways to wire Google's NotebookLM CLI into Claude Code as a grounded knowledge base: a second brain, research store, codebase onboarding, debugging KB, agent-readable visualizations, and a security handbook.

## Summary
The video argues that coding agents underperform mainly because they lack a controlled source of truth, and proposes Google's NotebookLM as that grounding layer. The team installs the NotebookLM CLI with one command, verifies it with the help command, and has Claude Code drive it to create notebooks, add sources and query them. They present seven uses: a project "second brain" referenced from CLAUDE.md, offloading web research into a notebook, codebase onboarding via a Repomix export, a debugging knowledge base that replaces web search, shared docs for non-technical readers and other agents, agent-readable mind maps and tables, and a security handbook built from OWASP and advisory material. The CLI is chosen for token efficiency on long-horizon runs. Evidence is a single team's anecdotes; no token counts, timings or accuracy measurements are given. A short sponsored segment for Make appears mid-video.

## Key ideas
- **Agents underperform because they are not grounded in a controlled source of truth, not because they lack information or memory.** — The speaker frames the core problem as agents working from bad or ungoverned context, and positions a curated notebook as the fix. ([0:00](https://youtu.be/eFCHwtufjJc?t=0))
- **The CLI, not an MCP-style integration, was chosen because it is token efficient on long-horizon tasks.** — The team says the CLI keeps overhead low for long runs. No token figures are given to back this up. ([1:02](https://youtu.be/eFCHwtufjJc?t=62))
- **A notebook can act as the project's single source of truth, referenced from CLAUDE.md.** — Claude creates the notebook through the CLI, its ID is stored in CLAUDE.md, and architectural decisions are written there after each feature build passes. Plan mode is used before implementation. The notebook's RAG answers replace raw file searches, so Claude gets synthesized answers rather than document dumps. ([1:02](https://youtu.be/eFCHwtufjJc?t=62))
- **Offloading research into a notebook saves context and makes sources reusable.** — Claude adds the sources to a notebook, the context is cleared, and then a notebook chat query returns the key findings. Sources stay in the notebook for later runs, so they do not need to be re-researched. ([2:22](https://youtu.be/eFCHwtufjJc?t=142))
- **Repomix plus NotebookLM gives an onboarding path for an unfamiliar codebase.** — Claude clones the repo with the GitHub CLI, packs it into a single token-efficient TXT file with the globally installed Repomix CLI, adds that file as a notebook source, and generates atlases, mind maps per feature and infographics in the studio. ([3:34](https://youtu.be/eFCHwtufjJc?t=214))
- **A debugging knowledge base can replace web search for error resolution.** — The team gathers official docs, forums, GitHub repos and blogs into one notebook, adds its ID to CLAUDE.md, and instructs Claude to query the notebook before searching the web. In the example, a deprecated middleware was resolved by asking the notebook how to migrate, which returned a structured answer. ([5:54](https://youtu.be/eFCHwtufjJc?t=354))
- **Notebook exports can give agents a navigable map instead of crawling the file tree.** — Mind maps are exported as JSON, and tables as CSV and Markdown, into a visualizations folder. ## Techniques
- **Install and verify the NotebookLM CLI** — Install with a single command, run the CLI help command to list the source, notebook, multimodal and generation subcommands, then authenticate. The exact authentication command is cut off in the available transcript, and the exact subcommand names other than help and the notebook query tool are not shown. *When:* Before any of the workflows below. Use the CLI rather than an MCP server when token overhead on long runs matters.
- **Notebook as project second brain via CLAUDE.md** — Have Claude create a notebook through the CLI and save the notebook ID in CLAUDE.md. Add an instruction that all project knowledge, architectural decisions and documentation live in that notebook. Use plan mode to plan each feature. After the build passes, have Claude write the implementation and the decisions it made into the notebook. *When:* On a long-running project where decisions need to survive context resets, and where Claude should query synthesized answers instead of searching files.
- **Research offload to a notebook** — Give Claude the research topic and ask it to find sources, create a notebook and upload them. Clear the context. Then ask Claude to locate the notebook through the CLI and run a chat query for the key findings. *When:* Multi-source research where the sources should be reusable and the research should not clutter the working context.
- **Codebase onboarding via Repomix** — Clone the repo with the GitHub CLI, install Repomix globally through npm, pack the repo into a TXT file, create a notebook, and add that file as a source. Generate mind maps, infographics and an atlas from the studio. *When:* Learning or documenting a codebase you did not write, or a repo you need to explain to others.
- **Debugging knowledge base in place of web search** — Collect official docs, community forums, GitHub repos and blogs into one notebook. Store its ID in CLAUDE.md with the rule to query the notebook first when a bug is hit and to search the web only afterwards. Ask specific migration or error questions against it. *When:* Recurring error classes in a stack with fast-moving docs, such as deprecated APIs or middleware.
- **Export mind maps and tables as agent-readable artifacts** — Generate mind maps, data tables and a slide deck in the notebook. Download them into a project folder: mind maps as JSON, tables as CSV and Markdown. Instruct the agent to check the relevant mind map before crawling the file system for flows and endpoints. *When:* When an agent repeatedly explores a large codebase to answer structural questions about flows or endpoints.
- **Security handbook notebook for grounded reviews** — Create a notebook from the stack's security resources: OWASP cheat sheets, the tech stack's own security guidance, GitHub and CVE advisories, and feature specs. Ask Claude to run a security check that is grounded in that notebook and to report findings with severities. *When:* Security reviews of AI-generated apps where the reviewer should cite authoritative sources rather than model recall.
- **Shared notebook as knowledge base for people and other agents** — Share the notebook link so non-technical readers can chat with it. Other agents such as Cursor or Gemini CLI can query the same notebook with the CLI's query tool instead of searching project files. *When:* Onboarding non-engineers, or multi-agent setups where several tools need the same project context.
