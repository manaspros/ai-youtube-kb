> Walkthrough of OpenDesign, an open-source, local alternative to Anthropic's Claude Design that generates HTML prototypes and slides on top of whichever coding agent is installed; the speaker argues design systems plus per-output skills drive quality more than the model.

## Summary
The Better Stack presenter introduces OpenDesign, an open-source tool from the Nexa team that generates web prototypes, mobile app designs and HTML slide decks using any agent or model the user already has installed. The speaker credits its output quality to two things: built-in design systems with full brand tokens (typography, spacing, color) and a large library of skills per output type, with an anti-AI checklist injected into every prompt. The tool asks about audience, tone and brand content before generating. In the demo, OpenDesign detects Claude Code, Codex and OpenCode, and the speaker runs it from source with GLM 5.1 via OpenCode and GPT-Image2 for images. He gives it the URL of an existing YouTube search app, and the agent browses the live site to design a new version; after about 20 minutes it returns five files, which can be finalized into one design MD file, exported as standalone HTML, handed to Claude Code, and deployed. The speaker's verdict is that it is worth trying if you already pay for a coding-agent subscription, but that it assumes some design knowledge, and that Impeccable's upfront planning is better for people without a design direction.

## Key ideas
- **Output quality comes from design systems and skills working together, not from the model.** — OpenDesign ships many design systems with full brand specs (typography, spacing, color tokens) modeled on brands like Linear, Stripe and Spotify, plus a skill for each output type (e.g., a dashboard skill that lays out charts, a deck skill that structures slides). The speaker says this is why it can match Claude Design's quality on a weaker model. ([1:14](https://youtu.be/B3coWv2ZV68?t=74))
- **It runs on top of the coding agents already installed, so the user chooses the harness and model.** — The UI auto-detects installed harnesses (Claude Code, Codex, OpenCode). Each harness exposes its own model picker, and Codex also exposes reasoning effort. The speaker picks GLM 5.1 through OpenCode. ([1:14](https://youtu.be/B3coWv2ZV68?t=74))
- **Before generating, the tool asks about audience, tone and brand content.** — Each project starts with clarifying questions about visual tone and brand context. The speaker says this makes it feel geared toward users who already know some design, since it expects them to pick a design system up front. ([3:52](https://youtu.be/B3coWv2ZV68?t=232))
- **A live reference URL can seed the design: the agent browses the existing product and reuses its real flows and data.** — The speaker gives the agent a URL to a YouTube channel search app it built earlier. The agent used curl to open the site in Chrome, then an agent-browser tool to step through pages and inputs. The result used real data from the site, though thumbnails were missing. The speaker did not know whether the agent scraped and stored the data. ([3:52](https://youtu.be/B3coWv2ZV68?t=232))
- **Generation is slow with a non-frontier model: about 20 minutes for five pages.** — GLM 5.1 took roughly 20 minutes to finish. The speaker notes it is not the fastest model and that the tool is less useful when the model is weak at design. ([5:08](https://youtu.be/B3coWv2ZV68?t=308))
- **Finalize Design Package consolidates the work into one artifact that can be handed off.** — It synthesizes the transcript, the chosen design system and all generated artifacts into a single design MD file. Share can export in several formats, including standalone HTML that Claude Code can implement in a real project. The output can be deployed to Vercel or Cloudflare Pages. ([5:08](https://youtu.be/B3coWv2ZV68?t=308))
- **Positioned against Claude Design on cost, lock-in and openness.** — The speaker describes Claude Design as proprietary, cloud-only, single-model and $20/month. OpenDesign is open source, runs locally, supports any model, and bundles 72 design systems. The speaker says the title's developer-count claim is not discussed in the video; the framing is the speaker's own. ([0:00](https://youtu.be/B3coWv2ZV68?t=0))
- **Trade-off against Impeccable: OpenDesign assumes design knowledge, while Impeccable plans upfront with image mockups.** — The speaker prefers Impeccable's planning, which asks everything first and produces image mockups to iterate on. He says OpenDesign suits someone with a rough direction, but that OpenDesign has the better UI, with responsive previews, export options, skills, MCP tools and pets. ([6:27](https://youtu.be/B3coWv2ZV68?t=387))

## Techniques
- **Run OpenDesign from source** — Clone the repo and run it from source (the speaker's choice), or use Docker, or download the macOS or Windows desktop app. Visit the local port in the browser; the UI detects installed harnesses. The video does not show the exact commands or port. *When:* Trying the tool locally when you already have Claude Code, Codex or OpenCode installed.
- **Harness and model selection per project** — In the harness panel, select Claude Code, Codex or OpenCode, scroll to the model list, and pick a model. The default is the model set in that CLI. For Codex, pick a reasoning effort level. Memory (instructions added to every prompt), media providers and API keys (OpenAI for GPT-Image2, ElevenLabs for TTS and sound effects) are configured in the same UI. *When:* Choosing a cheaper or different model for generation, or adding image and audio providers.
- **Seed a design from a live URL** — In the prompt, describe the product and include the URL of an existing site. Let the agent use a browser tool to open the site and step through its pages and inputs, then design from what it saw. Answer the clarifying questions about visual tone and brand before generation proceeds. *When:* Redesigning an existing internal or personal app and keeping its real flows and data.
- **Pick a design system before prompting** — Open the design system tab, review the tokens and the design MD file for each system, then select one when creating the project. The speaker picked the Miro system. Templates tab and live artifacts (data-driven updating pages) and slide decks are alternatives to the default prototype mode. *When:* Starting a new prototype or slide deck where you want consistent brand tokens.
- **Finalize, export and hand off** — Click Finalize Design Package to synthesize the transcript, design system and artifacts into one design MD file. Use Share to export a standalone HTML file, then give that file to Claude Code to implement in the real project. Deploy with Vercel or Cloudflare Pages. *When:* Moving a prototype from OpenDesign into a production codebase.
- **Iterate with follow-up prompts** — After the first generation, send another prompt to change the design, e.g. adding a dark mode, rather than regenerating from scratch. *When:* Refining a generated prototype.

## Hot takes
- The title's '40k developers abandoned Claude Design' claim is never backed up in the video.
- The speaker says the tool is for people who already know some design, yet he says any user can make something decent with a rough direction. The two claims are in tension.
- The speaker argues that letting users choose any model is a weakness because most models are bad at design, but then demos a model he says is not the best for design (GLM 5.1).
- The speaker says Claude Design produced better output 'with the exact same prompt', but the transcript shows no side-by-side comparison, so the claim is unverified in the video.
- The 'open' framing is mostly positioning; the speaker does not discuss licensing, and model calls still go to hosted providers (GLM 5.1 via OpenCode, GPT-Image2), even though the speaker says projects stay on the machine.
- Coverage is a single demo, with no failure cases, no output quality comparison and no evaluation method.
