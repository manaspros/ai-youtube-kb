> A walkthrough of a prompt-chained Figma Make workflow for planning and generating a React app, then converting it with a coding agent and feeding Figma designs to agents through the Dev Mode MCP server.

## Summary
The creator argues that Figma Make produces usable prototypes only when the input is structured, so he plans the app first in ChatGPT, then runs three prompts (app overview, per-page architecture, design system) and combines the outputs into one big prompt, pasted after a standing best-practices prompt. Figma Make outputs a React app with pages, which he downloads and converts into a Next.js-style full-stack app with mock data using Warp's coding agent and a custom conversion prompt, reviewing diffs before pushing to GitHub. For existing designs, he sets up the Figma desktop app's Dev Mode MCP server in a coding agent and describes how the agent classifies screens, writes a pagelinks.md, and builds a to-do list. He reports that a per-project implementation-rules file (images as assets, scrollable long screens, horizontally scrolling cards) took the output from broken layouts to mostly solid, with manual fixes still needed for icons. He closes by suggesting the shadcn MCP server for real component context, with Aceternity UI as an animated component source. The prompts themselves are not shown on screen; they are linked in the description and a Discord, so the reproducible detail is limited to the workflow shape and the MCP setup steps.

## Techniques
- **Plan-first prompt chain for Figma Make** — Before generating, run three planning prompts in a chat model: (1) full app overview, (2) architecture of every page, (3) design system (colors, fonts, style). Review and lock each output, paste them into placeholders in one combined prompt, then send a standing best-practices coding prompt first and the combined prompt second in the Figma Make session. The exact prompt text is linked in the video description and Discord, not shown on screen. *When:* Starting a new app prototype in Figma Make where a single dumped prompt gives disorganized, non-working output.
- **Universal full-stack conversion prompt** — Download the React code from Figma Make, then give a coding agent (he uses Warp in auto mode) a custom reusable prompt that describes how to convert the shared component format and dependencies into the target stack, including a mock-data backend. Review changes in the agent's diff view, then push to GitHub. The prompt is linked in the resources, not shown. *When:* Converting a generated prototype into a real app with a backend, especially when many components share the same format and dependencies.
- **Figma Dev Mode MCP setup** — 1) Install the Figma desktop app and switch from Design mode to Dev mode. 2) Enable the MCP server. 3) Copy the MCP configuration file from Figma's official site. 4) In the coding agent, run the add-MCP slash command (Warp: first option), paste the config and save. 5) Set the image source option to download instead of local server, so images are saved into the project as assets. *When:* Implementing an existing Figma design (for example, a mockup found online) with a coding agent. He prefers the local server over the remote one, and notes that open-source alternatives exist but are harder to set up.
- **Implementation-rules configuration file** — Keep a config file in the project with rules learned by testing. Rules he states: treat images and icons as image assets; make long screens scrollable; make card rows horizontally scrollable. The file is linked in the video resources and not shown in full. Without it the output looked fine at first but broke; with it, most UI was correct. *When:* Generating UI from Figma through an agent. Keep it in the repo so every agent session loads it, and check icon contrast and placement manually afterward.
- **Screen triage before implementation** — Let the Figma MCP agent pull page metadata and links, screenshot each page to separate real app screens from promotional pages, and write a links file (pagelinks.md). Above 10 pages, have it write a design guide to manage context; below that, skip the guide. Then have it generate the to-do list before coding. This is the agent's behavior as observed in the video, not a prompt the viewer must write. *When:* A Figma file has many pages that mix app screens with marketing material, and the agent needs a plan before implementing.
- **Add shadcn MCP for component context** — Add the shadcn MCP server to the agent in the same way as the Figma MCP. Then ask the agent to swap generated UI for real shadcn components; for animated components he cites Aceternity UI, whose component context can be passed to the agent as well. *When:* A Figma-derived UI is working but needs real, maintainable component library parts or animated components.

## Hot takes
- Figma is not being replaced by AI anytime soon, and not using its AI features is a major productivity disadvantage.
- Figma Make's output is good largely because Figma has a large body of design data to train on.
- If the planning is confused, the AI agent will be confused too, so planning matters more than prompting.
- Sponsorship is disclosed at 3:31 (Warp, as the coding agent used) and again at 8:47 (Warp Pro $5 promo); the Warp use is part of the demo, so treat tool recommendations as biased.
