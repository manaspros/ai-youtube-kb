> AI LABS tutorial on generating varied app UI designs inside Cursor with manually invoked rule files, replacing a paid-API design extension, with a Claude Code port and a plain-English method for writing rule files.

## Summary
The host wants AI-generated UI that is not generic and can be iterated until a design is liked. He first points to Super Design Dev, a Cursor extension by Jason Zhao that runs iterative UI generation on the paid Claude API, which gets expensive. His replacement uses only Cursor's built-in rule files, set to manual mode and called from the agent, so generation runs on the existing Cursor subscription. The method has two steps: first, targeted variations (persona, device type, geolocation) applied to an existing index file, after a design.json is extracted from a reference image; second, rapid iteration with an "infinite design" rule that makes three variants per run into a variations folder and re-sources a chosen file for the next round. He notes the same commands work as Claude Code custom commands, where Claude Code's real advantage is running several agents in parallel while Cursor runs them one by one. He recommends a fresh chat per generation round and says rule files can be written by describing the workflow in plain English and asking the model to write the file. The rule files themselves are linked in the video description and are not shown in the transcript.

## Key ideas
- **The problem is cost, not capability: Super Design Dev is a Cursor extension for iterative UI generation, but it calls the Claude API directly, so each round costs API money.** — The host reuses the same iterative-design idea inside Cursor's built-in rule system to run on the existing Cursor subscription. He also says a Claude Code version of the workflow needs either a separate $20 plan or API spend. ([0:00](https://youtu.be/H-ok6Zx9SR8?t=0))
- **Cursor rule files set to manual mode act as callable workflows, so they can replace custom commands.** — Rules are created from Cursor settings, their mode is set to manual, and the user invokes each one in the agent. The speaker says a rule with an arguments placeholder can do what a Claude Code custom command does, so the two tools can share the same flow. ([1:12](https://youtu.be/H-ok6Zx9SR8?t=72))
- **A design.json extracted from a reference image gives consistent palettes across generations.** — An extract-design rule takes an image and saves design.json in a designs folder. The generation rules then read that file, so each variant follows the same colors and design language while changing layout and styling. ([2:14](https://youtu.be/H-ok6Zx9SR8?t=134))
- **Claude Code's one structural advantage is running several agents in parallel, while Cursor runs variants one after another.** — The speaker says output quality was similar in both tools on the same task, and parallel fan-out only makes Claude Code faster, at the cost of extra API spend or the $20 plan. ([3:38](https://youtu.be/H-ok6Zx9SR8?t=218))
- **Step 1, targeted variations: separate rule files for persona, device type and geolocation each produce a differently tailored version of the same index file.** — Persona examples were a chef hub, a student-oriented campus eats UI and a corporate executive site. Device rules covered mobile (larger icons), desktop and TV. The geolocation rule changed language, colors and layout orientation for regions. ([4:54](https://youtu.be/H-ok6Zx9SR8?t=294))
- **Step 2, rapid iteration: an infinite-design rule takes one chosen file, creates a variations folder, copies the original as source.html, and generates three variants per run.** — Re-referencing a chosen variant makes it the new source and produces three more. Keeping the layout and animation while changing only colors and style is shown as the way to iterate on one part of a design. ([7:01](https://youtu.be/H-ok6Zx9SR8?t=421))
- **Start a fresh chat before each generation round so earlier context does not carry over.** — The speaker says this helps the agent follow the rule file precisely. He also says thinking models follow complex rule instructions more reliably than faster non-thinking models such as Claude 3.5 Sonnet. ([8:18](https://youtu.be/H-ok6Zx9SR8?t=498))

## Techniques
- **Manual-mode Cursor rule files as invocable workflows** — Initialize rules from Cursor settings, set each rule's mode to Manual, and call it by name in the agent with the source file referenced. The rule holds the generation procedure, examples, constraints and output folder layout. Rule files are linked in the video description; their contents are not shown in the transcript. *When:* To run a repeatable generation workflow inside Cursor without paying for separate API calls.
- **Extract a design.json from a reference image** — Run an extract-design rule with an image attached. It writes design.json into a designs folder. Generation rules then reference that file so every variant reuses the palette and design language. *When:* To keep many generated designs visually consistent with one reference, such as a landing page the user likes.
- **Targeted variation rules (persona, device, geolocation)** — Write one rule per dimension: persona (chef, student, executive), device (mobile with enlarged icons, desktop, TV), geolocation (language, colors, layout orientation). Reference the original index file and apply the rule so it writes several tailored variants. *When:* When the same UI needs to serve different audiences, devices or regions and you want control over how each variant changes.
- **Infinite-design iteration loop** — Reference a chosen HTML file and run the infinite-design rule. It creates a variations folder, copies the original to source.html, and writes three variants per run. To continue, reference a chosen variant again, so it becomes the new source. Ask for specific changes, such as keeping the layout and animation but changing colors and style. *When:* After you have one design you like and want quick variations on one dimension, such as color or style, while keeping the rest.
- **Fresh chat per generation round** — Open a new chat before each rule run, rather than continuing a long conversation, so the agent follows the rule file without earlier context. *When:* Whenever a rule run must produce genuinely fresh output or follow instructions precisely.
- **Writing rule files in plain English** — Describe the workflow step by step in plain English, then ask the model to write the rule file from that description. The speaker says the resulting agents follow these rule files reliably. *When:* To author complex multi-step workflow rules quickly, instead of writing them from scratch.
- **Porting a rule to Claude Code custom commands** — The same workflow can be a Claude Code custom command with an arguments placeholder that passes a variable, as in the speaker's earlier video. The speaker says Claude Code is the better choice when you want parallel subagent runs. *When:* When you already use Claude Code and want the same generation flow, or want several variants generated concurrently.

## Hot takes
- The title's 'PERFECT app UI every time' overstates it: the demo is subjective and gives no evaluation of design quality.
- The actual rule files are not shown in the transcript, and the reader is pointed to the video description, so the core method cannot be reproduced from the video alone.
- The claim that Cursor and Claude Code produce similar output is anecdotal, from one side-by-side example.
- Cost framing is the strongest part: it argues for running a design workflow on a flat subscription rather than per-call API usage.
- Parallel subagent fan-out is presented as Claude Code's one real advantage over Cursor for this kind of workflow.
