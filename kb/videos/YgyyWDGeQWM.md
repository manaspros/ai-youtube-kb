> A survey of local/open coding-agent harnesses (OpenCode, Aider, Pi, plus OpenHands, Cline, Goose) arguing the harness now matters more than the model, with local-model pairing advice and a warning that the list goes stale fast.

## Summary
The speaker argues that frontier models have largely converged on benchmarks, so the agent harness around the model now decides day-to-day reliability. He gives an informal tiered pick list: OpenCode as the default open-source starting point (MIT, model-agnostic, client/server, deep configuration), Aider for disciplined git-native editing with one commit per AI change, and Pi as a minimal, hackable foundation that loads instruction "skills" lazily. He then lists other options by use case (OpenHands for unattended runs, Cline for an in-editor loop, Goose for non-code agents) and mentions Claude Code as the strongest proprietary option, with a note on its heavy token use. For local hardware he suggests a 4-bit Qwen dense model that fits on a 24GB card, a Qwen MoE alternative that offloads experts to system RAM, and vLLM to run parallel agents so one GPU stays busy. The closing caveat is that the list is volatile: Roo Code was archived and Gemini CLI dropped individual users, so check license and last-commit date before standardizing. Most claims are the speaker's own framing and the community sentiment is unsourced, so treat this as an opinionated overview rather than a benchmark study.

## Key ideas
- **The harness now matters more than the model** — Frontier models have largely converged, so the wrapper around the model decides the experience. The same model in two different harnesses gives very different results. The speaker's reliability framing is his own, not a measured result. ([0:00](https://youtu.be/YgyyWDGeQWM?t=0))
- **Headline benchmark numbers used to frame the race** — Claude Opus 4.8 at 88.6% on SWE-bench Verified; GPT-5.5 in the Codex harness at 83.4% on Terminal-Bench 2.1; Gemini 3.5 Flash at 76.2. The speaker says the gaps are shrinking. ([0:53](https://youtu.be/YgyyWDGeQWM?t=53))
- **OpenCode as the default open-source starting point** — MIT licensed, model-agnostic across 75+ providers, runs local models via Ollama or any OpenAI-compatible endpoint, and has custom primary agents and subagents (defined in JSON or Markdown, each with its own model and permissions). Its client/server design includes a headless OpenAPI server for async and remote use. Caveat: Anthropic does not allow Claude Pro/Max subscriptions in OpenCode, so Claude needs an API key. ([0:53](https://youtu.be/YgyyWDGeQWM?t=53))
- **Aider's git-native, one-commit-per-edit workflow** — Each AI edit becomes one atomic commit with a model-written message, so the git log reads as a changelog and a bad edit is one revert away. Its repo map gives structural context. It supports 70+ models and mid-session model switching. It has no native MCP support as of mid-2026, and it is a pair-programmer rather than an overnight runner. ([3:36](https://youtu.be/YgyyWDGeQWM?t=216))
- **Pi's lazy skills keep the system prompt small** — Pi's core system prompt is under 1000 tokens. Modular instruction blocks load only when a task needs them, so a coding task does not load a deployment skill. The speaker presents this as the reason Pi is a base for custom agents (he cites OpenClaw as inspired by it). The trade-off is less polish out of the box. ([4:48](https://youtu.be/YgyyWDGeQWM?t=288))
- **Local pairing: pick a model that fits the hardware** — For most local setups the speaker suggests a dense Qwen model (quoted as 'QN327B' in captions) that fits on a single 24GB card, such as a used RTX 3090, using 4-bit Unsloth quantized builds from Hugging Face. For bigger jobs, a Qwen3.5 A3B mixture-of-experts model keeps idle experts in system RAM and only the active slice on the GPU. ([6:13](https://youtu.be/YgyyWDGeQWM?t=373))
- **Parallel agents on vLLM to fill the GPU, not a faster single stream** — A single local stream on a 3090 runs at about 37 tokens/s. Power users serve with vLLM and run parallel agents so the card is busy between tokens. The speaker frames this as the answer to slowness being more agents, not a faster one. ([7:35](https://youtu.be/YgyyWDGeQWM?t=455))
- **Claude Code as the deepest proprietary option, with a cost caveat** — The speaker cites 30 lifecycle hook events and dynamic workflows for parallel sub-agents, and says it is not local or open. He also says it is the heaviest token spender in the category, roughly 3 to 4 times Codex on the same task. That ratio is unsourced in the talk. ([7:35](https://youtu.be/YgyyWDGeQWM?t=455))
- **Lineup is volatile; check license and last commit before standardizing** — Roo Code was archived in May 2026 and Gemini CLI stopped serving individual users in June 2026. Stars show popularity, but recent commits show whether a project will still be maintained. ([9:56](https://youtu.be/YgyyWDGeQWM?t=596))

## Techniques
- **Git-native atomic AI commits (Aider)** — Run Aider inside a git repo so every AI edit lands as one commit with a model-written message. Review each change as it lands, and undo a bad edit with a single revert. The repo map gives the agent structural context from git. *When:* Surgical or reviewable edits where the git history must read as a changelog. Avoid it when you need autonomous overnight runs or MCP tools.
- **Mid-session model downgrade for cost** — In Aider, switch the active model mid-session with one slash command, for example from a frontier model for hard refactors to a cheaper model or a local DeepSeek or Qwen model served through Ollama. The exact command name is not given in the talk. *When:* Use a strong model for hard refactors and a cheap or local model for routine edits in the same session.
- **Lazy-loaded skill blocks to keep the base prompt small (Pi)** — Keep the core system prompt tiny (under 1000 tokens in Pi) and put task-specific instructions in modular blocks that load only when the task needs them, for example not loading a deployment skill on a coding task or a browser skill on a code task. *When:* Long-context or many-skill setups where instruction bloat degrades a session. Pi-style design suits building your own agent loop.
- **Custom subagents with per-agent model and permissions (OpenCode)** — Define primary agents and subagents in JSON or Markdown, giving each its own model and permission set. Use the headless OpenAPI server mode for async or remote runs. LSP integration across 20+ languages loads language-aware context automatically. *When:* Mixing models by task inside one harness, or driving the agent from a remote client or script.
- **Parallel agents on one GPU via vLLM** — Serve the local model with vLLM and run several agent sessions against it concurrently, so GPU utilization stays high instead of idling between tokens of a single stream. *When:* Local hardware where throughput across many tasks matters more than the latency of one deep task.
- **Local model sizing by memory footprint** — Pick a dense 4-bit quantized model that fits fully in a 24GB card (for example a used RTX 3090), or a mixture-of-experts model that keeps inactive experts in system RAM and only the active slice on GPU. *When:* Choosing a local model for an agent harness on consumer GPU hardware.
- **Pre-standardization vetting checklist** — Before a team standardizes on a harness, check the actual license and the date of the last commit, and treat stars as a popularity signal only. *When:* Choosing an agent tool for a team or long-lived workflow.
