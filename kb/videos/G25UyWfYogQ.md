> Walkthrough of the browser-tools MCP server, which lets Cursor's agent run accessibility/SEO/performance audits, read screenshots and selected DOM elements from Chrome, and iterate on front-end fixes.

## Summary
The host installs the browser-tools MCP server into Cursor and a Chrome extension that connects the browser to it, then demos the workflow on a family-manager web app. The MCP exposes audit tools (accessibility incl. WCAG contrast, SEO metadata and headings, performance) that return a JSON report the Cursor agent acts on. A screenshot tool pastes the current page image into the agent automatically, so the agent can fix contrast issues, re-run the audit, and verify with a new screenshot until the audit passes. A select-element tool lets the user point at a React component in the browser and have the agent act on that exact element. The host says console and network log tools matter less now because Cursor's agent already reads terminal logs. The video is a short, practical tutorial with no sponsor segment, and the host reports the resulting UI is still rough.

## Key ideas
- **A browser MCP server gives the IDE agent direct access to a live page, so UI work does not require switching between the editor and the browser.** — The host frames it as an MCP server integrated into Cursor, with the browser connected through a Chrome extension and a local server started from the terminal. ([0:00](https://youtu.be/G25UyWfYogQ?t=0))
- **Audits return a JSON report that the agent turns into code changes.** — Accessibility (WCAG, including color contrast and keyboard traps), SEO (metadata, headings, link structure) and performance audits return results that the Cursor agent uses to propose and apply fixes. The host says the recommendations go straight to the agent, with no manual edits. ([1:25](https://youtu.be/G25UyWfYogQ?t=85))
- **Console and network log tools are less necessary now.** — The host says Cursor's agent has improved enough to capture terminal logs on its own, so the explicit console and network error tools matter less. The screenshot tool is still useful. ([1:25](https://youtu.be/G25UyWfYogQ?t=85))
- **The core loop is audit, fix, screenshot, re-audit, and the screenshot closes the gap that the audit report alone leaves.** — In the demo, the agent first fixed low contrast, then the audit flagged calendar selected-date contrast. A screenshot showed the agent what it looked like, and it kept iterating until the audit and the final screenshot both passed. ([5:23](https://youtu.be/G25UyWfYogQ?t=323))
- **The screenshot tool can paste the image into the agent automatically with a prompt.** — Once a toggle is on, the screenshot is inserted into the agent along with an instruction to use it. The host also recommends saving screenshots to a dedicated folder, because the default save location is Downloads. ([6:46](https://youtu.be/G25UyWfYogQ?t=406))
- **The select-element tool removes repeated re-description of the same component.** — The user selects an element in the browser, then asks Cursor to get the selected element. The server returns that element (a React calendar component in the demo), so changes target the right code without the user re-describing it. The host says Windsurf already has this feature, but Cursor did not yet. ([6:46](https://youtu.be/G25UyWfYogQ?t=406))
- **The setup in the docs is out of date for current Cursor, so the MCP entry is added to mcp.json.** — The host says the docs' command predates the current Cursor UI, which expects the server entry in mcp.json. Cursor formats the pasted entry to match the file. ([2:44](https://youtu.be/G25UyWfYogQ?t=164))

## Techniques
- **Install browser-tools MCP into Cursor** — 1) Copy the server command from the repo's installation docs. 2) In Cursor's MCP settings, add a new entry on a new line in the mcp.json file, paste the command, and let Cursor format it. 3) Confirm in the MCP section that the server is installed and its tools are listed. The host says the docs' command is outdated for current Cursor, so the entry goes in mcp.json, not the older add-server flow. *When:* Setting up the MCP server in Cursor for the first time. The exact command is not spoken in the transcript; get it from the repo README.
- **Load the Chrome extension and start the connector** — 1) Download the browser-tools extension from the repo's installation docs. 2) Open the browser's extensions page, enable developer mode, click Load Unpacked, and select the extension folder. 3) Copy the connector command from the docs, run it in a terminal, and leave it running. The first run installs packages and then starts the server that links the extension to the MCP server. 4) Open DevTools on the page and go to the Browser Tools MCP tab to confirm the tools and settings are available. *When:* Each time you want the agent to inspect a local web app in Chrome. The host ran this against a local app in a Chrome-based browser.
- **Accessibility audit and fix loop** — Prompt the Cursor agent to 'run an accessibility audit, then take a screenshot.' The agent runs the audit, reads the JSON result, edits the code to fix the failing check (here, color contrast), re-runs the audit, and takes another screenshot. Repeat until the audit passes and the final screenshot shows no remaining issues. *When:* Fixing front-end issues that a Lighthouse-style audit can detect, such as WCAG contrast. Verify with the audit plus a screenshot, not the audit alone.
- **Configure screenshot folder and auto-paste** — Open DevTools, go to the Browser Tools MCP section, and set a custom screenshot folder. Turn on the toggle that inserts the screenshot into the agent with its prompt. Without a folder, screenshots go to Downloads. *When:* Before using the screenshot tool, so screenshots stay in a project folder and are fed to the agent automatically.
- **Select-element targeting** — In the browser, use the built-in inspector to select an element on the page. Then ask Cursor to 'get selected element.' The MCP tool returns the element and its source (here, a React calendar component), and the agent edits that element directly. *When:* When iterating on one specific UI component, to avoid re-describing it in each prompt. Windsurf already had this feature when the video was made; the host says Cursor did not.
- **Voice mode for prompting** — The host recommends using the editor's voice mode on Mac or Windows for prompting the agent while using the browser tools. No setup details are given. *When:* Driving the audit-fix loop by voice, as the host recommends.
