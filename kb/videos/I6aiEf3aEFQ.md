> Yu Su (Ohio State, CEO of NeoCognition) argues intelligence and expertise are different axes and that continual learning, not bigger models, is what turns agents into domain experts.

## Summary
Yu Su, a professor at Ohio State and CEO of NeoCognition, gives a short conceptual talk on why coding agents work well while agents struggle with everyday digital work. He frames this as a modern Moravec's paradox: symbolic tasks like code and math are easy for LLMs because code already has structure and tests, while computer use and on-the-job learning are hard. He argues that the world is made of many heterogeneous micro-worlds, so agents must keep learning on the job to build specialized expertise. He defines intelligence as reasoning through unfamiliar problems and expertise as accumulated, situated, reliable competence, with experts seeing deeper structure, holding conditional rules, and knowing when to stop. He defines continual learning as adaptive compression of experience into reusable structures, and claims that without it, scaling raw intelligence only produces a "smartest novice" that brute-forces every problem. The talk ends with open questions (measuring expertise, reliability vs plasticity, parametric vs non-parametric learning) and a call to scale expertise, with private domain data as the next data source. Most of the talk is framing with no benchmarks, and the closing section is a light company pitch.

## Key ideas
- **Coding is an easy market for agents because code is already symbolic and has built-in tests as rewards. The same skill does not transfer to everyday digital work.** — The speaker calls this a modern Moravec's paradox: symbolic reasoning (code, math) is easy for LLMs, while computer use and continual learning remain hard. ([3:56](https://youtu.be/I6aiEf3aEFQ?t=236))
- **Real work is a set of heterogeneous micro-worlds, each with its own local rules, structure and constraints, so a single static model cannot hold all of it.** — Even the same software is configured differently by each company. The speaker concludes agents must learn on the job to build specialized expertise for each micro-world. ([5:20](https://youtu.be/I6aiEf3aEFQ?t=320))
- **Intelligence and expertise are different things. Intelligence is reasoning on unfamiliar problems from context. Expertise is accumulated, reliable, efficient competence with judgment.** — Frontier models are increasingly strong at the first. The second needs experience inside a specific domain. ([6:18](https://youtu.be/I6aiEf3aEFQ?t=378))
- **Experts see deeper structure and know their rules' preconditions and exceptions. They also know what counts as good enough.** — The speaker argues experts carry a generalized world model of their environment that drives perception, reasoning and judgment, and that this is more than a stock of facts. ([7:41](https://youtu.be/I6aiEf3aEFQ?t=461))
- **Intelligence brute-forces a problem by searching widely, while expertise brings the right context and compresses the search space using learned shortcuts.** — This is the speaker's explanation for why current agents burn tokens on many parallel attempts. ([8:32](https://youtu.be/I6aiEf3aEFQ?t=512))
- **Continual learning is defined as adaptive compression of experience into reusable structures for future behavior.** — Experience can be episodes, facts, procedures or feedback. Compression can be embedding, symbolic indexing, distillation or RL. Structures can be adapters, vectors, graphs, skills or world models. Each compression step should depend on what was already learned. ([9:50](https://youtu.be/I6aiEf3aEFQ?t=590))
- **Without continual learning, more raw intelligence gives only a smart novice. With a strong learning algorithm, expertise can grow fast enough that intelligence stops being the bottleneck.** — The speaker plots raw intelligence against expertise as largely orthogonal axes. The learning algorithm sets the slope. He calls the hoped-for end state unbounded expertise from bounded intelligence. This is a conceptual claim with no data. ([12:24](https://youtu.be/I6aiEf3aEFQ?t=744))
- **The open problems are reliability versus plasticity, parametric versus non-parametric learning, and how to measure expertise per environment.** — The speaker treats humans as the existence proof that a system can be both plastic and dependable. He says both learning forms are probably needed, but he does not say how to combine them. ([14:45](https://youtu.be/I6aiEf3aEFQ?t=885))
- **Private domain data, learned in situ and fed back to general models, may be the next internet-scale data source.** — This is the speaker's closing argument for specialized agents. It is a claim about where future training data comes from, not a result. ([16:12](https://youtu.be/I6aiEf3aEFQ?t=972))

## Techniques
- **Adaptive compression loop for agent memory** — Store raw experience as episodes, facts, procedures or feedback. Compress it into vectors, a symbolic index, skills, graphs or fine-tuned parameters. Make each compression step depend on what the agent has already stored, so the structures build on each other. *When:* Designing cross-session memory or skill stores that should improve with use, not just grow. The speaker gives this as a definition only, with no implementation.
- **Rules stored with preconditions and exceptions** — Record each domain rule with the conditions where it applies and the cases where it can be bent. Judgment about when to stop or accept good enough is part of the expertise, not a separate step. *When:* Encoding domain playbooks or skills so that the agent knows when a rule does not hold.
- **Select context by expertise instead of parallel brute force** — Before solving, identify which context matters for this class of problem and load it. Prefer one well-chosen attempt over many parallel ones. *When:* Cutting token spend on agents that currently fan out many attempts for each task.
- **Measure expertise per environment** — Define competence for a specific domain as reliable, efficient, reproducible performance over repeated episodes, not single-shot accuracy. *When:* Evaluating whether a learning or skill system is actually improving inside one workflow.

## Hot takes
- Coding agents succeed because code is already a symbolic, self-testing world. That success does not carry over to everyday digital work.
- Expertise, not intelligence, is the scarce resource, because frontier models are already smarter than the average human.
- Current agents waste tokens because intelligence brute-forces search, and expertise would compress it.
- Private, domain-specific worlds are the next internet-scale training data source, and specialized agents can feed learning back into general models.
