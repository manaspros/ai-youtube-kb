> Hands-on tour of Google's Antigravity agent IDE: a useful agent manager, plan-review flow and browser self-testing, undercut by quotas, a markdown-image prompt-injection exfiltration issue, and a half-baked preview.

## Summary
The host spends about eight minutes using Google's Antigravity, a VS Code-based agent IDE in preview, and grades it good, bad and ugly. The good parts are the Agent Manager, a standalone view of parallel agent conversations that surfaces blocked runs awaiting approval, and an implementation-plan step that the user can comment on like a doc before the agent codes. The agent can also call an image-generation tool for mockups and placeholder images, and a browser subagent drives an agent-controlled Chrome instance to test a contact form, read console logs, and return screenshots and a video. The bad parts are free-tier quota limits on Gemini 3 Pro with no pricing yet, and a security demo where a prompt-injected markdown file made the agent read a gitignored file via cat and exfiltrate its contents through an image URL's query string, with auto-run on by default. The host also reports Mac lag and battery drain but says he cannot confirm it. He concludes it is another VS Code fork with some promising features and keeps Cursor as his daily driver.

## Key ideas
- **Agent Manager is a standalone UI for many agent conversations at once. An inbox lists running conversations and flags blocked ones that need user approval, which the host prefers to Cursor's agents view.** — Conversations can run in parallel; the inbox separates work that is progressing from work waiting on the user. ([0:00](https://youtu.be/KLq250wGeEg?t=0))
- **Agents can call an image-generation tool, so mockups and site stock images come from the same chat as the code.** — From one prompt the agent produced three landing-page mockups. The host picked one, and the agent then built it. He judged two of the three mockups weak and said the tool is probably backed by Nano Banana Pro, which he is unsure of. ([1:07](https://youtu.be/KLq250wGeEg?t=67))
- **Each task starts with an implementation plan that the user can review and comment on, and a review policy controls whether approval is needed.** — The policy has three settings: always proceed, agent decides, or always ask. Comments can be left on selected text or lines, similar to Google Docs. In the demo the agent judged a simple HTML page not to need review and skipped the approval step. ([2:07](https://youtu.be/KLq250wGeEg?t=127))
- **A browser subagent drives an agent-controlled Chrome instance to self-test the UI, then reports the results as a walkthrough with screenshots and video.** — The subagent filled in and submitted a form to test empty fields, invalid emails and successful sending. It read console logs to self-debug. A blue border shows the agent is in control and the user cannot interfere. Each validation check produced a screenshot, and the screenshots could be assembled into a video. ([3:21](https://youtu.be/KLq250wGeEg?t=201))
- **Free access to Gemini 3 Pro comes with quota limits that are hit quickly, so the host says it is not practical as a daily driver. There is no pricing yet.** — The host frames the preview as half-baked and expects pricing and quotas to change before a real launch. ([4:28](https://youtu.be/KLq250wGeEg?t=268))
- **Prompt injection through markdown image rendering can exfiltrate gitignored files. Remote images render from any URL, so the injected instruction makes the agent embed file contents in an image query string.** — The gitignore restriction on reading a file was bypassed by telling the agent to run cat when reads failed. Auto-run of terminal commands was on, and the host says Google wants it on by default. A report that Google might treat this as intended behavior is relayed secondhand and not verified by the host. ([5:38](https://youtu.be/KLq250wGeEg?t=338))
- **The host reports lag and battery drain on macOS while Antigravity runs, but says he cannot confirm the cause.** — Treat this as an anecdotal, unverified performance observation from a preview build. ([6:46](https://youtu.be/KLq250wGeEg?t=406))

## Techniques
- **Plan-first review gate for agent work** — Let the agent write an implementation plan before any code. The plan covers the overall goal, whether user review is needed, and the detailed proposed changes. Read it, leave comments on selected text or specific lines, and iterate until the direction is right. Set the review policy to always ask, agent decides, or always proceed based on task risk. *When:* Multi-file or risky changes where a wrong direction is costly. Use always-ask for risky work; agent-decides is fine for small, low-risk edits.
- **Browser-subagent UI self-test with visual evidence** — Prompt the agent to test a feature in the browser, for example a contact form for empty-field validation, invalid emails and successful submission. The browser subagent performs the actions, reads console logs, and saves a screenshot per check. Review the walkthrough artifact for the screenshots and optional video, not only the agent's claim that tests passed. *When:* UI or form features where a reviewer should see what the agent saw. The walkthrough is the evidence to check.
- **Agent-generated visual assets for prototypes** — Ask the agent to generate mockups with its image tool, then choose one. Ask it to generate placeholder or stock images wherever a page needs them. *When:* Early landing-page or marketing-site prototypes. The host did not claim these are production-ready assets.
- **Red-team the agent with a markdown image exfiltration test** — Plant an instruction in a repo file, such as a diagram markdown file, telling the agent to read a secret file and place its contents in an image URL query string. Point the image at a logging server and check whether the secret arrives. Also test whether a gitignore-style restriction holds when the agent can use a shell command such as cat. Keep auto-run of terminal commands off while testing. *When:* Before enabling auto-run of agent commands, or before trusting an agent IDE that renders remote images from model output. The host's demo shows the risk is real when auto-run is on.

## Hot takes
- Antigravity is 'yet another VS Code fork' with a few promising features and a half-baked preview.
- The markdown-image exfiltration issue is a real problem with auto-run on by default, and Google may treat it as intended behavior (a secondhand report the host did not verify).
- The Agent Manager's inbox and the browser subagent's self-testing are some of the host's best agent-browser experiences, but Cursor is still his daily driver.
- The host says the Mac performance problem is anecdotal and he cannot confirm it.
