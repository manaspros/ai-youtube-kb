> Apple's M5 Ultra puts neural accelerators in every GPU core, but LM Studio's bundled runtime switches them off; prefill-vs-decode math and rising memory prices decide whether to buy now or wait.

## Summary
The host argues that Apple's M5 Ultra is the strongest local AI machine shipped so far, but the software is not ready to use it. Accelerators sit in all 80 GPU cores, yet LM Studio's bundled llama.cpp runtime fails a Tensor API probe at startup and disables them, a bug filed in June and still open. He splits inference into prefill (compute-bound reading) and decode (bandwidth-bound writing), and notes the new hardware mainly speeds prefill, which matters most for agentic loops that reread context every turn. Apple's headline multipliers are its own July tests without stated model, quantization or context length, and there is no generation multiplier. The only independent M5 number he cites is a 14-inch M5 Max laptop, compared against an RTX Pro 6000. He then cites a third-party runtime, BaseRT, that reaches much higher prefill speed on an M5 Pro, and points out that the 512 GB configuration is unpriced and was pulled once before amid memory shortages. His verdict: buy on launch only if your model already fits and has been measured on M5 and your work is privacy-bound or overnight batch; everyone else should use the waiting time to fix the software setup and benchmark long prompts.

## Key ideas
- **The silicon is ahead of the software: accelerators are on every GPU core, but LM Studio's bundled llama.cpp disables them** — At startup the bundled runtime runs a Metal 4 tensor test, fails it, logs that the Tensor API is unsupported, and turns the accelerators off. The issue (LM Studio #2040, filed June 11) was still open with no assignee at recording time. The speaker says this software gap is wider than the M3 to M5 Ultra hardware gap. ([0:00](https://youtu.be/12lxN9NHuHc?t=0))
- **Base M5 Ultra specs and memory pricing** — Base model is $5,499 with 96 GB unified memory at 1.2 TB/s, about 50% more bandwidth than the M3 Ultra, with 36 CPU and 80 GPU cores. Upgrading to 256 GB costs $9,499, so the extra 160 GB works out to about $25/GB. ([0:00](https://youtu.be/12lxN9NHuHc?t=0))
- **Prefill is compute-bound and decode is bandwidth-bound, and the new accelerators only help prefill** — Prefill is one large matrix multiply over the whole prompt. Decode reloads the weights for every generated token. Bandwidth rose about 50%, so generation speed should rise roughly that much, not with the accelerators. An agentic coding loop rereads its full context every turn, which makes prefill the number that matters most for day-to-day feel. ([1:00](https://youtu.be/12lxN9NHuHc?t=60))
- **Apple's speedup claims are vague and come from Apple's own July tests** — The headline is up to 4x prompt processing versus M3 Ultra; the M5 Max LM Studio figure is up to 3.9x versus M4 Max, and there is a separate 4.3x for peak AI compute. None of these name the model, quantization or context length, and there is no generation multiplier. Apple's MLX post on M5 put writing speed nearer 20%. ([2:10](https://youtu.be/12lxN9NHuHc?t=130))
- **The only independent M5 data point comes from a laptop, and it is compared with an RTX Pro 6000** — On a 14-inch M5 Max MacBook Pro with 128 GB, a 4-bit Qwen 3.5 122B ran at 881 tok/s prefill and 65.9 tok/s generation at a 4,000-token context. On the same test, an RTX Pro 6000 Blackwell (96 GB) read prompts 3.46x faster at 4K and 2.41x faster at 32K, and generated 50% to 65% more tokens per second. ([3:23](https://youtu.be/12lxN9NHuHc?t=203))
- **Fixing the disabled accelerators roughly doubles prefill on the bundled runtime and leaves decode unchanged** — The speaker's GPT-OSS 120B measurement went from 877 to 1,833 tok/s prefill with the accelerators on, with generation flat at about 105 tok/s. A second model went from 342 to 833 prefill with generation flat. At 100K context, time to first word drops from about two minutes to about one. Upstream llama.cpp reports the Tensor API as working on the same machine, and the MLX build was never affected. ([4:29](https://youtu.be/12lxN9NHuHc?t=269))
- **A third-party runtime shows the matrix units can go much further on prefill** — BaseRT (published July 21 by three researchers) uses handwritten Metal 4 kernels aimed at prefill. On one M5 Pro across 15 configurations up to 35B parameters, it reads prompts up to 6.4x faster than llama.cpp and 3.9x faster than MLX, with generation gains of 1.75x and 1.33x. The code is public, but the evidence is a paper on one machine. ([5:34](https://youtu.be/12lxN9NHuHc?t=334))
- **Memory prices are rising, and the 512 GB configuration is still unpriced** — CounterPoint reports DRAM contract prices up 98% in Q1 and roughly 4x over three quarters. Apple raised some Mac prices by up to 20% on June 25 without changing components (MacBook Pro $1,699 to $1,999). The M5 Ultra starts $1,500 above the M3 Ultra's March 2025 launch price. The 512 GB model ships in late October with no price, expected above $10,000. Apple already pulled a 512 GB Mac Studio option once in March over the shortage. ([6:36](https://youtu.be/12lxN9NHuHc?t=396))
- **Buy-or-wait rule: buy on launch only if the model fits and is already measured, and the workload is privacy-bound or overnight batch** — If 96 or 256 GB already holds your model and someone has measured it on M5, the remaining unknown is only the software version. Shops that cannot send code out, and overnight batch jobs where time to first token does not matter, can order on day one. Everyone else should use the waiting period to set up the software correctly and benchmark. ([7:56](https://youtu.be/12lxN9NHuHc?t=476))

## Techniques
- **Benchmark prefill and decode separately** — Report prompt-processing tokens/s and generation tokens/s as two numbers. Never judge a machine by one blended figure, because the new silicon accelerates only prefill while decode tracks memory bandwidth. Use bandwidth to estimate decode, and use measured prefill to estimate how responsive an agent loop will feel. *When:* Evaluating local hardware or inference runtimes for agentic coding, where every turn resends the full context.
- **Benchmark at long context (32K tokens and up)** — Run a prefill test with a prompt of 32,000 tokens or more and record time to first token. Short 512-token benchmarks overstate how fast a machine is for long-context work. *When:* Deciding whether a machine handles real agent workloads, or comparing against another GPU at 4K and 32K.
- **Check the runtime startup log for the accelerator path before trusting any numbers** — On load, read the runtime's startup output and confirm the accelerated backend is active (for example, the Tensor API line should say it is on, not 'not supported'). Compare against an upstream build of the same runtime, and if one build disables the path, treat its numbers as invalid and blame the software, not the chip. *When:* Any local benchmark on new hardware, or any time prefill is unexpectedly slow.
- **Use the MLX build or upstream llama.cpp instead of the bundled LM Studio runtime for M5 Macs** — The speaker names an MLX build as unaffected and says upstream llama.cpp reports the Tensor API working. Load the model through one of those and confirm the startup line as above before benchmarking. *When:* Running local models on an M5 Mac while the LM Studio bundled runtime issue is open.
- **Buy-or-wait decision rule** — Check three conditions: (1) the model you need fits in the memory tier you would buy, (2) someone has measured that model on the same silicon, (3) the work is privacy-bound or overnight batch where time to first token is not critical. If all three hold, order at launch. Otherwise, use the waiting period to run the model on rented GPUs and measure long prompts. *When:* Choosing between buying new local AI hardware at launch and waiting for software and prices to settle.
- **Compare memory upgrades by price per gigabyte** — Divide each configuration's price difference by its added memory (for example, $4,000 for an extra 160 GB is about $25/GB). Track the price of the next tier before buying, since higher tiers may be unpriced at launch. *When:* Sizing a local model machine when memory is the constraint and prices are changing.

## Hot takes
- The software gap (accelerators disabled in a popular runtime) is wider than the hardware gap between M3 Ultra and M5 Ultra.
- Apple's speedup multipliers are not usable as buying evidence because they omit model, quantization and context, and no generation multiplier is given.
- Waiting carries real cost: memory prices are rising and the 512 GB configuration was already pulled once, so it may not come back.
- Most of the evidence is Apple's own tests or one laptop measurement; the speaker says no one outside Apple had measured the M5 Ultra at the time of recording.
