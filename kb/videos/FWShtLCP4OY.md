> Why Claude's Max-plan limits feel smaller: unpublished capacity fractions, per-turn overhead from CLAUDE.md and MCP servers re-billed every turn, and default high reasoning effort. Practical fixes included.

## Summary
The host describes hitting Claude Code's weekly cap on a $200 Max 20x plan and sets out to explain why the allowance feels smaller than the name suggests. His core argument is that consumer plans sell a share of a five-hour session and a weekly cap, not a published token count, so the total is set by the vendor and moves without announcement while the burn rate is set by the user's own setup. He measures a fixed per-turn floor of roughly 70k tokens (system prompt, CLAUDE.md, memory, skill descriptions and three MCP servers) that is re-read on every turn, and notes that output tokens, including extended thinking which is on by default, cost about five times input. He reports a cited measurement that dropping reasoning effort from high to medium cuts usage by about 45%, and a silent roughly 17% bump to the Max 20x weekly cap. Much of the pricing critique leans on secondhand sources: a lawsuit complaint (one five-hour session used 15% of a weekly quota) and an unnamed article and measurement. He closes with a checklist (read the floor, prune idle MCP servers, set effort per task, fetch markdown instead of HTML, write specific prompts) and says none of it matters on a light $20 plan.

## Key ideas
- **Consumer plans (Pro, Max 5x, Max 20x) do not sell tokens. They sell a five-hour session and a weekly cap, both expressed as a fraction of an unpublished total. Any published token count for these plans is someone's estimate, not an official figure.** — The total is set by the vendor and can change without notice; the burn rate is set by the user's prompts, tools and defaults. OpenAI's Codex estimate of 5 to 225 messages per five-hour window is cited as a 9x range, offered as an example of weak transparency. ([1:13](https://youtu.be/FWShtLCP4OY?t=73))
- **A fixed per-turn overhead is loaded before the first message: system prompt, CLAUDE.md, memory files and skill descriptions come to roughly 20k to 30k tokens, and each connected MCP server adds roughly 10k to 20k more. The speaker's floor was about 70k before typing a word.** — This overhead is re-read on every turn, not charged once. He estimates 50 turns means about 3.5M read tokens from overhead alone, under a dollar at the read prices he quotes, so reading is not the main cost driver. ([2:25](https://youtu.be/FWShtLCP4OY?t=145))
- **Output is the expensive side. He quotes about $10 per million input tokens and $50 per million output, and says extended thinking is on by default in Claude Code and billed as output. Reasoning tokens therefore dominate spend more than codebase context does.** — The prices are the speaker's quoted figures, not checked against a pricing page in the video. ([3:50](https://youtu.be/FWShtLCP4OY?t=230))
- **Lowering reasoning effort from high to medium is the largest user-controlled lever. He cites a measurement showing about a 45% drop in token use with no meaningful quality difference for most tasks.** — The measurement is unnamed. He says the lever has been available in Claude Code the whole time and was never announced as a cost saving. ([3:50](https://youtu.be/FWShtLCP4OY?t=230))
- **September changes shipped alongside an unannounced cap increase. The Limit Reset command clears the five-hour session once a week, and Low Priority Mode lets work continue past the session cap by drawing on the weekly allowance at lower priority. He argues the second is a scheduler rather than a refill.** — He reports the weekly Max 20x cap rose about 17% with no changelog entry. That figure comes from his own observation, not from a source he cites. ([5:10](https://youtu.be/FWShtLCP4OY?t=310))
- **The lawsuit's sharpest figure is the consumption rate. One five-hour session reportedly used 15% of a Max 20x weekly quota, which works out to about six and a half sessions (roughly 33 working hours) per week. The amended complaint puts effective Max 20x capacity at 6 to 8 times Pro, against a 10x price difference.** — The speaker explicitly does not litigate the case. He reproduces the arithmetic as a plausibility check. Anthropic moved to dismiss in August, with a hearing set for November 6. ([6:36](https://youtu.be/FWShtLCP4OY?t=396))
- **Fetch format changes the cost of a lookup dramatically. The speaker's example is an average of about 38k tokens for a raw HTML page versus about 2.8k tokens for the same page as clean markdown, roughly 13x.** — The default fetch format is what makes the difference, not the content. He says nobody told the agent to ask for markdown. ([7:34](https://youtu.be/FWShtLCP4OY?t=454))
- **GitHub Copilot's switch to metered credits shows where pricing may go. Credits moved to a penny each on June 1, promotional credits covered the transition through August, and September was the first full invoice. He cites developers whose bills rose from $29 to $750 and from $50 to $3,000.** — These are anecdotal figures he cites, with no source given. The argument is that the current percentage-based quotas hide the real per-unit cost. ([7:34](https://youtu.be/FWShtLCP4OY?t=454))

## Techniques
- **Read the floor before a session** — In a fresh Claude Code session, before typing any prompt, run the usage command and note the baseline already consumed by system prompt, CLAUDE.md, memory, skills and MCP servers. The speaker uses this number to decide whether the session should be for deep, expensive reasoning or for smaller tasks. *When:* At the start of any session on a capped plan, especially close to a weekly reset.
- **Prune idle MCP servers** — List the connected MCP servers and disconnect any not used in the last month or so. The speaker removed one unused server, which cut per-turn overhead by about 15k tokens in roughly two minutes. *When:* On any setup with several MCP servers, since each one adds 10k to 20k tokens of fixed overhead per turn whether or not it is called.
- **Set reasoning effort per task instead of leaving it on high** — Use medium for renames and for writing tests against code that is already understood, and low where it is safe. Keep high for hard debugging such as a subtle race condition. The speaker says the setting is in Claude Code and is not a default he changes globally. *When:* Every task. Effort should follow the difficulty of the work rather than the default.
- **Ask for markdown when fetching docs** — When the agent reads documentation, have it request or receive clean markdown rather than raw HTML. The speaker's measured example is about 38k tokens for HTML versus about 2.8k for markdown. He does not show the exact mechanism he used. *When:* Any documentation lookup or web fetch inside an agent session.
- **Write specific prompts with form and constraints** — State what the output should look like, what form it should take and what limits apply, so the model does not explore the codebase to work out the intent. The speaker argues this lowers cost as well as improving the result. *When:* Any ambiguous task. Vague prompts trigger expensive exploration.
- **Measure what an hour of your work costs** — Track how much of the weekly allowance a typical session uses, and compare that against the hours of useful work it produced. The speaker treats this as the only way to manage a budget that is not published. *When:* If you are on a Max plan and regularly hit the weekly cap. He says this does not matter on a light $20 plan.

## Hot takes
- The real problem is an unpublished denominator. A percentage of a number nobody publishes is not a number, so users cannot budget or optimize what they cannot measure.
- Leaving reasoning effort on high by default is the most controllable waste in Claude Code, and it was never announced as a cost issue.
- If you are on the $20 plan and code a few hours a week, none of these optimizations are worth the attention. Do not optimize a problem you do not have.
- The 17% cap increase and the reasoning-effort measurement are unsourced or secondhand. The lawsuit figures come from a complaint and are not verified. Treat the specific percentages as indicative only.
- The title (Subscription Worth Less) is more dramatic than the evidence, which is one user's measurements plus cited secondary numbers. The practical checklist is the useful part.
