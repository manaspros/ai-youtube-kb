> Tutorial on scheduling Node.js jobs with Agenda, MongoDB-backed persistence, priorities, one-off and cron schedules, a JSDOM Hacker News scraper, and Better Stack heartbeat alerts. Not AI-related.

## Summary
The video walks through Agenda, a lightweight Node.js job scheduler that stores job definitions and schedules in MongoDB so they survive restarts. It runs MongoDB in Docker, defines a trivial recurring job, and then builds a job that scrapes Hacker News with JSDOM, sorts the stories by points, and writes the top five to a JSON file. It covers job priorities, graceful shutdown with cancel, human-readable and cron intervals, and one-off scheduling with schedule and now. The last section wires a job to a Better Stack heartbeat URL so that a missed run triggers an incident and alert. Substance is practical and step-by-step, but the monitoring section doubles as a plug for the channel's own product. Nothing in the talk concerns AI or LLMs.

## Key ideas
- **Agenda persists job definitions and schedules in MongoDB, so scheduled work is not lost during application downtime.** — On restart, Agenda reads the collection and resumes the stored jobs. The presenter demonstrates this by inspecting the stored 'welcome' job with find() in mongosh. ([0:00](https://youtu.be/ZE_P7uXZm2c?t=0))
- **Defining and scheduling a job is two steps: agenda.define() registers a named handler, then agenda.every() schedules it by name.** — Intervals can be human-readable ('3 minutes', '5 seconds') or cron expressions. Calling agenda.start() first starts the job processor. ([6:32](https://youtu.be/ZE_P7uXZm2c?t=392))
- **Agenda needs a MongoDB instance; the presenter uses a Docker container, and the Node process connects with a mongodb:// URL and a DB option that also names the collection.** — Agenda is configured with a db object holding the connection address and collection name. Collection names are shown as 'agenda jobs' in the video. ([1:47](https://youtu.be/ZE_P7uXZm2c?t=107))
- **The scraper pipeline is: fetch HTML, parse with JSDOM, extract title and points per story, normalise points to integers, sort descending, and keep the top five.** — Points default to 0 when missing, using optional chaining and a fallback. Sorting uses the comparator b.score - a.score. Output is written with fs.writeFileSync as indented JSON. ([19:34](https://youtu.be/ZE_P7uXZm2c?t=1174))
- **Priorities (lowest, low, normal, high, highest) order jobs when several are due. The presenter suggests setting priority from dependencies between tasks.** — Priority is set through an options object passed to agenda.define(). The example gives the useful scrape job high priority and the placeholder welcome job lowest. ([27:01](https://youtu.be/ZE_P7uXZm2c?t=1621))
- **Shutdown should be graceful: on SIGINT or SIGTERM, stop Agenda, cancel the demo jobs so they do not persist, and exit.** — A graceful() handler awaits agenda.stop() and agenda.cancel({name}) for each job, then calls process.exit(0). ([28:15](https://youtu.be/ZE_P7uXZm2c?t=1695))
- **Heartbeat monitoring: the job pings a Better Stack heartbeat URL after successful work. If pings stop, the monitor flips the job from up to down and alerts the team.** — The heartbeat is configured with a 30-second period and a 5-second grace period. The ping goes after the file write, so it only fires on success. Alerts can be sent by email, SMS, call, or push. ([31:56](https://youtu.be/ZE_P7uXZm2c?t=1916))
- **One-off runs use agenda.schedule() with a natural-language time such as 'in 10 seconds' or 'tomorrow at noon', and agenda.now() runs a job immediately.** — The scrape job is switched from every() to schedule() and runs once, producing the output file and stopping. ([30:45](https://youtu.be/ZE_P7uXZm2c?t=1845))

## Techniques
- **Run MongoDB as the Agenda backing store in Docker** — docker pull mongo, then docker run -d --name AgendaDB with a host port mapping to MongoDB's default port (27017) and the mongo image. Verify with docker ps. Inspect data with docker exec -it <container> mongosh, then use agenda and show collections. Video does not spell out the port number, so 27017 is the default assumed. *When:* Local development of any Agenda-based scheduler, when you need persistence across restarts.
- **Minimal Agenda setup in an ES module** — npm init -y; npm install agenda; add "type": "module" to package.json (without it, the import statement fails under plain node). Create const agenda = new Agenda({ db: { address: 'mongodb://localhost/agenda', collection: '<collection name>' } }). Define with agenda.define('name', async (job) => {...}). Then await agenda.start(), and schedule with await agenda.every('5 seconds', 'name'). *When:* Starting any new Node.js job scheduler backed by MongoDB.
- **Graceful shutdown with cancel** — const graceful = async () => { await agenda.stop(); await agenda.cancel({ name: 'welcome' }); process.exit(0); }; process.on('SIGTERM', graceful); process.on('SIGINT', graceful). The cancel call removes the demo job rows from MongoDB so they do not run next time. *When:* Demo or ephemeral scripts where stored job rows should not survive the process. Production jobs may want the opposite behaviour (keep rows, only stop the processor).
- **Priority via define options** — agenda.define('scrape hacker news', { priority: 'high' }, async (job) => {...}). Valid values: lowest, low, normal, high, highest. *When:* When several jobs are due at the same time and one must run first, or when one job's output feeds another.
- **One-off and immediate runs** — await agenda.schedule('in 10 seconds', 'scrape hacker news') runs once. await agenda.now('name') runs immediately. Natural-language times are accepted, for example 'tomorrow at noon'. *When:* Single runs or delayed one-shot work, instead of a recurring every() schedule.
- **Dead-man heartbeat for scheduled jobs** — In Better Stack, create a heartbeat with a 30 s period and a 5 s grace period, and copy its URL. At the end of the job, after the work succeeds, call await fetch(heartbeatUrl). The presenter notes HEAD, GET, or POST all work. Stopping the process stops the pings, so the monitor marks the job down and alerts. *When:* Detecting silently failing or stalled periodic jobs without building your own alerting. The same pattern works for serverless functions.
- **Scraping Hacker News with fetch and JSDOM** — const html = await (await fetch(url)).text(); const document = new JSDOM(html).window.document; rows = [...document.querySelectorAll('.athing')]; for each row, title = row.querySelector('.titleline > a'); its points live in row.nextSibling, read via .querySelector('.score'). Parse points with score?.textContent.split(' ')[0] then parseInt, with 0 as the default. Sort with (a, b) => b.score - a.score, slice(0, 5), then fs.writeFileSync('topArticles.json', JSON.stringify(top, null, '\t')). The output file name is spoken as 'top articles.json' in the video. *When:* Quick structured extraction from a server-rendered page, without a headless browser.

## Hot takes
- Better Stack, the channel's own vendor, is promoted in the heartbeat section. Treat that section as a product tour rather than an independent comparison.
- Agenda's usefulness here depends on MongoDB as the single persistence layer. The video never discusses multi-process locking, duplicate runs across replicas, or retry behaviour, so treat it as an intro.
- Reviewer's note (not from the video): the video uses DOM nextSibling to find each story's score row. That is a text node on some layouts, so nextElementSibling is the safer call when reusing this pattern.
