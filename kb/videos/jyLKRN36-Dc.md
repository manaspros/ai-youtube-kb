> AI LABS walks through six new agent skills: a self-improving skill-learning log, a four-rule coding baseline, a logged-in website CLI (OpenCLI), a variant-picker for UI, and two product-business skill sets for onboarding, paywalls, churn and validation.

## Summary
The host reviews six agent skills and demos a few on a Next.js gym app backed by Supabase. The task-observer skill records lessons and suggested skill edits into a log during real work, and a human reviews them before they become part of a skill. A four-rule Karpathy-derived baseline (ask on ambiguity, minimal solution, touch only what was asked, define checks and loop until they pass) is placed in a parent-folder CLAUDE.md so every project inherits it. OpenCLI turns 100+ websites into CLI commands that reuse the user's logged-in Chrome session, with a caveat that it is for personal-account jobs, not products sold to others. The Variate skill adds a menu to swap between variants of one page section, and a set of marketing skills (onboarding, paywall, churn-cancellation) and a Gumroad-founder-derived business skill set (validate demand with 10 named people, 3 paying) round it out. Most examples are generic prototypes shown without measured results, and the video is heavy on promotion for the host's paid community.

## Key ideas
- **Skills decay because agents repeat mistakes, so a task-observer skill should capture lessons during the work instead of relying on someone to notice and edit the skill later.** — The skill writes candidate lessons and suggested skill changes into a log.md kept outside the project. A separate shared file holds rules that should apply across all of the user's skills. A CLAUDE.md line tells Claude to run the observer during sessions. Installing it per project keeps each project's lessons separate. ([0:46](https://youtu.be/jyLKRN36-Dc?t=46))
- **Learned lessons should not auto-apply to the skill; they are reviewed before promotion so one bad result does not become a permanent rule.** — The host's example: an agent tried to fetch brand logos with a tool meant for something else. The observer logged both the wrong tool and the correct logo source, and the team reviewed both before editing the skill. ([2:14](https://youtu.be/jyLKRN36-Dc?t=134))
- **The paid-funnel skills target three in-app points where apps lose people: onboarding, the paywall, and cancellation (churn).** — The set is one of 48 marketing skills from Corey. In the demo, the onboarding prototype cut a five-step, five-question signup down to a prefilled name, one new field (gym location), a preselected popular plan, and a progress bar for the rest. The host says these choices come from years of testing, but shows no numbers. ([3:41](https://youtu.be/jyLKRN36-Dc?t=221))
- **A paywall can let users sign up free, show them locked content, and then send them to pricing, a pattern a plain agent prompt will not produce on its own.** — The host argues agents lack these product principles unless they are encoded in a skill. Cancellation flow: ask for a reason, then offer a tailored alternative. Pause is the primary button and cancel is plain text underneath. ([5:58](https://youtu.be/jyLKRN36-Dc?t=358))
- **Four behavioral rules derived from Karpathy's coding advice address most agent failures, which the host says come from unrequested decisions rather than bad code.** — The rules: surface assumptions and options and ask before choosing a direction; use the simplest solution that works; match existing code and only clean up your own mess, reporting other issues instead of fixing them; and set the expected result and its check before starting, then keep working until the checks pass. ([7:07](https://youtu.be/jyLKRN36-Dc?t=427))
- **Put the base rules in a CLAUDE.md at a common parent folder rather than installing them as a skill, so every project under it inherits them and unrelated sessions do not.** — Claude Code loads CLAUDE.md files from the project and from its ancestor folders. The host keeps all coding projects in one developer folder and copies the four rules into that folder's CLAUDE.md. ([7:07](https://youtu.be/jyLKRN36-Dc?t=427))
- **OpenCLI gives the agent site commands that reuse the user's logged-in Chrome session, which is faster than browser-driving but only fits personal-account jobs.** — It has three parts: the OpenCLI tool, a Chrome extension that attaches to logged-in sessions, and skills that teach the agent to find, create, and repair commands when a site changes. The X example covers search, bookmarks, posting, and following through the user's account. The host says this should not replace official APIs for a product sold to others, and does not discuss terms-of-service or account risk. ([8:34](https://youtu.be/jyLKRN36-Dc?t=514))
- **The Variate skill lets you generate several versions of one page section and switch between them in a small menu, then send the choice back to the agent to iterate on the next section.** — The demo applies it to the hero section of a landing page in Next.js and in a plain HTML prototype. The rest of the page stays fixed while the variant changes. The host recommends it mainly for landing pages. ([10:49](https://youtu.be/jyLKRN36-Dc?t=649))
- **A minimalist-entrepreneur skill set (from Gumroad's founder, based on a book, 10 skills) starts with the customer group and tests demand before building.** — Its validation skill rejects broad answers such as 'businesses' and requires 10 named real people, with at least 3 who say they would pay before anything is built. The other skills cover MVP scope, manual work first, first customers, pricing, marketing, growth without funding, and hiring. ([12:17](https://youtu.be/jyLKRN36-Dc?t=737))

## Techniques
- **Per-project learning log for skills** — Install the task-observer skill in each project (or globally). It writes a log.md outside the project with one section per skill. Add a shared rules file for cross-skill rules, and a CLAUDE.md instruction so the observer runs during sessions. Review the logged suggestions and apply them to the skill by hand. *When:* Any team with recurring skills that drift from real work and that want a gate between noticing a lesson and making it permanent.
- **Parent-folder CLAUDE.md for base coding rules** — Copy a short set of universal rules (ask on ambiguity, simplest working solution, touch only the requested scope and report other issues, define the verification check before starting and keep going until it passes) into CLAUDE.md at the root of the folder that contains all your projects. Project-level CLAUDE.md files add to it. *When:* You want the same baseline behavior across many repos without polluting unrelated Claude Code sessions on the machine.
- **Onboarding and paywall pattern** — Signup asks only for what is needed to create the account; fill in known fields from earlier input; pre-select the most popular plan; move the rest of the setup into a persistent progress bar. Paywall: allow free signup, show some content locked with a visible upgrade path, route to pricing. *When:* Consumer or SaaS app with setup friction or a freemium conversion step.
- **Cancellation save flow** — Before cancelling, ask why the user is leaving; match a retention offer to the reason; make pause the primary button and show cancel as plain text beneath it. *When:* Subscription products where churn is measured and some cancellations are recoverable.
- **Logged-in site commands via OpenCLI** — Install the OpenCLI tool, add its Chrome extension so it can use an already logged-in browser session, and install its skills so the agent can locate, create, or repair per-site commands. Ask the agent for a clean list (for example bookmarks) instead of having it drive the page. *When:* Personal research or data pulls from sites with no usable API. Not for building a product on top of someone else's platform.
- **Variant exploration for one UI section** — Install the Variate skill and generate alternative versions of one section (hero, button, header). Use the on-page menu to switch between them. Send the chosen variant back to the agent, then generate variants for the next section and mix the winners. *When:* Landing-page or section design where the first AI-generated design is usually generic. Works in Next.js and in plain HTML prototypes.
- **Demand validation before building** — Start from groups you already belong to and the complaints they repeat. Check you can reach them without paid ads and that they already pay to solve the problem. Name 10 real people with the problem and get at least 3 to say they would pay before building. *When:* Early product ideas where the team has not yet confirmed that anyone will pay.

## Hot takes
- Title says 'actually insane'. The content is six modest, mostly generic skill demos; the framing overstates them.
- Onboarding and cancellation design choices are presented as tested over years, but no conversion, retention, or churn numbers are shown.
- OpenCLI's logged-in account reuse is pitched as a convenience. The video does not discuss account-policy or security risk of automating personal accounts.
- Heavy self-promotion (subscribe, hype button, super thanks, and a paid AI LABS Pro community) runs through the video. It is not labeled as sponsored, but it is a channel pitch for its own product.
- The four-rule baseline is useful and portable, but it is a restatement of general advice, not measured evidence that it reduces agent errors.
