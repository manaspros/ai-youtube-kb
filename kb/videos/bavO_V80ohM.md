> Andres from Better Stack runs Cactus's 16.9 MB Whistle speech-to-text model fully offline on a $10 ESP32-S3, trimming decoder layers and quantizing math to fit and speed it up.

## Summary
The video is a hands-on build: a push-to-talk voice command device on an ESP32-S3 with an INMP441 microphone and a button, running Cactus Compute's Whistle speech-to-text model with no Wi-Fi or Bluetooth. Whistle is a single 16.9 MB file covering seven languages with auto language detection, word timestamps and embeddings, and the speaker reports that it beats OpenAI's WhisperBase on LibriSpeech per Cactus's own benchmarks. The board has only 16 MB of flash, so the model does not fit as shipped; the speaker strips the decoder down to four of its eight layers, keeping the encoder whole, and leaves about 98 KB spare. He then explains the inference pipeline (mel spectrogram, 80 ms frames, encoder, language token, cross-attention) to show where latency goes. Optimizations cut a two-second command from about 24 s to about 10 s on average: batching audio frames per pass, splitting work across both cores and using 8-bit integer math. Accuracy is about 78% on synthetic English color commands, and he argues his trimmed on-chip model beats Cactus's full model on that narrow test thanks to keyword biasing and a confidence-gated retry in a second language. Code is in a linked GitHub repo, which was not part of the transcript.

## Key ideas
- **A 16.9 MB speech model can run offline on a $10 MCU, but only after trimming: the full model is larger than the board's 16 MB flash before firmware is counted.** — Whistle has an 8-layer encoder and 8-layer decoder. The encoder cannot be trimmed, but the decoder can be cut to 2, 3, 4 or more layers and each cut still works as a standalone model. ([0:00](https://youtu.be/bavO_V80ohM?t=0))
- **Whistle is a Cactus model on the same engine as Needle, released 2 Oct 2026, supporting seven languages with automatic language detection and per-word timestamps.** — The speaker says it is about 9x smaller than WhisperBase (145 MB) and beats it on LibriSpeech per Cactus's own benchmarks. Cactus ships prebuilt engines for 17 platforms but none for ESP32, so he built his own. ([0:50](https://youtu.be/bavO_V80ohM?t=50))
- **Layer trimming is a file-level operation: write a tool that keeps only the chosen decoder layers, then verify it matches the full model at the same depth and loads in the vendor engine.** — Measured sizes: the n-gram lookup tables are about 5.3 MB (roughly a third of the file), one decoder layer is about 0.5 MB. He picked four decoder layers and found it made noticeably fewer mistakes than two. ([3:36](https://youtu.be/bavO_V80ohM?t=216))
- **Audio is reduced to 80 ms frames before the encoder, so compute scales with frame count: a 2 s command becomes about 25 frames.** — Audio is 16 kHz, split into 10 ms slices, turned into mel-energy features, then a convolution stack downsamples to 80 ms frames. The encoder uses full self-attention over all frames; the decoder emits a language token first, then text via cross-attention. ([4:46](https://youtu.be/bavO_V80ohM?t=286))
- **Short phrases are recognized far more reliably than single command words on a speech model trained on full sentences.** — The speaker reports 82-93% accuracy for short phrases such as 'make it red' versus 44% for a lone color word, because a single word gives the model little acoustic context. ([8:58](https://youtu.be/bavO_V80ohM?t=538))
- **The first port took about 24 s for a 2 s command; the speaker got it to about 10 s on average with batching, dual-core splitting and 8-bit integer math on the ESP32-S3 vector unit.** — Matrix multiplication dominates runtime. He processes several audio frames per pass, splits work across both cores, and moves the heavy math to int8 on the vector unit. ([10:07](https://youtu.be/bavO_V80ohM?t=607))
- **On a narrow English and multilingual color-command test, the trimmed on-chip model beat the full model, and the gain came from decoding tricks rather than a smarter model.** — Two tricks: keyword biasing that nudges the decoder toward a list of color words when unsure, and a retry in a different language that is accepted only if its confidence is nearly as high as the first pass. Accuracy is about 78% on synthetic voices and barely changes with real microphone noise. ([10:07](https://youtu.be/bavO_V80ohM?t=607))

## Techniques
- **Decoder layer trimming for flash-constrained devices** — Write a tool that reads the full model file and writes a new one containing only the wanted decoder layers (encoder kept whole). Check the stripped model gives the same output as the full model at the same depth, then confirm the vendor engine loads it. Print a per-component size breakdown first to see where the bytes go (here the n-gram tables were the largest chunk). *When:* The model is larger than the target's flash, or you need a latency/quality trade-off on a fixed memory budget. Trade quality for depth by picking the layer count that fits.
- **Keyword biasing on a constrained command vocabulary** — Supply a list of expected command words to the decoder so it gets a small nudge toward them whenever its output is uncertain. *When:* The app is a fixed command set (colors, light modes, short actions) and recognition of rare words matters more than open transcription.
- **Confidence-gated retry in another language** — If the first transcription does not contain an expected keyword, rerun with a different language setting and accept the second result only if its confidence is almost as high as the first. *When:* Language auto-detection is unreliable on short utterances and you have a small set of expected outputs to check against.
- **Use short phrases, not single words, as voice commands** — Ask users to say a short phrase ('make it red') instead of a bare keyword ('red'). *When:* Designing voice UX on a speech model trained on sentences; a single word gives too little acoustic context.
- **Microcontroller inference speedups** — Batch several audio frames into one matrix pass, split the matmuls across both cores, and use 8-bit integer arithmetic on the vector unit instead of float. *When:* Running transformer-style models on MCUs where per-pass overhead and float math dominate runtime.
- **Push-to-talk with local feedback** — Hold a button to record, show a status LED (white while recording, dim pulse while processing), and on release run transcription and command parsing on-device. *When:* A simple offline voice input on hardware, where recording state must be visible and nothing leaves the device.

## Hot takes
- The trimmed on-chip model beats Cactus's full-size model on color commands in every language. The speaker attributes this to keyword biasing and retry logic, not model quality. The test is narrow, the voices are synthetic, and the full model's default configuration is not stated.
- Cactus's benchmark claim that Whistle beats WhisperBase on LibriSpeech is vendor-reported and was not verified in the video.
- Single words are harder for speech models than short phrases, which contradicts the intuition that one clear word is easiest to recognize.
