> Walkthrough of Graft, a free open-source CLI that builds a code knowledge graph and hooks into Claude Code to cut search turns, tokens and cost; the benchmark is self-reported by its makers.

## Summary
The host argues that default agent file search (grep-style keyword tools, multi-turn narrowing) resends the growing conversation on every tool turn, which burns usage limits and degrades focus. He dismisses vector search as a fix because semantic similarity cannot tell that account creation and deletion are opposites. Graft instead builds a knowledge graph of code parts (nodes) and their dependencies (edges), stored as JSON with a browser viewer, and updates only changed parts. It installs with an init command per project plus three Claude Code hooks: session-start instructions, per-prompt matching of up to three locations, and a post-edit map refresh. Graft also offers an MCP mode where the agent queries the graph on demand. The team's own benchmark over 162 runs reports 60% less time, 46% fewer tool calls, 42% fewer tokens and 32% lower cost, with savings growing on larger projects. In a booking-app test with Fable 5.1, a build took 39 minutes and about 31% of context with Graft versus 47 minutes and 35% without, and a landing-page change took under two minutes. Graft maps only code, so PRDs and notes still use default search; the team's paid community tier carries a variant for multi-plan-file projects.

## Key ideas
- **Default agent search costs tokens every turn** — Each search tool call sends the whole conversation plus prior tool results back to the model, so multi-step narrowing grows the context and slows the model. The host ties this to hitting usage limits and to lower output quality. ([1:25](https://youtu.be/cyIWQHYoUg8?t=85))
- **Vector search misses how code connects** — Embedding-similarity search matches meaning, not dependency. Account-creation and account-deletion code both match an 'accounts' question but do opposite things, so picking the wrong hit is costly. ([2:52](https://youtu.be/cyIWQHYoUg8?t=172))
- **Graft models the codebase as a graph of nodes and edges** — It records each part with its name and location (node), then which parts use which (edge). Impact questions are answered by following edges, so the agent can see what a change could break. No embeddings and no separate model API key are needed, so it runs on the existing subscription. ([2:52](https://youtu.be/cyIWQHYoUg8?t=172))
- **Per-prompt matching attaches locations before the first tool call** — On each prompt, Graft matches the message words against the map and attaches up to three matching locations. Code enters context only when the agent reads those lines, which means fewer turns. The speaker notes this guesses from the prompt and attaches results whether or not they are needed. ([6:52](https://youtu.be/cyIWQHYoUg8?t=412))
- **CLI injection and MCP are two lookup modes** — The CLI pushes matches into every prompt, while MCP lets the agent ask only when it needs something. In Graft's own tests MCP got a few more answers right and the CLI was faster. Installing gives both. ([6:52](https://youtu.be/cyIWQHYoUg8?t=412))
- **The map stays fresh without the model** — A post-edit hook updates the map after Claude edits a file. Before answering a question, Graft checks whether code changed since the last build and re-indexes first. Re-indexing does not use the LLM. ([6:52](https://youtu.be/cyIWQHYoUg8?t=412))
- **Savings grow with project size and are self-reported** — The team's 162-run benchmark reports 60% less time, 46% fewer tool calls, 42% fewer tokens and 32% lower cost on average. The host says savings scale with project size because small projects have little searching to save. The headline claim is 'four times cheaper' in tokens, which does not match the 42% figure. ([4:03](https://youtu.be/cyIWQHYoUg8?t=243))
- **Long autonomous builds need a PRD and a CLAUDE.md template** — For Fable 5.1, the host wrote a PRD, filled a CLAUDE.md template from it, and told the model explicitly that it works autonomously and must not stop to ask permission. The Graft build then finished in 39 minutes versus 47 without it. ([9:45](https://youtu.be/cyIWQHYoUg8?t=585))
- **Graft only maps code, so non-code context uses default search** — PRDs, area notes and learnings.md files are not mapped, so the agent still searches them the old way. The team built a variant for multi-plan-file projects and put it in its paid community tier. ([11:02](https://youtu.be/cyIWQHYoUg8?t=662))

## Techniques
- **Code knowledge graph for impact-aware retrieval** — Index the repo as nodes (named code parts with file and line location) and edges (which part uses which). Answer 'what uses X' by traversing edges, and 'what could this change break' by walking dependents. Store as JSON and keep it incremental by re-indexing only changed files. *When:* Agent sessions on a mid-to-large codebase where grep-style search takes several turns per change, and where semantic similarity returns plausible but wrong files.
- **Pre-prompt context injection via a UserPromptSubmit hook** — On each user prompt, match the prompt's words against the graph index and inject up to 3 matching file:line locations into context, so the agent reads the right lines on turn one. Only the lines it then reads enter the context window. *When:* Repeated edit-style requests where the target location can be inferred from the prompt. Monitor false positives, because the lookup is guess-based.
- **Hook trio for a Claude Code workflow** — Use three hooks: a session-start hook that gives the model the index-usage instructions; a per-prompt hook that injects matches; and a post-edit hook that refreshes the index after Claude edits a file. Graft's init installs these for Claude Code. *When:* When a coding-agent workflow must be enforced by the harness rather than relying on the model to follow instructions.
- **Pick CLI injection or MCP on-demand lookup** — CLI mode pushes matches into every prompt, which is faster. MCP mode lets the agent query only when it decides it needs context, which avoids noise. Graft's own test found MCP slightly more accurate and the CLI faster. *When:* Choose CLI for speed on routine edits; choose MCP when accuracy on ambiguous questions matters more than latency.
- **Long autonomous run setup for a token-hungry model** — 1) Write a PRD of features. 2) Keep a CLAUDE.md with run instructions; have the model fill its gaps from the PRD. 3) Tell the model explicitly that it is working alone and must not stop to ask permission. 4) Give the build prompt and the tool choices. If no PRD exists, describe the app in the prompt instead. *When:* Single long build sessions where the model should finish a whole app without check-ins and token use must be controlled.
- **Install and initialize Graft in a Claude Code project** — 1) Install via the command on Graft's site, or paste its setup prompt into the agent. 2) cd into the project folder and run the init command (it asks for the coding agent and picks Claude Code). 3) Init adds a graph skill file to the project folder and installs the hooks. 4) For an existing project, run the build command in the same folder. For an empty project, the skill builds the map once files exist. 5) Open the browser map viewer to inspect nodes and edges. The transcript does not name the viewer command, the installer URL, or the exact init and build flags. *When:* Adopting Graft in a new or existing repo that uses Claude Code.

## Hot takes
- The 'four times cheaper' headline does not match the team's own 42% token and 32% cost numbers. Treat the headline as marketing.
- The benchmark is self-reported by the tool's makers, and the video gives no task set, baseline agent config, repo size or variance. Single-app timing (39 vs 47 min) is an anecdote.
- The video says graph retrieval beats vector search but shows no retrieval-accuracy comparison against vector or grep baselines.
- The per-prompt injection is admitted to guess from prompt words and attach results whether or not they are needed. The noise cost is not measured.
- About one minute is a Hydra sponsor read. The paid community tier upsell for the non-code variant is a plug. The core content is still substantive, so no quality cap applies.
