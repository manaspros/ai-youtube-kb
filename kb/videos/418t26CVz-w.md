> NYT engineers on running small agents on-device inside mobile games, under per-frame time, memory and battery budgets, with live accessibility tuning through graded dials instead of fixed menus.

## Summary
Two New York Times speakers present experimental work on local, on-device agents for games, stressing that NYT puzzles themselves contain no AI. They contrast reinforcement learning, which changes model weights, with agents that reason over game state in context and act through tool calls. A demo Space Invaders agent runs a perceive, predict, decide, act loop, and a constraint-satisfaction agent solves mini crosswords by backtracking. The main on-device limits are memory, a 16 ms frame budget at 60 Hz, and battery, handled with a constraint graph that penalizes time overruns more softly than memory overruns. The second half argues for adaptive accessibility: grounded in WCAG 2.2, the agent tunes graded dials (input tolerance, step granularity) from live signals such as gaze, shaky taps and focus loops, and can inject exit routes or resize tiny targets. The closing open problems are sub-frame planning, predicting layout changes before applying them, per-user long-term memory, a shared game-state language, and honest benchmarks. Overall this is a conceptual showcase with little measured data.

## Key ideas
- **Run agents on-device instead of in the cloud** — Cloud inference adds round-trip latency and cost. On-device inference keeps data private, still works offline (for example in a subway), and makes personalization easier. ([2:22](https://youtu.be/418t26CVz-w?t=142))
- **Agentic play differs from RL** — RL changes model weights through many training cycles. An agent instead uses a language model with in-context reasoning over the game state and tool calls on the device, so it adapts to new situations without retraining. ([5:43](https://youtu.be/418t26CVz-w?t=343))
- **Per-frame perceive, predict, decide, act loop** — The demo Space Invaders agent perceives the scene, predicts the next enemy move, decides, acts, and then loops. The speaker calls this a simple agent running on a small on-device model. ([7:48](https://youtu.be/418t26CVz-w?t=468))
- **Three budgets constrain on-device agents: space, time and energy** — Space covers model weights, state history and planning artifacts, plus render headroom. Time means fitting planning into a 16 ms frame. Energy means battery life, since phones are not yet tuned for agent workloads even with NPUs. ([8:51](https://youtu.be/418t26CVz-w?t=531))
- **Soft versus hard penalties in a constraint graph** — The team penalizes over-focus on one budget, applies soft constraints where small overruns are acceptable (memory), and penalizes time overruns more firmly because they disrupt the user experience. ([9:55](https://youtu.be/418t26CVz-w?t=595))
- **Constraint satisfaction with backtracking for crosswords** — A mini-crossword agent places words under a constraint graph. When constraints get too crowded or wrong, it backtracks efficiently and uses natural language from the graph to find a correct layout. ([11:18](https://youtu.be/418t26CVz-w?t=678))
- **Accessibility as graded dials, not a checkbox** — Building on WCAG 2.2's perceivable, operable, understandable and robust pillars, the speakers propose tuning graded dials per player. WCAG 3.0 (draft) moves to bronze, silver and gold scoring, and they argue games should follow the same shift. ([12:59](https://youtu.be/418t26CVz-w?t=779))
- **Live adaptation through focus monitoring and layout auditing** — The agent watches the focus path to detect keyboard traps and injects an exit route. It also measures the interface and resizes tiny targets on the fly, so the layout adapts to the player. ([15:28](https://youtu.be/418t26CVz-w?t=928))
- **Open problems for local game agents** — Plans must fit a 16 ms frame. Models should predict the effect of a layout change before applying it. Long-term per-user memory, a shared game-state language across titles, faster chips and honest benchmarks are still needed. ([16:32](https://youtu.be/418t26CVz-w?t=992))

## Techniques
- **Per-frame perceive-predict-decide-act agent loop** — Split the agent into a few explicit states, each a small on-device model call, and run the loop within the frame budget. *When:* Real-time game or UI agents that must respond within a fixed frame time.
- **Constraint graph over space, time and energy** — Model each resource as a constraint node. Use hard or soft penalties depending on how much an overrun harms the user experience, and avoid over-focusing on one resource. *When:* Resource-limited on-device agents with several competing budgets.
- **Constraint satisfaction with backtracking** — Represent placements as a constraint graph, detect when constraints become too crowded or incorrect, backtrack, and use natural-language explanations from the graph to guide the retry. *When:* Puzzle or layout problems with many interdependent choices, such as crosswords.
- **Graded accessibility dials driven by live signals** — Define continuous controls such as input tolerance and step granularity. Set them from live cues (gaze, shaky taps, focus loops, handwriting) and move them together. *When:* Adapting an interface to a user's needs in real time instead of offering a fixed easy mode.
- **Live focus-path monitoring and layout auditing** — Track the focus or tab order to flag loops, inject an exit route, and measure controls at runtime to resize targets that are too small. *When:* Interfaces where keyboard, switch or fine-motor users can get trapped or miss small targets.

## Numbers
- Frame budget of about 16 ms per frame at a 60 Hz refresh rate for fitting agent planning ([8:51](https://youtu.be/418t26CVz-w?t=531))
- WCAG 2.2 has four pillars (perceivable, operable, understandable, robust); WCAG 3.0 draft moves from pass/fail to bronze, silver, gold ([12:59](https://youtu.be/418t26CVz-w?t=779))
- Efficient Zero and Efficient Zero V2 are described as sample-efficient RL models that learn from much less data than traditional RL. No figures given. ([5:43](https://youtu.be/418t26CVz-w?t=343))

## Hot takes
- Accessibility and challenge should be two ends of one continuously tuned dial, not separate features.
- Games should move from fixed easy modes and toggles to graded, live-adjusted accessibility, as WCAG 3.0 does for web accessibility.
- The future of AI is many small local models, each shaped by one person, rather than one centralized brain.
