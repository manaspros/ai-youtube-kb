> Better Stack demos an unreleased Claude Code "agent swarm" mode, hidden behind a flag, where an orchestrator spawns specialized sub-agents on the fly, then argues Anthropic is unlikely to ship it soon as-is.

## Summary
The video says Claude Code contains a hidden agent-swarm mode in which a team-lead orchestrator dynamically creates specialized sub-agents for a task, instead of the user hand-authoring them. The presenter found it via a flag surfaced on Twitter by Mike Kelly, who shared a fork of CC Mirror called "Claude Sneak Peek". In the demo, the presenter gives the tool a plan file for a small X/Twitter video-download web frontend, has it create tasks, then has it execute them, and the orchestrator spins up a QA tester, backend builder, component builder and front-end builder, growing to eight agents. At the end it produces a project-complete file and a swarm execution report listing agent roles and completion status. The presenter's critique is that the feature probably has less training than Kimi K2.5's orchestrator, and that dynamic creation gets hard when a user already has custom sub-agents and skills, because the orchestrator would need data to decide between reusing and creating agents. The last ~1.5 minutes are a sponsored plug for Better Stack log monitoring and error tracking.

## Key ideas
- **Custom sub-agents are manual: you define each one's role, skills, tools and permissions, and they start with a fresh context each time.** — The presenter describes the common workaround of having sub-agents write findings to a markdown file and update a shared context file so later agents can pick up where others stopped. This is the baseline the swarm mode is meant to replace. ([0:00](https://youtu.be/eRu5kIYAAz8?t=0))
- **Claude Code's orchestrator can create sub-agents itself, based on the task, which is the core difference from the manual approach.** — Per the presenter, the orchestrator spawns a specialized sub-agent for each subtask, runs them in parallel, and can spin up new ones using the returned data. Kimi K2.5's swarm, which he says can spawn up to 100 agents, is the reference point, and he frames it as still a research project. ([1:17](https://youtu.be/eRu5kIYAAz8?t=77))
- **The feature is hidden behind a flag and was surfaced by a user on Twitter, not announced by Anthropic.** — Mike Kelly's tweet showed it working and linked a fork of CC Mirror called Claude Sneak Peek, which the presenter installed and ran as a minimal Claude Code-like interface. ([2:24](https://youtu.be/eRu5kIYAAz8?t=144))
- **Plain task fan-out already exists, but the sub-agents are general-purpose, not specialized.** — The presenter notes that the task feature can create a task list and fan it out to sub-agents, but he is not sure Claude auto-assigns tasks to matching custom sub-agents. This is the gap the swarm mode is said to close. ([1:17](https://youtu.be/eRu5kIYAAz8?t=77))
- **In the demo, the swarm created role-specific agents on its own and showed their status in a team view.** — A plan file for a web frontend for an X/Twitter video downloader was turned into tasks. The team lead, QA tester, backend builder, component builder and front-end builder ran at once, and the list grew to eight agents (adding a components creator, API server, Vite setup, API integration, CSS). Each agent's system prompt was viewable. ([2:24](https://youtu.be/eRu5kIYAAz8?t=144))
- **The run ends with a summary artifact: a project-complete file and an execution report.** — The execution report lists the specialized agents used, their roles, and whether each completed its task. Full per-agent activity can be scrolled through in the main view. ([3:51](https://youtu.be/eRu5kIYAAz8?t=231))
- **Dynamic sub-agent creation gets hard when users already have agents and skills.** — The presenter asks how the orchestrator would decide between creating a new front-end agent and reusing an existing one, what data it would use to judge, and whether it would pick up user-installed skills or download its own. He says it would need to inspect existing agents, tools and skills before deciding, which is why he thinks Anthropic may not ship it as is. ([5:14](https://youtu.be/eRu5kIYAAz8?t=314))
- **The demo is a single run, and the presenter's reasoning about Anthropic's motives is speculation.** — He thinks Anthropic built the feature in response to open implementations, not copying Kimi, and says he does not know whether it is still being worked on. No benchmarks or repeated runs are shown. ([2:24](https://youtu.be/eRu5kIYAAz8?t=144))

## Techniques
- **Plan-file to swarm execution (reproducing the demo)** — 1) Write a plan markdown file describing the project. 2) In the (flagged) Claude Code build, ask it to read the plan file and create tasks that sub-agents can execute. 3) Confirm the task list. 4) Ask it to execute the tasks using sub-agents. The orchestrator creates the specialized agents itself. The video shows no exact prompts or flag names; it names only the 'agent' slash command, used to confirm no custom sub-agents exist before the run. *When:* To test whether an orchestrator-created team of role-specific agents beats a general-purpose task fan-out on a multi-part build. Requires the flagged build, which is not an official release.
- **Checking existing sub-agents before a swarm run** — Run the agent slash command to list custom sub-agents, so you know whether the orchestrator will reuse or create agents. In the team view, press down to see teammates' current activity, press enter on one to open its system prompt, and press enter on the team lead to return to the main orchestrator view. *When:* When you want to inspect what an auto-spawned team is doing and what prompt each member got, or to compare against your hand-defined sub-agents.
- **Manual sub-agent memory via shared markdown files** — Have each sub-agent write its findings to a markdown file and update a main context file. A later agent, or the same one, reads these files to see where others stopped. The presenter describes this as the way people fake memory across sub-agents today. *When:* When running hand-defined sub-agents that do not share context, to hand state from one agent run to the next without an orchestrator.

## Hot takes
- The presenter thinks Anthropic did not copy Kimi and built the feature in response to open implementations. He gives no evidence for this.
- The feature is probably unreleased because dynamic sub-agent creation is hard to get right once users already have custom agents and skills.
- Kimi K2.5's orchestrator has had far more training than this Claude Code version, so the comparison is not like-for-like.
- Quality is capped at 2 because the last ~1.5 minutes are a sponsored Better Stack plug, and the substance is one unrepeated demo with no prompts, flags or benchmarks.
