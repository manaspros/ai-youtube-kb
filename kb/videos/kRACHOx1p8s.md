> Better Stack demos MemPalace, a local tool that stores coding-agent conversations verbatim and exposes them to Claude Code over MCP so decisions persist across sessions.

## Summary
Better Stack walks through MemPalace, an open-source local memory tool for Claude Code and other MCP-capable agents, pitched as a fix for agents forgetting past decisions. The core design choice is to store the original conversation text word for word in ChromaDB and build a compact index above it, instead of asking an LLM to distill facts, so edge cases and the reasons behind decisions survive. The demo installs the package with uv, initializes a palace in a project, mines project files and past Claude Code sessions, and asks why the team moved to GraphQL, retrieving the original discussion. A Claude Code plugin starts an MCP server and teaches Claude to search the palace before answering questions about past work. The presenter positions it as complementary to context mode (which manages in-session context size) and better than hosted SDK-style memory products for local developer use. Caveats: local databases need manual backup, cleanup and migration, there are no admin dashboards or permissioning, and the viral project has lookalike domains, so install only from the official repo, Python packaging and doc site.

- **The demo flow is install, initialize a palace in a project, mine project files and old Claude Code sessions, then search in natural language.** — Real project context is spread across commits, docs, chats, notes and markdown files, so the tool mines all of them. A search for why the team switched to GraphQL pulls the older discussion where that decision was made. ([1:26](https://youtu.be/kRACHOx1p8s?t=86))
- **Verbatim storage with a compact index beats LLM-summarized memory for recall of edge cases and rationale.** — Most memory systems turn conversations into clean facts, and a summary can drop a constraint or the reason behind a decision. MemPalace keeps the original text intact and indexes it so the agent can find the right area first. The presenter frames this as the main contrast with other tools. ([2:25](https://youtu.be/kRACHOx1p8s?t=145))
- **Architecture is local and developer-oriented: ChromaDB on disk for retrieval, SQLite for a knowledge graph, an MCP server for agent access, and Claude Code hooks for workflow integration.** — The Claude Code plugin starts the MCP server, exposes its tools, and teaches Claude a memory protocol so it searches the palace before answering questions about past work. The presenter says the difference from a database that merely exists is that the agent knows when to look. ([3:25](https://youtu.be/kRACHOx1p8s?t=205))
- **A temporal knowledge graph helps with software decisions that expire, such as an API choice that was right a few months ago and is wrong now.** — Memory is framed as being about time as well as facts. ## Techniques
- **Verbatim store plus compact index** — Keep the original conversation and document text word for word in chunks on disk, and build a small index above it so retrieval finds the right region without summarizing away the source. Retrieve the original wording rather than a distilled fact. *When:* Decisions where constraints, edge cases or the reasoning behind a choice matter more than a clean summary of what was decided.
- **Local project memory setup** — Install with uv (spoken as: uv tool install mempalace; the presenter notes pip also works). Run the tool inside the project folder to create a local palace. Mine the project folder (notes, docs, commits, markdown), then mine past Claude Code session logs. Query with a natural-language question. Exact init and mine subcommand syntax is spoken rather than shown on screen, so confirm it against the project readme before running. *When:* A project whose context is scattered across commits, docs, markdown notes and old agent chats that you no longer remember writing.
- **Claude Code plugin with a memory protocol** — Install the MemPalace Claude Code plugin so it starts the MCP server, exposes the memory tools, and adds instructions telling Claude to search memory before answering questions about past work. *When:* Any Claude Code workflow where the agent should check prior decisions before answering, instead of relying on the user to paste history into the prompt.
- **Run alongside context mode** — Use context mode to keep one long coding session within the context window, and use MemPalace for recall across separate sessions and days. The presenter says they run together without conflict. *When:* Long single-session coding work combined with recurring multi-day work on the same project.
- **Load pointers instead of project lore** — Give the agent a small set of pointers into memory and let it search on demand, rather than pasting a large project history into every prompt. *When:* Projects whose accumulated context would consume a large share of the prompt if included each time.
- **Install hygiene for memory tools** — Install only from the official GitHub repo, the Python packaging listing and the documentation site named in the readme. Treat the memory store as part of the dev environment and plan backups, cleanup and migration of the local databases. *When:* Adopting any viral developer tool that reads and stores project history.

## Hot takes
- Verbatim storage beats LLM-distilled memory for recalling constraints and rationale. Reasonable as a design argument, but the video shows no benchmark comparing recall quality.
- The 'Stop Forgetting' title overstates the case. The presenter's own caveats say local databases need maintenance and there are no admin tools.
- The 52,000-star figure is used as a credibility signal without verification.
- MemPalace is complementary to context mode, not a replacement, so you can run both.
- A viral developer tool with lookalike domains should be installed only from official sources, and memory stores should be treated as part of the dev environment.
