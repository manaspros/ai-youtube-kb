> A practitioner comparison of LangGraph, the OpenAI Agents SDK and the Claude Agent SDK: the architectures have converged, but licensing, billing, language support, version stability and data-retention terms are what should drive the choice.

## Summary
The speaker, Kai, compares LangGraph, the OpenAI Agents SDK and the Claude Agent SDK after months of building with each. He defines a "harness" as everything around the model (tool loop, memory, routing, multi-agent wiring) and uses a workshop analogy: LangGraph is an empty unit you wire yourself, the OpenAI SDK is a serviced unit, and the Claude Agent SDK is a fully equipped shop because it ships the production coding agent as a library. He argues GitHub stars are meaningless here, since the dead AutoGen leads on stars. He cites a vendor breakdown to claim that every framework implements handoffs as an ordinary tool call over an explicit graph, so the architectural differences are smaller than marketing suggests. The real differences he identifies are version stability (LangGraph at 1.0, OpenAI SDK at 0.22, Claude Agent SDK at 0.2.x), language support (the Claude Agent SDK is Python and TypeScript only), latency overhead, and the usage terms. The most important finding is his reading of Anthropic's documentation: third-party products cannot offer Claude.ai login or subscription rate limits without approval, and a planned billing change was paused. He also notes that managed agents are not eligible for zero data retention or a HIPAA BAA. He closes with a decision rule based on how far the task is from what the models were trained on, plus concrete picks per use case.

## Key ideas
- **Stars track hype, not usefulness.** — Claude Agent SDK Python has about 8,000 stars and the TypeScript one about 1,700, while LangGraph has about 28,000. AutoGen, with no meaningful commit since April, leads with over 60,000. The speaker says to judge on version numbers, language support and terms instead. ([3:10](https://youtu.be/8C3LB6TPxwk?t=190))
- **Handoffs are plain tool calls in every framework.** — A vendor breakdown (Arcade, which sells a tool-auth product) found each handoff is a tool call named something like 'transfer to agent X'. LangGraph, Google's ADK and Microsoft's new framework all converged on an explicit graph over shared state. LangChain's middleware runs inside the compiled graph, not a separate runtime. ([4:27](https://youtu.be/8C3LB6TPxwk?t=267))
- **Version stability differs sharply.** — LangGraph has crossed 1.0, so breaking changes need a major bump. The OpenAI Agents SDK is at 0.22 after about 18 months public, and any minor bump can break you. The Claude Agent SDK is at patch 152 of 0.2 and is not yet stabilized enough for a 1.0 label. ([5:40](https://youtu.be/8C3LB6TPxwk?t=340))
- **Checkpointing claims in comparison articles are out of date.** — The speaker says the OpenAI SDK added resume via run state and saved snapshots in 0.14, durable staged input in 0.20, and checkpoint terminology by 0.22. He still rates LangGraph's checkpointing as better, with typed state, per-field reducers and a swappable Postgres checkpointer. ([7:03](https://youtu.be/8C3LB6TPxwk?t=423))
- **Language support is a hard constraint for non-Python/TS stacks.** — The Claude Agent SDK supports only Python and TypeScript. Anthropic's documented workaround for other languages is to run the CLI as a subprocess and parse its JSON output. Google's ADK ships native support for four languages. ([8:11](https://youtu.be/8C3LB6TPxwk?t=491))
- **Latency overhead can matter for customer-facing paths.** — One developer measured about 10 seconds with the Claude Agent SDK against sub-second on a lighter framework for a comparable task. The speaker calls it a single anecdote, but says to test latency early. ([8:11](https://youtu.be/8C3LB6TPxwk?t=491))
- **The terms of use are the real decision for product builders.** — Per the speaker's paraphrase of the Claude Agent SDK overview, third-party products cannot offer Claude.ai login or subscription rate limits without Anthropic's approval, so they must use API-key auth. There is also a branding restriction on the name 'Claude Code'. A June 15 switch of third-party SDK usage from subscription limits to a dedicated monthly credit was paused, with no replacement announced. ([11:23](https://youtu.be/8C3LB6TPxwk?t=683))
- **Managed tiers may be ineligible for compliance regimes.** — The speaker says Anthropic's managed agents docs state they are not currently eligible for zero data retention or a HIPAA business associate agreement, because they are stateful by design. For healthcare, fintech or legal workloads, he says this alone settles the evaluation. ([12:47](https://youtu.be/8C3LB6TPxwk?t=767))
- **Pick a harness by how in-distribution your task is.** — Harrison Chase's rule, as the speaker relays it: the more your task resembles what the model was trained on, the better an off-the-shelf harness works. Coding, computer use and filesystem work are in-distribution for Claude. Domain workflows such as claims triage or refund policies are out of distribution, so wire your own infrastructure. ([14:10](https://youtu.be/8C3LB6TPxwk?t=850))

## Techniques
- **In-distribution test for harness choice** — Score the task by how close it is to coding, computer use or filesystem work. Close: use the vendor's full harness (for Claude, the Claude Agent SDK). Far: build on a low-level, explicit-graph framework and own the infrastructure. *When:* Before choosing a framework for a new agent product.
- **Pick by constraint, not by benchmark** — Claude models with API-key auth and coding or computer-use work: Claude Agent SDK. OpenAI models and need to be running fast: OpenAI Agents SDK, with the version pinned. Multi-step process with a human approval gate that cannot restart from zero: LangGraph, which is the only one of the three at a stable 1.x. *When:* When the decision needs a short, defensible rationale.
- **Read the terms section before building** — Read the overview and terms pages, not just the getting-started guide. Check the auth model (API key vs claude.ai login), subscription-limit use, branding rules, billing changes, and whether managed tiers are eligible for zero data retention or a HIPAA BAA. *When:* Before committing a product to a vendor SDK or managed tier, and before any compliance review.
- **Verify checkpoint and resume claims against release notes** — Check the framework's changelog for resume, run-state and checkpoint entries by version, rather than relying on comparison articles. Confirm durable state survives serialization. Plan a Postgres-backed checkpointer if in-memory is not enough. *When:* When comparing durable execution or resume support across frameworks.
- **Measure latency on a representative task early** — Run one representative agent task on each candidate and time end-to-end latency, including the harness's context management overhead, before building on top of it. *When:* When the agent is customer-facing or latency-sensitive.
- **Trace handoffs as tool calls** — Since every framework the speaker checked implements agent-to-agent handoff as a tool call named like 'transfer to agent X', detect those tool names in traces to reconstruct the agent graph across frameworks. *When:* When observing or auditing multi-agent systems built on mixed frameworks.

## Hot takes
- GitHub stars track hype timelines more than usefulness; AutoGen leads on stars despite being effectively dead.
- The architectural differences between the major agent frameworks are much smaller than the marketing suggests; the leases (terms, billing, data retention) are what diverge.
- For product builders, the Claude Agent SDK's auth and branding terms are a product decision to make before building, not after.
- The Claude Agent SDK is the strongest option for coding, computer use and filesystem work, but narrow outside that slice.
- Managed agents' statefulness can rule them out entirely for regulated workloads.
