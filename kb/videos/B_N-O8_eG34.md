> Walkthrough of TSRX, a statement-based JSX syntax from the creator of Ripple that compiles to React, Preact, Solid, Vue and Ripple. The presenter likes several control-flow ideas but will stay with React and Tailwind.

## Summary
The video introduces TSRX, a component syntax from the creator of Ripple that replaces the return-based JSX pattern with statement-based markup and compiles to several frameworks through a build plugin. The presenter walks through its main features: no return statement, if/else and switch as plain statements, for...of loops for lists, try/catch and a pending block for error and async boundaries, and hooks placed anywhere that the compiler hoists to the top of the generated function. It also covers scoped style blocks with a style keyword for sharing styles, quoted or template-literal text with text and html keywords for escaping or raw HTML, lazy destructuring with an ampersand prefix that keeps reactivity, and prop shorthand. The verdict is mixed: the presenter finds several features cleaner than React, but considers TSRX too niche and too late in an era where AI writes mostly JSX and React, and adds compiler magic that is harder to debug. The video is a qualitative feature tour with no benchmarks.

## Key ideas
- **TSRX is a new component syntax from the Ripple creator. It uses statement-based markup, not return-based JSX, and compiles to React, Preact, Solid, Vue and Ripple through a build plugin (the transcript mentions a Vite plugin).** — Files use a .tsrx extension and components are declared with the component keyword. Compilation is a build step that the presenter says is easy to set up. ([0:00](https://youtu.be/B_N-O8_eG34?t=0))
- **Markup renders where it is written, so a component reads linearly from top to bottom. A bare return is allowed only for early exit.** — The presenter notes this makes it harder to see at a glance what a component renders compared with jumping to a return statement in React. ([1:24](https://youtu.be/B_N-O8_eG34?t=84))
- **Conditional rendering uses ordinary if/else-if/else and switch statements with JSX as the statement body, avoiding the nested ternaries that JSX branches often require.** — The presenter finds complex conditions easier to read, but says simple single conditions get more verbose. ([1:24](https://youtu.be/B_N-O8_eG34?t=84))
- **List rendering drops .map in favour of a for...of loop that exposes index and a stable key, with continue to skip items. Only for...of is supported, not for-in, while or do-while.** — The presenter says they will keep using .map, filter and similar methods because they are used to them. ([2:26](https://youtu.be/B_N-O8_eG34?t=146))
- **Error boundaries are plain try/catch blocks. Async boundaries add a pending block whose body is the loading UI, and the compiler maps it to lazy in React, Preact and Solid, or the Ripple equivalent.** — Both constructs are presented as using normal JavaScript rather than framework APIs. ([3:30](https://youtu.be/B_N-O8_eG34?t=210))
- **Hooks can be placed after conditions and early returns and inside loops, because the compiler hoists every hook to the top of the generated function so React still sees a stable order. The presenter sees this as compiler magic that could make debugging harder.** — This is the feature the presenter says they struggle most to accept, given years of React habits. ([3:30](https://youtu.be/B_N-O8_eG34?t=210))
- **Every nested element and each if, for, switch or try block has its own lexical scope, so repeated const names in sibling blocks do not collide.** — This supports the co-location goal of keeping declarations next to the markup that uses them. ([4:28](https://youtu.be/B_N-O8_eG34?t=268))
- **A style block inside a component is scoped to that component through a hash on the class name. Styles are shared by passing a style name through the style keyword to a child that accepts className. The presenter prefers Tailwind and sees global selectors as messy.** — A child without its own style block does not inherit the parent's scoped styles. ([4:28](https://youtu.be/B_N-O8_eG34?t=268))
- **Lazy destructuring uses an ampersand before the props parameter. The destructured names compile to property lookups at each use, so signal reactivity still triggers updates in Ripple and Solid.** — The presenter describes this as keeping destructuring ergonomics without losing per-access reactivity. ([6:42](https://youtu.be/B_N-O8_eG34?t=402))
- **The presenter's verdict is that TSRX is too niche and arrives too late, since AI tools are strongest on JSX and React. Claude wrote working TSRX demos from the site's llms.txt alone, but the presenter will stay with React.** — They expect people coming from Svelte, and existing Ripple users, to like it more than React developers. ([7:57](https://youtu.be/B_N-O8_eG34?t=477))

## Techniques
- **Statement-based conditional rendering** — Write if / else if / else as statements with the JSX for each branch in its body, and use a normal switch with case blocks that each render markup. No ternaries and no wrapping in a function. *When:* Use it when a branch has several conditions or nested cases, where a nested ternary chain in React would be hard to read. The presenter says simple single conditions are more verbose this way.
- **for...of list rendering with key and index** — Loop with for...of over the collection and use the loop's index and stable key to render each item. Use continue to skip items. for-in, while and do-while are not supported. *When:* Use it if you prefer imperative flow close to vanilla JavaScript. The presenter prefers .map and filter, so it is a matter of taste.
- **try/catch error boundary plus pending block for async** — Wrap markup in try/catch for an error boundary. Add a pending block containing the loading UI for an async boundary. The compiler lowers it to lazy in React, Preact and Solid. *When:* Use it when you want error and loading handling without framework-specific boundary components.
- **Hooks after conditions and early returns** — Declare hooks at the point where they are used, including after an if or inside a loop. The compiler hoists them to the top of the generated function. *When:* Use it to co-locate state with the code that needs it. The presenter warns that debugging can be harder because the compiled output differs from the source.
- **Component-scoped CSS with shared style keyword** — Put a style block inside the component. Each class gets a unique hash at compile time. To share, the parent passes a style name through the style keyword to a child that accepts className, and the hash travels with it. A global selector escapes the scope if needed. *When:* Use it if you want CSS colocated with the component. The presenter says they will keep using Tailwind.
- **Escaped text vs raw HTML** — Bare text must be a double-quoted string or a template literal. Use the text keyword to render a string as escaped text. Use the html keyword to render raw HTML, which the presenter says works only in Ripple View with a narrower subset. *When:* Use text when the source of a string is untrusted, since it is escaped. Use html only when you need real markup and the target is Ripple View.
- **Lazy destructuring with ampersand** — Prefix the props parameter with an ampersand so destructured names compile to property lookups at each use instead of snapshots at call time. *When:* Use it in Ripple View or Solid components where you want destructuring but must keep signal reactivity per access.

## Hot takes
- TSRX is too niche and too late for an era where AI writes most code, and AI is best at JSX and React.
- Statement-based JSX reads top to bottom, but it makes it harder to see what a component renders compared with a return statement.
- Hook hoisting is compiler magic the presenter finds hard to debug.
- Claude wrote working TSRX demos from a site's llms.txt alone.
- Svelte users and existing Ripple users are likely to like TSRX more than React developers.
- The title says it replaces JSX, but the presenter does not expect that and says the syntax is not for them.
