> Pre-review critique of the RTX Spark / Surface Laptop Ultra for local AI: the cold-prefill wait on long prompts (about 170 s at 128K) matters more for agent work than decode speed, and the wattage is still unpublished.

## Summary
The host argues that the Surface Laptop Ultra (RTX Spark N1X, 128 GB unified memory, about $5,899) looks strong on decode speed but is weak on prefill, which dominates coding-agent workloads. He splits local LLM work into prefill (compute-bound, reading the prompt) and decode (memory-bandwidth-bound, writing output) and says most marketing compares decode. Using Microsoft's own developer-blog numbers, a cold 128K prompt takes about 170 s before the first token, which he ties to an 80 W laptop budget versus the DGX Spark's 140 W. He notes the DGX Spark price rose 74% in October, which narrows the price gap, but the laptop still reads prompts roughly 2.3x slower by his cross-source comparison. He then lists who the argument does not apply to (short prompts, travelers with air-gapped data, long single-repo sessions with warm cache) and points to AMD Ryzen AI Max alternatives. He closes with four things to test once reviews land: cold prefill at real context length, sustained and battery performance, the final wattage, and ship dates.

## Key ideas
- **Local LLM time splits into two jobs on different hardware limits. Prefill (reading the prompt) is compute-bound. Decode (writing each output token) is memory-bandwidth-bound. Bandwidth comparisons only describe decode.** — Speaker's framing: bandwidth specs predict output speed, but long prompts, big codebases and agent loops are dominated by prefill, which depends on clock speed, which depends on power. ([3:48](https://youtu.be/aQKGejbv-Rs?t=228))
- **Microsoft's own numbers put the wait for a cold long prompt at minutes, not seconds.** — Per Microsoft's launch-day blog: 923 tok/s prefill at 64K (about 71 s cold) and 769 tok/s at 128K (about 170 s cold) for MAI Code 1.1 Flash. Decode was 63 tok/s on short prompts with speculative decoding. The 170 s figure is in the footnotes and not in most reviews. ([6:32](https://youtu.be/aQKGejbv-Rs?t=392))
- **The prefill gap follows from the power budget. The laptop chip is specified at 45 to 80 W, while the DGX Spark runs at 140 W, and Microsoft has not published the final wattage.** — Speaker's reading: more watts means higher clocks, which means faster math and faster prefill. Earlier Microsoft reps cited a design around 110 W, and Microsoft later said it is not targeting 110 W sustained TDP. Memory bandwidth is roughly 10% higher on the laptop, but compute is not. ([5:05](https://youtu.be/aQKGejbv-Rs?t=305))
- **Coding agents make prefill the main cost because context grows every turn. Cold cache misses bring the full cost back.** — Each agent turn re-sends the repo, the tool results and the history, so most tokens go in, not out. A warm prompt cache helps, and warm turns can take seconds. A new session, a new repo, a big log dump or a second agent makes the cache miss, and the cold-prefill wait returns. ([7:46](https://youtu.be/aQKGejbv-Rs?t=466))
- **Price comparisons changed. The DGX Spark 128 GB went from $4,699 to $6,950 on Oct 2, so the $5,899 laptop now looks cheaper than the box it is compared with.** — The laptop includes a screen, battery and keyboard. The DGX Spark still has 140 W, a 200 GB networking port for chaining units, and NVIDIA's Linux, while the laptop is Windows 11 only. The DGX Spark still prefills about 2.3x faster by the speaker's cross-source comparison (different model and engine, so only directional). ([9:07](https://youtu.be/aQKGejbv-Rs?t=547))
- **The 110 GB ceiling is more important than the 128 GB label. The GPU can address about 110 GB, and the OS and apps take more. At 256K context the model alone used 75.5 GB.** — Microsoft's footnote-level task manager shows 63 of 110 GB used by the GPU. The speaker says VS Code, a browser and a Docker container have to be managed carefully within that limit. ([10:31](https://youtu.be/aQKGejbv-Rs?t=631))
- **The argument does not apply to every workload. It mostly hurts long prompts, while short prompts are decode-bound and the hardware is still useful for some users.** — Speaker lists cases where the laptop still makes sense: short prompts of a few thousand tokens, travel with data that cannot leave the machine (for example HIPAA or NDA material, where the alternative is nothing), long single-repo sessions where the cache carries most of the load, and users who also need gaming or video editing on Windows. ([11:53](https://youtu.be/aQKGejbv-Rs?t=713))
- **Cheaper AMD alternatives run the same class of model. A 128 GB Ryzen AI Max Plus 395 laptop is around $3,200, and a $3,099 mini PC with the same chip reportedly prefills about 1,320 tok/s at 128K (about 99 s), though on a different model and engine.** — Speaker says the software gap closed faster than the pricing suggests and treats the AMD figures as direction, not verdict. ([13:02](https://youtu.be/aQKGejbv-Rs?t=782))
- **Four tests to run before buying: cold prefill at real context length, sustained load and battery runs, the final wattage, and actual ship dates. The holiday return window was also flagged.** — Test cold prefill in seconds-to-first-token on 64K or 128K prompts with the model you would run, not tokens/sec on a 256-token chat. Repeat after 30 minutes of load and on battery with a 50 GB model loaded. Anything bought Oct 1 to Dec 2 can be returned until Jan 31. ([14:16](https://youtu.be/aQKGejbv-Rs?t=856))

## Techniques
- **Cold prefill benchmark at real context length** — Start a fresh session with no cache. Send a 64K or 128K prompt using the model you would actually run. Measure seconds until the first output token, not tokens/sec on a short chat. Record the prompt size, cache state and model. *When:* Evaluating local hardware for agent or coding workloads, where prefill dominates and cache misses happen often.
- **Split throughput into prefill and decode** — Report prompt-processing speed (tok/s in) and generation speed (tok/s out) separately. Estimate the decode ceiling as memory bandwidth divided by the bytes of active weights read per token (speaker's example: 300 GB/s / 2.8 GB per token is about 107 tok/s). Expect prefill to scale with compute and clock power, not bandwidth. *When:* Comparing hardware or diagnosing slow responses. Using bandwidth alone to predict agent latency will mislead.
- **Sustained and battery soak test** — After 30 minutes of continuous load, rerun the cold-prefill and decode numbers. Repeat on battery with a large model (about 50 GB) loaded, not a light video file. *When:* Before trusting vendor claims about thermal or battery performance on laptops.
- **Memory budget with OS and tooling headroom** — Compare the model's footprint with the GPU-addressable limit (about 110 GB here), not the physical total. Subtract the OS, IDE, browser and container overhead. Check KV-cache growth at long context (the speaker cites 75.5 GB for the model alone at 256K). *When:* Sizing a local machine for long-context agent sessions with a development environment open.
- **Speculative decoding for decode speed** — Speaker says Microsoft's test used a speculative decoding method (DFlash 2, transcribed as DF Flash 2) with llama.cpp to raise decode from the baseline to 63 tok/s on short prompts. No configuration is shown in the video. *When:* When decode is the bottleneck, such as short-prompt chat. It does not fix cold prefill.
- **Keep the prompt cache warm in long sessions** — Keep one long-running agent session per repo so the cache carries repeated context. Avoid dumping large logs into a fresh session, since each cache miss pays full prefill again. *When:* Running coding agents on local hardware where cold prefill is slow.

## Hot takes
- The cold-prefill wait (about 170 s for 128K) is the number that matters for coding agents, and it is buried in vendor footnotes, not in headline benchmarks.
- Bandwidth-based comparisons (including with the MacBook Pro M5 Max) are misleading for agent work because they only describe decode.
- The laptop looks cheaper than the DGX Spark only because the DGX Spark price rose 74%. Compute per dollar is still worse for long prompts.
- Vendor-sourced numbers and cross-model, cross-engine comparisons are only directional. Reviews are needed before buying.
- The 128 GB label overstates usable GPU memory (about 110 GB addressable).
