> Anthropic engineers explain how agent surfaces moved from the Messages API to Claude Managed Agents, which separates the brain from the hands, logs sessions durably, and adds vaults, dreaming and outcomes.

## Summary
Gagan Bhat and Isabella Kai He, from Anthropic's Applied AI team, trace the evolution of agent surfaces: a raw Messages API, then hand-built agentic loops, then the Claude Agent SDK, then Claude Managed Agents, which hosts the loop, sandbox, credentials, sessions and observability. The core design choice is decoupling the "brain" (agent loop and model) from the "hands" (sandbox and tool execution), with every interaction written to a durable session log that enables resume, context recovery and observability. They argue harness code goes stale as models improve, citing a Sonnet 4.5 context-anxiety workaround that became dead weight with Opus 4.5. A semi-live SRE demo builds an incident-investigation agent from an agent definition, an environment with allowlisted network access, and uploaded logs and skills. Four field lessons follow: keep credentials in vaults, use decoupling for latency (with a reported 60% P50 and over 90% P95 time-to-first-token improvement), treat session logs as the basis for memory and self-improvement, and offer self-hosted sandboxes and MCP tunnels for private networks. The close previews "dreaming" (batch review of transcripts and memory) and "outcomes" (rubric-graded retry loop). The talk is partly product pitch, and the latency numbers come without workload or baseline detail.

## Key ideas
- **Agent surfaces evolved in three steps: the Messages API (tokens in, tokens out), then hand-built agentic loops, then the Claude Agent SDK with a built-in harness, then Managed Agents, which also runs the production infrastructure.** — Hand-rolled loops were painful, and the SDK still left credentials, hosting and scaling to the builder. Managed Agents moves session management, credentials, sandboxing, observability and hosting onto the vendor side. ([1:28](https://youtu.be/K0X9QDRkIdg?t=88))
- **Harness assumptions go stale as models improve, and stale harness code degrades agents.** — Sonnet 4.5 showed context anxiety, so the team added context resets to the harness. Opus 4.5 did not show it, so those resets became latency and cache overhead. The speaker says customer harnesses differ in how agile they are, and rigid ones can take weeks or months to migrate. ([6:50](https://youtu.be/K0X9QDRkIdg?t=410))
- **Decouple the brain (agent loop) from the hands (sandbox and tool execution).** — Coupling the loop and container meant the model could not start reasoning until the container was ready, and one failure took down the whole unit. Separating them lets reasoning start at once, lets sandboxes spin up on demand, and lets the brain replace a dead sandbox. ([10:59](https://youtu.be/K0X9QDRkIdg?t=659))
- **The durable session log is the recovery mechanism and the context store.** — Every user message, model response, tool call and result is written to a persisted log. A dead brain can resume by reading the log. Context Claude edits or drops can be re-read in slices from the log, so the context window is no longer the same thing as the session. ([12:25](https://youtu.be/K0X9QDRkIdg?t=745))
- **Sessions have four explicit states: idle, running, rescheduling (retrying after an error) and terminated (unrecoverable).** — Explicit states let an existing session be resumed later and let failures be retried in production. The speaker frames this as the reliability requirement for agents running for hours or days. ([13:47](https://youtu.be/K0X9QDRkIdg?t=827))
- **Credentials go in vaults and are decrypted only at tool-execution time, so the model never sees the secret.** — This builds on the brain/hands split, since tool calls run in a separate place where the secret can be injected. Customers ask how to stop agents from reading environment files holding tokens. ([22:13](https://youtu.be/K0X9QDRkIdg?t=1333))
- **One session log can serve observability, memory and self-improvement.** — The same event log powers a UI trace for users, a history for memory, and a batch process called dreaming that reviews transcripts plus the current memory state and writes back improved memory. The speaker also describes an organization-scale memory for team runbooks. ([23:37](https://youtu.be/K0X9QDRkIdg?t=1417))
- **Outcomes add a rubric-graded retry loop with a separate grader agent.** — The developer defines success criteria, a rubric and failure cases. A grader agent runs beside the main loop and judges the result, and the agent retries until the rubric is met. The speaker presents this as a way to unlock tasks that were not reliable before. ([29:00](https://youtu.be/K0X9QDRkIdg?t=1740))

## Techniques
- **Brain/hands decoupling with on-demand sandboxes** — Keep the model loop in one process and tool execution in a separate sandbox. Start model reasoning immediately and provision the container in parallel, or skip the container when the task does not need one. Replace a dead sandbox without losing the loop. *When:* Latency-sensitive agents, or long-running agents where the sandbox may crash and must not take the loop down.
- **Append-only session log as the resume point** — Write every user message, model response, tool call and tool result to a durable log. After a crash, rebuild state by reading the log back into context. Model the session with explicit idle, running, rescheduling and terminated states. *When:* Agents that run for hours or days, or that need to continue after a failure or a later user message.
- **Re-reading discarded context from the log** — Do not treat the context window as the only copy of the session. When context is edited or dropped, read the needed slice back from the persisted log. *When:* Long agent runs where compaction or pruning might remove something still needed.
- **Vault-based credential injection** — Store secrets in a vault. Decrypt them only inside the tool-execution step, and keep them out of the model's context and environment files. *When:* Agents that call sensitive internal systems, where the model must not see the tokens.
- **Restricted network allowlist per environment** — Define the environment with networking limited to named hosts, such as one MCP server, so the agent cannot reach anything else. *When:* Agents that touch production systems and should be bounded to specific endpoints.
- **Rubric and failure-case grader loop (outcomes)** — Write success criteria and failure cases as a rubric. A separate grader agent checks each attempt, and the main agent keeps retrying until the rubric passes. *When:* Tasks with a checkable definition of done, where retries are cheap compared with a silent failure.
- **Batch dreaming over transcripts and memory** — Run a periodic batch job over the day's session logs and current memory state. Extract insights and organized structures, then write them back to memory so the next sessions start from them. *When:* Agents that repeat similar work daily and should improve from their own history.
- **Harness-debt audit when models change** — Periodically test whether each harness workaround, such as context resets, is still needed on the new model. Remove the ones that now only add latency or cache misses. *When:* Any team that upgrades models often and has built scaffolding around an older model's weaknesses.

## Numbers
- Time-to-first-token improved about 60% at P50 after decoupling the brain from the hands. ([23:37](https://youtu.be/K0X9QDRkIdg?t=1417))
- Time-to-first-token improved over 90% at P95 after decoupling. ([23:37](https://youtu.be/K0X9QDRkIdg?t=1417))
- Managed Agents defines four session states: idle, running, rescheduling, terminated. ([13:47](https://youtu.be/K0X9QDRkIdg?t=827))
- Demo scenario: P99 latency spikes to 10x baseline, which triggers the SRE investigator agent (illustrative scenario, not a measured result). ([16:21](https://youtu.be/K0X9QDRkIdg?t=981))

## Hot takes
- Harnesses have become the limiting factor on what models can achieve, according to the speaker.
- Harness fixes written for one model become pure overhead on the next, so keeping a harness agile matters more than the scaffolding itself.
- Session logs, not the context window, should be the durable system of record for agent state.
