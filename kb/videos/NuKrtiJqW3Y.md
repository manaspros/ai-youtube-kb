## Techniques
- **Full-page screenshot script behind a slash command** — Write a script that uses the available web tools to capture the full page. Add it to the project and give a custom slash command instructions to use the script for full-page checks, not scroll-and-stitch per section. Speaker's script and command text are not shown on screen. *When:* Visual landing-page or layout checks where section-by-section screenshots waste time and tokens.
- **CLAUDE.md rule to limit DOM extraction** — Add a CLAUDE.md instruction telling Claude to extract only the specific divs or elements the task needs, not the whole main tag. *When:* Any browser read on a large page where whole-page HTML bloats the context.
- **Cookie-banner dismissal script run first** — Write a JavaScript snippet with common accept-button selectors and text patterns, find matching elements and click them. Add a CLAUDE.md instruction to run it before the main content on each site visit. *When:* Sites with consent or cookie popups that otherwise cost screenshot and scroll cycles.
- **Authenticate before handing off the task** — Log in and clear any CAPTCHA in the signed-in Chrome profile yourself, then give Claude the task. The extension keeps the session, and Claude will not do auth or CAPTCHA steps. *When:* Testing or automating sites that require login or CAPTCHA verification.
- **Split end-to-end testing into per-area test files** — Create one test file per feature area. Each file lists priority, preconditions, testing steps and expected results. Add a testing guide that explains how to run them and a README for the test docs. *When:* Testing a large web app where one long browser run may be stopped by the Manifest V3 limit.
- **Progress report after each test file** — Add a CLAUDE.md instruction to write a comprehensive test report after finishing each file. After a compaction, Claude reads these progress files to see what has been tested and what remains. *When:* Multi-file browser test runs that will exceed the context window.
- **Compact and check context before browser test runs** — Run /compact before starting browser testing. Add a CLAUDE.md instruction to check context usage before starting any task so compaction does not happen midway through a test. *When:* Browser-heavy sessions where the extension consumes a lot of context.
- **Guided testing slash command** — Create a slash command that takes a test file as argument. It tells Claude to run the file's steps in the browser, read console output for hidden errors, and write the results into a fixed report structure as specified in CLAUDE.md. *When:* Systematic QA of a web app driven by a set of test files.
