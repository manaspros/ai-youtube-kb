> Alvin Pane (OutRival) on cutting LLM token spend in production: measure baseline variance with a ceiling test, shrink prompts with DSPy-style optimization, downsize models, then gate release on paired shadow-deployment stats with a lower confidence bound above zero.

## Summary
The speaker, head of agent intelligence at OutRival (a digital-worker company handling phone, text and email tasks), argues that token usage is a poor success metric and that the goal is to get the most intelligence per token. His playbook has four steps: instrument model calls with OpenTelemetry-style traces, run a "ceiling test" that measures how often production disagrees with itself, reduce cost via prefix caching, prompt shrinking with a DSPy optimizer, and smaller models. The final step is a shadow deployment judged on paired disagreements with confidence intervals and per-category checks. In his example, a candidate prompt halved in size had 443 regressions against 2,463 improvements, and he ships only when the lower confidence bound is above zero. The talk is a practitioner walkthrough with a synthetic example (HarborBite) and no product pitch beyond the company name. Several figures come from a fictional or synthetic setup, so they should be read as illustrative.

## Key ideas
- **Token usage is a poor success metric; the target is maximum capability per token** — Token maxing as a leaderboard is criticised. Tokens are a cost, not the work. Redundant calls compound into latency and compute cost at billions of tokens per day. ([0:00](https://youtu.be/8g1N_a3h9H0?t=0))
- **Instrument the shared model client so every attempt is in a trace** — Link model calls, tools and retries per task. Record prompt version, model settings, token usage, latency and cost. Build a production benchmark from this telemetry. ([1:43](https://youtu.be/8g1N_a3h9H0?t=103))
- **Run a ceiling test: production versus itself sets the noise floor** — Run the expensive production model three times on the same inputs. It disagreed with itself about 7% of the time (93% agreement). A cheaper candidate at 18% disagreement was being held to a stricter standard than production itself meets. ([2:49](https://youtu.be/8g1N_a3h9H0?t=169))
- **Three cost levers in sequence: caching, prompt shrinking, downsizing** — Maximise prefix cache hits first. Then shrink the prompt. A prompt of nearly 5,000 tokens had grown from bolted-on rules and hard-coded worked examples. Then move work to smaller models. ([3:57](https://youtu.be/8g1N_a3h9H0?t=237))
- **Treat prompt shrinking as a search problem with an optimizer** — Define the interface contract (inputs, output schema, scoring function). An optimizer such as DSPy's searches the prompt space against labelled historical data and uses failure feedback to revise. It replaced long examples with compact rules, cutting instruction tokens by 51% with the same contract. ([4:32](https://youtu.be/8g1N_a3h9H0?t=272))
- **Smaller models can be tuned with the same loop, but they overfit and compression adds failure points** — Routing or extraction can go to a cheap model, with frontier models kept for heavy reasoning. Distilling a large model's behaviour into a small one introduced new failure modes and overfitting, and several small-model prompts were not good enough to release. ([6:15](https://youtu.be/8g1N_a3h9H0?t=375))
- **Shadow deployment with a paired, noise-aware diff, not a point estimate** — Run both versions on the same inputs and measure production vs production, candidate vs candidate, and candidate vs production. Subtract within-version disagreement from cross-version disagreement to isolate real change. ([7:22](https://youtu.be/8g1N_a3h9H0?t=442))
- **Different is not the same as worse: review the diffs manually and check the confidence interval** — Of the diffs, 443 were regressions and 2,463 improvements (about 6:1). Keep comparisons paired and group repeated runs. Ship only when the lower confidence bound on net gain is above zero. Check critical intent categories separately, since a good global average can hide one category getting worse. ([9:02](https://youtu.be/8g1N_a3h9H0?t=542))

## Techniques
- **Ceiling test (self-agreement baseline)** — Run the production model several times on the same inputs and measure how often it disagrees with itself. Use that as the achievable target before judging a cheaper candidate. *When:* Before comparing any cheaper model or prompt, on messy or ambiguous inputs where variance is expected.
- **Prompt optimization as search (DSPy-style)** — Declare the input and output schema and a scoring function. Let an optimizer revise the instructions against a labelled benchmark, using failure feedback. Replace long worked examples with compact rules. *When:* When a prompt has grown through bolted-on rules and examples and must be made smaller without changing the interface.
- **Prefix-cache-friendly prompt structure** — Structure prompts so the stable prefix is shared across requests to raise cache hit rates. *When:* As the first cost lever, before shrinking or downsizing, for high-volume prompts.
- **Split pipeline by model size** — Use a cheap model for routing or extraction and reserve the expensive frontier model for heavy reasoning steps. *When:* When a single large prompt does several jobs of different difficulty.
- **Paired shadow-deployment statistics** — Run the candidate and baseline on identical inputs. Compute net gain (improvements minus regressions) and its confidence interval, grouping repeated runs of the same conversation. Subtract within-version variance. Break results down per critical category. *When:* As a release gate for any prompt or model change in production.

## Hot takes
- Token maxing as a leaderboard metric is a bad measure; the goal is intelligence per token
- Comparing a cheap model to a production model without measuring the production model's own variance is a mistake
- A good global average can hide a critical category that is getting worse
- Different outputs are not automatically worse outputs

OpenTelemetry, DSPy, Jeepa optimizer (as transcribed; likely DSPy's GEPA optimizer)
