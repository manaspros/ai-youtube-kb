## Key ideas
- **CLAUDE.md should hold only what the agent cannot learn by reading the code. The New Init flow asks about setup, git and deployment, proposes a plan, and writes files only after approval.** — Stated setting name is 'Claude Code New Init', set to 1 in the terminal before launching claude. The result is a CLAUDE.md with the user's workflow plus generated skills and hooks. ([0:00](https://youtu.be/i6Q7bXnWGlM?t=0))
- **Instructions and skills go stale as models improve. Outdated instructions fill context and can make answers worse, so audit them after each new model release.** — The speaker says the prompt audit runs sub-agents over the whole setup and produces a report of problems and fixes. Skill doctor shows per-skill usage frequency, last-used date and context token cost, so unused skills can be deleted. ([2:34](https://youtu.be/i6Q7bXnWGlM?t=154))
- **Permission and auto-mode config can be derived from history instead of written by hand.** — Auto Mode Setup reads the project and past session history and proposes new auto-mode rules for approval. The fewer-permission-prompts command allowlists read-only tools found in past sessions into the project settings file. ([3:56](https://youtu.be/i6Q7bXnWGlM?t=236))
- **Connectors and artifacts load into every session and consume context even when unused, so disabling them frees context for long autonomous runs.** — Claude app connectors (e.g. Notion, Slack) are removed with a settings.json flag, 'Disable Claude AI Connectors' set to true. Artifacts are turned off with 'enable artifact' set to false. Claude can make these edits on request. ([5:21](https://youtu.be/i6Q7bXnWGlM?t=321))
- **For apps that call an LLM, build eval writes a fixed test set once and hillclimb iterates on the app, keeping only changes that score higher. Both spend real API money on each run.** — Speaker says build eval also works without model calls, by planning tests from the code. Hillclimb makes a change, runs the tests, scores the responses and keeps improvements only. ([6:22](https://youtu.be/i6Q7bXnWGlM?t=382))
- **Plan-mode context can be cleared on plan acceptance, and plans can be saved inside the project for sharing.** — The setting 'show clear context on plan accept' is set to true to restore the clear-context option. A 'plans directory' setting in settings.json points at a folder in the project. Default plan storage is a plans folder under the user's global Claude folder. ([7:27](https://youtu.be/i6Q7bXnWGlM?t=447))
- **Parallel sessions can be coordinated. list agents shows reachable sessions, and one session can message another to get an answer. branch, fork and subtask are three different ways to split work off a chat.** — branch copies the chat into a new session the user drives. fork copies it into a background session that runs a given task and ends when done. subtask runs a sub-agent that inherits the full chat context, unlike a normal sub-agent that starts with only its prompt. ([10:43](https://youtu.be/i6Q7bXnWGlM?t=643))
- **Unattended runs need a question timeout and a notification. After the timeout Claude picks the suggested answer, but only when it can proceed safely. Otherwise it keeps waiting.** — Setting: 'Ask User Question Timeout' in settings.json, value in seconds (example 60). Notifications: run the config command, open 'local notifications', and choose a type; the speaker chose terminal bell. ([12:49](https://youtu.be/i6Q7bXnWGlM?t=769))
- **Model routing can cut usage. opusplan uses Opus only in plan mode and Sonnet for building. Sub-agents can be pinned to one smaller model, and the force setting overrides a sub-agent file's own model choice.** — Command: model with 'opusplan'. Settings: 'Claude Code sub-agent model' and 'Claude Code sub-agent model force' set to 1. Speaker says Sonnet draws less of the usage limit than Opus, which matters most on the Pro plan. Settings apply from the next session. ([13:51](https://youtu.be/i6Q7bXnWGlM?t=831))

## Techniques
- **Enable New Init** — Set 'Claude Code New Init' to 1 in the terminal before typing claude. Answer the questions about improving vs. starting fresh, skills and hooks, git, and deployment. Approve the plan before it writes CLAUDE.md, skills and hooks. *When:* Setting up or refreshing CLAUDE.md so it holds only non-discoverable, always-needed instructions.
- **Import setup from another agent** — Run the import command with the previous agent's name (e.g. Codex or Cursor). Choose which instruction files and MCP servers to copy. Claude generates a skill that performs the copy. *When:* Moving an existing instruction and MCP setup into Claude Code.
- **Prompt audit after a model release** — Run the claude api command followed by prompt audit (auto-captions say 'Cloud API'). It reads the whole setup, uses sub-agents to check each part, and returns a problem report with fixes. Ask Claude to apply the fixes you accept. *When:* Right after a new model comes out, to remove instructions the new model no longer needs.
- **Prune skills by token cost and usage** — Run skill doctor to see usage counts, last-used dates and context tokens per skill. Run the skills command and press t to sort by tokens ascending. Ask Claude to delete unused skills. *When:* Context is crowded with skills that are rarely used.
- **Auto Mode Setup** — Run the Auto Mode Setup command. It reads the project and past session history, proposes new auto-mode rules, and updates the auto-mode settings after you approve. *When:* Auto mode keeps asking about commands you normally allow.
- **Fewer permission prompts allowlist** — Run the fewer permission prompts command. It scans past sessions for the most-used read-only commands and tools, then writes them to the allow list in the current project's settings file. *When:* Before a long unattended task, to cut permission prompts without loosening write permissions.
- **Disable connectors and artifacts** — In ~/.claude/settings.json set 'Disable Claude AI Connectors' to true to stop claude.ai connector MCP servers loading. Set 'enable artifact' to false to stop artifact creation. Claude can edit the file on request. *When:* You do not use those connectors or artifacts and want the context back.
- **Build eval and hillclimb for LLM apps** — Run claude api build eval once to write a fixed test set, then run the hillclimb command to iterate on the app. Hillclimb tests each change, scores the responses and keeps only improvements. Each run calls the model and costs API money. For apps without model calls, build eval can plan tests from the code without the API. *When:* Measuring an app that calls an LLM across versions against the same tests.
- **Clear context on plan accept and save plans in-repo** — In settings.json set 'show clear context on plan accept' to true. Set 'plans directory' to a folder name inside the project so plan files are saved there. *When:* Building from a plan with a clean context, and sharing plans with teammates.
- **Output styles** — Run the output style command to list styles, then run it with a name. Styles: default, proactive (acts first), concise, explanatory, learning (user writes part of the work). *When:* Changing how verbose or hands-on Claude's responses are.
- **Show thinking summaries** — Set 'show thinking summaries' to true in settings.json so the Ctrl+O view shows reasoning summaries again. *When:* You want to review the reasoning summary of a run.
- **Focus mode** — Run the tui command and set the terminal to full screen, since focus mode only works there. Then run the focus command. Intermediate steps disappear when the task finishes, leaving the prompt and the answer. *When:* Returning to a long task and wanting only the prompt, answer and a short summary.
- **Branch, fork and subtask** — branch: copies the current chat into a new session you drive. fork: copies the chat into a background session given a task, which ends itself when done. subtask: starts a sub-agent in the current session that inherits the full chat context. *When:* Trying an alternative idea (branch), running a side task away from the main session (fork), or doing a side task that needs the whole chat context (subtask).
- **Cross-session messaging** — Run the list agents command to see reachable sessions on the project. Ask one session to message another to get its answer without copying context by hand. *When:* Several Claude Code sessions work on different parts of one project.
- **Ask User Question Timeout and notifications** — Add 'Ask User Question Timeout' to settings.json with a value in seconds (example 60). Claude then picks the suggested answer when it can continue without you. For notifications, run the config command, open local notifications, and select a type (speaker uses terminal bell). *When:* Running many sessions where you cannot watch each one for questions.
- **opusplan model routing** — Run the model command with 'opusplan'. Claude uses Opus only in plan mode and Sonnet for everything else. *When:* Wanting stronger planning while keeping build-phase usage lower, especially on the Pro plan.
- **Pin sub-agent model** — Set 'Claude Code sub-agent model' to the chosen model in settings.json. Set 'Claude Code sub-agent model force' to 1 to override any model a sub-agent file names. Omit force to let sub-agent files choose. Takes effect from the next session. *When:* Keeping all sub-agents on a smaller, cheaper model.
- **Prompt-editing shortcuts** — Ctrl+S stashes the current prompt and clears the box; the stashed prompt returns after you send the next one. Ctrl+Y restores text deleted by mistake. Ctrl+_ undoes the last change to the prompt. Run powerup for short interactive lessons with animated demos. *When:* Writing long prompts and interrupting yourself, or learning features.
