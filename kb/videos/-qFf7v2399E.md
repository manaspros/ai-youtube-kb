> A single-repo demo comparing Claude Code's cloud Ultraplan with the Superpowers plugin for planning a release pipeline: Ultraplan is faster and cheaper but thinner, and the host plans locally about 90% of the time.

## Summary
The host compares two ways to plan a feature in Claude Code: Ultraplan, which hands planning to a cloud session that clones the GitHub repo, and the Superpowers plugin, which plans locally in the terminal. Both are asked to plan the same release pipeline for a film-emulation CLI. Ultraplan's first run failed at about 4% usage, so the host reran it in debug mode. The plan it produced wrongly said the repo was empty, and the revision round cost about a third of the five-hour usage. Superpowers asked twice as many clarifying questions, produced a two-stage design and implementation plan of about 833 lines versus about 195 for Ultraplan, and wrote tests before each task. Its session cost about 75k tokens, which the host notes is a lot against an assumed 44k five-hour limit. The host's verdict is that Ultraplan suits starting work away from the machine, while local Superpowers suits most planning because it can talk to local code, skills and MCP tools. The evidence is one anecdotal run per tool, and the implementation was not reviewed.

## Key ideas
- **Ultraplan moves planning from the CLI to Claude Code on the web** — It clones the GitHub repo into a cloud container, writes a detailed plan there, and the plan can then run in the cloud or locally. The repo must be on GitHub because the cloud session needs to clone it. ([0:00](https://youtu.be/-qFf7v2399E?t=0))
- **The first Ultraplan run failed and needed a debug-mode rerun** — The run failed at about 4% usage. Rerunning the same prompt in debug mode produced a browser link to the plan. ([1:01](https://youtu.be/-qFf7v2399E?t=61))
- **The first Ultraplan plan misread the repo** — It said the repo was empty with no commits, which was false. The plan's shape looked reasonable, and it included build scripts and a minimal CLI for a smoke test. Revising it made the cloud session clone the correct repo and produced a plan that understood the project. ([2:19](https://youtu.be/-qFf7v2399E?t=139))
- **Plan revisions are expensive in usage** — Revising the plan took usage from about 19% to 37%, roughly a third of the five-hour allowance for one plan. The first full plan took about 15% of usage. ([3:37](https://youtu.be/-qFf7v2399E?t=217))
- **Ultraplan executes remotely without GitHub credentials** — Implementation ran in the cloud and took about five minutes. The sandbox had no GitHub credentials, so the host made the branch and PR by hand. The host did not find an obvious way to run the plan in the CLI. ([3:37](https://youtu.be/-qFf7v2399E?t=217))
- **Superpowers asks more questions and writes tests first** — Ultraplan asked three questions and Superpowers six. Superpowers separates a design doc (problem and requirements) from an implementation plan of bite-sized tasks. Each task starts with a failing test, then the implementation. Ultraplan's plan had no tests. ([3:37](https://youtu.be/-qFf7v2399E?t=217))
- **Superpowers plans are longer and cost more tokens** — The Superpowers plan is about 833 lines against about 195 for Ultraplan. The whole Superpowers design and plan session used about 75.1k tokens, 57k for messages and 1.9k for skills. The host estimates a five-hour limit at about 44k tokens but says he is not sure of that figure, and the 75.1k excludes prompt caching. ([5:01](https://youtu.be/-qFf7v2399E?t=301))
- **The choice depends on where you work** — The host plans locally about 90% of the time. Local planning keeps the code, skills and MCP tools in reach and allows a back-and-forth dialogue. Ultraplan fits starting a feature and continuing from a phone or tablet while away from the machine, with the cloud session creating PRs. ([6:23](https://youtu.be/-qFf7v2399E?t=383))
- **Ultraplan availability is limited** — At recording time it was only in the Claude Code CLI and needed a paid Claude subscription with the Claude Code web link. The host hopes it will reach other plans and platforms, including starting it from Claude Code on the web. ([7:34](https://youtu.be/-qFf7v2399E?t=454))

## Techniques
- **Launch Ultraplan from the Claude Code CLI** — Use the /ultraplan slash command, or type the word 'ultraplan' in the prompt (it gets a rainbow highlight, like 'ultrathink'). The repo must be on GitHub and the Claude Code CLI version must be recent enough. When Claude asks whether to run the interactive plan on the web, answer yes. Wait about 2 to 3 minutes for the terminal notification that the plan is ready. *When:* Starting a feature you will continue away from your machine, or when you want the cloud session to clone and plan from the repo.
- **Review and revise an Ultraplan plan in the browser** — Open the plan in the browser (the host used the Claude Code desktop app for Mac). Select text in the plan and add a comment, for example to ask which repo it means or whether it has access. Ask Claude to revise the plan. Check the usage percentage before and after, because each revision spends usage. Accept the plan to run it remotely. *When:* When the first plan misreads the project. Revise it, and expect a second revision to cost about a third of the five-hour usage.
- **Superpowers two-stage planning** — Install the Superpowers plugin. First have it write a design doc that captures the problem and requirements, after a question round of about six questions. Then have it write an implementation plan that includes goal, architecture, tech stack, file structure and bite-sized tasks. Each task starts with a test that is run to confirm it fails, then the implementation. Use this path when you want the model to ask questions locally. *When:* Planning locally when you want a thorough plan with tests, and you can afford about 75k tokens for one planning session.
- **Stop the planner from using a skill when comparing** — For a fair comparison, tell the model in the prompt not to use the superpowers skill, so the run tests only the built-in feature. *When:* Benchmarking one planning feature against another inside the same environment.

## Hot takes
- Ultraplan's plan said the repo was empty when it was not, and its first run failed; the host calls it not ready for serious planning without a revision.
- Superpowers' longer, test-first plan is more thorough, but the host notes thoroughness does not guarantee better execution, and he did not compare the implementations.
- A full revision cycle on Ultraplan cost about a third of the five-hour usage, which the host calls a lot for one plan.
- For most work done locally, a dialogue-based local planner beats a cloud planner. Cloud planning is for leaving the machine, so the choice depends on where you work.
- Evidence is one demo per tool on one repo; the 44k-token limit is the host's own unverified assumption.
