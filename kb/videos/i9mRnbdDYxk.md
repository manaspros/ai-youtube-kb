> Kai Explains argues a 16GB GPU fits a 27B model but can't finish real agentic coding sessions: the KV cache, bandwidth, prefill and multi-token prediction decide usable speed and context, not whether the weights load.

## Summary
The host responds to a viral video claiming a 27B-class model runs at 45.6 tokens/s on a $429 RTX 5060 Ti 16GB. He ran the same setup in a long coding-agent session and saw speed fall to about 15 tokens/s after roughly 20 minutes. He explains that the viral claim is true but incomplete: a DASLab (IST Austria) quantization brings the model to 11.8 GB, yet the KV cache grows with every token and quickly eats the remaining VRAM. He walks through the budget math for a 16GB card (usable VRAM, weights, vision and MTP add-ons, KV bytes per token), then three speed limits: spilling out of VRAM, memory bandwidth as a ceiling on tokens/s, and prefill time before the first token. He covers current 16GB card prices and bandwidth, Mac unified-memory limits, laptop naming traps, a local-vs-hosted cost break-even, and when two 16GB cards with tensor split are the practical answer. His advice: buy for bandwidth, run a model that leaves room, turn off unused memory consumers, and size the model to the conversation.

## Key ideas
- **A model that fits is not a model that finishes. The viral video answers whether the weights load on 16GB, but never asks how much room is left for conversation once they do.** — The weights are fixed, but the KV cache grows with every token sent and generated. Real agent sessions push past 100k tokens, so the remaining VRAM is the real constraint. ([0:00](https://youtu.be/i9mRnbdDYxk?t=0))
- **KV cache footprint per token varies a lot by model. Qwen (27B class) is about 64 KB per token, while Devstral Small 2 is about 160 KB per token.** — At 64 KB/token, 32k tokens is about 2 GB and 128k is about 8 GB. On a 16GB card with Devstral Small 2, the host estimates room for only about 11k tokens next to the weights. ([4:47](https://youtu.be/i9mRnbdDYxk?t=287))
- **Budget VRAM explicitly: usable memory, minus runtime margin, minus weights and auto-loaded extras, equals tokens of cache.** — A 16GB card is about 17.18 GB in model-file units. llama.cpp keeps about 1 GB back by default. Adding an 11.8 GB model, a 0.35 GB MTP head and a 0.93 GB vision file leaves about 47k tokens at 16-bit cache. Turning vision off and using an 8-bit cache raises that to about 110k tokens. ([6:09](https://youtu.be/i9mRnbdDYxk?t=369))
- **Agent system prompts and tool output consume the window before the user types anything. Tool output is the main source of growth.** — Claude Code's system prompt alone is said to be 30-32k tokens. Luke's Dev Lab measured a Kanban app using 87% of a 128k window and a Blender task using 96%, mainly from file reads, command output and error logs. ([6:09](https://youtu.be/i9mRnbdDYxk?t=369))
- **Three separate effects explain most of the wide tokens/s spread on the same card: spilling out of VRAM, the bandwidth ceiling, and multi-token prediction.** — Once any weights or cache spill into system RAM, speed collapses. A 5070 Ti hit its context limit near 8k tokens and finished 61% of a job, while a 5090 ran at 98 tokens/s on the same task. Decode speed cannot exceed memory bandwidth divided by model file size, because every token reads the full model. ([7:27](https://youtu.be/i9mRnbdDYxk?t=447))
- **Prefill is the hidden latency cost. Before the first token, the whole prompt is processed, so a large agent context can mean minutes of silence.** — The 5060 Ti prefills at about 738 tokens/s, so a 30k-token context means about 41 seconds before output starts. An AMD RX 9060 XT measured 149 tokens/s at 32k context, which is over three minutes. Nvidia's prefill advantage in llama.cpp is large (a 5070 Ti read a 32k prompt more than 3x faster than an RX 9070 XT). ([9:56](https://youtu.be/i9mRnbdDYxk?t=596))
- **Multi-token prediction doubles speed but uses cache. Turn it off once the conversation grows, and pick between speed and context.** — One user on a 5060 Ti went from 27.4 to 45.6 tokens/s with MTP. Another ran about 70 tokens/s with MTP at 32k context and turned it off beyond that because drafts need room. ([9:56](https://youtu.be/i9mRnbdDYxk?t=596))
- **Buy for memory bandwidth and dollars per GB/s, not for a name or a viral video. Price shifts quickly, and the 5060 Ti's street price has risen far above its sticker.** — The RX 9070 XT gives about 43% more bandwidth (640 vs 448 GB/s) at about the same price as a 5060 Ti. The 5060 Ti 16GB is now listed around $789 vs a $429 sticker, up about 84% over retail. ([11:18](https://youtu.be/i9mRnbdDYxk?t=678))
- **The local-vs-hosted decision depends on which model you would run and how many tokens you would generate. Owning a card for a $2.95/M model breaks even at about 294M tokens, but for a $0.16/M model it takes years.** — Hosted Qwen costs about $2.95 per million output tokens on OpenRouter. The local 5060 Ti at 35 tokens/s, 180 W and about 26 cents per million tokens of electricity saves about $2.69/M. Running around the clock, break-even is about 97 days, or about 10 months at 8 hours a day. With a $0.16/M model, break-even stretches to about 2.9 years of nonstop use. ([13:41](https://youtu.be/i9mRnbdDYxk?t=821))
- **For heavy long-context agent work, two 16GB cards with tensor split are the practical answer. Split mode alone can change speed a lot.** — Two 5060 Ti cards cost about $1578. One owner went from 27 to 46 tokens/s by switching from layer split to tensor split. A shared preset goes from a 3-bit model at 64k context on one card to a 6-bit model at 131k on two. ([14:55](https://youtu.be/i9mRnbdDYxk?t=895))

## Techniques
- **VRAM budget before loading a model** — Start from usable VRAM (card size converted to model-file units, minus the runtime's default safety margin, about 1 GB in llama.cpp per the speaker). Subtract the weights, the MTP head and the vision projector file that auto-loads. Divide the remaining space by the model's KV bytes per token (about 64 KB for Qwen 27B, 160 KB for Devstral Small 2) to get the context you can hold. The speaker's example: a 16GB card with an 11.8 GB model leaves about 47k tokens at 16-bit cache. *When:* Before choosing a model and quantization for a local coding agent, and before assuming a 'it fits' demo will last a full session.
- **Reclaim memory from defaults** — Disable the vision file when the work is text-only coding (the speaker cites about 0.93 GB saved). Compress the KV cache to 8-bit instead of 16-bit (the speaker says this roughly doubles usable context on his example, from about 47k to about 110k tokens). Plug the monitor into integrated graphics if available, which the speaker says can recover about 0.5 GB. The exact flag names are not shown in the video. *When:* When the card is almost full at idle and you want more context without changing the model.
- **Turn multi-token prediction off past a context threshold** — Keep MTP on while the conversation is short, since it can nearly double tokens/s. Once the KV cache is large enough that the MTP head's cache need can't be met, disable it. The speaker's example uses about 32k as the switch point on a 16GB card. *When:* Local agent sessions where speed matters early but context growth later eats the room that MTP needs.
- **Size the model to the conversation** — Choose the smallest model that solves the task, and leave enough room for expected context (the speaker's test: how much context is left once the model loads and a real session has run). Avoid the biggest model that barely loads. *When:* Choosing between a bigger quantized model and a smaller model with more context, for an agent that runs for long sessions.
- **Measure prefill and decode separately** — Time-to-first-token is roughly prompt length divided by prefill tokens/s. Decode speed is capped at memory bandwidth divided by model file size. The speaker's check: 448 GB/s over a 10.93 GB model gives an upper bound of about 41 tokens/s, and he measured 35 (85%). *When:* Estimating whether a local setup can hold interactive latency for a long agent prompt, or whether a card's listed bandwidth explains a benchmark.
- **Local-vs-hosted break-even** — Break-even tokens = card price / (hosted $/M output tokens minus local electricity $/M). Local electricity $/M = watts / tokens-per-second, converted to hourly cost and per million tokens. The speaker's example: $789 / ($2.95 - $0.26) per M ≈ 294M tokens. *When:* Deciding whether to buy a local GPU for steady, high-volume generation vs renting hosted tokens for occasional use.
- **Tensor split for two cards** — Use tensor split (rather than layer split) across two identical GPUs to raise tokens/s (speaker: 27 to 46 tokens/s on the same setup). Pair this with a bigger quant and more context across both cards (the speaker's example: 3-bit at 64k on one card, 6-bit at 131k on two). *When:* A workload needs more than about 100k tokens of context routinely and a single 16GB card can't hold it.

## Hot takes
- Fits-in-VRAM demos are misleading; the question to ask is how much room is left once a real session starts.
- The biggest model that loads is the wrong target; the smallest model that solves the problem, with room to spare, is the right one.
- A 16GB Mac is not a 16GB GPU because the GPU share of unified memory is smaller by default.
- Laptop GPU naming is unreliable; check the memory line on the spec, since the same name can ship with 8GB or 16GB.
- For heavy long-context agent work, two mid-range 16GB cards beat one card with more hype.
