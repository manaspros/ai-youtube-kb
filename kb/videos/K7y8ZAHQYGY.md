## Summary
Better Stack podcast episode with SRE consultant Amin Astani, who covers his background (Acquia operations, Meta production engineering) and his view of how agentic coding changes operations. His thesis is that AI-generated code multiplies the change volume flowing through CI/CD, review, deployment and incident response, and that incident load tracks change count, so ops becomes the constraint. He favors compensatory automation: machines handle simple, well-defined mechanisms such as automatic rollback on failed readiness checks, while humans keep judgment over production changes, and AI SRE tools should act only on tightly constrained paths. Practical advice centers on SLOs with error budgets that product leadership actually enforces, fixing the production-to-support-to-product feedback loop, and rewarding reliability work in performance reviews. He pushes back on predictions that code will ship unreviewed and languages will die, using bridge and regulated-software analogies. The back half covers career, burnout and his nomadic lifestyle, with light tool mentions (Concourse for self-hosted CI, a dig at Jenkins). The substance is opinion-driven practitioner advice with anecdotes and no measured data; the consulting and webinar plugs are not sponsored segments.

- **Agentic coding pushes an order of magnitude more change through CI/CD, testing, review and incident response. The speaker says change count and page count scale roughly linearly, so 10x code implies roughly 10x alerts unless the operating model changes.** — Presented as established fact but not backed by data in the episode. Ties to the claim that small teams now face big-tech-scale change flow. ([13:35](https://youtu.be/K7y8ZAHQYGY?t=815))
- **When writing code gets cheap, operations becomes the constraint. The question shifts from whether we can ship to whether it is working and meeting customer expectations, so ops and SRE demand should rise.** — Also argues the fundamentals big companies wrote about for a decade (testing, rollout, postmortems, pipelines) now have to be done by small teams too. ([14:33](https://youtu.be/K7y8ZAHQYGY?t=873))
- **Agentic first-pass diagnosis before a human is paged. - **Two automation philosophies. The leftover principle automates everything and gives humans what is left, which means PhD-level work and over-trusting autonomous systems. - **AI tooling should not change production unless the path is well constrained and well defined. ## Techniques
- **Error-budget decision test for SLO maturity** — When assessing an org's SLO program, ask what the product manager does when an error budget is spent. A concrete answer (sprint scope changes) indicates medium or higher maturity; shipping anyway indicates low. Use SLOs from the customer's point of view to throttle the rate of production changes against revenue risk. The speaker's model rates maturity 1 (immature) to 5 (optimizing). *When:* Before investing in dashboards or alerting, to check whether an SLO program will actually change decisions.
- **Compensatory automation split for production changes** — Automate simple, deterministic mechanisms that are easy to reason about, such as auto-revert when a Kubernetes rollout fails readiness checks. Keep humans on decisions about whether a change should reach production. Restrict any AI-driven production action to a well-defined, pre-approved path, and require human review of infrastructure changes. *When:* Designing AI SRE or agent tooling that can touch production or infrastructure.
- **Agentic first-pass alert triage with human escalation** — On each page, an agent collects recent code changes, alert text and metrics and proposes a diagnosis before a human acts. Escalate to a human when the agent is uncertain or when the fix changes production. Measure ROI per use case before adopting it broadly. *When:* High alert volume where on-call engineers spend time on first-pass diagnosis.
- **Release-path check before scaling AI code output** — Before increasing code output with coding agents, check CI/CD, code review, progressive rollout and test strategy. Track build-to-production latency as a signal of pipeline saturation, and expect alert volume to grow in proportion to change volume. *When:* A team is adopting AI coding tools and seeing more incidents or slower deploys.
- **Postmortem framing beyond human error** — Treat 'human error' as the start of the postmortem, not the conclusion. Ask what factors contributed: access scope, tool ergonomics, sleep, paging load. *When:* Writing or reviewing incident postmortems.
- **Operational excellence in performance criteria** — Include incidents participated in and reliability or scalability work in engineer performance and promotion criteria, so reliability work is rewarded alongside feature shipping. *When:* A company has outgrown founder-level shared ownership and needs aligned incentives across teams.
- **Self-hosted CI with Concourse** — Write pipelines in YAML where each step runs in a container, and self-host the Concourse server. The speaker prefers its open-source governance over vendor-owned CI that can change license. He notes it may be a step back in convenience. *When:* Frustrated by hosted CI outages or license changes, or needing pipelines that stay under your control.

## Hot takes
- If your SRE job is mainly writing YAML and getting paged, question whether it is an SRE role; SRE is about SLOs, toil management and capacity planning, and YAML is not a programming language.
- Leaders who predict unreviewed shipping and dead languages are not on call; monitoring, security and regulated domains still require review.
- The 'DevOps' title has been diluted to a job or tool label, when it should describe a practice joining technology, people, leadership and process.
- 'Friends don't let friends run Jenkins'.
- AI was promised to reduce hours, but the speaker thinks it is increasing burnout through higher expected output; he says the work need is for more workers in more humane conditions.
- Software engineering should adopt a professional-engineer style of discipline (licensing, supervised practice) for systems that affect lives, though he does not say it should copy that model exactly.
