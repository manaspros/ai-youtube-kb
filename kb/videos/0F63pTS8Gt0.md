> Breakdown of the "Avalon beats Strata by 47% on AMD" claim: a llama.cpp fork tuned for one 7900 XT box, and why the number only holds on that machine and that model file.

## Summary
The video takes apart a viral benchmark table in which Avalon, a llama.cpp fork, reports 91 tok/s against Strata's 61.9 tok/s for Qwen 3.8B Flash Next on a Radeon RX 7900 XT. The speaker walks through the hardware (2020 Ryzen, B450 board, PCIe 3 slot, DDR4 at about 34 GB/s measured) and the model's mixture-of-experts layout, then derives a bandwidth ceiling showing why expert caching matters. Avalon's gains are attributed to an expert cache that uses all idle VRAM (27% over Strata without drafting) plus a cheap speculative draft head that accounts for the rest (about 1.15x). The speaker stresses the confounds: two engines and two different model files, a Strata table that was already out of date when posted, and results that flip on other GPUs (RDNA4 favors Strata, Nvidia is roughly tied, dual W7800 gets slower). Avalon's file has better perplexity than Strata's and beats an Unsloth IQ4 quant, but downstream task scores are not published. The closing advice is a four-question checklist for reading any tok/s benchmark: engine version, same model file or not, full hardware including RAM and motherboard, and who owns the hardware.

## Key ideas
- **Benchmark numbers are a photo of one machine and one file pair.** — The 47% is real under the author's protocol (same night, same box, greedy decoding, 512 tokens, median of 3), but it measures the gap between two desks. Strata had speculative drafting on, so neither side was crippled. The comparison still mixes engine and model file, and the speaker says the 27% base gain is partly file versus file. ([3:57](https://youtu.be/0F63pTS8Gt0?t=237))
- **Bandwidth math sets the ceiling for MoE decode.** — Each token touches about 1 GB of expert weights (480 of 24,576 experts across 48 layers, top-10 per layer). At about 34 GB/s of DDR4 that caps decode near 34 tok/s before the GPU does anything; over PCIe 3 at about 14 GB/s the cap falls to about 14 tok/s. The GPU is not the bottleneck, reading expert weights is. ([9:05](https://youtu.be/0F63pTS8Gt0?t=545))
- **Expert cache: use every idle byte of VRAM for hot experts.** — Compute buffers, the unused part of the KV cache and the safety reserve (fixed at 400 MB) all hold experts. The GPU computes resident experts while the CPU handles misses in parallel, and the engine picks per miss whether moving the expert to the card is faster than computing it on the CPU. This is the 27% gain over Strata without drafting (49 to 62.4 tok/s on the same machine). ([11:50](https://youtu.be/0F63pTS8Gt0?t=710))
- **Speculative drafting is expensive on MoE, so the draft head has to be cheap.** — Each guessed token picks its own experts, so verifying guesses costs far more memory traffic than on a dense model. Avalon's draft head is about 1.5 GB (Strata's was 3.4 GB), uses a 65k-token vocabulary and shares the main model's expert cache. It agrees with the main model on 80.7% of positions, and the measured gain is 1.46x, about 1.15x on top of the cache gains. ([13:02](https://youtu.be/0F63pTS8Gt0?t=782))
- **Quality check: the file is larger but scores better on perplexity.** — Avalon's file is about 88 GB against Strata's 78 GB, so it reads more bytes per token and still runs faster. Perplexity is 1.443 vs 1.469 in English and 1.331 vs 1.338 in code, and it beats an Unsloth IQ4 quant (1.401). Perplexity is not task accuracy, and no downstream benchmarks are published yet. ([15:29](https://youtu.be/0F63pTS8Gt0?t=929))
- **Strata's table was stale when posted, and optimization has moved to other GPUs.** — The table lists Strata 0.1.43, but 0.2.8 was current, 14 releases later in 18 days. Strata's AMD work since then targets RDNA4 (R9700), and its 0.2 release notes say the RX 7000 packages were built but not run by maintainers. On a 7900 XT, Strata's community results cluster near 60 tok/s, so the 61.9 figure is fair. ([17:59](https://youtu.be/0F63pTS8Gt0?t=1079))
- **The speed-up does not transfer across GPUs, and it can reverse on multi-GPU.** — On an RTX 4090 Avalon matched Strata, and on RDNA3 W7800s it was slower than on the 7900 XT. With two W7800s, all experts fit in VRAM, the memory-bandwidth floor disappears, and throughput fell to 46/70 tok/s from 58/87 on one card. The speaker's read: once memory is solved, the bottleneck becomes compute, and the 7900 XT-specific tuning does not carry over. ([20:31](https://youtu.be/0F63pTS8Gt0?t=1231))
- **Memory mapping makes a 32 GB machine run the model, but prompt ingestion pays the price.** — With RAM capped at 28 GB, decode fell from 91.2 to 89 tok/s (about 2%), but ingesting a 19k-token prompt went from about 15 s to about 21 s. The tax is paid on each new prompt or agent turn, and the README omits which SSD was tested. ([21:50](https://youtu.be/0F63pTS8Gt0?t=1310))
- **Early single-maintainer forks ship fast and also ship bugs; watch the upstream PR.** — Avalon was counting the expert file size three times in a two-card test (150 GB vs the correct 53 GB) and hung on that setup, both fixed within days. Avalon is a fork and not a pull request. A draft llama.cpp PR from Piotr Wilkin asks maintainers how much specialized code they will accept to compete with specialist engines. ([23:51](https://youtu.be/0F63pTS8Gt0?t=1431))

## Techniques
- **Benchmark provenance checklist** — Before quoting a tok/s number, record the exact engine version (commit or release), whether both engines used the same model file or hash, full hardware (GPU, CPU, motherboard, PCIe generation, RAM speed and channels), and who owns the box. Also record the protocol: same run window, greedy decoding, fixed output length, median of N runs, speculative settings on or off. *When:* Any time a speed comparison is cited in KB notes, in InferCraft/gateway benchmark reports, or in a README. Use it to decide whether a claim transfers to another machine.
- **Bandwidth-ceiling estimate for MoE decode** — Work out bytes of active weights read per token (here about 1 GB: active experts times bytes per expert). Divide by the slowest link that serves them (DDR4 measured at about 34 GB/s, or PCIe 3 at about 14 GB/s). That gives a hard tok/s ceiling. Compare the reported number to it: anything above the ceiling means the weights are being served from VRAM or the numbers are wrong. *When:* Sanity-checking any local-inference claim on a model bigger than VRAM, and choosing whether offload or a bigger card is the fix.
- **Expert cache from spare VRAM with CPU fallback** — Fill every VRAM byte not used for active compute with the most-used experts (buffers borrowed between pipeline phases, unused KV headroom, a computed safety reserve). Run resident experts on the GPU and misses on the CPU in parallel. For each miss, choose dynamically between moving the expert to the GPU and computing it on the CPU. *When:* MoE models whose experts do not fit in VRAM, where reads from RAM set the decode speed. The reported gain is about 27% on a 20 GB card with DDR4-3200.
- **Cheap draft head that shares the expert cache for MoE speculative decoding** — Use a small draft head (about 1.5 GB, a 65k-token vocabulary cut from the full vocab) that reads from the main model's expert cache rather than competing for VRAM. Verify two guessed tokens per pass. Expect a much lower gain than the theoretical maximum because each verification pass touches new experts (about 1.7 normal steps of cost per pass). *When:* When a MoE model has spare memory for drafting. Dense-model speculative decoding numbers do not transfer, because each guessed token picks its own experts.
- **Perplexity as a fast quant-quality screen, with a caveat** — Compare perplexity of two quantized files on the same English and code text sets. Lower is better. Treat it as a screen only and run task benchmarks before claiming parity. *When:* Deciding whether a more aggressive or custom quant is safe to use in place of a standard one.
- **mmap for models larger than VRAM plus RAM** — Let the OS map the model file and page the overflow from SSD. Expect little decode slowdown when capped to about 28 GB of RAM, but a large hit on prompt ingestion (about 40% on a 19k-token prompt) whenever new context is loaded. Check the SSD type, since NVMe and SATA differ widely. *When:* Trying a large model on a 32 GB machine for interactive use with few new long prompts. Avoid it for agent loops that load large contexts often.
- **Diagnose multi-GPU slowdowns as a bottleneck shift** — If adding a GPU lets all weights fit in VRAM and throughput drops, check whether the bottleneck moved from memory bandwidth to compute. Compare compute units across cards (70 CUs on W7800 vs 84 on 7900 XT in the video). *When:* Scaling a local model across cards, or when a kernel tuned for one GPU family regresses on another.

## Hot takes
- The 47% headline compares two engines and two model files on one box. Only the 27% base gain can be separated, and even that is partly file versus file.
- Avalon's own README calls the AI the engine and the author the driver, and says Claude Opus wrote all the GPU and CPU kernels. The video treats this as a provenance fact to note, not a criticism.
- A stale competitor table makes a comparison meaningless: Strata had shipped 14 releases, mostly for RDNA4, after the table was posted.
- Perplexity favoring Avalon's file does not show task quality. The author admits no downstream benchmarks are published.
- Optimizing for one GPU's bandwidth-to-compute balance can make multi-GPU setups slower (dual W7800 lost to one card), so a win on one box is not a general engine win.
- Nvidia is roughly tied with Strata for now because the kernels are not tuned for CUDA. Windows is unsupported (no Vulkan backend).
