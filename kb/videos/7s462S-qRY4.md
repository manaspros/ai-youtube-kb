> Better Stack walkthrough of Floci, a free open-source Docker emulator for AWS services (S3, DynamoDB, Lambda) pitched as a LocalStack alternative after LocalStack's free-tier change; the host re-measures the benchmark claims and runs an end-to-end thumbnail pipeline.

## Summary
Better Stack presents Floci as a free, open-source replacement for LocalStack, which recently moved useful services behind a paid tier. Floci runs as a Docker container and emulates AWS services so code can be tested without an AWS account. The host re-measured the README claims: Floci started in about 129 ms versus the claimed 24 ms, and LocalStack took about 7 s versus the claimed 3.3 s, so the stated numbers are best-case. The relative gap still held, with Floci roughly 50x faster to start, about one-twentieth the memory, and a quarter of the image size. He then ran a realistic pipeline (S3 upload triggers a Python Lambda that writes a thumbnail to a second bucket and metadata to DynamoDB) and reported that the Lambda ran in a real Lambda runtime container that was torn down after invocation. The video also covers a built-in web UI, a one-line migration from an existing LocalStack compose file, and a Testcontainers module for Lambda tests. The video is a tutorial-style tool walkthrough with a donation request at the end, not a sponsored segment, and it shows one test case rather than a broad comparison.

## Techniques
- **Swap LocalStack for Floci in an existing Compose setup** — Keep the existing docker-compose file that points at LocalStack, change the image/service line to Floci, and keep AWS CLI or SDK calls unchanged. The host says this is a one-line change. He did not show the exact line. *When:* Migrating local or CI AWS tests after LocalStack's free-tier change.
- **Run AWS CLI commands against the local emulator** — Start the Floci container with a single docker command, then run aws s3 mb to create a bucket, aws dynamodb create-table to create a table, and aws dynamodb list-tables to check it. The exact endpoint override is not spoken in the video. *When:* Quick smoke tests of bucket and table creation before writing integration tests.
- **Measure emulator startup and idle memory yourself** — The host wrote a small benchmark script that timed container startup and checked idle memory for both Floci and LocalStack. Use the same approach before trusting README numbers. The script itself is not shown. *When:* Choosing an emulator for CI where container startup time costs money across many runs.
- **Test Lambda handlers against a real runtime container** — Deploy a Python Lambda through the setup script and upload an object to the trigger bucket. The emulator starts the Lambda Python runtime image, runs the handler, and removes the container. Check results in the target bucket and DynamoDB table. *When:* End-to-end testing of S3-triggered Lambda pipelines without an AWS account.
- **Inspect state in the bundled web UI** — Open the web UI to browse buckets and objects, view DynamoDB items, look at Lambda config, and invoke a function with a custom JSON payload. *When:* Debugging a local pipeline when CLI output is not enough.
- **Use the Testcontainers module for Lambda tests** — Use Floci's Testcontainers module so the emulator starts and stops inside the test suite lifecycle. No code is shown in the video. *When:* JVM or other Testcontainers-based test suites that need Lambda plus AWS services.
