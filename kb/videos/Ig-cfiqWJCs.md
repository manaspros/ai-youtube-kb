> Feature tour of Cursor 1.0 covering BugBot PR review, remote background agents, per-project memories and one-click MCP install with OAuth, plus the security caveats of background agents.

## Summary
The host walks through four headline features of Cursor 1.0. BugBot reviews GitHub pull request diffs with the same AI as Cursor's agent and leaves comments, but it does not fix anything itself; a "Fix in Cursor" button opens a prefilled prompt. Background agents run asynchronously in a remote Cursor IDE that clones the GitHub repo, not the local machine, and can be steered mid-run. The environment can be set up as a saved snapshot or through a Dockerfile and environment.json. The host flags that background agents run on Cursor's AWS infrastructure, have internet access and auto-run commands, and that environment variables are encrypted at rest. Memories let Cursor remember rules per project (and the host says teammates can see project memories), and MCP servers can be installed with one click plus an OAuth login. The release also adds Jupyter notebook support, Mermaid and markdown table rendering in chat, and usage dashboards. Most of the content is a UI tour with little measurement, and the title's "BEST update yet" is hype.

## Key ideas
- **BugBot reviews PR diffs for bugs with the same AI as Cursor's agent, but it only comments; a 'Fix in Cursor' button opens Cursor with a prefilled fix prompt and marks the relevant line.** — It is a review-then-human-fixes loop rather than an auto-fixer. The host likes this for projects where the AI often misreads intent. ([0:00](https://youtu.be/Ig-cfiqWJCs?t=0))
- **BugBot can be configured to run only when mentioned (e.g. a 'bugbot run' comment), run only once per PR (not again on new commits), and hide the 'no bugs found' comments.** — Configured at cursor.com under integrations after connecting GitHub, with per-repo selection and a spend limit. A 7-day free trial is offered. ([0:59](https://youtu.be/Ig-cfiqWJCs?t=59))
- **Background agents are asynchronous remote agents that clone the repo from GitHub (the host says code is not sent from the local machine), run in a remote Cursor IDE session, and accept follow-up prompts while running.** — Started with Cmd+E from a floating control panel. Results include a green tick, a diff review, and options to create a PR, check out locally, or import into local chat. The host calls it one of the smoothest background-agent UIs he has seen. ([0:59](https://youtu.be/Ig-cfiqWJCs?t=59))
- **Background agent environments can be set up two ways: a base environment saved as a snapshot from the remote IDE, or an advanced setup with a Dockerfile and an environment.json that holds install command, start command and terminals.** — The host says this is in beta, requires turning off privacy mode (so code and telemetry may be sent to Cursor), and that the beta toggle must be enabled. ([3:28](https://youtu.be/Ig-cfiqWJCs?t=208))
- **The host raises a security caveat for background agents: they run on Cursor's AWS infrastructure, have internet access, auto-run all commands, and store environment variables encrypted at rest.** — He says to be careful about what the agent can reach and to understand the implications before using it. He does not go deeper than the docs. ([3:28](https://youtu.be/Ig-cfiqWJCs?t=208))
- **Memories let Cursor store facts from a conversation (e.g. 'always use bun and bunx instead of npm, and use Vite unless a framework is specified') and apply them in later sessions.** — The host demonstrates a stale create-react-app/npx default being replaced by the saved rule. Memories are stored per project and per individual, and the host says teammates on the same project can see them. ([4:40](https://youtu.be/Ig-cfiqWJCs?t=280))
- **MCP servers can be installed in one click from 'Add to Cursor' buttons that developers place on their docs, followed by an OAuth login flow ('needs login') that handles auth without manual token setup.** — The host demonstrates Notion. Cursor also publishes a list of officially recommended MCP servers. ([5:36](https://youtu.be/Ig-cfiqWJCs?t=336))

## Techniques
- **BugBot on GitHub PRs with trigger control** — cursor.com -> Integrations -> connect GitHub -> pick repos -> set spend limit. In preferences, enable 'run only when mentioned' (comment 'bugbot run'), or 'run once per PR' so new commits don't retrigger, and hide 'no bugs found' comments. Use the 'Fix in Cursor' link on a finding to open a prefilled prompt and fix it manually. *When:* PRs where AI review is noisy or costly, and where you want to stay in the loop rather than accept autonomous fixes.
- **Launching a background agent from a prompt** — Press Cmd+E to open the background agent control panel. Paste the task prompt, attach file context (e.g. the relevant .ts file), choose the model, and set the target branch. Reopen with Cmd+E to monitor running agents. Open the remote IDE to watch or send follow-ups; use the menu for checkout locally, create PR, or copy request ID. *When:* Well-scoped, hands-off tasks such as fixing a reported PR bug, where you want the work to run while you do something else.
- **Background agent environment via snapshot or environment.json** — Basic path: open the remote IDE from a background agent, install dependencies, and save the state as a snapshot so future agents start configured. Advanced path: provide a Dockerfile for the machine and an environment.json defining the install command, start command, and terminals. *When:* Repos with setup steps that a fresh agent would otherwise repeat each run.
- **Saving persistent project rules as memories** — In chat, state a rule (e.g. 'always use bun and bunx instead of npm; use Vite unless a framework is specified') and ask Cursor to save it as a memory. Verify the memory updated, then the rule applies in later sessions on that project. *When:* Recurring preferences or corrections on a project, to avoid repeating the same instruction in each session. The host notes memories are per project and per individual.
- **One-click MCP install with OAuth** — Click an 'Add to Cursor' button on the MCP server's docs or Cursor's recommended list, confirm install in Cursor, then click 'needs login' and complete the provider's OAuth flow (the host uses Notion). *When:* Sharing an MCP server with a team, or onboarding to a third-party MCP without managing tokens by hand.

## Hot takes
- The title's 'BEST update yet' is hype. The content is a feature tour with no measurements or comparisons.
- The host calls Cursor's background agent UI one of the smoothest he has seen, because the agent works inside a remote Cursor instance the user can also drive.
- The host treats background agent security as a caveat to be aware of, but background agents with internet access, auto-run commands and env vars deserve more scrutiny than a single mention gives them.
- The 'stored per project, visible to teammates' memory behavior is a potential data-sharing concern that the host presents as a plus.
