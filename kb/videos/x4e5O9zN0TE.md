> Long-running, stateful agents need controlled scenario suites, balanced scorecards and a ratchet loop, not just prompt tweaks; the speaker's case study is a game-village multi-agent system tuned by an outer auto-research loop.

## Summary
Erina Karati (ex-Microsoft, ex-Supercell) presents Project Paradox, a Supercell AI Innovation Lab framework for autonomous game agents with per-agent RAG memory, emotion vectors, trust/belief scores and importance-scored memories. Over long horizons the agents lost social consistency: rumors hardened into facts and sources were forgotten. The team wrapped the system in an auto-research loop, inspired by Karpathy's auto-research, that runs controlled scenarios, collects structured traces, scores behavior, proposes a small policy change, reruns, and keeps the change only if the scorecard improves and guardrails hold. The core argument is that memory alone is not enough: agents must preserve provenance (first-hand vs second-hand, confidence, verified vs uncertain) and separate raw episodic memory from current beliefs. They stress balanced scorecards over one "agent quality" metric and freezing the harness, scenarios and metrics while exposing only a small editable policy surface. The speaker explicitly says they do not yet have repeated loop results, so the talk is a method proposal with one anecdote rather than a proven benchmark.

## Key ideas
- **Long-horizon agents fail in ways single-turn evals miss** — Per-agent RAG memory and a short-term plan worked for brief play, but over longer runs a rumor about mangoes lost its source and became a stated fact, and agents forgot facts they had learned. ([5:58](https://youtu.be/x4e5O9zN0TE?t=358))
- **Auto-research as an outer meta loop, not another agent** — The auto-research layer sits outside the simulated village. It reads full run traces, compares them with scenario ground truth, proposes a constrained protocol change, and reruns to see whether society-level behavior improved. ([7:13](https://youtu.be/x4e5O9zN0TE?t=433))
- **Keep only changes that survive measurement (ratchet)** — Each candidate change is scored and kept only if the scorecard improves and guardrails hold; otherwise it is reverted. Rollback is treated as mandatory because one fix can damage another behavior, such as faster fact spread leaking private info. ([9:54](https://youtu.be/x4e5O9zN0TE?t=594))
- **Use controlled scenarios with ground truth instead of letting agents wander** — Scenarios such as public-fact diffusion, rumor uncertainty and replanning after a blocked route make social behavior measurable. Open-ended simulation can look good in demos but is hard to evaluate. ([11:16](https://youtu.be/x4e5O9zN0TE?t=676))
- **Balanced scorecard, one metric per behavior** — Metrics include reach after N steps (diffusion), source retention (provenance), uncertainty preservation and false-certainty rate (rumors), action consistency and time to re-plan (planning), and containment (privacy). Optimizing one metric alone makes agents overshare or create stale memories. ([12:42](https://youtu.be/x4e5O9zN0TE?t=762))
- **Freeze the harness and expose only a small policy surface** — The loop may edit memory-write and retrieval policy, communication prompts, trust rules, attribution rules and planning triggers. It may not rewrite the codebase, the scenarios or the metrics, which blocks gaming the evaluation. ([14:58](https://youtu.be/x4e5O9zN0TE?t=898))
- **Memory is not enough: store provenance and belief state** — Agents need to know whether a fact was first-hand or second-hand, verified or uncertain, and should separate raw episodic memories from current beliefs. Hedging is required when retelling uncertain claims. ([16:10](https://youtu.be/x4e5O9zN0TE?t=970))
- **Generalizes to other stateful agents (support, personal, research, coding, workflow)** — The speaker argues that any agent whose state affects future action needs scenario suites and behavioral scorecards, with examples like policy-update provenance, commitments, citations and handoffs. ([19:00](https://youtu.be/x4e5O9zN0TE?t=1140))

## Techniques
- **Controlled scenario suite with ground truth** — Define small scenarios with known truth (for example, Agent A learns the bakery closes tomorrow; does the right agent learn it, cite the source and change its plan?). Run the agents, then score against the known answer. *When:* Evaluating multi-agent or long-running stateful behavior where a single answer-quality score hides failures.
- **Balanced behavioral scorecard with guardrails** — Measure several separate dimensions (reach, source retention, uncertainty preservation, false-certainty rate, re-plan time, containment). Accept a change only if the target metric improves and the guardrail metrics do not regress. *When:* Any auto-optimization loop, so the optimizer cannot game one number.
- **Frozen-harness ratchet loop** — Freeze the harness, scenarios and metrics. Let an outer loop edit only a small policy surface, rerun the suite, and keep the change if it passes the scorecard. Otherwise revert. *When:* Self-improvement of an agent system where the optimizer might rewrite the evaluation or the codebase.
- **Structured run-trace logging** — Log observations, conversations, memory writes, retrievals and belief updates for each run, so an outer analyzer can compare what happened with the ground truth. *When:* Before building any automated analysis of agent behavior.
- **Importance-scored memory with a threshold cache** — The LLM rates each event's importance. Memories above a threshold go into a separate high-priority store, so important context is retrieved more reliably later. *When:* Long-lived agents where routine memories would crowd out critical ones.
- **Provenance and confidence tags on memories** — Store the source, whether the info was first-hand or second-hand, a confidence level, and whether it is verified or uncertain. When the agent retells a claim, it must carry the hedge. *When:* Agents that pass information between each other or answer questions about who said what.
- **Separate episodic memory from current belief** — Keep raw episodic memories apart from a derived belief layer that holds what the agent currently holds to be true, with trust and emotion scores that the LLM updates after each interaction. *When:* Agents that must track what is true, uncertain or outdated over time.

## Hot takes
- Memory alone (RAG) does not give long-horizon agent behavior; agents also need provenance and a separate belief state.
- A single vague 'agent quality' metric hides the failures that matter; use a balanced scorecard.
- Self-improvement loops should freeze the harness, scenarios and metrics, and expose only a small policy surface.
- Any agent whose stored state affects future action (support, personal, research, coding, workflow) has the same problem.
