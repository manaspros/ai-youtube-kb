> Walkthrough of Bun 1.4 (the Rust rewrite) and its built-in standard library: headless browser, image processing, markdown, pseudo-terminal, cron, parallel scripts and tar archives, each replacing an npm package.

## Summary
The speaker walks through Bun 1.4 and frames the release as a standard library that replaces about 15 npm dependencies. The main additions are Bun.WebView (a headless browser that can use the system WebKit on macOS or Chrome elsewhere), an image library with chainable transforms and placeholder generation, and three markdown rendering APIs. Other additions are Bun.Terminal for pseudo-terminals via bun.spawn, bun.cron for in-process or OS-level scheduling, a parallel and sequential script runner, and a native tar/gzip archive API that can read files without extracting. The release also adds static file serving in Bun.serve, JSON5 and XML support, and terminal-width-aware string helpers. The speaker reports faster startup and CPU use and a binary about 17% smaller, plus a global virtual store for the isolated linker. The video is a feature tour with little benchmarking, and the speaker is explicit that BunWebView does not yet replace Playwright (no test runner or trace viewer).

## Key ideas
- **Bun 1.4 is a Rust rewrite whose most useful part is a built-in standard library. The speaker frames it as a response to the lack of a JS standard library and to supply-chain risk, and says the video skips the rewrite debate.** — Replaces about 15 npm packages in total. The speaker covers roughly half the release in this video. ([0:00](https://youtu.be/IcoB5AZ6TJ0?t=0))
- **BunWebView replaces Playwright and Puppeteer for lightweight automation, but not for test suites.** — Click, type, press and scroll dispatch native browser events so pages see a real user. On macOS it uses the system WebKit with nothing to install. On Windows or Linux a Chrome backend runs a headless Chrome subprocess or attaches to a running Chrome. Evaluate returns native JS values, and raw CDP is available as a fallback. The speaker says it has no test runner or trace viewer, so it is suited to scraping and computer-use scripts. ([0:00](https://youtu.be/IcoB5AZ6TJ0?t=0))
- **A built-in image library covers the sharp use case, including low-quality placeholders for inlining before the real image loads.** — Operations are chainable: resize, rotate, flip, flop, brightness, sharpness, and format conversion. Width, height and format can be read without decoding pixels. The speaker had deployment and build problems with sharp, so this is the feature they are most excited about. ([1:01](https://youtu.be/IcoB5AZ6TJ0?t=61))
- **Bun.markdown replaces the marked package with three rendering targets.** — Bun.markdown.html returns an HTML string. Bun.markdown.render calls custom callbacks per element, for custom classes or ANSI output. Bun.markdown.react renders React elements and accepts custom components per element. Options toggle GFM tables, autolinks, heading IDs and wiki links. HTML output is not sanitized, so user-authored markdown still needs sanitizing by the caller. ([2:07](https://youtu.be/IcoB5AZ6TJ0?t=127))
- **Bun.Terminal adds a pseudo-terminal, which removes the need for node-pty in Electron-style apps.** — It is passed as the terminal option to bun.spawn, so the subprocess sees a real TTY with colors, cursor movement and interactive prompts. The API can write, resize and close the terminal, and a terminal can be created separately and reused across subprocesses. The speaker suggests Claude Code would be a natural user of these features and wishes it were open source. ([2:07](https://youtu.be/IcoB5AZ6TJ0?t=127))
- **bun.cron has two modes: an in-process callback on the event loop, or a registered OS-level job.** — Passing a function runs it on the event loop with no system cron. Passing a script registers a job with crontab on Linux, launchd on macOS, or Task Scheduler on Windows. It takes standard cron syntax, including named days and helpers such as daily, and can parse an expression to return the next run date. Jobs use local time by default, with an option to set a different zone. ([3:10](https://youtu.be/IcoB5AZ6TJ0?t=190))
- **bun run --parallel and --sequential replace concurrently and npm-run-all, and the speaker expects to use them most.** — Output is prefixed by script name. Options include glob matching of script names, filtering packages within a workspace, and continuing when one script errors. The sequential mode uses the same output and filtering. ([4:09](https://youtu.be/IcoB5AZ6TJ0?t=249))
- **Bun.Archive is a native tar and gzip implementation that can read an archive without extracting it.** — An archive is built from an object mapping paths to contents, where contents can be a string, blob, array or ArrayBuffer. Compression is set with a gzip option at levels 1 to 12. Extraction supports glob patterns. The speaker reads lodash's package.json directly from the npm registry tarball with nothing extracted. ([4:09](https://youtu.be/IcoB5AZ6TJ0?t=249))
- **Bun.serve can now serve static files, and the release adds JSON5, XML and terminal string helpers.** — Static serving replaces serve-static for a public directory. JSON5 and XML can be imported, parsed and stringified natively. Bun.sliceAnsi, Bun.wrapAnsi and Bun.stringWidth are terminal-column-aware and replace slice-ansi, cli-truncate, wrap-ansi and string-width. ([4:09](https://youtu.be/IcoB5AZ6TJ0?t=249))
- **Performance and install-side changes: faster startup and CPU use, a binary 17% smaller, and a global virtual store for the isolated linker.** — With the isolated linker, packages are extracted once per machine and symlinked into each project's node_modules rather than copied per project. The speaker expects this to help with speed and disk use across many projects. No benchmark numbers beyond the binary size are shown. ([5:29](https://youtu.be/IcoB5AZ6TJ0?t=329))

## Techniques
- **Replace Playwright/Puppeteer for light scraping with BunWebView** — Use the Bun.WebView API to drive a page with click, type, press and scroll (native events). Set the backend option to Chrome on Windows and Linux to use a headless Chrome subprocess or attach to a running Chrome. Use evaluate to run JS and get native values back. Fall back to raw CDP commands for anything without a wrapper. The transcript shows no exact code for these calls. *When:* Scraping or computer-use scripts where the page must see real user input. Not for test suites, since there is no test runner or trace viewer.
- **Render markdown with Bun.markdown and sanitize it yourself** — Use Bun.markdown.html for an HTML string, Bun.markdown.render with per-element callbacks for custom classes or ANSI output, or Bun.markdown.react with per-element components. Toggle GFM tables, autolinks, heading IDs and wiki links through the options object. Sanitize HTML output before showing user-authored input. *When:* Replacing the marked package, or rendering markdown into terminal output or React trees.
- **Spawn a subprocess with a pseudo-terminal using bun.spawn** — Pass a terminal option to bun.spawn. The child gets a real TTY. Use the returned terminal to write input, resize it, or close it. Create a terminal separately to reuse it across subprocesses. *When:* Driving interactive CLIs or shells with colors, cursor movement and prompts, instead of node-pty. Relevant when wrapping an interactive CLI from JS.
- **Choose in-process cron or OS-level cron with bun.cron** — bun.cron(fn, expression) runs a function on the event loop. bun.cron(scriptPath, expression) registers a system job (crontab, launchd or Task Scheduler). Expressions use standard cron syntax with named days and helpers like daily. Parsing an expression returns the next run date. Local time is the default, and an explicit timezone can be set. *When:* Scheduled tasks in a Bun app. Use the in-process form while the process lives, and the OS form when the job must survive restarts.
- **Run package.json scripts in parallel or sequence with bun run** — Use bun run --parallel or --sequential. Pass a glob for script names, a workspace filter, and an option to keep running other scripts after a failure. Output is prefixed by script name. *When:* Monorepos or multi-package workspaces that currently use concurrently or npm-run-all.
- **Create, compress and partially read tar archives with Bun.Archive** — Build an archive from an object mapping paths to contents (string, blob, array or ArrayBuffer). Set compress to gzip with a level from 1 to 12. Extract with a glob to select files. Read a single file from an archive without extracting, such as package.json from an npm tarball. *When:* Packaging or inspecting tarballs in build or publish steps, or checking package metadata without writing to disk.
- **Enable the isolated linker with the global virtual store** — Turn on the isolated linker in Bun's install config. Packages are extracted once per machine and symlinked into each project's node_modules. The exact config key was not shown. *When:* Many projects on one machine where duplicate package copies waste disk space and install time.

## Hot takes
- BunWebView does not fully replace Playwright yet because it lacks a test runner and trace viewer; the speaker suits it to scraping and computer-use scripts.
- Bun's standard library reduces supply-chain exposure, which the speaker frames as a response to weekly supply-chain attacks (an unsupported claim in the video).
- Bun.markdown HTML output is not sanitized, so rendering user-written markdown is still the developer's problem.
- The speaker thinks Bun.Terminal and related APIs are the kind of thing Claude Code would use, and wishes Claude Code were open source so these could be seen at scale (speculation).
- The video is a feature tour of release notes with demo snippets, not a benchmark or a comparison.
