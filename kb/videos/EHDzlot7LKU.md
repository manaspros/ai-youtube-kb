## Summary
The host argues that off-the-shelf AI coding frameworks (BMAD, SpecKit and others) often fail because they do not fit a specific project, so engineers should build their own workflow from a few shared principles. The main principle is progressive disclosure: give the model only what it needs now, with skills as the main mechanism and MCP servers reserved for external data. The context window also holds memory files, tool definitions and MCP results, so it fills faster than messages alone suggest. The host recommends keeping decisions and open issues in external note files that survive compaction, and manually compacting or rewinding before the window gets crowded, around 70 percent, instead of waiting for auto-compact near 90 percent. Subagents are presented as a way to isolate research and tool noise from the main context. The talk also covers file formats for notes (YAML, Markdown, XML, JSON), using git history and worktrees as memory, and slash commands for repeated procedures. It is a principles overview with examples, not a step-by-step tutorial, and gives no benchmarks.

## Key ideas
- **Progressive disclosure is the key principle behind any workflow: reveal only what matters now and keep the context window free of things needed later.** — Vague instructions make even newer models load unneeded material. Instead of asking the agent to fix a backend error, ask it to check endpoints one at a time. Narrow, step-by-step requests keep the window clean. ([1:07](https://youtu.be/EHDzlot7LKU?t=67))
- **The context window holds more than the conversation.** — The host says it also includes past messages, memory files, tool definitions and MCP call results. Anthropic models are cited at a 200k-token window and Gemini at 1M, but the host says these numbers shrink quickly in agent tools. ([0:00](https://youtu.be/EHDzlot7LKU?t=0))
- **Skills embody progressive disclosure; MCP servers should be used only when external data is needed.** — A skill's short description tells the agent when to use it, so the full body loads only when needed. The host calls using MCPs for everything a huge mistake and says to reserve them for external sources such as Jira tickets or Figma style guides. ([2:35](https://youtu.be/EHDzlot7LKU?t=155))
- **External note files keep critical context across compaction and resets.** — The agent records decisions, issues and technical debt in files outside the window. After a reset it reads these notes plus the compaction summary to see what is done and what remains. The host calls this especially useful for long-horizon tasks. Agent.md, CLAUDE.md and similar files tell the agent how to structure these notes. ([2:35](https://youtu.be/EHDzlot7LKU?t=155))
- **Attention degrades as the window fills, so manage it yourself before auto-compact.** — The host says that when context passes about 70 percent of its limit, agents pause, hallucinate more and ignore tools. Rather than letting it reach roughly 90 percent and trigger auto-compact, compact or rewind manually, and clear the context between unrelated tasks. This is anecdotal and no measurements are shown. ([3:43](https://youtu.be/EHDzlot7LKU?t=223))
- **Subagents protect the main context by running tool-heavy work in isolation.** — A subagent has its own window and reports only its answer back. The host uses subagents for researching the rules of a new framework and for independent tasks, so the main agent is not filled with searches and tool calls. ([3:43](https://youtu.be/EHDzlot7LKU?t=223))
- **File format affects token cost: use YAML or Markdown for context files and avoid JSON except for small state.** — YAML is the most token-efficient, so the host uses it for schemas, security configs and API details. Markdown suits CLAUDE.md because heading levels aid navigation. XML is said to suit Claude models. JSON is the least efficient and is reserved for small task states. ([5:11](https://youtu.be/EHDzlot7LKU?t=311))
- **Git history works as the progress record, and worktrees support parallel subagents.** — Developers can use commit history as a reminder of progress across a project or a single task. Working in a git-initialized repo lets the agent act on planned steps one at a time and revert when a step fails. Subagents can use separate git worktrees for parallel work. ([6:23](https://youtu.be/EHDzlot7LKU?t=383))
- **Slash commands turn repeated procedures into reusable guides.** — The host uses a catch-up command that explains how project memory is structured, so the agent does not read every file. A commit command sets the message format and the pre-commit checks. MCP calls can be embedded in slash commands. ([6:23](https://youtu.be/EHDzlot7LKU?t=383))

## Techniques
- **Progressive disclosure via skills** — Write each skill with a short description that says when it applies, and keep the detailed instructions in the body so they load only when triggered. Use MCP only for external data, and skills for everything else. *When:* Any time a project accumulates many procedures or reference details that would otherwise bloat every session.
- **External note files for long tasks** — Have the agent keep files for decisions, open issues and technical debt. Tell it in CLAUDE.md or AGENTS.md how the files are organized and what goes in each. After compaction or a fresh session, the agent reads these files to resume. *When:* Complex, multi-session or long-horizon work where the summary alone may lose important details.
- **Manual context hygiene** — Watch the context usage. At around 70 percent, compact manually with a summary, or rewind to delete noisy turns instead of continuing them. Start a new context for each new task. The host does not show exact commands for these actions. *When:* Long sessions where you notice pauses, ignored tools or drift, and before auto-compact would trigger.
- **Delegating research to subagents** — Send research or tool-heavy exploration, such as learning a new framework's rules, to a subagent. It returns only the answer, and the main agent proceeds. Give independent tasks to subagents so they can run in the background. *When:* When a task needs many searches or tool calls whose intermediate output you do not need to keep.
- **Format selection for context files** — Use YAML for schemas, security configs and API details, Markdown for CLAUDE.md-style documentation, and JSON only for small state such as task status. *When:* When writing persistent context files and you want to reduce token cost and keep structure readable.
- **Git as memory and parallelism** — Keep the project in a git repo and commit after each planned step, so the commit history shows progress and failed steps can be reverted. Use git worktrees so subagents can work on separate tasks in parallel. *When:* Multi-step agent work where progress must be tracked and changes must be reversible.
- **Slash commands for repeated procedures** — Create a catch-up command that describes the project's memory layout, so the agent loads the right files. Create a commit command that specifies the message format and the pre-commit checks. Embed the needed MCP calls in the command. *When:* Any procedure you find yourself repeating in prompts, such as commits, documentation updates or project re-orientation.
