> AI LABS walks through four ways to get better websites and UIs from Claude Code: refresh design skills from model prompting guides, use design.md files, plan functional UIs as HTML mockups, and clone existing UIs. Mostly anecdotal, with a sponsor segment.

## Summary
The presenter argues that a harness (the process and skills wrapped around a model) goes stale as models change, and that the default model output drifts toward a safe, average design. An official front-end design skill, which is just a prompt with no references, produced a noticeably better landing page than the model did unaided in their test. Their workflow is to feed a new model's prompting guide and the skill prompt back to Claude and ask for an updated skill, and to check older guides for fixes that were dropped from newer ones. For marketing pages they use design.md brand files applied after generation, effort settings (low to medium for simple tasks, x-high for animation), and a GSAP skill that loads conditionally. For functional UI (dashboards, apps) they plan first, build HTML mockups, generate several variants in a gallery viewer, and convert the approved mockup to shadcn components with the shadcn skill. Verification is set up through an instruction in CLAUDE.md and a verifier subagent that checks output against design.md. Cloning a marketing site uses a single-file capture CLI plus sitemap.xml, and auth-gated apps are cloned from carefully captured screenshots of each state. Most quantitative claims are the authors' own informal tests, and the video includes a paid community plug and a sponsor segment for Kimi K2.6.

## Key ideas
- **Models drift to the safest average design. The presenter calls this converging on the distribution, and says a generic prompt with no skill still produces a bland result.** — Test prompt: landing page for a plantation site, told to be creative and not to load skills. The output had contrast problems and some images failed to load. ([0:00](https://youtu.be/HqD5a2Cae60?t=0))
- **An official front-end design skill, with no references or external resources, is just a prompt. In their test it produced a clearly more polished result with subtle animations.** — This is the main evidence for the claim that a well-written skill prompt changes output quality. ([1:25](https://youtu.be/HqD5a2Cae60?t=85))
- **Refresh a design skill for each new model by feeding it the vendor prompting guide. Paste the skill prompt and the guide into Claude and ask for a rewritten version tuned to that model.** — Result was a layout that turned page elements into cards, with small details such as a CTA styled as a postcard with a stamp. ([1:25](https://youtu.be/HqD5a2Cae60?t=85))
- **Older prompting guides still contain fixes that newer guides dropped. Opus 4.8's guide asked for several design alternatives before committing; the Fable 5 guide omits this, and the model still converges on the same style.** — By the presenter's testing, roughly two in three generated sites still came out with very similar styling. The fix was never really in the newer guide. ([2:53](https://youtu.be/HqD5a2Cae60?t=173))
- **design.md files lock brand language down to fonts and components, which matters because the font drives most of the perceived quality. Use them only for marketing and landing pages, and apply them after the page is generated.** — Sources named: GetDesign.md, a site with design.md files for many brands. Not recommended for functional UI, where the design skill makes dashboards look nice but hard to use. ([2:53](https://youtu.be/HqD5a2Cae60?t=173))
- **Effort is the main control lever. Use low to medium for simple tasks and x-high for animation tasks, which the presenter says need fewer retries. Animation in marketing pages should use GSAP, not CSS.** — The marketing skill has a rule that loads the GSAP skill automatically when an animation is needed. The presenter says the skill setup came from repeatedly hitting 5-hour usage limits. ([4:21](https://youtu.be/HqD5a2Cae60?t=261))
- **Functional UI runs in a separate pipeline: plan, build HTML mockups with a design.md as source of truth, validate the mockups, then convert the approved mockup into the app.** — They also generate several variants and open them together in an internal gallery viewer for side-by-side comparison. The presenter says sub-agents are no longer needed for this with about a million tokens of context. ([5:48](https://youtu.be/HqD5a2Cae60?t=348))
- **Use the shadcn skill to turn the final HTML mockup into shadcn components almost one-to-one. This replaces an earlier, more elaborate workflow built around a shadcn MCP implementation plan. Do not overdo animation in productivity UIs.** — The shadcn skill carries context packaged by the shadcn creators. The functional UI skill is wired to the shadcn skill so most of the workflow is automatic. ([8:44](https://youtu.be/HqD5a2Cae60?t=524))
- **Make self-verification explicit: put a verify instruction and product context in CLAUDE.md, and have a sub-agent check output against design.md rather than trusting the main agent.** — The presenter prefers CLAUDE.md over a separate product.md for product context. The functional UI skill makes the model read CLAUDE.md on every task, and points it at a folder of HTML mockup files for reuse. ([10:11](https://youtu.be/HqD5a2Cae60?t=611))
- **To clone a marketing site, capture HTML, CSS and images with a single-file capture CLI, and use sitemap.xml to discover other pages. For auth-gated apps, capture screenshots of each state (hover, interactions, layout changes) and drag them into Claude instead of pasting them.** — Dragging gives the model file paths, so screenshots can be copied into the clone folder as references. The model then produces an initial HTML version of the interface. ([11:39](https://youtu.be/HqD5a2Cae60?t=699))

## Techniques
- **Refresh a design skill from the model's prompting guide** — Paste the general-purpose design skill prompt and the target model's prompting guide into Claude. Say the guide is for that model and ask for an updated version of the skill. Use the rewritten prompt as the new skill. *When:* Each time a new model ships. Use it to keep a design skill from going stale.
- **Mine older prompting guides for dropped fixes** — Read the prompting guides for previous models as well as the latest one. Look for behavioral fixes that were removed from newer guides, such as asking for several design alternatives before committing, and re-apply them to your skill prompt. *When:* When a newer model still shows a known behavior the latest guide no longer mentions.
- **Set effort by task type** — Use low to medium effort for simple tasks. Use x-high for animation work, which the presenter says gives fewer retries. *When:* When choosing the effort level for a coding or design task with Claude.
- **Conditionally load a sub-skill from a rule** — In the marketing UI skill, add a rule saying when GSAP should be used. When the condition is met, the GSAP skill is loaded automatically alongside it. *When:* When one skill needs specialized knowledge only for some tasks, such as animation.
- **Apply design.md after generation for marketing pages** — Let the design skill generate the landing page first. Then apply a design.md brand file (such as one from GetDesign.md) to lock down fonts, colors, spacing and components. Do not apply it to functional dashboards. *When:* Landing pages where the brand look must be fixed. Skip for app UIs that need usability first.
- **Functional UI pipeline: plan, mockups, gallery, port** — 1) Write a plan. 2) Ask Claude for HTML mockups, not the app. 3) Keep a design.md as the source of truth for all mockups so variants stay visually consistent. 4) Generate several variants and open them together in a viewer for side-by-side comparison. 5) Pick one and convert it to the app with the shadcn skill. *When:* Building dashboards, admin tools or community interfaces where UX choices are unclear up front.
- **Consistent variants via a shared design.md** — When generating multiple UX alternatives, point each generation at the same design.md. The colors, spacing, typography and components then stay consistent while the interaction patterns differ. *When:* Exploring several UX directions and comparing them.
- **CLAUDE.md as product context and verify contract** — Put a self-verification instruction and a description of the product in CLAUDE.md. Have the functional UI skill read CLAUDE.md on every task. Keep HTML mockups in a folder that the skill can reference, and keep design.md in the project. *When:* Projects that use design skills and need the agent to check its own output.
- **Verify with a sub-agent against design.md** — Instead of having the main agent check its own output, spawn a sub-agent to verify the output. Point it at design.md as the reference to compare against. *When:* Before accepting generated UI as done.
- **Clone a marketing site with a capture CLI and sitemap** — Use the single-file capture CLI named in the video to save the page's HTML, CSS and images. If the site has several pages, fetch sitemap.xml and use it to find and capture the other pages. *When:* Cloning a public marketing site.
- **Clone an auth-gated app from screenshots** — Capture screenshots of every state of the interface, including hover states and how interactions change the layout, such as two-column layouts. Drag the images into Claude so the paths are accessible, then have the model copy them into the clone folder as references and generate an initial HTML version. *When:* Cloning an app behind login, where only screenshots are available.

## Hot takes
- Presenter's framing that the harness matters more than the model is asserted, not measured.
- The 'two out of three sites look similar' figure is an informal test with no stated method or sample size.
- The claim that sub-agents no longer matter with a million-token context is asserted without evidence.
- Sponsor segment (Kimi K2.6, with unverified price and parallel-agent claims) and a paid community plug are both present, so treat recommendations in those parts as marketing.
- Much of the advice is generic prompt-engineering for design. The concrete, reusable parts are the prompting-guide rewrite loop, the mockup-first functional UI flow, and the CLAUDE.md verify contract.
