## Summary
The speaker argues that AI-built sites converge on the same generic look because models default to the most common design choices, and that packaged design skills can force a deliberate direction instead. He walks through Anthropic's frontend-design skill, AI Labs' own modified "Break the Default" marketing skill, and a split between functional and marketing UI skills. For product UI he covers ShadCN, presented as a skill (rules plus project context, loaded on demand) paired with a ShadCN MCP (a live registry connection), plus a separate dashboard-layout skill. UI UX Pro Max is described as running a search engine over an open-source database of 161 industry categories before generating a design system, and GSAP is recommended for animation with a performance rule about avoiding layout-triggering property changes. The second half covers taste presets, Higgsfield for image and video generation from the terminal, and mobile skills for platform-specific design (thumb zone rules, Material 3, SwiftUI with Apple docs, Expo). A SciSpace sponsor segment sits in the middle. Most of the value is in the list of named skills; the tutorial steps and concrete commands are absent, and claims are mostly unverified.

## Key ideas
- **AI-generated sites look alike because models reach for the most common design choices; a design skill counters this by forcing a committed direction before any code is written.** — Anthropic's frontend-design skill names common AI-slop patterns in its skill.md (overused fonts, purple gradients on white) and makes the model pick a direction and stay consistent. Best suited to landing pages and portfolios where the design is part of the product. ([0:00](https://youtu.be/Ot582-E61ac?t=0))
- **Split design skills by job: functional UI (dashboards, apps) versus marketing UI (landing pages).** — AI Labs' design system has two skills. The marketing one uses a modified 'Break the Default' prompt, updated from Anthropic's skill because the speaker says it had become outdated for newer models. He says the Anthropic skill works poorly for functional UI, where components must behave correctly. ([2:18](https://youtu.be/Ot582-E61ac?t=138))
- **ShadCN is a skill and an MCP working together: the skill carries rules and project context, and the MCP gives live access to the component registry.** — The speaker says the skill loads only when needed, whereas MCP tool context sits in the window all the time. The skill supplies judgement about correct component usage; the MCP supplies real components pulled into the project. ([3:44](https://youtu.be/Ot582-E61ac?t=224))
- **Dashboards have a layout problem more than a component-consistency problem, so a separate dashboard skill focuses on grouping data and limiting density per screen.** — The dashboard skill is by another developer, not ShadCN. It makes the model reason about information arrangement before building. ([5:12](https://youtu.be/Ot582-E61ac?t=312))
- **UI UX Pro Max runs a reasoning step before code generation rather than only giving design principles.** — The speaker says it fires five searches at once against an open-source database, draws styles from 161 industry categories, selects palette, font pairing and layout, filters out unsuitable options, and outputs a design system the model follows. ([5:12](https://youtu.be/Ot582-E61ac?t=312))
- **Animation written by models usually means a scroll-reveal; GSAP's skill gives correct patterns and a performance rule.** — The speaker's key performance point is to animate properties the browser can composite cheaply rather than size or position, since those force page-wide layout work on each frame. He recommends GSAP for landing pages and scroll-driven storytelling. ([7:52](https://youtu.be/Ot582-E61ac?t=472))
- **Mobile design is treated as its own discipline, with platform-specific skills for Material 3, SwiftUI and Expo.** — Covers thumb-zone placement, consistent spacing, and a limited set of font sizes. Material 3 is said to generate a full theme from one colour. The SwiftUI skill reads Apple documentation from Xcode. Expo covers cross-platform iOS and Android apps. ([11:46](https://youtu.be/Ot582-E61ac?t=706))

## Techniques
- **Commit to a design direction before generating** — Load a design skill (Anthropic frontend-design or a modified variant) whose skill.md names common AI-slop defaults and requires the model to pick one direction and stay consistent with it before writing code. *When:* Landing pages or portfolios where visual identity is the product. The speaker says it is a poor fit for functional app UI.
- **Separate functional and marketing design skills** — Keep one skill for app/dashboard UI and one for marketing pages. Route animation requests on landing pages to the GSAP skill from the marketing skill's instructions. *When:* When one design system has to cover both product screens and landing pages.
- **Pair a rules skill with a component-registry MCP** — Install the ShadCN skill for rules and project context, plus the ShadCN MCP for live registry access. Pull pre-built components instead of having the model write them from scratch. *When:* Building dashboards or product UI on React/Tailwind where consistency and production quality matter more than novelty.
- **Separate layout reasoning from component work for dashboards** — Use a dashboard-specific skill to decide grouping and density of information on screen before component assembly. *When:* Analytics or admin screens that feel cluttered when the model builds them directly.
- **Use a taste preset instead of a full design system** — Drop in one preset skill (minimalist, industrial brutalist, a general front-end UI/UX default, or premium) to steer the look. Do not stack several presets. *When:* When the desired visual direction is already known and a full design system is unnecessary.
- **Prefer compositor-friendly animation properties** — Animate transform and opacity rather than width, height, top or left, so the browser avoids rebuilding layout on every frame. *When:* Scroll-driven or reveal animations on AI-generated pages that stutter.
