## Summary
The speaker argues that AI coding models are weaker at Swift than at Python or JavaScript, citing a study and three causes: little public Swift code, API drift in SwiftUI and concurrency, and benchmarks that are mostly Python and web. He gives seven models (Qwen 3 Coder Next, Grok Code Fast, Kimi K2.5, Gemini 3 Pro, GPT-5.3 Codex, Opus 4.6, GLM-5) the same prompt to build an iOS swipe-and-chat app that uses the Dog CEO API. Where a vendor CLI did not produce an openable Xcode project, he switched to a manually created project and Xcode's built-in AI assistant pointed at OpenRouter, so tool and model change together. The same Gemini 3 Pro gave a broken app through its CLI and a strong first-try app through Xcode's assistant, which shows the harness matters. GPT-5.3 Codex was the first non-Claude model to produce a complete project unaided but had layout bugs. Opus 4.6 through Claude Code, with only permissions granted, produced a working project with the best design. GLM-5 needed three fix rounds and cycled through only three dogs. The ranking rests on one run per model and subjective grading.

## Techniques
- **Fixed-spec, first-try app build as a coding-agent eval** — Give every agent the same single prompt that specifies the app, data source (Dog CEO API), and required features (swipe gestures, match list, per-match chat). Grade in stages: does the project open and compile on the first try, do images load, do swipe and matches work, and how does it look. Record how many fix rounds each run needed. *When:* Comparing coding agents on a stack that public benchmarks under-cover, such as Swift/SwiftUI. Use it as a smoke eval before a larger suite.
- **Check that the output opens, not just that files exist** — Treat a generated Xcode project as a pass only if it opens and compiles in Xcode. Several CLIs emitted files or a README instead of a working .xcodeproj, and the speaker counted that as a failure. *When:* Any agent that writes an IDE project, package or build config. Use it as an acceptance gate before scoring other qualities.
- **Generate an Xcode project from a YAML spec with the codegen CLI** — Write a YAML file with the project details, then run the CodeGen command to produce the .xcodeproj. The transcript says 'CodeGen'; this is probably XcodeGen, but the exact tool and flags are not shown. Give the agent permission to run that command. *When:* When an agent cannot produce a valid .xcodeproj directly. The speaker says some models refuse to write or do not know how to write it.
- **Use Xcode's built-in AI assistant with OpenRouter as the model backend** — Connect the OpenRouter account in Xcode's coding-intelligence settings, pick the model from the dropdown, then highlight all current build issues and ask the assistant to fix the selected issues in one request. Repeat until it compiles. Exact menu paths are not shown. *When:* When you are building an iOS app and want an IDE-native loop rather than a terminal agent. The speaker found it gave better results than some vendor CLIs.
- **Give Claude Code only the permissions it needs, then let it run the whole project** — Run Claude Code with the prompt and the permission prompts pre-approved. No manual Xcode project setup is done beforehand. The transcript does not show a CLAUDE.md or other config. *When:* When you want the agent to create the project, files and build from scratch. This was the only run in the video that worked first try with no pre-setup.

## Hot takes
- The leaderboard is one run per model with subjective grading, and tool and model change together, so it ranks model-plus-harness pairs, not models.
- Gemini 3 Pro's CLI and Xcode results differ so much that 'which model is best' is ill-posed for this kind of test.
- The strongest result (Opus 4.6) was run with only permissions granted and no pre-set-up project, but the transcript does not report config files, system prompts or retries.
- The speaker suggests language-specific coding models for niche stacks but does not test one.
- The GLM-5 claim is checked only on Swift, which he admits, so the Opus-beating claim is neither confirmed nor refuted for web tasks.
