> Towards AI workshop on context engineering: prompt caching makes compaction costly, and on their AI tutor keeping full history beat every compaction preset on recall, cost and latency.

## Summary
Three Towards AI speakers present how they manage context for their AI tutor, which answers student questions from course lessons and docs. They first argue that old tool outputs bloat context, which degrades answer quality (context rot) and raises cost and time-to-first-token. They then explain prompt caching and why it changes the economics of compaction: rewriting context kills the cache, so compaction must shrink context by more than about 50x to pay off. Their tutor uses hybrid retrieval (dense plus BM25, top 30 merged and reranked to 5) and a read-only filesystem knowledge base. They ran presets-by-tasks evals (single-turn Q&A and multi-turn planted-fact sessions) on Gemini 3.5 Flash and then DeepSeek V4 Flash. Across these, keeping the full history beat every compaction preset on recall, cost and latency, because compaction removed tool outputs and forced the agent to re-retrieve. Their conclusion is to name the constraint first and not compact by default; they set a 30K-token compaction threshold and chose DeepSeek for cost. Local 32K-context experiments on a MacBook performed much worse on chat memory, while RAG still worked locally. Numbers are small-sample (60 Q/A pairs, 11-13 turn sessions, one or two trials), and the speakers say so.

## Key ideas
- **Old tool outputs are the main context bloat in their tutor, not the user question.** — Retrieved chunks and past tool call/result pairs grow across turns. The speaker says quality degrades (context rot) and cost and time-to-first-token rise even on the same model. Model switching is not the fix. ([6:06](https://youtu.be/WP3hjUXd918?t=366))
- **Prompt caching changes the compaction math.** — Cached input tokens are much cheaper and faster. Any transform of the prefix (summary, rewrite) is a new context, so the cache misses and you pay full price. The speaker says compaction must compress by more than about 50x to be worth it, and that caching can cut cost by around 90% or more. ([16:37](https://youtu.be/WP3hjUXd918?t=997))
- **Summarization is potentially a trap.** — It rewrites the prefix and kills the cache. The speaker says serious harnesses (Claude Code, Codex) use caching and a different compaction method, so compaction should be used very specifically. ([18:06](https://youtu.be/WP3hjUXd918?t=1086))
- **Keeping full history won on their evals.** — On Gemini 3.5 Flash, across 11 presets, not touching the context gave the best recall, lower cost and lower latency than the production defaults and the compaction presets. The unmeasured production defaults (clear after 5K tokens, summarize after 30K) were not the best. ([43:00](https://youtu.be/WP3hjUXd918?t=2580))
- **Compaction hurt because it removed tool outputs the agent needed again.** — When old tool results are dropped, the agent re-retrieves the same information, which adds tool calls, tokens and latency and lowers recall. ([45:25](https://youtu.be/WP3hjUXd918?t=2725))
- **Summarizing the chat loses specific details; keeping everything does not.** — On DeepSeek, the model answered specific detail questions correctly 95% of the time with full history, versus 32% after summarization. The speaker says the summary drops the exact details. ([51:18](https://youtu.be/WP3hjUXd918?t=3078))
- **The cheapest run was the one that sent the most tokens, because the tokens were cached.** — The full-history DeepSeek setup sent the most tokens, but about 97% were cached, so it was the cheapest. A 36-turn conversation was about 1.78M tokens. Summarizing made the model read and write new tokens every turn. ([52:19](https://youtu.be/WP3hjUXd918?t=3139))
- **Local models fail once the conversation or lessons exceed the window.** — On a MacBook with a 32K window, lessons were already bigger than the window, so caching stopped helping. Keep-all chat recall was about 92-95% in cloud versus about 33% locally. RAG over local documents still reached 100% accuracy. ([55:50](https://youtu.be/WP3hjUXd918?t=3350))
- **Dense-only retrieval fails on facts buried in long context; hybrid holds up.** — Dense retrieval went from about 80% at 50K-200K tokens to 0% recall at 400K for buried facts. BM25 stayed at 100%. This is the reason the tutor uses hybrid search. ([58:48](https://youtu.be/WP3hjUXd918?t=3528))
- **Their rule: do not compact by default; name the constraint first.** — They chose DeepSeek V4 Flash for cost, keep everything, and set compaction at 30K tokens as a backstop. The speaker says the cost gap at scale is large (about $40K/month for Gemini versus about $1.9K/month for DeepSeek at 1,000 students, as stated). ([1:01:21](https://youtu.be/WP3hjUXd918?t=3681))

## Techniques
- **Head and tail truncation of big tool outputs** — Keep the start and end of a large tool result and insert a truncation marker, so the model can re-call the tool if it needs the middle. Needs no LLM. *When:* Tools that return long outputs such as logs, search results or code, where most of the content is not needed.
- **Sliding window and clearing old tool outputs** — Keep only the last N user turns, or clear old tool outputs once they pass a token threshold (their example: clear after 5K tokens but keep the last 5). Pick N and thresholds from your own users and measure them. *When:* Chats with stale tool outputs; a cheap first pass before any LLM-based compaction. Measure against full history because it can cost recall.
- **Selective retention and summarization with a threshold** — A model decides what to keep versus drop (selective retention), or summarizes older turns after a token threshold while keeping the last N messages verbatim (their example: summarize after 30K tokens, keep the last 20 messages). Claude Code's style is to summarize everything and reset. Delta summarization keeps a running summary that a subagent can return to the main agent. *When:* Only when you have a named constraint (window size, cost, latency) that full history cannot meet. Test against keep-all first.
- **Filesystem knowledge base with progressive disclosure** — Store chunks in raw, generated and wiki folders with cross-links to raw files. Expose a short index (about 450 tokens) and let the agent browse it with read-only bash, with an 8-second command timeout, a 40K-character output cap and a 20-command limit per turn. Keep skills small and load them one at a time. *When:* Large corpora that cannot fit in one window. Note the speaker's finding that the extra bash browsing tool added about 50% latency with no recall gain for their simple questions.
- **Hybrid retrieval with a token cap** — Run semantic search and BM25 keyword search, take the top 30 from each, merge, rerank to the top 5, and drop trailing chunks if the total passes 100K tokens. Optionally filter by source first to raise precision. *When:* Retrieval over a large, mixed corpus with code and exact terms. Tune k and the token cap with recall measurements.
- **Eval harness: presets by tasks, then grade** — Define presets (context strategies) and tasks (single-turn Q&A from real student questions, and multi-turn sessions). Run each preset-task pair to save a bundle of metrics as JSON, then grade later with deterministic code checks (correct lesson retrieved) plus an LLM judge. Add a check that the compaction actually fired, so a run counts only if the strategy was exercised. *When:* Before choosing a context strategy for an agent. Their full run cost over $500-600 in API spend.
- **Planted-fact recall probe** — Have a simulated student state a fact early, pad the conversation with filler turns, then ask a question that depends on the fact. Score whether the answer recalls it. *When:* Testing whether a compaction strategy keeps long-range details; cheaper than full task evals.
- **Log every turn** — Record input tokens, output tokens, cached tokens, cost, time to first token, tool call count and whether summarization ran. Also track user frustration signals and abnormally long outputs. *When:* Always, in any production agent. The speaker calls this the step most teams skip.

## Hot takes
- Do not compact by default; name the constraint first and test keep-all against it.
- Summarization is potentially a trap because it kills the prompt cache.
- Full-history context with caching can beat compaction on cost, latency and recall on frontier and cheap cloud models.
- GraphRAG was costlier to set up and tied RAG on their real-user evals, so it was not worth it for them.
- Most teams do not log their agent traffic, and that is the highest-value gap.
