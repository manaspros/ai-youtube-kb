> Walkthrough for running many Claude Code sessions in parallel: resume and handoff basics, file ownership, background dashboards, git worktrees, issue-driven orchestration, and Docker Sandbox isolation.

## Summary
The AI LABS team describes how they run several Claude Code sessions at once without them colliding. They first cover basics: resuming or continuing sessions, a recap command to re-orient, and an export command to move a chat into a new session. For parallel work, they assign each shared file to one session via the prompt and use plan mode to split a project into independent tasks. A handoff skill turns each task into a handover document that references existing files rather than copying them, and background sessions are monitored from an agent dashboard. For coding-specific conflicts (branches, localhost ports, shared dependencies) they recommend git worktrees, then describe an open-source orchestrator (OpenAI Symphony) and a Claude Code fork that polls GitHub issues and opens PRs. Their final layer is Docker Sandbox, a micro-VM sandbox with a clone mode, orchestrated by a planning session that pulls changes back and deletes sandboxes after confirmation. The segment on Docker Sandbox is sponsored, and most commands are described without being spelled out.

## Techniques
- **Session recovery with continue, resume, recap, export** — Run the claude command with the continue flag to reopen the last session on this device. Use the resume flag to pick from a list or pass a session name for a specific one. Run the recap command inside a session to get a short summary of what it was doing. Run the export command to dump the whole chat to a text or markdown file, then start a new session with that file as input. (Exact recap and export syntax is not shown in the video.) *When:* After a crash or reboot, when returning to a session you forgot, or when moving context into a fresh session without carrying all the chat history.
- **File ownership by prompt** — At kickoff, decide which session owns each shared file. Tell every other session in its prompt that it may read that file but must not write to it. *When:* Several sessions must touch the same codebase or shared config and you want to avoid overwrites, without locking or tooling.
- **Plan-mode task decomposition** — In Claude Code plan mode, give the agent all task context and ask it to split the goal into independent tasks that can run in parallel toward one end goal. Review the breakdown for shared-file conflicts before starting sessions. *When:* Building something new with separable parts, where parallel sessions should finish faster without fighting.
- **Handoff documents via the handoff skill** — Install the handoff skill with the install command the video shows (not spelled out in the transcript). In the planning session, invoke it with the keyword handoff and ask for one handover document per task. Each document references the plan file and existing project files instead of copying them, and lists skills to install. Start each task in a new session from its document. *When:* Passing a task to a fresh session without inheriting the planning session's bloated context.
- **Background sessions and the agent dashboard** — Open the agent dashboard with its command (named in the video, exact syntax not spelled out) to see running and finished sessions, move between them, and open any one. Launch a background session with the claude command plus a background flag and a prompt. Inside an active session, run the bg command to keep it running while freeing the terminal. *When:* Running several long tasks at once and needing one place to watch progress.
- **Git worktrees per session** — Ask Claude Code to create a new git worktree for each session. Each session then works on its own branch in its own folder, avoiding file and branch clashes. *When:* Parallel sessions editing the same repo on different branches; does not isolate dependencies or localhost ports.
- **Issue-driven background orchestration** — Run a daemon that watches a GitHub repo for issues with a specific label. When one appears, it launches a background Claude Code session, creates a branch for the task, and opens a PR when finished. OpenAI Symphony uses Linear as the tracker, with a column per task state. *When:* A backlog of well-scoped tasks that should run unattended and land as reviewable PRs.
- **Docker Sandbox for isolated execution with clone mode** — Run the install command, then log in with the login command. Create a sandbox with the sbx command, the name flag and a sandbox name, then Claude as the agent. To keep the real project untouched, add the clone flag so the sandbox works on a clone. Let the planning session spawn one sandbox per subtask, pull changes from each when it finishes, delete the sandbox after confirming the task, and watch progress in the sandbox dashboard. *When:* Agents need to install dependencies, build, or run containers without touching the host, or several subtasks need separate environments.
