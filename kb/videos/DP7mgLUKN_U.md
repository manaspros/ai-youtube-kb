## Summary
The host argues that AI-generated sites look alike because people skip a structured process, not because of the models. He walks through a six-stage workflow on a demo landing page for a fictional architecture firm, starting from installing Warp and VS Code and basic terminal navigation. Stages cover plan mode before building, a CLAUDE.md enriched with business context, a third-party design-rules skill (Hallmark) to de-genericize the layout, a design.md file to lock colors and fonts, and deployment via GitHub and Vercel with commits as checkpoints. The final stages cover feature branches, a pull request reviewed by CodeRabbit (a sponsor), and a ScrollWorld skill that generates scroll-driven 3D video scenes. ## Techniques
- **Plan mode before building** — Start Claude Code in the project folder, press Shift+Tab (or use /plan) to enter plan mode, and give an initial prompt that describes what you are building. Answer its clarifying questions (stack, sections, style, content). When it presents the plan, choose auto mode to execute, or use the third option to suggest changes. *When:* Start of any new build or feature, to catch wrong assumptions before any files are written.
- **Enrich CLAUDE.md with business context** — Run /init to generate CLAUDE.md. Then ask Claude to add the business context: what the business is, why a visitor arrives, and what conversion means (e.g. visitor to client). Keep that file current as the project changes. *When:* When /init output is technically correct but misses the purpose of the product, so later edits keep the business goal.
- **Install and apply a design-rules skill to an existing project** — Install it by typing ! in Claude Code's input (terminal mode), then pasting the installer command. Invoke the skill by name (e.g. 'hallmark') and ask it to rebuild the site. Answer its visual-style question. *When:* When the first AI-generated layout looks generic and needs a redesign without rewriting the product context.
- **Lock visual style with design.md** — Download a design.md from a catalog (the speaker uses aura.build), copy it from Downloads into the project root, rename it to design.md, then prompt: read design.md and revamp the site to match, preserving the existing page structure and animations. *When:* When colors and fonts keep reverting to the model default, and you want the same visual system across later changes.
- **Commit checkpoints and set up GitHub via the CLI** — Ask Claude Code to initialize git and make a commit. For GitHub, ask it to install and set up the GitHub CLI (gh), run the login command it prints in terminal mode, open the link, and enter the one-time code. Then ask it to create a private repo and upload the project. Create a new commit for each new feature. Revert to an earlier commit if a feature is not useful. *When:* Before any risky change, and before deployment, so you can revert and the deploy has a source.
- **Deploy from GitHub to Vercel** — Sign in to Vercel, click Add New, then Project. Connect GitHub, grant access to the repo, click Import, and leave the default settings. Vercel builds on each push. If a build fails, paste the Vercel logs into Claude Code. Later, install the Vercel CLI through Claude Code and log in with the command it prints, so Claude can deploy and fix issues itself. *When:* When a local site needs a public URL that updates on every push.
- **Feature branch, PR, and automated review loop** — Create a branch for the feature (for example, a scrollable version of the landing page), so the live site on main stays untouched. Open a pull request. Use an AI reviewer (the speaker uses CodeRabbit) to list issues, then copy each issue's prompt into Claude Code, or use the reviewer's Fix action, and merge when the findings are resolved. CodeRabbit's free trial was 14 days, per the speaker. *When:* When a change is large or risky enough that you do not want to merge it unreviewed.
- **Scroll-driven 3D site via ScrollWorld skill** — Install the skill by pasting each install command from its GitHub repo into Claude Code one at a time. Run the scroll-world command to plan, then answer the questions about world, look, camera path, and whether to make a mobile version. The skill plans clips on its own from the context and CLAUDE.md, and you can revise them later. Choose a video platform: the default is Higgsfield and the fallback is Midjourney (spoken as 'Higgs field' and 'Manid'), but the speaker used Runway. Any non-default platform needs an MCP server, because the skill gets videos through MCP. *When:* When the site should become a scroll-driven cinematic experience built from generated video clips.
