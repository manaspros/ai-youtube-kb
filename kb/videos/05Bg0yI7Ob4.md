## Summary
The host argues that Lovable apps are hard to scale because they are vendor-locked and lack a proper backend, and presents Leap, which is built on the open-source Encore backend framework, as a fix. In a sponsored demo, he builds a carpet e-commerce store step by step: a React and shadcn/ui MVP prompt, then follow-up prompts for demo Unsplash images, a card-size fix using a reference screenshot, and an auth prompt. He shows the generated backend's ERD and service catalog, then deploys to Encore Cloud with one button. The key segment is the handoff: he clones the repo locally with the platform's clone command and continues in Claude Code to add animations. He admits the broad animation prompt produced more than he wanted, and he runs the backend and frontend locally with Encore's run command and a development.md guide. The video makes no benchmarks or scale tests, so the scaling claims are unverified.

## Techniques
- **Step-by-step MVP prompting for a generated app** — Stack constraints go in the first prompt (for example, React frontend and shadcn as the UI library), plus a list of pages (home, admin). Then add features in follow-up prompts, one at a time, and let the platform validate each step. *When:* Use it for a first version of a CRUD or e-commerce app when you want to check progress between steps. Use a full PRD instead when you already have all the requirements.
- **Reference-image fixes for UI drift** — When a generated UI looks wrong, attach a reference screenshot of the component you want (for example, a product card) and ask for that design. *When:* Use it for visual corrections that are hard to describe in words.
- **Auth as a detailed prompt** — Describe the auth flow in detail in a separate prompt after the core app builds. The platform implements it and then the preview shows an auth page. *When:* Use it when auth is a separate, well-specified step rather than part of the first MVP prompt.
- **Clone-and-continue handoff to a local coding agent** — 1) Log in to the platform from the terminal (the login command is not spelled out in the video, and the presenter presses enter and then clicks allow access in the browser). 2) Open your account, then My apps, then your app. 3) In the Code panel, click Clone and copy the command. 4) Paste it in your terminal. 5) Open Claude Code in the cloned repo and prompt it, for example to add animations. 6) Run the backend with the Encore run command from the backend folder. 7) Set up the frontend using development.md. *When:* Use it when a generated app needs manual changes by a developer or a coding agent and you want the code in your own repo. The video says this is easier than pushing the repo through your own deploy pipeline.
- **Give the agent a platform rule file** — Attach the platform's Encore rule file (linked in the video description, not shown on screen) as context for the coding agent, so it follows the framework's conventions instead of guessing. *When:* Use it for any local edit of an Encore project, so the agent does not need to set up the local preview itself.
- **Scope agent edits tightly** — Name the exact elements to change (for example, 'animate only the hero and the product cards') instead of asking for 'add some animations'. *When:* Use it whenever a broad design request could produce many unwanted changes. The presenter's own broad prompt produced too many animations.
