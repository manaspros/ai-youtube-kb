> Recap of Anthropic's report accusing Alibaba, Moonshot, DeepSeek, Z.ai, Xiaomi and others of industrial-scale distillation of Claude via fake accounts and proxies, plus the API changes it prompted.

## Summary
The presenter summarizes an Anthropic report that accuses several Chinese labs of "illicit distillation": running large volumes of Claude requests through thousands of fake accounts, stolen payment cards and keys, and residential proxy networks. Alibaba (Qwen) is named as the largest case, with 151M+ exchanges between May and July, targeting Claude's chain-of-thought to fine-tune Qwen 3.5 to 3.7 on agentic coding. Moonshot (Kimi) and DeepSeek are described as silently routing customer requests through Opus and then recovering reasoning by "cross-session replay" of thinking signatures, with DeepSeek also routing requests from Claude Code, the Agent SDK and OpenCode to Opus. Smaller cases cover Z.ai, Xiaomi, SenseTime and MiniMax. The report also says forwarded requests exposed sensitive data such as surveillance records and live credentials. Anthropic's countermeasures, as described, are reasoning summaries, "Preserved Thinking" for new accounts, classifiers for extraction prompts, and identity checks for accounts from China, Russia or Iran. Every attribution comes from Anthropic's own report and is not independently verified in the video.

## Techniques
- **Preserved Thinking constraint (Anthropic API, per speaker)** — For multi-turn conversations, keep earlier messages and reasoning blocks unchanged when continuing a conversation. Per the speaker, new API accounts cannot edit the system prompt, tools, or messages before a reasoning block. Do not rewrite history in place to compact or re-inject context. *When:* Any agent loop that changes history: context compaction, checkpoint/resume, or re-running a turn with a modified prompt. Test these paths on a new API account before relying on them. The speaker's description is secondhand, so check the current API docs.
- **Do not depend on raw reasoning text** — Per the speaker, Claude now summarizes its reasoning before responding, and thinking signatures are opaque references. Avoid code that expects full, verbatim thinking text in responses, or that stores and replays thinking blocks as if they were raw traces. *When:* Code that logs, parses or persists thinking blocks, for example eval or trace pipelines that assume complete chain-of-thought.
- **Platform-side extraction defenses (extrapolated, not stated in the video)** — The speaker describes Anthropic classifiers for extraction prompts, with examples of prompts that ask the model to reveal or re-emit its reasoning, and identity verification for risky origins. An operator running a multi-tenant proxy could apply the same idea: flag requests with fixed injected prefixes that ask for reasoning output, and flag bulk account patterns, and log both. *When:* A gateway or proxy that serves many tenants or relays model traffic. This is an extrapolation by the reviewer, not a technique the video teaches.

## Hot takes

- The presenter's asides, such as the sympathy-for-Anthropic joke and the '10% chance of destruction' remark, are opinion and not analysis.

- The Preserved Thinking limit (Fable 5.1, new accounts only) and the summarized-reasoning change are API behavior claims made in passing. Verify them against current docs before building around them.
- Practitioner value is limited: the video gives no reproducible steps. Its main value is the implications for API usage and for proxy and gateway operators.
