> Kai Explains on DeepSeek's open harness: benchmark scores are model-plus-harness pairs, the harness can move scores 5-8 points, and its append-only, cache-stable context design is the most reusable idea, alongside licensing and security concerns.

## Summary
The host argues that every agent benchmark score is a pair of model and harness, and the industry usually publishes only one half. He uses the public Terminal Bench leaderboard, where the same model weights score differently in different harnesses (Gemini 3 Pro moves 8.1 points between Terminus 2 and Gemini CLI). He then walks through DeepSeek's harness, which DeepSeek published alongside a model whose 87.9 Terminal Bench score was produced in its own "minimal mode" with no independently submitted row. The most transferable part is the context design: an append-only event log, a message history rebuilt every turn, and summarization that keeps the cached prefix byte-identical to protect prefix-cache hit rates. A single anecdotal comparison against Claude Code shows a very different cost, token and speed profile, with a worse output. He flags several risks: sub-agent wrappers around Anthropic's and OpenAI's CLIs, a licensing notice he says is unclear, plugins with no isolation, a disabled issues tab on a v0.1 release, and a roughly 12x cache-hit price increase shipped the same day. Quality is high on the benchmark argument, but the talk is a single-reviewer read of a fast-moving repo.

## Key ideas
- **Every benchmark score is a model plus the harness it ran in, and labs usually publish only the model half.** — The host compares an exam-room analogy to benchmark tables. He argues that scores cannot be compared without knowing the harness, and that the harness can move results as much as a model generation. ([1:17](https://youtu.be/y0BW4hpMpyM?t=77))
- **The public Terminal Bench leaderboard lets the wrapper's contribution be read directly.** — Gemini 3 Pro scores 73.9 in Terminus 2 and 65.8 in Gemini CLI, an 8.1-point gap with identical weights. Gemini 3.1 Pro scores 65.8 in the same harness as 3 Pro. He cites similar gaps of about 3.4 points for Claude Code and 5.1 points for Codex CLI. He says the wrapper is worth more than a model generation in four of five pairs. This is the speaker's reading of the table. ([2:33](https://youtu.be/y0BW4hpMpyM?t=153))
- **DeepSeek's headline score has no independent leaderboard row, and its own table shows a competitor ahead.** — The 87.9 Terminal Bench result came from DeepSeek's own run in minimal mode, mentioned in a footnote. No DeepSeek row was submitted to the public board. DeepSeek's own table puts Kimi K3 at 88.3. Two of the ten published rows are internal test sets. ([1:17](https://youtu.be/y0BW4hpMpyM?t=77))
- **The harness keeps an append-only event log and rebuilds the message history from it on every turn.** — Events are only added, never edited. The model's history is derived by replaying the log from the top each turn, and the derived history is frozen, so a plugin that tries to mutate it throws instead of silently corrupting context. The design note with the one-rule philosophy is dated in the repo and is described as the most transferable idea in the repo. ([3:54](https://youtu.be/y0BW4hpMpyM?t=234))
- **Prefix caching drives the design: cache misses cost far more than hits, so the bytes at the start of a request must not change.** — At the time of the note, DeepSeek's cache miss cost 120 times a cache hit. Prefix caching works only when the leading bytes are identical, so any reshuffling or summarization at the front of the request wastes money on every turn of a long agent session. ([5:09](https://youtu.be/y0BW4hpMpyM?t=309))
- **The summarizer is moved to the end of the request so the cached prefix stays intact.** — The first version placed the summarizer instruction at the front, invalidating the cache at the point when history was longest. The fix replays the previous request word for word, then appends the summarization instruction as one new message. Tool definitions the summarizer cannot use are kept, because removing them would shift every later token out of alignment with the cache. ([6:19](https://youtu.be/y0BW4hpMpyM?t=379))
- **A single-tester comparison shows a different cost-speed-quality trade-off from Claude Code.** — On a satellite-tracking task, the DeepSeek harness finished in 11 minutes, used about 483,000 tokens and cost about five cents. Claude Code with Opus 5 was still running at 30 minutes, having used about 48,000 tokens, and the judge preferred its output. The host says this trade-off does not fit a simple better or worse framing. This is one run with one judge. ([6:19](https://youtu.be/y0BW4hpMpyM?t=379))
- **The repo wraps Anthropic's and OpenAI's own CLIs as sub-agent back ends.** — The Claude back end pins the Claude Agent SDK at version 0.3, which bundles Claude Code 2.1 as a roughly 256 MB unpacked payload and defaults to not asking for confirmation, with a Bypass Permissions option. The Codex back end runs the OpenAI Codex app server over stdio. The repo also ships CLAUDE.md and a skills symlink, so Claude Code works inside it. ([7:37](https://youtu.be/y0BW4hpMpyM?t=457))
- **The security model has no plugin isolation, and the licensing notice raises questions.** — Every plugin gets full shell and filesystem access. Plugins are installed from GitHub, and a creator mode runs arbitrary JavaScript against the live runtime, which the docs say to treat as shell access. The third-party notices state that the owner authorizes distribution of Claude Code payloads, and that the terms are not permissive, while the repo is MIT. The host says he is not a lawyer and does not resolve the question. ([10:02](https://youtu.be/y0BW4hpMpyM?t=602))
- **Publishing the harness and its failure postmortems makes the claims checkable, but the release is immature.** — The repo has 728 public design notes, each with an Alternatives Considered section, and four written postmortems, one where an agent edited the UI it was running in and declared success. The issues tab is disabled on a version 0.1 release. Claude Code has about 14,785 open issues by comparison. The host advises against putting production workloads on it. ([11:15](https://youtu.be/y0BW4hpMpyM?t=675))

## Techniques
- **Report scores as model-plus-harness pairs** — Run the same model weights in two or more harnesses on the same task, and record the harness version and mode with each score. Compare the gap between harnesses against the gap between models before drawing conclusions. The public Terminal Bench board lets you read the wrapper's contribution this way. For a vendor's own benchmark, run its minimal mode or rig against a real task you have, rather than trusting the published table. *When:* Choosing a model or harness for agent work, or reading any leaderboard that does not state the harness.
- **Append-only event log with a rebuilt, frozen message history** — Store every agent event (user message, model output, tool call, tool result) as an appended record and never edit an earlier one. On each turn, build the request by replaying the log from the start into a derived message array. Freeze the derived array, so plugins or hooks that try to mutate it throw an error, rather than silently changing context. *When:* Long-running or checkpointed agent sessions, and any harness that must support resume or plugins without corrupting history.
- **Cache-stable summarization and compaction** — Do not put the summarizer instruction at the start of the request, because it invalidates the cached prefix. Replay the previous request exactly as sent, byte for byte, then append the summarization instruction as a new final message. Keep the tool definitions in the request even if the summarizer cannot use them, so that later bytes stay aligned with the cache. *When:* Compacting context in a session that relies on prompt or prefix caching, where a cache miss costs much more than a hit.
- **Track cache-hit rate per agent session** — Log cached and uncached input tokens for each model call. Compute the cache-hit share per session and flag sessions where history is mutated or reordered between turns. The host cites a 100% cache-hit run over two turns and about 20 million tokens as an example of what good looks like. *When:* Auditing the cost of a long agent workload, or checking that a harness change has not broken prefix stability.

## Hot takes
- Benchmark tables that omit the harness are not measurements, and the 8.1-point same-weights gap is the strongest evidence in the talk.
- The talk's title is hype-style ('Not What You Think'), but the content is substantive. Quality is not capped because the claims are checkable from cited leaderboard numbers.
- The host's claim that the wrapper is worth more than a year of model development in four of five pairs is an interpretation of one leaderboard, not a general result.
- The 10x-tokens, 1/20-cost, worse-output comparison is one tester with one judge. The host says so himself and does not generalize it.
- The claim that 20% of the commits came from Codex work trees is a single tweet, and the host flags it as unconfirmed.
- The licensing concern is raised but not resolved: the host says he is not a lawyer, and the MIT repo's third-party notices and the upstream Claude Code repo's missing license point in different directions.
- Shipping a version 0.1 release with a disabled issues tab, plus bypass-permission defaults and no plugin isolation, makes this unsafe for production, as the host warns.
- The append-only log with frozen derived history is the most reusable idea here, and it applies independently of the DeepSeek harness.
- Model names as captioned (Fable 5, Opus 5, GPT 5.5) may be transcription errors. The scores attached to them were not verified against the leaderboard in this session.
