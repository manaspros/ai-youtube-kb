> Walkthrough of Mirage, a virtual file system that mounts Gmail, Drive, Slack and similar services as folders so Claude Code can read them with bash instead of MCP tool calls. Partly sponsored, with a hype title.

## Summary
The presenter introduces Mirage, a virtual file system that exposes SaaS services (Gmail, Google Drive, Slack, Notion, Google Chat and others) as directories an agent can browse with ordinary file commands. The core argument is that models already know Unix file operations from training, so a file interface costs fewer tokens than many MCP tool descriptions. The demo covers reading email attachments as files, copying a large Drive file with cp instead of the Drive MCP's string-based download (about four minutes for a 2 MB file in their test), and chaining bash commands across services so intermediate data never enters the context window. Setup is mostly delegated to Claude Code, but macOS needs macFUSE, a restart and security changes, and OAuth credentials must be created by hand in Google Cloud Console. The presenter notes that the workspace's cache and index are lost on process restart, and that a background daemon (a persistent HTTP server with named workspaces) addresses this and allows hosting the workspace elsewhere. The video runs about ten minutes and includes a sponsor segment for an AI subscription aggregator.

## Key ideas
- **Mirage turns SaaS APIs into a virtual file system: each service (Gmail labels, Drive, Slack channels, Notion) appears as a folder, and emails, chats and files appear as files that Claude reads like markdown in a repo.** — The presenter frames this as an alternative to the search-then-fetch-then-reply MCP sequence. The backend uses the same APIs the MCP servers call, but exposes the results as a filesystem. ([0:00](https://youtu.be/B44bXmzU60s?t=0))
- **The presenter's rationale is that a file interface is one the model already knows well from training, so it needs little or no tool-description overhead, while each new MCP or API tool has to be learned and paid for in tokens.** — This is asserted, not measured. The claim is that basic file commands appear so often in training code that the model does not need a schema for them. ([1:22](https://youtu.be/B44bXmzU60s?t=82))
- **MCP attachment handling is a real limitation: the Gmail MCP exposes only attachment filenames, while a mounted Gmail folder lets the agent open and read the attachment contents directly.** — In the demo the agent read a full invoice from an inbox attachment. With MCP, the user had to download the file and paste it into context by hand. ([3:13](https://youtu.be/B44bXmzU60s?t=193))
- **Large file transfer through an MCP download tool is inefficient: content is returned as a string, decoded and written back, which bloats context and can hit response limits for big files.** — A 2 MB Drive file took about four minutes through the Drive MCP, and the presenter estimates a 100 MB file would exceed the response limit. With the file mounted, a plain cp copied it directly. ([4:20](https://youtu.be/B44bXmzU60s?t=260))
- **Bash pipelines over mounted folders replace MCP tool chaining, and the data never has to enter the model's context window.** — The example is finding emails that mention sponsors, ranking the top three by payment, and writing them to a Notion page. The presenter compares this to Docker's code mode, where tool calls are composed in code. ([6:58](https://youtu.be/B44bXmzU60s?t=418))
- **The setup is a multi-step install with real friction on macOS: macFUSE is a system extension that requires a restart and security settings changes, and the chat session is lost on restart.** — Claude Code can drive most of the install via Homebrew. The presenter's workaround for session loss is to rename the chat or have the agent read the stored prior chats from disk. ([5:31](https://youtu.be/B44bXmzU60s?t=331))
- **Authentication is not automatic. Each new service gets a TypeScript mount file, then needs its own credentials; Google services require enabling APIs and creating OAuth credentials in Google Cloud Console.** — The presenter says Claude walks through the Google Cloud steps, which the presenter calls time-consuming. ([5:31](https://youtu.be/B44bXmzU60s?t=331))
- **Cache and index are lost whenever the mount process restarts. Mirage's answer is a daemon that runs as a persistent HTTP server with named workspaces, which also allows hosting the workspace on another machine.** — The presenter notes that a plain background process starts over on each restart. The daemon fix is described but not benchmarked in the video. ([9:39](https://youtu.be/B44bXmzU60s?t=579))

## Techniques
- **Mount a SaaS service as a folder** — Clone the Mirage source repo locally, open Claude Code inside it, and ask it to install and mount a service (e.g. Gmail). Claude adds a TypeScript file that defines the service as a directory in the workspace, then asks for credentials. For Google services, enable the needed APIs and create OAuth credentials in Google Cloud Console (Claude guides the steps). Each Gmail label or category then appears as its own directory. Exact commands, the repo name and config file names are not shown in the transcript. *When:* Any time you want an agent to browse and search an API-backed service with ls, cat and grep instead of tool calls, for example email triage or document search across services.
- **Run the mount as a long-lived process** — After setup, Claude asks you to run the mount command in a separate terminal and keep that terminal open. Alternatively, run it as a background process. The persistent option is the daemon, a standard HTTP server that holds named workspaces, each started in the mode you choose. *When:* Use a background process for quick experiments. Use the daemon when cache and index must survive restarts, or when the workspace should run on a different machine, such as a laptop accessing a home server.
- **Start the agent inside the mounted workspace** — cd into the Mirage workspace folder and start Claude Code there. The mounted services show up as directories, so Claude can list, search and read them with standard file commands. *When:* Any session that works across multiple mounted services, so the agent does not need a separate tool schema for each one.
- **Chain bash commands across services instead of MCP calls** — Let the agent write a pipeline of shell commands. Examples from the video: copy a Drive file into a local documents folder with cp, or search the inbox for sponsor emails, rank them, and write the top three to a Notion page. Intermediate results stay in the shell, not in the model's context. *When:* Bulk or multi-step operations, or any transfer of large files that would otherwise be returned as text through an MCP tool.
- **Read attachments as files** — Ask the agent to search the inbox for attachments and open them. The attachment is an ordinary file in the mounted tree, so its contents can be read directly without downloading and pasting. *When:* Document-heavy email workflows such as invoice review, where MCP only exposes attachment filenames.
- **Preserve a session across restarts** — Before a restart that will end the chat, rename the session with Claude Code's built-in slash command, or after restarting ask Claude to read the earlier chats, which are stored on disk. *When:* Whenever a macOS install or other restart would otherwise lose the working context.
- **Wrap any API as a file system** — Take the API a service's MCP server uses and expose its resources as files, as in the Google Chat example: add the app to a space, grant read access, and let the agent fetch the space's messages as files. Expect retries and feedback loops, because the agent makes mistakes while building the adapter. *When:* When an MCP server is missing, too heavy, or does not expose the data as files, and you can accept building and debugging a custom adapter.
- **macOS FUSE prerequisite** — Mirage needs macFUSE to mount as a file system on macOS. Claude Code can install it through Homebrew. Follow the steps, approve the system extension, change the macOS security configuration, and restart. *When:* Only on macOS. Linux setups are not covered in the video.
