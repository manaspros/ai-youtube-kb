> A tutorial on pairing Cursor's agent with the CodeRabbit extension: commit each implementation chunk, run a review, feed suggestions back, and drive a phased implementation plan.

## Summary
The presenter argues that agent-written code needs a review step after each chunk, since Cursor's agent introduces errors and security gaps. They install the CodeRabbit extension in Cursor, which reviews changes when they are committed to git, not when they are saved. Reviews are then fed back to the agent, either one suggestion at a time through a "Fix with AI" button or as pasted feedback. A known bug stops reviews from triggering unless the working branch is visible in the branch list, and the presenter worked around it by creating a test branch from main. The main workflow is a 10-phase implementation plan generated from a structure.md file, where the agent marks each phase in progress, commits locally, gets reviewed, and then marks the phase complete. The video is a single-builder demo of a Next.js storefront, so the evidence is anecdotal, and the presenter names one concrete security fix (password storage) and one model preference (Gemini 2.5 Pro).

## Key ideas
- **Review agent output at every chunk, not at the end** — The presenter argues Cursor's agent throws random errors and leaves security holes, so a review after each generated segment catches them early. CodeRabbit's extension is positioned as the reviewer that runs between agent steps. ([0:00](https://youtu.be/LXk8nWwOPuY?t=0))
- **The review trigger is git commit, not file save** — CodeRabbit reads changes through git. The repo must be initialized, and each commit triggers a review prompt, so the 'save' that matters is a commit. The presenter notes that committing is what triggers the review, which makes the commit the review gate. ([2:38](https://youtu.be/LXk8nWwOPuY?t=158))
- **Known bug: reviews don't trigger unless the branch is visible** — The presenter reports a bug where commits did not trigger reviews. The fix from the vendor's Discord was to make the branch visible in the branch list. Once it was created from main and selected, commits on that branch were reviewed. The presenter says this is a known bug, relayed secondhand. ([3:45](https://youtu.be/LXk8nWwOPuY?t=225))
- **Suggestions are fed back to the agent one at a time** — Each review comment has a 'Fix with AI' action that copies code-gen instructions to the clipboard. The presenter pastes them into the Cursor agent one by one, since models handle multiple tasks poorly. He calls this the tedious part and wants the comments extracted automatically. ([5:54](https://youtu.be/LXk8nWwOPuY?t=354))
- **Gemini 2.5 Pro handled multiple review comments at once** — The presenter reports that Gemini 2.5 Pro was the only model that reliably took several instructions together. He gave it three comments from the address form in one go. This is one person's experience on one project. ([5:54](https://youtu.be/LXk8nWwOPuY?t=354))
- **Phased implementation plan drives the agent with review gates** — The workflow is: describe the project and stack, have the agent list pages and modules in structure.md, generate a 10-phase plan, then run each phase. The agent marks a phase in progress, implements it, commits locally, gets reviewed, takes the pasted suggestions as input, marks the phase complete, and moves on. ([8:34](https://youtu.be/LXk8nWwOPuY?t=514))
- **Review caught a concrete security issue, and the agent-built UI was a regret** — The presenter says the review tightened security, especially password storage that had been handled incorrectly. He regrets having the agent hand-build components instead of using shadcn components, which he calls the wrong decision in hindsight. ([7:22](https://youtu.be/LXk8nWwOPuY?t=442))

## Techniques
- **Commit-gated review loop** — Run `git init` in the project, then `git add .` and `git commit -m "initial commit"`. After each implementation chunk, commit with `git add` and `git commit`. Each commit triggers the CodeRabbit extension to review the changes. Take the suggestions and feed them back to the Cursor agent before continuing. *When:* Use it when an agent builds a project in chunks and you want security and quality issues caught after each chunk, not at the end.
- **Branch-visibility workaround for missing reviews** — If commits do not trigger a review, open the branch panel, make sure the working branch is visible in the branch list, and create a new branch from main (the presenter named it 'test'). Select that branch, make a change, commit it, and the review runs against the selected branch. *When:* Use it when CodeRabbit does not start reviewing commits. The presenter attributes the problem to a known bug, so check the vendor's community channels first.
- **One-comment-per-paste fix loop** — Open a review comment, click 'Fix with AI' to copy its code-gen instructions, and paste them into the Cursor agent. Repeat for each comment. The presenter says Gemini 2.5 Pro was the one model that handled several pasted comments at once. *When:* Use it when the review returns several suggestions and you want the agent to apply them. Batching comments into one prompt may fail on other models.
- **Phase-by-phase plan with a structure file** — 1) Describe the project and tech stack to the agent. 2) Have it list every page and module in a structure.md file. 3) Ask for a 10-phase implementation plan based on that file. 4) Add a Cursor settings rule so the agent stays attached and asks clarifying questions before proceeding. 5) For each phase, the agent marks it in progress, implements it, commits locally, runs the review, takes the pasted suggestions as input, then marks the phase complete and moves to the next one. *When:* Use it for a greenfield app built by an agent when you want autonomous progress with a review checkpoint at each phase boundary.
