> Mac Studio M5 vs Ryzen AI Max+ 395 for local AI: prefill, not tokens/sec, dominates wait time, MoE models shrink Apple's lead, and cheap AMD mini PCs can be misconfigured traps.

## Summary
Kai Explains compares a 128GB Mac Studio M5 with a 128GB AMD Ryzen AI Max+ 395 machine after living with both for local AI work. The core argument is that local inference has two phases: prefill (compute-bound, reading the whole prompt) and decode (memory-bandwidth-bound, generating tokens), and the tokens-per-second number that reviews publish only measures decode. Apple's bandwidth lead is real but shrinks sharply on mixture-of-experts models, which are the mainstream choice at 128GB. On AMD, the software stack matters a great deal: the same chip ran under 5 TFLOPS in one configuration and 36 TFLOPS with the right BLAS library, and a few config changes plus newer open-source attention kernels gave large gains. The speaker recommends a multi-model "constellation" architecture where several small models stay resident in memory, and warns that some cheap Ryzen AI Max+ mini PCs ship with half-speed memory or broken ROCm. Most performance figures come from community or secondhand developer benchmarks, and the speaker's own methodology is only partly shown.

## Key ideas
- **Local inference has two phases with different bottlenecks** — Prefill reads the whole input (prompt, files, history, agent context) and is limited by raw GPU compute. Decode generates one token at a time, reading weights from memory each token, so it is limited by memory bandwidth. Standard tokens/sec benchmarks measure only decode. ([2:38](https://youtu.be/dlyic4oco4s?t=158))
- **Decode speed is the less important half of the wait** — A developer benchmark on an M1 Max with a 35B model showed a framework with faster decode (57 tok/s, ~655 token context) finishing last end to end because prefill dominated. At ~8,500 context tokens prefill was 94% of total wait time. ([3:54](https://youtu.be/dlyic4oco4s?t=234))
- **MoE models shrink the Mac's bandwidth advantage** — The Mac leads 2.26x on dense Gemma 4 12B, 1.6x on gpt-oss-120b (about 5.1B active params), and only about 25% on a Qwen3.6 35B-A3B-class MoE (about 3B active). Most models worth running at 128GB are MoE. ([5:05](https://youtu.be/dlyic4oco4s?t=305))
- **The AMD platform's performance depends heavily on the software stack** — Theoretical GPU peak is about 59 TFLOPS. Without the right stack the chip delivered under 5 TFLOPS; with hipBLASLt it reached 36 TFLOPS on the same hardware. Measured memory bandwidth was about 212 GB/s against a 256 GB/s spec. ([6:21](https://youtu.be/dlyic4oco4s?t=381))
- **Free configuration tuning gave about 12-13% prefill gains** — Four software-only changes, roughly 20 minutes of work, documented by a developer: run headless so the desktop does not hold memory, raise GPU allocation to near max, install a performance daemon, and add one kernel command-line option. Prefill rose 13% on a 35B model and 12% on a 122B model, with sustained generation gains too. ([7:45](https://youtu.be/dlyic4oco4s?t=465))
- **Open-source attention kernels roughly doubled decode and tripled prefill on AMD** — Newer MIT-licensed attention implementations (dflash and pflash) for the integrated GPU took Qwen 3.6 decode above 2x and prefill above 3x. A 16k-token prompt with a 1k-token answer dropped from 147s to 58s. The speaker frames this as a free software gain versus the chip-purchase gains on Apple. ([8:46](https://youtu.be/dlyic4oco4s?t=526))
- **Use a constellation of small resident models rather than one giant model** — A 27-30B coding model as the main brain, plus small models for routing, summarization, vision/OCR, cleaning retrieval results, and checking tool outputs. Small models prefill fast and can run concurrently. The target is 30-60 tok/s per session with 3-4 sessions under an orchestrator. 128GB keeps them all resident and avoids model swapping. ([9:44](https://youtu.be/dlyic4oco4s?t=584))
- **Power draw changes the economics of always-on local AI** — The Mac Studio peaks around 480W sustained. The AMD box runs under 100W on a 35B model. On a 120B model the AMD box reached 46.9 tok/s versus 13.77 tok/s on a dual-3090 Ti tower drawing from a 1500W PSU. ([10:56](https://youtu.be/dlyic4oco4s?t=656))
- **Cheap Ryzen AI Max+ mini PCs can be traps** — Some cheap boxes shipped with the memory bus at half speed (about 117 GB/s measured versus about 215 expected when correct). Others have ROCm broken, with a critical memory error and an open AMD bug; falling back to another backend loses flash attention. The known-good variants cost $600-1,000 more. Named as known-good: Minis Forum MS-S1 Max and Framework Desktop. ([12:21](https://youtu.be/dlyic4oco4s?t=741))
- **Buying guidance depends on workload** — Choose Mac for dense models, image or video generation, more than 128GB (up to 512GB on M5 Ultra), or a machine that doubles as a workstation (about 27% faster single-core and roughly a third faster llama.cpp compile). Choose AMD for MoE models, a local-over-cloud requirement, and willingness to do configuration work. ([13:39](https://youtu.be/dlyic4oco4s?t=819))

## Techniques
- **Measure prefill and decode separately, at your real context length** — Report time-to-first-token (prefill) and decode tok/s separately, and also end-to-end wall time, for prompts at the context size you actually use (the speaker's examples are 655 and 8,500 tokens). Use end-to-end time to rank frameworks and hardware. *When:* Comparing inference frameworks or hardware for agent or coding workloads where prompts are long and reused.
- **Pick hardware by model architecture** — Dense models: memory bandwidth dominates decode, so a higher-bandwidth platform wins by a large margin. MoE models: the bandwidth advantage shrinks, so compute (prefill) and cost per capacity matter more. *When:* Deciding between a high-bandwidth Apple machine and a cheaper unified-memory AMD box for a given model mix.
- **Check that the GPU math library is actually in use** — Compare achieved matmul throughput with the GPU's theoretical TFLOPS. The speaker saw under 9% of peak on AMD without the right stack and about 61% with hipBLASLt. The talk names the library but gives no benchmark command. *When:* Bringing up or diagnosing a local inference box that is slower than its spec predicts.
- **Tune the AMD unified-memory box (documented steps as described)** — (1) Run headless so the desktop does not hold memory. (2) Raise the GPU memory allocation from default to near maximum. (3) Install a performance daemon. (4) Append one line to the kernel command line. The talk names no exact keys, package or file names. *When:* After buying a Ryzen AI Max+ 395 machine. Expect about 12-13% prefill gains, with about 20 minutes of work.
- **Run a constellation of small resident models under an orchestrator** — Keep one 27-30B coding model as the main agent brain. Add small models for routing, summarization, vision/OCR, retrieval cleanup, and tool-output checking. Keep all of them in memory and run 3-4 sessions concurrently under an orchestrator, targeting 30-60 tok/s per session. *When:* Building a local multi-agent or RAG workflow where model swapping would hurt latency, and a single large model would be too slow.
- **Vet mini-PC SKUs before buying** — Measure memory bandwidth (about 215 GB/s expected when correct for this platform) and confirm ROCm works (no critical memory error, flash attention available). Check community reports for the specific variant, since listings do not show firmware memory-bus settings. *When:* Buying a Ryzen AI Max+ 395 mini PC from a mix of vendors at different price points.
- **Use newer open-source attention kernels on the AMD iGPU** — The talk credits MIT-licensed dflash and pflash attention implementations for the integrated GPU, with decode above 2x and prefill above 3x on Qwen 3.6. No repository URL or install steps are given in the talk. *When:* Running long-context inference on the Ryzen AI Max+ platform; treat the numbers as the speaker's cited figures, not independently verified here.

## Hot takes
- Tokens/sec, the number every review plots, is the less important half of the local AI experience for real long-prompt work.
- On AMD, software-stack improvements over a year (2-3x) are a bigger lever than the Mac's hardware generation gain, and they are free.
- Cheap Ryzen AI Max+ 395 mini PCs are traps; paying $600-1,000 more for a community-verified variant is worth it.
- Caveat: many figures are secondhand community or single-developer benchmarks; the 94% prefill figure is from an M1 Max with a 35B model, not the M5 Mac Studio. The speaker's own methodology and full run conditions are only partly shown.
- The talk is opinionated but not sponsored as far as the transcript shows; the buying advice is the speaker's judgment, not a benchmark result.
