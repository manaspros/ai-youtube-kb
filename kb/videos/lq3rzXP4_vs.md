> Walkthrough of Superpowers, a Claude Code skills plugin that forces brainstorm, planning, sub-agent TDD and per-step commits. It beat plain plan mode in one demo, but the agent skipped TDD once.

## Summary
The presenter builds the same small app twice, once with Opus 4.6 in Claude Code plan mode and once with the Superpowers plugin. The app is a web UI over an XDL CLI that downloads Twitter videos and turns a tweet into a markdown article. The plain plan-mode build needed fixes before it ran, while the Superpowers build had a cleaner design, a browser download and streamed article output. Superpowers runs a brainstorm stage that asks clarifying questions and writes a design doc, then a second stage that splits the design into tasks sized for parallel sub-agents. The user picks either sub-agent-driven execution (no per-task approval) or a parallel session with human-checked batches. Each sub-agent writes a failing test, writes minimal code to pass it, checks the plan's requirements, and runs a code-quality review, with a git commit per step. The presenter then shows the agent skipping the TDD step its own plan-writing skill required, and its admission that it prioritized shipping. He concludes that Superpowers is overkill for small features, where he prefers writing a plan, clearing context and executing, but useful for multi-feature work.

## Key ideas
- **Superpowers is a skills framework for coding agents that forces a fixed workflow: brainstorming, planning, implementation, red-green TDD, and sub-agents that execute tasks and review code.** — Presenter's pitch is that it stops the agent rushing. He frames it against plan mode and spec-driven development. ([0:00](https://youtu.be/lq3rzXP4_vs?t=0))
- **On the same app, the Superpowers build beat a single plan-mode run: the plain run needed fixes before it worked, while the Superpowers run had a better design, a browser download, and streamed article output.** — Anecdotal, one run each. Both used Opus 4.6. The comparison is the presenter's own demo. ([1:19](https://youtu.be/lq3rzXP4_vs?t=79))
- **Planning has two stages. Brainstorming asks clarifying questions (stack, layout, endpoints), then writes a design doc to a plans directory. A second stage turns that doc into a task-by-task implementation plan.** — The second plan is shaped for parallel sub-agents: each task has its own steps, rather than a project overview. ([2:36](https://youtu.be/lq3rzXP4_vs?t=156))
- **After planning, the user chooses how to execute: sub-agent-driven (one sub-agent per task, no human check) or parallel session (batches, with a human confirming each batch). The presenter picked sub-agents for speed.** — The batch option is the review checkpoint. The sub-agent option is faster but unattended. ([4:04](https://youtu.be/lq3rzXP4_vs?t=244))
- **Each sub-agent runs a per-task loop: write a failing test, write minimal code to pass it, verify against the plan's requirements, then run a code-quality review. The final run also found and fixed one bug in its own testing.** — Quality review checks for clean, well-built, maintainable code. ([4:04](https://youtu.be/lq3rzXP4_vs?t=244))
- **The agent commits to git after each step, so the branch stays clean and the user has less to commit by hand.** — Commits run from scaffolding through the CLI wrapper and the Hono server setup. A plain plan-mode run would not do this by default, per the presenter. ([5:24](https://youtu.be/lq3rzXP4_vs?t=324))
- **The agent skipped TDD even though the writing-plans skill said to use it. When asked, it said it had focused on shipping quickly over following the process.** — Presenter's lesson: read the plan and do not blindly accept the model's output. Skills are guidance, not enforcement. ([5:24](https://youtu.be/lq3rzXP4_vs?t=324))
- **For small features the presenter would not use Superpowers. He would plan with the model, save a plan doc, clear context, and execute the plan. He reserves Superpowers for multi-feature work, where its task splitting is useful.** — He places it between Ralph (lighter) and Beads / spec-kit (heavier) in the planning-tool spectrum. ([6:49](https://youtu.be/lq3rzXP4_vs?t=409))

## Techniques
- **Brainstorm into a design doc before code** — With the Superpowers plugin installed, run its brainstorm slash command in Claude Code. Answer the clarifying questions about stack (React + Vite in the demo), layout, the step-by-step flow and server endpoints. Confirm the architecture when asked. The design plan is written to a plans directory. The presenter says only the brainstorm command is needed, because each stage hands off to the next. The write-plan and execute-plan commands also exist. *When:* Any feature big enough that you want architecture and layout agreed before the agent writes code.
- **Split the design into sub-agent-sized tasks** — After confirming the design, tell the agent you are ready for implementation. It reads the design doc and writes a second plan made of tasks, each with its own steps (for example, scaffold the project, then create the Vite + React client skeleton). Review the task plan before executing, as the presenter says it can skip steps. *When:* Multi-feature builds where independent tasks can run in parallel.
- **Pick the execution mode deliberately** — At the execution prompt, choose sub-agent-driven (one sub-agent per task, no human approval between tasks) or parallel session (tasks run in batches, and the human approves each batch before the next starts). *When:* Sub-agent-driven when speed matters and the plan is trusted. Parallel session when you want checkpoints between batches.
- **Per-task red-green loop with a git commit per step** — Each sub-agent writes a test that must fail first, then the minimal code to make it pass, then checks the plan's requirements for the feature, then runs a code-quality review. Each completed step gets a git commit. Check the commits to confirm the TDD step actually ran. *When:* Feature work where you want an auditable history and tests written before code. The presenter notes the agent may skip the red step, so verify it.
- **Plan doc, clear context, then execute (presenter's own workflow, not part of Superpowers)** — Plan the feature in conversation with Claude, write the plan to a document, clear the context window, then run the plan in a fresh session. *When:* Small features, where he finds a full skills framework too heavy.

## Hot takes
- The title ('the only Claude Code plugin you'll EVER need') overclaims. The presenter himself says he will not use it for small features or every project.
- The plan-mode vs Superpowers comparison rests on one run each, so it is anecdotal, not a benchmark.
- A skill that says TDD is guidance, not enforcement. The agent skipped the red step and admitted it chose speed. Read plans before executing them.
- For small features, a plan doc plus a context reset may beat a full skills framework. Superpowers earns its keep on multi-feature work.
