> LiveKit's Jesse Hall argues voice agents must be evaluated as whole conversations: measure time-to-first-audio and time-to-first-sentence, use non-blocking tool calls, use audio-aware turn detection, and benchmark full stacks with simulated callers.

## Summary
Jesse Hall of LiveKit argues that voice agents fail in conversation, not on leaderboards, so teams should choose a stack by testing the whole pipeline on their own use case. He says the metric that matters is what the caller hears: time-to-first-audio and time-to-first-sentence, since TTS needs a full sentence and a provider's time-to-first-byte can hide up to about 0.75s of silence. He recommends making tool calls non-blocking so the agent keeps talking while slow back-end lookups run, and shows a hotel-booking demo that handles interruptions and saves each field to a back end. He describes an audio-aware turn detector that also listens to pitch, rhythm and intonation, which LiveKit reports cuts off users 4.5% of the time versus 9.9% for the leading alternative. The evaluation method is simulated callers with goals, interruptions and background noise, scored on final outcomes and on the steps taken, with identical inputs replayed across model swaps. He closes with a checklist and advice to turn each production failure into a regression scenario. Most of the numbers come from LiveKit's own stack and one hotel demo agent, so they should be treated as a vendor data point rather than a general benchmark.

## Key ideas
- **Leaderboards score models in isolation on clean audio, but a voice agent ships a conversation, so pick the stack by testing it end to end on your own use case.** — Example: a speech-to-text error (hearing 30th instead of 3rd) flows downstream into the LLM and the outcome; a leaderboard cannot see that. Callers are on speakerphone in traffic, so scoring must use realistic audio. ([5:19](https://youtu.be/OmyqelTwpOo?t=319))
- **Measure time-to-first-audio and time-to-first-sentence, not time-to-first-byte or time-to-first-token.** — A TTS dashboard showed 210 ms time-to-first-byte, but popular providers add up to about 0.75s of silence after that byte. TTS needs a full sentence before speaking, so a fast-token LLM is not necessarily the one that produces the first sentence fastest. ([6:39](https://youtu.be/OmyqelTwpOo?t=399))
- **Back-end tool calls should not block the conversation; the await on a tool call is the key change that hands the mic back to the agent.** — The agent keeps saving fields and talking while a lookup or payment runs, and it can self-correct or hand off to a human if a tool errors. Humans do the same thing: say 'give me a second' or keep asking questions. ([9:26](https://youtu.be/OmyqelTwpOo?t=566))
- **Turn detection should use audio (pitch, rhythm, intonation), not only the transcript.** — A transcript-only detector stops at $500 in '$555.23' after a pause. LiveKit reports its detector interrupts users 4.5% of the time in its use case versus 9.9% for the leading alternative. The eval is open source and can be run on your own data. ([12:07](https://youtu.be/OmyqelTwpOo?t=727))
- **Keep the caller-to-agent response gap in a latency budget: about 1.5s starts to feel off, and 500-600 ms feels human.** — The budget covers the turn detector, the LLM's provisional-transcript response, each model, each function call and each handoff. The question to ask is how human-like an agent can be within the budget, not how fast it can go. ([13:25](https://youtu.be/OmyqelTwpOo?t=805))
- **Test with simulated callers against a complete working agent, and score outcomes and steps, not just task completion.** — Simulated callers have goals and can change their mind, interrupt, mumble and talk over background noise. Text simulations test business logic; audio simulations also test ASR and turn-taking. Scoring checks the final database state, excess steps and hallucinated function calls. ([16:04](https://youtu.be/OmyqelTwpOo?t=964))
- **Replay identical input across model swaps to build a personal benchmark; the best model may not be the top of a leaderboard.** — The hotel agent's top LLM was Gemma 4 31B (auto-caption reads 'Gemma 431B') on LiveKit inference, which the speaker says is tuned for voice. The same model on another provider was slower. ([17:30](https://youtu.be/OmyqelTwpOo?t=1050))
- **Turn every production failure into a regression scenario and keep re-running it.** — Checklist: set the latency budget, measure time-to-first-audio and time-to-first-sentence, confirm critical dates and amounts, verify identity before account access, keep listening while slow tools run, run full conversations repeatedly in simulation, and test final state, privacy, unnecessary tool calls and turn-taking. ([19:55](https://youtu.be/OmyqelTwpOo?t=1195))

## Techniques
- **Time-to-first-audio and time-to-first-sentence instrumentation** — Measure from the caller's last syllable to the first audible TTS sample, and also to the first full sentence the TTS can speak. Report these alongside TTFT and TTFB, which can look fast while silence remains. *When:* Any voice agent latency work or vendor comparison. Use it to decide the real latency budget, not dashboard numbers.
- **Non-blocking (async) tool calls in a voice agent** — Run back-end tools (look up transaction, check payment status, submit dispute, save each field) with an await that releases the conversation, so the agent keeps talking and collecting input. Agent narrates progress, then self-corrects on a tool error or escalates to a human. *When:* Any tool call that can take more than about a second, such as payments, lookups or bookings.
- **Audio-aware turn detection** — Use a turn detector that uses audio features (pitch, rhythm, intonation) plus the transcript, so a mid-amount like '$555.23' is not cut at '$500' after a pause. Evaluate it on your own recordings before trusting it. *When:* Callers pause mid-utterance, such as while reading numbers, dates, card digits or amounts.
- **Full-stack scenario simulation with identical replay** — Write each scenario as caller goal, expected agent actions and expected outcome. Run simulated callers (goal changes, interruptions, mumbling, background noise) against a complete agent with a real back end, in both text mode (business logic) and audio mode (ASR and turn-taking). Score final state (e.g., reservation in DB, correct amount charged) and number of steps taken. Swap models or providers while keeping input identical, byte for byte, and repeat. *When:* Choosing between LLM, STT and TTS providers for a production agent, or any regression testing of a conversational agent.
- **Regression scenarios from production failures** — Convert each observed failure (missed date change, wrong amount, interrupted caller) into a scenario in the simulation suite and re-run the suite on each change. *When:* Continuous improvement of an agent after launch.
- **Financial voice-agent guardrail checklist** — Confirm critical dates and money amounts back to the caller. Verify identity before any account access. Keep listening while slow tools run. Check privacy safeguards and unnecessary tool calls. *When:* Voice agents handling payments, account changes or other high-risk financial actions.

## Hot takes
- The 'leaderboards cannot answer which model to pick; only end-to-end tests can' point is well argued and applies to any multi-model agent, not just voice.
- Vendor talk: the turn-detector and inference numbers come from LiveKit's own stack and one hotel demo agent, and no independent replication is shown. The claim that the benchmark is open source is presented but not demonstrated on screen.
- Strong claim that 'a byte does not equal audio'. Presented with a concrete measurement, so it is useful as a metric definition even if the 0.75 s figure is one provider sample.
