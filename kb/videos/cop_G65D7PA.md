## Summary
The AI LABS presenter argues that poor output from non-developers using Cowork (the non-developer side of Claude Code) comes from missing pre-setup, not the tool. The core move is a manifest.md in each working folder that tells the agent which files are the source of truth, which are on-demand, which are archive to ignore, and what to skip, which the presenter says cut noise and speed up answers. Next come identity, brand-voice and working-style context files, plus global instructions that make the agent read the manifest first, ask clarifying questions, show a plan, avoid filler, and ask instead of guessing when confidence is low. Prompts should state the end state (the correct output and edge-case handling) rather than the process. Interdependent tasks should be batched into one session, unrelated ones kept apart, and subagents used sparingly because they cost tokens. Scheduled tasks are demoed with a daily meeting-notes report, with the caveat that they run only while the computer is awake and the desktop app is open. The video closes with plugins as bundles of skills, commands and subagents, and guardrails: sensitive data in separate folders, explicit no-delete rules, and prompt-injection risk. The claims are anecdotal, with no measurements, and a Scrimba sponsor segment and a paid-community plug appear mid-video.

## Key ideas
- **Low-quality output from Cowork is a pre-setup problem, not a tool problem** — The presenter says most users skip setup and then blame usage limits. Each workflow needs tailoring through a series of setup steps before the first real prompt. ([0:00](https://youtu.be/cop_G65D7PA?t=0))
- **A manifest.md in every working folder acts as the agent's map** — It lives at the folder root and says which documents are the source of truth, which subfolders map to which domain, and what to skip. The presenter says Claude otherwise gets lost in nested folders and pulls irrelevant files, which bloats context and yields wrong sources. ([0:00](https://youtu.be/cop_G65D7PA?t=0))
- **Manifest files use three tiers of file importance** — Tier 1 is always loaded and is the source of truth. Tier 2 is loaded on demand. Tier 3 is archived past versions that the agent should ignore unless asked. The presenter reports faster and more reliable answers once the manifest is loaded first. ([1:07](https://youtu.be/cop_G65D7PA?t=67))
- **Identity, brand voice and working-style files tune behaviour** — Three context files (about me, brand voice, working style) sit in a shared context folder and are referenced from the instructions. They are meant to be refined repeatedly. When the agent ignores an instruction, decide whether the fault is the prompt or the context and edit the files. ([1:07](https://youtu.be/cop_G65D7PA?t=67))
- **Global instructions load before every prompt and are the cheapest lever** — The presenter's global instructions point the agent at the manifest first, require clarifying questions and a brief plan before action, ban filler and padding, and require asking when confidence is low. They also reference the voice files. ([2:34](https://youtu.be/cop_G65D7PA?t=154))
- **Describe the end state and the edge-case rule, not just the process** — For a reorganisation task the prompt named which file version goes where, what each folder should hold, how nested folders are treated, and what must not be touched. Edge-case handling is stated explicitly, with an instruction to ask and flag uncertainty instead of guessing. ([5:03](https://youtu.be/cop_G65D7PA?t=303))
- **Batch interdependent tasks in one session and split unrelated ones** — Tasks whose outputs feed the next step share context and belong in one session, framed as a goal followed by ordered steps. Unrelated tasks batched together waste tokens and can produce wrong output. Parallelisable work can be stated explicitly, and subagents are useful for large jobs but consume many tokens. ([7:35](https://youtu.be/cop_G65D7PA?t=455))
- **Scheduled tasks run only while the machine and desktop app are up** — The presenter uses the schedule skill to have Cowork turn the day's meeting notes into a dated report with actionable items. Claude asked about frequency before scheduling. The limitation is that the task runs only while the computer is awake and the Claude desktop app is open. Connectors (Gmail, Google Drive) or Claude Code cron jobs with MCP tools or CLIs are suggested as alternatives. ([9:03](https://youtu.be/cop_G65D7PA?t=543))
- **Plugins bundle skills, commands and subagents for one domain, and a plugin can build plugins** — Plugins are open source on GitHub. The presenter used the plugin-creation skill: Claude asked a set of questions, presented a plan, and built the plugin after approval. Custom skills are suggested for unique use cases. ([10:08](https://youtu.be/cop_G65D7PA?t=608))
- **Treat Cowork like an employee: scope it, isolate data, and watch for prompt injection** — Cowork is described as a research preview with limited guardrails. Sensitive data should sit in separate folders with only the needed files exposed. Explicit rules such as do not delete anything, ask before removing, and tight task scope are recommended. Documents or websites can carry injected instructions, and heavy use exhausts context limits quickly. ([11:16](https://youtu.be/cop_G65D7PA?t=676))

## Techniques
- **Per-folder manifest.md with tiered sources** — Create manifest.md at the root of each working folder. List Tier 1 files (always load, source of truth), Tier 2 files (load on demand), and Tier 3 archive files (ignore unless asked). Map each subfolder to its domain and list what to skip entirely. Tell the agent in global instructions to read this file first. *When:* Working in nested, structured folders where the agent otherwise guesses file locations and pulls noisy or outdated documents.
- **Identity, voice and working-style context files** — Write three files (about me, brand voice, working style) in one shared context folder that the agent can reach from any project. Reference them from global instructions. Refine them each time the agent ignores an instruction, and decide whether the fix belongs in the prompt or in the context files. *When:* Recurring work where generic, off-voice output keeps appearing.
- **Global instructions as a default operating contract** — In the global Claude Code instructions (the presenter's CLAUDE.md, which sits in the user's home-directory .claude folder), add rules to: read manifest.md first; ask clarifying questions before acting; show a brief plan before any action; avoid filler and padding; ask instead of guessing when confidence is low; apply the voice and working-style files. *When:* Any agent setup, because these instructions load before every prompt.
- **State the end state and the edge-case rule** — Specify the correct final output (which version of each file goes where, what each folder should contain), how nested folders are treated, and what must not be touched. Add an explicit rule for uncertainty: ask, flag low confidence in words, and do not present guesses as facts. *When:* Reorganisation, batch file-handling or any multi-step task where the agent would otherwise guess at edge cases.
- **Batch by shared context, keep unrelated work apart** — Put tasks whose output feeds the next step into one session. Open the prompt with the goal, then list the steps in order. Start separate sessions for unrelated tasks. If steps are independent, say so in the prompt so they run in parallel. *When:* Multi-step pipelines such as a monthly budget summary; avoid it for independent tasks to save tokens and limits.
- **Scheduled report from meeting notes via the schedule skill** — Ask Cowork, using the schedule skill, to read that day's meeting notes, write a report to a named folder with a stated filename format, and list the actionable items. Answer its frequency question so it can create the schedule. Keep the computer awake and the desktop app open for it to run. *When:* Recurring daily summaries or research digests where the notes are already being written.
- **Build a plugin with the plugin-creation skill** — Ask Claude in the chat interface to create a plugin. Answer its set of questions, review the plan it presents, approve it, and let it build the skills, commands and subagent integrations. *When:* A repeated domain workflow that needs a bundle of skills and commands tailored to your own use case.
- **Guardrails for agent file access** — Keep sensitive data in separate folders and expose only the files the task needs. Add explicit constraints such as do not delete anything and ask before removing. Treat instructions found inside documents or web pages as untrusted. *When:* Giving a non-developer agent access to a shared or private document folder.
