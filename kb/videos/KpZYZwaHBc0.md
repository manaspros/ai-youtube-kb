> Beginner walkthrough of OpenAI's Codex CLI and cloud agents: approval modes, AGENTS.md, MCP setup, role-specialized agent files, and running background tasks that end in a GitHub PR.

## Summary
The presenter gives a beginner tutorial on the Codex CLI and its IDE extension, and on Codex cloud tasks that run against a GitHub repo. He covers slash commands, model choice (GPT-5 Codex Low vs High), the Full Access approval mode, and /compact for context. He then shows how to generate an AGENTS.md with /init, how to keep several role-specific agent markdown files, and how to build an MCP config by feeding a repo-to-text dump to a chatbot and asking for config.toml format. The last section runs a dark mode task and a settings-page task in the cloud from a phone, then pushes the result to a PR and merges it. The video opens with a sponsor segment, and most of the content is introductory; the concrete steps are the useful part. Several claims (context-window comparison, BMAD eliminating hallucinations) are asserted without evidence.

## Key ideas
- **Codex cloud agents take a task from the phone or ChatGPT app, run against a selected GitHub repo and branch in the background, and return a summary and preview that can be pushed as a PR.** — The presenter claims you can assign tasks from a phone and wake up to completed PRs. He starts the dark mode task on the cloud, and a settings-page task from the ChatGPT mobile app, and merges the resulting PR. ([0:00](https://youtu.be/KpZYZwaHBc0?t=0))
- **Approval mode determines how often Codex stops to ask permission. Full Access removes prompts for unattended background work.** — He recommends Full Access for uninterrupted autonomous runs. The help output also lists a dangerously-bypass-approvals-and-sandbox flag, which he compares to Claude's skip-permissions flag. ([2:22](https://youtu.be/KpZYZwaHBc0?t=142))
- **Model choice trades capability against plan allowance. Low is fine for standard tasks, and High burns messages faster.** — He cites GPT-5 Codex Low as the model he uses and GPT-5 Codex High as the most powerful option. Allowance is counted in 5-hour windows on Plus; Pro is priced at $200 and has substantially more capacity. ([2:22](https://youtu.be/KpZYZwaHBc0?t=142))
- **Run /init in a repo to generate AGENTS.md, which is the project-level instructions file future sessions read.** — The generated file covers folder structure, build and test commands, and coding style. Custom rules, such as always using shadcn components instead of hand-built ones, go there too. ([6:01](https://youtu.be/KpZYZwaHBc0?t=361))
- **Codex has no slash-command injection for roles, so keep one markdown file per role (content marketer, Django backend, UI/UX) and tell Codex to adopt it.** — He keeps three agent.md files in an agents folder, references one file in the prompt, and confirms Codex is operating in that role. He notes that templates written for Claude Code also work with Codex. ([7:00](https://youtu.be/KpZYZwaHBc0?t=420))
- **To set up an MCP server, he builds a context dump of the Codex repo, asks a chatbot for config, and adds the result to Codex's config.toml.** — The full repo is about 760k tokens, too large for the 200k to 274k context windows he cites. Filtering to include only .md files brings it to about 50k. He pastes it into a chatbot and asks for config.toml format for a docs MCP server (context7), then checks it in the Codex MCP settings. ([4:46](https://youtu.be/KpZYZwaHBc0?t=286))
- **For larger projects he runs a planning-first method (BMAD): PRD, then stories, then a dev agent per story, then a QA agent.** — He describes the dev agent completing stories sequentially and a QA agent testing afterwards, and claims this virtually eliminates hallucination risk. He gives no evidence for that claim, and says he runs BMAD through custom commands because Codex lacks other prompt injection. ([8:25](https://youtu.be/KpZYZwaHBc0?t=505))
- **Cloud tasks can run on a chosen branch, so you can keep parallel work separate: a new task for a feature branch, or a design-system branch cut from main.** — Starting a task creates a new branch automatically when needed. The result comes back with a summary and preview; you can request changes, or push to create a PR and merge it. ([9:47](https://youtu.be/KpZYZwaHBc0?t=587))

## Techniques
- **Full Access approval mode for unattended runs** — Set the approval setting to Full Access in the Codex CLI so the agent runs without permission prompts. The presenter also mentions the dangerously-bypass-approvals-and-sandbox flag as the equivalent of Claude's skip-permissions flag, but does not demonstrate it. *When:* Trusted repos where you plan to leave the agent running in the background. Not for untrusted code.
- **Model selection by task difficulty** — Use /model to pick a model. Choose GPT-5 Codex Low for standard tasks and High for harder ones, with the trade-off that High uses the allowance faster. *When:* Default to Low to conserve the 5-hour allowance; move to High for hard tasks.
- **Compact to manage context** — Run the Compact feature when the context window fills, so it reduces automatically. The presenter says the same feature exists in Claude Code. *When:* Long sessions that approach the context limit.
- **Generate AGENTS.md with /init** — In the repo, type the init slash command. Codex generates AGENTS.md with folder structure and project information, which you then edit to add build and test commands, style rules, and testing guidelines. *When:* Start of any new repo Codex will work in repeatedly.
- **Role-specialized agent files** — Keep one markdown file per role in an agents folder (for example content marketing, Django backend, UI/UX). At the start of a session, reference the file in the prompt and tell Codex to assume that role. The presenter says templates made for Claude Code work with Codex. *When:* When you want domain-specific behavior without a built-in command for it.
- **Build MCP config from a repo-to-text dump** — Replace github with the Git-engine site in the repo URL (the auto-caption reads 'replace GitHub with Git engine'; this is likely gitingest, which the video does not name). In the site's filter, choose include mode and select only .md files, which cut the repo from about 760k tokens to about 50k. Paste that into a chatbot, ask for the MCP config in config.toml format for the server you want (context7 in the example), copy it into the Codex MCP settings, and check the MCP section after launching Codex. *When:* Adding MCP servers to Codex when you do not want to hand-write TOML and the repo is too big to paste whole.
- **Cloud task per branch with PR handoff** — Connect GitHub in the Codex cloud page (first run: initialize an environment and connect GitHub; multiple repos can be listed). Choose the branch for the task, describe the change, and let it run in the background. On completion, review the summary and preview, request changes or push, which creates a PR. Merge after review, and ask Codex in a new task to pull latest main if the branch is behind. *When:* Parallel feature work you want to kick off from a phone and review later.
- **Plan mode before implementation** — Switch the mode at the bottom of the IDE extension to plan mode to outline tasks before Codex implements them. *When:* Non-trivial changes where you want to review the approach first.
- **BMAD-style planning loop** — Start from a PRD, split it into stories, run a dev agent through the stories in order, then run a QA agent. The presenter runs it through custom commands and links a separate BMAD tutorial. *When:* Larger projects where you want planned stories and a separate QA pass rather than improvised prompts.
