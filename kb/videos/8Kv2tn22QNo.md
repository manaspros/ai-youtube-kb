> Walkthrough of Graphify, which builds a queryable code and docs graph, paired with Obsidian as a markdown second brain; the useful parts are provenance labels, tiered data egress, and the lint maintenance loop.

## Summary
The host argues that coding assistants re-read files on every question, and that a persistent graph of the project (entities plus relationships) beats similarity-based RAG for code because call relationships are not captured by text similarity. He presents Graphify as a tool that builds such a graph once, updates it incrementally by per-file SHA256 hash, and exports it as HTML, JSON, a markdown report, Neo4j, or an MCP server. Graphify's ingestion is split into three passes with different data egress: code is parsed locally with TreeSitter, recordings are transcribed locally with faster-whisper, and PDFs or images go to the user's AI provider, with a code-only mode that skips the last pass. Every edge is labeled Extracted, Inferred, or Ambiguous. He then places it inside Karpathy's three-layer LLM wiki design (raw sources, AI-owned wiki, schema file, with Ingest, Query and Lint operations) and shows Obsidian as the viewing and editing front end, with plugins for chat and embeddings. The second half lists four ways the setup rots: vault size, confident fabrication, AI citing its own pages, and skipping the lint pass. The performance figure of about 70x fewer tokens per query is Graphify's own unreproduced benchmark, and the host says so. The video contains no exact commands or config beyond the slash command name.

## Key ideas
- **Code relationships live in the call graph, so similarity-based RAG over chunks finds related-looking text but misses the links that matter.** — The host frames RAG as a poor fit for code questions and argues for an explicit graph of entities and relationships, built once up front, so answering means walking the graph instead of re-reading files. ([1:21](https://youtu.be/8Kv2tn22QNo?t=81))
- **The token cost comes from re-deriving project knowledge on every query; the proposed fix is a maintained wiki the model keeps up to date.** — He frames the problem as the assistant reopening many files per question. He credits Karpathy's April 3 post with the wiki-first idea and says a tool implementing it appeared two days later. ([0:00](https://youtu.be/8Kv2tn22QNo?t=0))
- **Graphify ingests in three passes with different data egress: local parsing for code, local transcription for recordings, and remote AI only for PDFs and images.** — Code goes through TreeSitter with no model call and its links are tagged as hard facts. Recordings are transcribed locally with faster-whisper. PDFs and whiteboard photos go to the user's own AI provider via their API key, and this is the only pass that leaves the machine. Code-only mode skips pass 3. ([2:43](https://youtu.be/8Kv2tn22QNo?t=163))
- **Every graph edge carries provenance: Extracted, Inferred or Ambiguous.** — Extracted means it is visible in the code, Inferred means the model reasoned it from context, and Ambiguous means the model flagged uncertainty. The host presents this as the guard against confident wrong answers. ([2:43](https://youtu.be/8Kv2tn22QNo?t=163))
- **Incremental updates are cheap: each file gets a SHA256 hash, so a re-run reads only changed files, and a git hook can rebuild the graph on every commit.** — This keeps the graph matched to the checked-out branch. Query modes are explain (a plain-English tour of one entity), path (shortest chain between two entities), and deep (hunts for fuzzier inferred links that a quick pass skips). ([4:05](https://youtu.be/8Kv2tn22QNo?t=245))
- **Karpathy's design has three layers and three operations: raw sources the AI never touches, an AI-owned wiki, a schema file, and Ingest, Query and Lint.** — Ingest updates every page a new source touches. Query answers with citations. Lint checks for contradictions, dead pages and stale claims. The host calls lint the part most tutorials skip. ([5:25](https://youtu.be/8Kv2tn22QNo?t=325))
- **The main failure modes are size, invented content, AI citing its own pages, and skipped lint; memory keeps bad notes unless someone cleans it.** — A 50-note vault feels fine, but at around 2,000 notes the model spends its context navigating structure. Without a rule like 'do not add anything I did not write' it fills gaps. Unattended, the AI cites its own earlier pages and mistakes harden into facts. The host recommends about five minutes of weekly lint. ([6:52](https://youtu.be/8Kv2tn22QNo?t=412))
- **Obsidian is used as the human-readable and editable layer, with graded write access through plugins.** — Graphify exports entities as pages and relationships as wikilinks. A Claude Code plugin (Claudian) can make the vault the agent's working directory. Read-only or lighter plugins (Smart Connections for embeddings, Khoj for self-hosted local use, Copilot for Obsidian for vault-aware chat) are suggested before granting full write access. ([5:25](https://youtu.be/8Kv2tn22QNo?t=325))

## Techniques
- **Persistent codebase graph, queried by traversal instead of re-reading files** — Run the graphify slash command (in Claude Code, Codex or Cursor) pointed at a directory; it writes a graphify-out folder next to the code. Query with explain (entity tour), path (shortest chain between two entities) or deep (includes inferred links). Install a git hook so the graph rebuilds on each commit; re-runs reread only files whose SHA256 changed. Expose the graph to agents through the MCP server export. *When:* Multi-file codebases where questions are about relationships (how a login flow works, what a root component depends on) and where repeated file reads cost too many tokens. The host reports about 70x fewer tokens per query on a mixed codebase, but this is Graphify's own benchmark and the host notes it is unreproduced.
- **Provenance labels on every derived link (Extracted / Inferred / Ambiguous)** — Tag each edge when it is created by its source: deterministic parse (Extracted), LLM reasoning (Inferred), or model-flagged uncertainty (Ambiguous). Surface the label when answering, and treat Inferred and Ambiguous links as needing verification before they drive decisions. *When:* Any LLM-built knowledge store or graph that feeds later answers, where confident wrong links are the main risk.
- **Tiered data egress across ingestion sources** — Parse source code with a deterministic parser (TreeSitter), transcribe audio or video locally (faster-whisper), and send only PDFs and images to a remote model through your own API key. Provide a code-only mode that skips remote passes entirely. *When:* Mixed corpora with private code or recordings, where some sources may leave the machine and others must not.
- **Three-layer LLM wiki (Karpathy design)** — Keep three layers: a raw sources folder the AI only reads, an AI-maintained wiki folder, and a schema file that describes the wiki layout. Run three operations: Ingest (new source updates every page it touches), Query (answer from the wiki with citations), Lint (check for contradictions, dead pages and stale claims). *When:* Personal or team knowledge bases that accumulate over time and need the model to keep cross-links current.
- **Anti-fabrication rule and weekly lint loop for an AI-maintained notes vault** — Add an explicit instruction to the assistant's instructions: do not add anything the user did not write. Schedule a recurring review (the host suggests about five minutes a week) to read what the agent wrote, prune stale pages and resolve contradictions. The host also warns against letting AI-written pages become sources for later AI pages; no specific mechanism for this is given. *When:* Any setup where an agent writes or edits long-lived notes from user input, to prevent invented memories and AI-quoting-AI drift.
- **Staged write access to an Obsidian vault** — Start with read-only or lightweight plugins (embedding-based related-note surfacing, vault-aware chat) and grant agent write access and command execution only after the setup has proven reliable. Use a Claude Code plugin in the Obsidian sidebar only when the vault should be the agent's working directory. *When:* Adopting an agent on a personal knowledge base where wrong writes persist and are hard to notice.

## Numbers

## Hot takes
- The title ('INSANE') and 'viral' framing oversell the tool; the host's own caveats (self-reported 70x figure, rot over time) are more useful than the headline.
- The RAG-versus-graph argument for code is plausible and asserted; the video shows no head-to-head comparison against RAG on the same questions.
- The fix for invented content is a single prompt line ('do not add anything I did not write'); its effectiveness is asserted, not tested.
- For agent infrastructure the transferable parts are the provenance labels and the scheduled lint pass; the Obsidian and personal-vault framing is mostly a delivery choice.
- Graphify's marketing claims (private by design, code parsed with no model call) are the tool's self-description as relayed by the host, not independently checked.
