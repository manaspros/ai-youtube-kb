> Three practical ways to turn website designs into working Next.js UI in Cursor: a structured front-end spec prompt, a design.json built from screenshots, Browser MCP for cloning structure, and stagewise for precise element-level edits.

## Summary
The host argues that handing Cursor a design image or asking it to clone a site produces hallucinated, generic output, and that agents need a structured spec up front. Method 1 is a prompt template covering required pages, user roles and auth, shared components, modals, technical requirements and framework, which an LLM such as Claude can fill in for you. Method 2 turns six or seven screenshots of a reference design into a design.json through a prompt, then tells Cursor to follow it strictly for a Next.js and Tailwind weather app, with Claude Code brought in to fix dependency conflicts. Method 3 clones a site's structure with Browser MCP, which drives a real browser tab through the Chrome extension, and the host says to strip the design section from the prompt if you want your own styling. The final method is stagewise, a Cursor-side bar that lets you select a live element and send its code location and context back to the agent, so a small change like a hover state does not disturb the rest of the layout. The video shows demos but no before/after measurements, and the first generated design needed manual correction.

## Techniques
- **Structured front-end spec prompt** — Before building, write a prompt with these sections: required pages; user roles and permissions (if auth is needed); shared components such as nav bar, header and breadcrumbs; modals and popups; technical requirements for later backend connection; and the target framework. Have an LLM such as Claude fill in any section you skip, then review and edit. Give the completed prompt to Cursor or another agent together with the build request. *When:* At the start of a new front-end project, so the agent plans all components before writing code instead of guessing.
- **Screenshot to design.json style profile** — Send six or seven screenshots of a reference design to Claude (or ChatGPT) with the design-to-JSON prompt. The author links an updated prompt in the video description (not shown in the transcript). Save the output as design.json in the project. Tell Cursor: 'build the front-end app in this Next.js app, and for the design, strictly follow the design.json'. Ask it to focus on how gradients and cards are built. Expect to correct mistakes, and use a second coding agent for dependency or version conflicts. *When:* When you want a particular visual style (gradients, card treatment) reproduced consistently across generated pages.
- **Clone a site's structure with Browser MCP** — 1) Install the Browser MCP extension from the Chrome Web Store. 2) Connect it to the tab of the site you want to clone. 3) Add the Browser MCP server to Cursor's mcp.json, using the setup snippet for your IDE from the project's install docs. 4) Prompt the agent with the target URL and ask it to explore the site thoroughly and break down its architecture, navigation patterns and styling approach. 5) To use your own design, remove the styling part of the prompt so only structure is copied. 6) Ask it to build the clone in Next.js. *When:* When you want a proven layout and navigation as a starting structure before applying your own design.
- **Element-level UI edits with stagewise** — 1) In Cursor, open the Extensions tab and install stagewise. 2) Run the command palette (Ctrl/Cmd+Shift+P in the video) and type 'stagewise'. 3) Pick the setup option; it runs a prompt that initializes the stagewise bar in the current project. 4) Repeat per project. 5) In the running app, select the exact element, write the change (e.g. a hover animation consistent with the UI), and send it. The context includes the element's code location, which the agent uses for a targeted edit. *When:* For small, precise UI tweaks on a running app where a broad instruction might break surrounding layout.
