## Summary
The presenter introduces POML (transcribed as "Pommel"), an open-source markup language from Microsoft's prompt engineering researchers for writing reliable, maintainable AI prompts. A POML file looks like HTML and compiles to Markdown by default, or to JSON, HTML, YAML or XML, and the Python SDK can also emit OpenAI chat messages, raw strings, LangChain or Pydantic objects. The presenter says the TypeScript SDK was not yet stable when he tried it, so the demos use Python. Prompt structure comes from components: role, task and hint tags, basic components such as bold and code, intentional ones such as example and stepwise instructions, and data components that embed documents, images and tables. A data component reads an Excel file, keeps five records and converts it to CSV, and the output still renders correctly when switched to JSON. The template engine adds variables, JSON data sources, Python context, for loops, if conditions and file includes. The main use case is a Python script that picks style documents by CLI argument (React, TypeScript, Next.js) and asks a cheap model to draft an AGENTS.md, which the presenter says produced a usable file without an agent reading the codebase. The video closes by listing features it skipped: stylesheets for data shape, tool specification, Zod expression evaluation and trace capture before the LLM call. Evidence is demo-level only, with no output comparisons or benchmarks.

## Key ideas
- **POML is a markup language for prompts that compiles to Markdown by default, with JSON, HTML, YAML and XML as alternatives, so one prompt file can target any model or tool.** — The presenter's pitch is that prompts written in POML are not tied to one tool, and the same file can feed Codex, a coding agent, or the OpenAI API directly. ([0:00](https://youtu.be/tfOwh6YCY8M?t=0))
- **Structure comes from components (role, task, hint) plus data components for documents, images and tables.** — Components are wrapped in POML tags. Intentional components such as example, hint and stepwise instructions render with consistent formatting. Uppercase tag names also work if the React-style lowercase convention feels odd. ([1:20](https://youtu.be/tfOwh6YCY8M?t=80))
- **Data components embed external files such as Excel into a prompt, and the output format can change without changing the source.** — The demo reads an Excel file, keeps five records, converts it to CSV, and inserts it into the prompt. Switching the output to JSON and dropping the CSV conversion still renders the data correctly. ([1:20](https://youtu.be/tfOwh6YCY8M?t=80))
- **The POML SDK can output directly in the format an API expects, such as OpenAI chat messages, instead of a single text blob.** — The presenter sets the format to OpenAI chat, prints the messages, and sends only the content to GPT-5 mini. Other formats named are raw, MessageDict, LangChain and Pydantic. ([1:20](https://youtu.be/tfOwh6YCY8M?t=80))
- **The template engine makes prompts data-driven: variables, JSON sources, Python context, loops, conditionals and includes.** — Variables are set with let and referenced with double curly braces. Python passes context values and objects into the file. The for and if attributes and file includes complete the set. The presenter notes that Claude Code can include files too, but POML prompts are portable across tools. ([4:03](https://youtu.be/tfOwh6YCY8M?t=243))
- **A generator script can choose prompt fragments from CLI arguments and use a cheap model to draft a repo instruction file.** — The script maps the React or TypeScript arguments to style documents, appends guidance on writing a good AGENTS.md, and calls GPT-5 nano. The result captured the import order and styling patterns, and the presenter says it avoided having an agent scan every code file. ([5:29](https://youtu.be/tfOwh6YCY8M?t=329))
- **POML can drive a coding agent through a subprocess call, so a compiled prompt can be sent to a non-interactive agent CLI.** — The demo runs a non-interactive Codex command and passes the compiled prompt as an argument. The presenter says the same approach works with Claude Code, OpenCode or Gemini. ([1:20](https://youtu.be/tfOwh6YCY8M?t=80))
- **Several POML features are mentioned but not shown: stylesheets, tool specification, Zod expression evaluation and trace capture.** — Stylesheets are said to control the shape or format of data. Trace capture is said to record prompts before they reach the LLM, which the presenter links to a separate explainer video. ([6:50](https://youtu.be/tfOwh6YCY8M?t=410))

## Techniques
- **Compile a POML file to an API-ready message list** — Write the prompt in POML with role, task and hint components. In Python, pass the file (with a context dict) to the POML class, set the output format to OpenAI chat, and read the compiled messages. Send the content to the OpenAI SDK. Other supported targets are raw, MessageDict, LangChain and Pydantic. *When:* When you want one prompt source that feeds several models or tools and want the compiler to handle the format conversion.
- **Embed a spreadsheet as a prompt data component** — Use a POML data component pointing at an Excel file. Limit the rows (the demo keeps five), convert to CSV, and let the output format handle the rest. Change the output format to JSON and remove the conversion to test portability. *When:* When a prompt needs a table or record set from a file, and you want to switch serialization formats without editing the data source.
- **Parameterize a prompt with templating and Python context** — Declare values with let and reference them with double curly braces. Load JSON data inside the template. From Python, pass a dict of strings and objects as context. Use for and if attributes for loops and conditions, and include other POML files for shared fragments. *When:* When the same prompt must vary by input (a project type, a user record list) and should live in a template rather than in string concatenation.
- **Generate an AGENTS.md from style documents with a cheap model** — Write one style-guide document per stack (for example React, TypeScript, Next.js). In a Python script, read CLI flags such as --react and --typescript, include the matching documents in the POML context, append instructions for writing a good AGENTS.md, and call a small model (GPT-5 nano in the demo). Write the output to AGENTS.md. *When:* When you need a starting AGENTS.md or CLAUDE.md for a repo quickly and the stack conventions already exist as documents, without an agent reading every source file.
- **Run a compiled prompt through a non-interactive coding agent** — Compile the POML file to a string and pass it as an argument to a subprocess that runs the agent in non-interactive mode. The demo uses codex with its non-interactive command. The same pattern should apply to other agent CLIs. *When:* When another pipeline stage needs to call a coding agent with a templated prompt, such as a critique or review step.

## Hot takes
- Presenter's pitch that POML prompts are portable across any model or tool, versus Claude Code's own include mechanism, was not tested in the video.
- The video offers no comparison of output quality against a plain-text prompt, so the claim that POML prompts are more reliable (from the title and intro) is unsupported by the demo.
- The presenter says the TypeScript SDK was unstable when he tried it, which matters for JS and TS teams.
- Speaker admits the GPT-5 response from the first test was not what he expected and does not explain why.
