## Summary
The video covers Moonshot AI's Kimi K3, a 2.8T-parameter mixture-of-experts model with open weights (about 1.56 TB in MXFP4) and a 1M-token context. The speaker explains the architecture: 69 of 93 layers use Kimi Delta Attention with a fixed-size recurrent state, which keeps the memory wall off the KV cache. Moonshot trained the model at 4-bit precision (quantization-aware training through SFT and RL) rather than quantizing it afterwards, and the license is custom, not MIT. Unsloth published a quant ladder from 594 GB to 8-bit, with next-token agreement numbers for each step. The DeltaFin project (MIT, two days old at recording) keeps a resident spine of about 60 GB (INT8) and fetches only the 16 routed experts per layer that each token needs, using HTTP range requests and a growing disk cache. The first version took about 40 minutes per token; the current version takes 14.6 s per token on the M1 Max, roughly 82x faster. The speaker stresses that the speed is a research artifact and a testbed, and that serving the full model properly still needs about 2.3 TB of memory on an 8-way B300 node. He also notes that Apple dropped the 512 GB Mac Studio option in March.

## Techniques
- **Expert streaming from disk with a resident spine** — Keep attention, shared experts, latent projections, and embeddings resident (INT8, about 60 GB). Store routed experts separately. Per token, the router picks top-k experts per layer and the runtime fetches only those byte ranges (about 17 MB each, via HTTP range requests or local reads) into a growing disk cache. The speaker's arithmetic: 16 experts x 92 layers = 25.8 GB read per token. *When:* The model is far larger than RAM or VRAM, and you accept per-token IO latency. Useful for research testbeds, or for an offline fallback where a local copy is the only option.
- **Selective mixed-precision quantization for MoE** — Quantize the bulk expert weights to 4-bit MXFP4 (block floating point, a shared scale per block of weights). Keep routers and attention projections at higher precision, since small errors there flip routing or answers. *When:* Choosing what to quantize in an MoE model. Put precision where output errors compound, and compress where they only degrade gracefully.
- **Quantization-aware training instead of post-hoc quantization** — Run training (SFT and RL) with the target low-bit format in the loop so the model learns to work at 4 bits. The shipped file then matches the served precision. *When:* You control the training run and want the downloaded artifact to match production precision, with no quality gap from a later squeeze.
- **Measure a quant ladder by next-token agreement** — For each quant level (1-bit, 2-bit, 4-bit, 8-bit), measure how often its top next-token pick matches the full-precision model's. The speaker cites 78.9% for 1-bit S, 90.4% for 2-bit XL, and near 100% for 4-bit. *When:* Picking the smallest quant that still behaves like the full model on your workload, before committing to a benchmark suite.
- **Fused dequantize-and-matvec kernel** — Dequantize MXFP4 weights and run the matrix-vector product in a single pass, with per-architecture kernels: NEON on Apple Silicon and AVX2 on x86. The transcript gives no code or flags. *When:* Single-token decode is bound by memory bandwidth on quantized weights. Fusing avoids a full-precision intermediate write.
- **Deterministic decoding with lossless n-gram speculation** — Use greedy decoding and n-gram (prompt-lookup style) speculative drafting that does not change the output. The same prompt gives the same tokens across runs. Temperature and top-p are not supported. *When:* You need reproducible outputs for testing or verification, and speedup must not change the result.
- **Architecture-level KV cache reduction with hybrid attention** — Replace most attention layers with a fixed-size recurrent state (Kimi Delta Attention, with per-channel forget gates), and keep a smaller number of gated latent attention layers. The speaker reports 69 of 93 layers in the recurrent form. *When:* Designing or choosing a model for very long context where the KV cache would otherwise dominate memory.
