> Walkthrough of six GitHub repos that give coding agents design references, multi-viewport checks, design-token extraction, multi-agent page builds, app-store screenshots and launch-video generation. Mostly sponsored tool demos with little measurement.

## Summary
The video argues that the tools and references given to a coding agent matter more than the model for avoiding generic "AI-built" site styles. It walks through six repos: Awards MCP (pick real award-winning sites as references, with screenshots and a browser-recorded motion study), Responsively MCP (the agent screenshots the built page at several viewport sizes and fixes overflow), Genjutsu design-taste skills (Cast for one section, Paint for a whole page, Bunshin for a multi-agent page build), Dembrandt (extract a live site's design tokens into design.md and diff scans before and after an edit), an app-store screenshot generator that exports store-sized zips from a local editor project, and Brag (Full and Slim modes for a roughly 20-second launch video). The demos are run with Klein CLI and Kleinpass, which the video sponsors, so model and tool choices are biased toward the sponsor. The speaker reports only single-run visual impressions with no metrics, and warns that Brag can invent clicks that the app does not support, so generated videos must be checked against the real product. Captions were read with obvious fixes applied (Klein is probably Cline, Whisperflow is probably Wispr Flow, Bragg is Brag).

## Key ideas
- **Model choice matters less than the references and tools given to the agent. Without them, agents converge on the same AI-looking site styles.** — The speaker's framing for the whole video. The claim is asserted, and the demos are visual comparisons, not measurements. ([0:00](https://youtu.be/NZjjmf3I6I4?t=0))
- **Give the agent real award-winning sites to study before building. Awards MCP returns screenshots with links, and a skill tells the agent how to study them.** — The agent searches the awards catalogue from a plain-language description, returns screenshots with links, reads the design details on the chosen site's page, and records a full-page screenshot plus motion with the browser tool. ([1:03](https://youtu.be/NZjjmf3I6I4?t=63))
- **Do not accept the setup defaults for Awards MCP. Several of the tools the workflow needs are disabled by default.** — The speaker says the setup command asks for settings and that the needed options must be picked explicitly. Without the MCP, the first build lacked the animations they wanted. ([1:03](https://youtu.be/NZjjmf3I6I4?t=63))
- **Build from a mix of references: take layout from one site and animation from another, rather than copying a single site.** — The speaker ran the inspiration command, rejected the first list, asked for a second, and then told the agent which parts to take from each site. ([2:31](https://youtu.be/NZjjmf3I6I4?t=151))
- **Responsively MCP lets the agent check the built page at several viewport sizes, including with the menu open, and recheck its own fixes.** — The agent gets a screenshot per view, looks for overflow or breakage, then takes new screenshots after each fix. The app itself is a Mac app with side-by-side viewports. ([3:56](https://youtu.be/NZjjmf3I6I4?t=236))
- **Bunshin is a multi-agent design system inside one skill. A lead agent sets a shared style, sub-agents build pages in parallel, and reviewer agents send issues back.** — Rounds stop when only small issues remain, when a round limit is reached, or when a round fixes nothing. The speaker says it does well with an illustrative style and weaker with a minimal one. ([3:56](https://youtu.be/NZjjmf3I6I4?t=236))
- **A screenshot does not carry small details such as spacing. Dembrandt reads the computed styles from the live page and writes them to design.md.** — The skill opens the URL in a browser, extracts the styles, and saves a style guide the agent follows. The speaker also suggests saving a snapshot before an edit and diffing a new scan afterward to catch unintended design drift. ([5:20](https://youtu.be/NZjjmf3I6I4?t=320))
- **Generated app-store and launch media stays local and editable. The app-store skill keeps an editor project on disk and exports store-sized zips.** — The agent builds a local editor from screenshots, an icon and a description, then exports per-device sizes. The project can be regenerated when the app changes. ([7:40](https://youtu.be/NZjjmf3I6I4?t=460))
- **Generated launch videos can contain interactions the product does not have. Verify the video against the real app before publishing.** — Brag rebuilds parts of the app as scenes and can add clicks that did not happen. Full Mode follows a fixed Hyperframes step list. Slim Mode gives the agent more freedom and produces better output, but only with larger models. ([8:44](https://youtu.be/NZjjmf3I6I4?t=524))

## Techniques
- **Reference-first design with an awards MCP** — Install the Awards MCP and its skill into the agent's tools. Run the awards setup command and pick the options explicitly instead of accepting the defaults, since several needed tools are off by default. Run the awards inspiration command for a product category, describe the site, and review the returned sites with their screenshots. Tell the agent which section or motion to borrow from each site, then ask for the build. The speaker uses one site for the product page layout and another for the animations. *When:* Before building a landing page, when the output keeps looking like a generic AI-built site.
- **Post-build responsive check with Responsively MCP** — Open the site URL in the Responsively Mac app and pick the widths to view side by side. Connect the Responsively MCP server to the agent. After the build, have the agent take a screenshot per viewport, look for content that does not fit, open the mobile menu and screenshot it, then fix and re-screenshot every viewport. *When:* After any UI build, to catch laptop-only layouts that break on tablet or phone widths.
- **Design taste skills, chosen by scope** — Genjutsu ships three skills: Cast changes one section using its design taste, Paint plans and builds a whole page, and Bunshin runs a multi-agent build. Choose by scope. For Bunshin, the main agent sets a shared style, each sub-agent builds one page, and reviewer agents return issues. Set a round limit and stop when a round fixes nothing or only small issues remain. Check the style fit: the speaker found it strong for illustrative designs and weak for minimal ones. *When:* When one section, one page, or several pages need a consistent look built in parallel.
- **Extract and diff design tokens with Dembrandt** — Use the Dembrandt skill with a site URL and ask it to save the extracted styles to design.md. Give the agent design.md as a style guide for the new build. Before any later edit, save a scan. After the edit, run a new scan and compare the two to find design details that changed unintentionally. *When:* When an existing site's look must be reproduced, or when a design must be protected from regressions during later agent edits.
- **Generate app-store screenshots with a local editor project** — Set up the app-store screenshot skill. Give the agent real app screenshots, the app icon, a description of the app, the target store and a style. The agent builds a local editor, and you approve a device layout. Export the per-device sizes as a zip for upload. Keep the project folder so the images can be regenerated after app changes. *When:* When store listing images must be produced and later updated as the app changes.
- **Launch video with Brag, with a verification pass** — Give the agent the Brag GitHub link and ask it to install the skills into the project folder. Run the brag command with a landing page or product URL, and choose the whole product or one feature, plus the mood. Pick Full Mode for a fixed Hyperframes step list, or Slim Mode with a large model for more creative freedom. Review the preview and request changes. Output is an mp4 of about 20 seconds, a cover image and a short post. Before publishing, check every shown interaction against what the app can actually do. *When:* When a short product launch video is needed quickly and the user will verify it against the real product.
