> Pencil's CEO on "vibe designing": a canvas stored as structured JSON in git that humans and agents edit together, with elicitation, parallel agents and speed as the real bottlenecks.

## Summary
Better Stack podcast episode with Tom, CEO of Pencil (a design canvas that runs inside VS Code-based IDEs), who traces his path from Flash and Adobe XD to building it. Pencil began as a May 2025 prototype that turned canvas drawings into structured JSON for LLMs; the design file lives in the git repo, so engineers and agents read and edit the same artifact. Tom argues that elicitation (agents asking clarifying questions before designing), speed, and parallelism matter more than raw model quality, and names Opus 4.6 as the strongest design model he has used, though slow. Multiple agents can work on one page by splitting non-overlapping regions, which he contrasts with code and with a cited Cognition paper warning against multi-agent setups. He favours visual, chat-plus-canvas interfaces over prompt-only chat and predicts that illustration and animation will be the next frontier, with eye and hand tracking as possible interfaces. The rest is mostly background: style guides as inspiration, Pencil's team of about 10, the a16z Speedrun experience, and the Around/Miro history. The episode gives few hard benchmarks, so its value is practitioner product reasoning rather than measured results.

## Key ideas
- **Pencil's origin was a May 2025 prototype that turned a visual canvas into structured JSON that LLMs read well** — Tom was frustrated writing prose prompts in Cursor to describe a visual layout. The prototype went viral, which convinced him that others needed a visual-to-code helping hand. Pencil then grew into agents generating designs, not only converting them. ([8:45](https://youtu.be/FqD_hlQSQIk?t=525))
- **The design file is structured JSON in the git repo that humans and agents edit the same way** — The .pen file lives in the repo, so any engineer or agent can read it. Conversion rules (a baked-in Tailwind mapping) can be replaced with a team's own rules. The representation is framework-agnostic, so React or any other library works. ([11:40](https://youtu.be/FqD_hlQSQIk?t=700))
- **Elicitation, where the agent asks clarifying questions first, is a major unlock** — Tom compares it to a design agency's intake interview. Earlier models needed exhaustive specs or produced output the user did not want. Dialogue first now extracts what the user actually wants before the build. ([14:18](https://youtu.be/FqD_hlQSQIk?t=858))
- **Opus 4.6 is the model Tom favours for design, but it is slow** — He says other models need correction rounds ('you've done this wrong, do one more round'), while Opus 4.6 makes the fewest layout mistakes and handles structured data well. He hopes the next gains focus on speed. ([15:45](https://youtu.be/FqD_hlQSQIk?t=945))
- **Speed and parallelism keep designers in flow** — Visible moving cursors show what the model is doing. Parallelism hides latency, because the user can rearrange other parts of the canvas while agents work. Tom contrasts this with code, where editing while an agent builds can break compilation. ([18:26](https://youtu.be/FqD_hlQSQIk?t=1106))
- **Multiple agents can work on the same page by splitting non-conflicting regions** — Tom says the canvas splits work more cleanly than code. One agent takes the hero section, another the middle, a third the footer, and each page can get several agents. He contrasts this with a cited Cognition paper that warns of context loss, arguing that good orchestration avoids that problem. ([22:38](https://youtu.be/FqD_hlQSQIk?t=1358))
- **Vibe images and style guides are starting points, not canonical taste** — Users can drop a photo of a flower or fruit and ask the model to extract a colour palette. Pencil's style guides exist to fix the blank-canvas problem, and Pencil plans to open them so the community can contribute. ([29:17](https://youtu.be/FqD_hlQSQIk?t=1757))
- **Human taste is what separates good output from cookie-cutter AI output, and illustration and animation are the next frontier** — Tom expects AI output to converge on generic results without a human steering it. He expects illustrations and motion to matter next, while noting that SVG and animation tooling are not yet at After Effects quality. ([34:18](https://youtu.be/FqD_hlQSQIk?t=2058))
- **Chat is a poor interface for creative work, so new interfaces such as eye tracking and hand tracking are needed** — Tom says prompting for a page visually is hard. He points to a designer's iPhone eye-tracking prototype, where the model knows what the user is looking at, as an example of the direction he expects. ([49:58](https://youtu.be/FqD_hlQSQIk?t=2998))

## Techniques
- **Keep the design as a structured file in the repo** — Store the canvas as JSON (Pencil's .pen file) in git. Let engineers and agents both read and write it. Put team conversion rules (e.g. to Tailwind or shadcn) in your own rules file so the agent applies them. *When:* Design-to-code workflows where the design and the implementation should stay in sync and agents do the conversion.
- **Drop references into the agent chat as a rules-plus-libraries-plus-images bundle** — Drag images, multiple images, and Markdown or text files with guidelines into the chat. Tom says many users build a set of rules plus component libraries plus reference images for each project. *When:* When the agent needs a house style or visual references beyond a text prompt.
- **Extract a palette from a vibe image** — Give the model a photo of an everyday object (a flower, fruit, or landscape) and ask it to extract a colour palette. Pencil used this to generate several of its style guides. *When:* Exploring colour directions quickly when there is no brand palette yet.
- **Partition a page across parallel agents by region** — Assign each agent a non-overlapping section (hero, middle, footer). Give all agents the same shared understanding of the goal up front, so they split the work without conflicts. Tom ran three pages with two agents each. *When:* Building multi-section pages or screens where regions are independent. Avoid it where sections depend on each other.
- **Run the same task across several models side by side** — Put one frame in Codex, another in Opus, and another in Gemini, and compare the results. Tom says users combine models and harnesses in many ways. *When:* Choosing a model for a task type or checking a new model release against your current best.
- **Elicit requirements before building** — Have the agent ask extra questions about intent, audience and style before generating anything, as a design agency would in an intake interview. *When:* Ambiguous briefs where a first attempt would likely be discarded.
- **Correct the agent in a second round instead of restarting** — When a model misses something, tell it what was wrong and ask for one more round. Tom says this usually fixes the behaviour for the models that need it. *When:* Working with models that are close to the target but miss specific details.
- **Edit other regions while the agent works** — Partition the workspace so the human can reorganize areas the agent is not touching. Tom contrasts this with code, where editing mid-build can break compilation. *When:* Slow generations where waiting wastes flow time.

## Hot takes
- Chat is a bad interface for creative work; the next interfaces will use visual context such as eye or hand tracking, and shared memory.
- Vibe designing and vibe coding are the closest thing to Flash in two decades, letting problem-solvers pick up whatever tools they need instead of job titles.
- Parallel agents on a canvas avoid the conflicts that code has, which pushes back on the claim that multi-agent setups fail on shared context.
- Taste is the moat: AI output trends toward cookie-cutter results, and a human steering loop is still needed.
- Opus 4.6 is the design state of the art in Tom's view, and speed (not quality) is the next bottleneck to solve.
- Illustration and motion are the next big unlock for AI design tools, with SVG models not yet strong enough.
