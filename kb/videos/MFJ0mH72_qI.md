## Summary
The creator argues that AI agents adding features to an existing ShadCN app tend to break other parts of the app, and that the fix is making the agent prove it finished. He uses Anthropic's Ralph plugin, a stop-hook loop that re-feeds the original prompt file until the agent outputs a chosen completion word, with a max-iteration cap as a safety stop. Features are built test-first with Playwright end-to-end tests and per-behavior screenshots. The command palette finished in one loop. On a board-view feature, the agent output the completion word while ignoring UI errors visible in its own screenshots, because its only UI check was glancing at them. The fix was a screenshot protocol: each reviewed image gets a verified prefix, the agent may not output the completion word in the iteration that marks them, and a later iteration confirms all images are marked before finishing. Image checks are kept separate from functional tests, and the board feature then completed in two loops. The evidence is one project and one session, with no error rates. The video ends with a sponsored segment for Automata.

## Techniques
- **Stop-hook completion-promise loop** — Install the Anthropic Ralph plugin. It provides three commands: a loop command, a cancel command and a help command. Give the loop command a prompt file that lays out the workflow, a promise word (the example is 'complete') and a max-iteration count. Tell the agent to output the promise only when the exit criteria are met. The stop hook re-feeds the prompt whenever Claude stops without the promise. *When:* Multi-step features where the agent might quit partway through or claim done too early. The exit criteria must be checkable, such as a test suite or screenshot checks.
- **Test-first workflow inside the loop** — Ask Claude Code to set up a TDD structure: an e2e test folder, a screenshots folder and one test per behavior. Workflow steps from the speaker: run the tests and expect failures, write the minimum code to pass, review all screenshots, rerun the tests, and only then output the promise. Track the passing-test count across iterations so regressions show up. *When:* Any feature that touches existing UI, where a change can break unrelated parts of the app.
- **Screenshot verification protocol** — Playwright captures a screenshot for each functional behavior. The agent reviews each image, then renames it with a verified prefix only after it has actually read it. In a later iteration, the agent checks that every file carries the prefix, re-reviews any that do not, and then runs the functional tests. *When:* UI work where tests pass but visual errors remain, as seen on the board-view feature.
- **Two-phase completion gate** — Do verification in one iteration and forbid the completion promise in that same iteration. Allow the promise only in a later iteration, after the file state (the verified prefixes) and the tests confirm the work. Keep image verification separate from functional tests so each can be checked on its own. *When:* Any loop where the agent tends to claim done right after skimming its own output. The speaker calls this the key change that fixed the premature completions.
