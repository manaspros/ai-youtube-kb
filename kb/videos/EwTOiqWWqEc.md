> Walkthrough of running Kimi K3 inside Claude Code via a local proxy on a Kimi subscription, then using the Hallmark anti-slop design skill to push Kimi, Opus and Codex off their default visual styles.

## Summary
The host argues every model has recognizable default design patterns, and that a design skill is needed to push output off them. He recaps Kimi K3's claimed performance and pricing ($3/$15 per million tokens) against GPT 5.6 and Fable 5, and reports that Kimi Code, Kimi's own terminal harness, felt slow (about 10 minutes versus about 3 for Claude Code or Codex on one task) and mishandled context and subagents. Instead he runs Kimi inside Claude Code through CLIProxy API, a local tool that turns an existing coding-tool login into a local API endpoint, so usage stays on the flat subscription. He then installs the Hallmark skill, explains its four verbs (default, audit, redesign, study), and runs it on a Next.js landing page with Kimi, Opus 4.8 and Codex. His baseline comparison is one run per model, with no measured design scores. The sponsored segment is mid-video, and the channel plugs its paid community at the end.

He calls Kimi K3 strong at front end, with its claimed edge coming from screenshotting its own output and self-correcting. ([0:00](https://youtu.be/EwTOiqWWqEc?t=0))
- **Kimi K3 is claimed to match the top tier at the lowest price, but the speaker does not verify the ranking himself.** — He cites Artificial Analysis for intelligence and LM Arena for front-end preference, with Kimi placed just behind Fable 5 and GPT 5.6 on intelligence and ahead of them on LM Arena design rankings. Pricing is $3/$15 per million tokens for Kimi, versus $5/$30 for GPT 5.6 and $10/$50 for Fable 5. ([1:05](https://youtu.be/EwTOiqWWqEc?t=65))
- **Kimi Code is the slow path. The speaker blames hosting on Kimi's own servers and a rough harness.** — One task took about 10 minutes in Kimi Code versus about 3 in Claude Code or Codex. Context broke when switching models, and the subagent count it reported did not match what it claimed (it said five after appearing to spawn many). ([2:33](https://youtu.be/EwTOiqWWqEc?t=153))
- **Run Kimi inside Claude Code through a local proxy so the flat subscription covers usage instead of per-token API billing.** — CLIProxy API takes a logged-in coding tool and exposes it as a local API. Setup: install via brew, log in with the Kimi login command, start the server, generate a local API key (the speaker suggests letting an agent do this), then point Claude Code's base URL at localhost, set the auth token to that key, and set the model to Kimi K3. - **Environment changes made for the Claude Code session last only for that terminal session.** — The base URL, token and model overrides are not permanent. A new terminal goes back to normal Claude use. ([5:08](https://youtu.be/EwTOiqWWqEc?t=308))
- **Hallmark is a design skill with four verbs. Study mode treats a reference site as inspiration rather than something to clone.** — Verbs: default (build a new UI), audit (check code against anti-patterns and return a report you choose fixes from), redesign (fresh direction, rerun questions and workflow), and study (pull style from a site you like without copying it). With the skill installed in .agents and a plain prompt, the Codex app (which has browser tools) produced a site the speaker rated much better. ## Techniques
- **Run a non-Claude model inside Claude Code via a local subscription proxy** — 1) Install CLIProxy API with brew. 2) Run the Kimi login command and sign in on the page that opens. 3) Start the CLIProxy server and keep it running. 4) Generate a local API key for that setup (the speaker asks Claude Code to do this). 5) In Claude Code, change the request base URL to localhost, paste the key as the Anthropic auth token, and set the model to Kimi K3. 6) Run claude. Exact env var names are not spoken on screen; the speaker just says base URL, auth token and model. Settings last only for that terminal session. *When:* You want to try a model that lives on a flat-rate subscription, but Claude Code's harness is more reliable than that vendor's own CLI. Avoid it if you need persistent config across terminals.
- **Install Hallmark for the right agent** — Copy the install command from the Hallmark GitHub repo and paste it in a terminal. At the agent prompt, choose the agent you need. Kimi Code and Codex install into .agents with no change. For Claude Code, select Claude Code too, which installs into the .claude folder. The skill's SKILL.md holds how-to-invoke details. *When:* Adding a design-quality skill to a project for one or more coding agents.
- **Invoke a skill manually with its slash command when the model is not Claude** — Type the skill's slash command explicitly at the start of the task instead of relying on auto-invocation, so the skill loads before the first build step. *When:* Using a non-Claude model in Claude Code, where the auto-trigger logic is tuned for Claude models and may not fire.
- **Prompt Hallmark with the three pre-flight answers** — State the audience, the site's purpose and the tone in the first prompt. If you leave them out, the skill asks them itself during pre-flight. *When:* Starting a landing page build with a design skill, to skip an interactive round.
- **Run the audit verb, then pick which findings to fix** — Ask for an audit. The skill loads its anti-pattern references, produces a report of flagged patterns (high and low confidence), and you choose which fixes to apply. In the test, the fixes swapped the font, replaced Unsplash images with another stock site (Pixum), and improved mobile responsiveness. *When:* After an initial build, to check a design against known AI-slop patterns before shipping.
- **Use the study verb, not a clone request** — Point the skill at a site you like and ask it to study the style. Hallmark is set to take the site as a reference, not copy it, so the result should be original. *When:* You want a style direction from a reference site without copying its code or layout.
- **Manage context manually on long design sessions** — Auto-compaction does not run for Kimi in Claude Code. When answers start drifting from the instructions or turning generic, start a fresh session or otherwise reduce the context. *When:* Long iterative design runs with a non-Claude model in Claude Code.
