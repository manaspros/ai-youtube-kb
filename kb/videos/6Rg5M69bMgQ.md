> A walkthrough of two free add-ons for Claude Code: the SuperClaude configuration framework (slash commands, flags, personas, MCP-wired workflows) and a basic browser web UI for reaching Claude Code from other devices on the LAN.

## Summary
The host presents two free tools that extend Claude Code. The first, SuperClaude, is a configuration framework of 18 slash commands, flags and 9 personas, backed by custom command files, YAML workflows and CLAUDE.md config. Because the framework has no usable guide, the host has Cursor read all the config files and write a roughly 450-word docs.md, then asks Cursor for phase-by-phase commands plus matching prompts, which are pasted into Claude Code. The demo runs phase 1 (analysis and research), where Claude picks Context7 for docs and asks permission before calling the Sequential MCP. The second tool is a web GUI for Claude Code: it runs locally on port 8080 by default, can be started in a network-reachable mode, and is opened from a phone or another machine on the same network via the host machine's IP. The host admits the web UI is basic, that SuperClaude slash commands do not work in it, and that the framework itself is mostly prompting with nothing fundamentally new. The video gives a usable install and usage path but thin evidence of results.

## Key ideas
- **SuperClaude is a configuration framework for Claude Code: 18 structured slash commands, flags that modify them, and 9 personas covering lifecycle roles (front-end, architecture, backend, security, problem analysis).** — Under the hood it is custom command files, YAML workflow definitions and a CLAUDE.md that tells the model how to use everything. The host calls it 'all just prompting', which is how the framework's author encodes development-cycle context. ([0:00](https://youtu.be/6Rg5M69bMgQ?t=0))
- **Framework workflows wire MCP servers into specific steps: Context7 for external docs, Sequential for multi-step reasoning, plus Magic UI and Puppeteer.** — The framework says where each MCP belongs in a workflow, but the user still has to configure the MCP servers in Claude Code. The host could not set up Magic and Puppeteer, so it told Cursor to leave them out of the flags. ([1:10](https://youtu.be/6Rg5M69bMgQ?t=70))
- **The main obstacle is the lack of documentation, and the workaround is to have an AI read the config and write a guide.** — Cursor read all the config files and produced a usage guide, then a roughly 450-word docs.md that the host later fed to Claude Code as context. The host reports this quickly and accurately, but gives no measure of how correct the generated guide was. ([2:36](https://youtu.be/6Rg5M69bMgQ?t=156))
- **Generated commands need their accompanying prompts. Ask for command, flags and prompt together, in a structured form per phase.** — The first Cursor output had commands but no prompts. Asking for slash commands, flags and prompts in a structured form per phase produced an 11-phase outline ending at deployment. The host then pastes the command into Claude Code's slash menu and the prompt after it. ([4:44](https://youtu.be/6Rg5M69bMgQ?t=284))
- **Claude Code picks tools from the workflow's context. In the phase-1 research run it chose Context7, created to-dos, and asked permission before using Sequential.** — The host frames it as 'nothing fundamentally new': the workflow is a prompt that the framework supplies, not a new capability of the model. ([6:54](https://youtu.be/6Rg5M69bMgQ?t=414))
- **The web UI is a browser front end for Claude Code that runs on the desktop and can be reached from a phone on the same network. It is basic, with no special features.** — The default launch binds to localhost:8080, which is local only. A network launch mode makes it reachable from other devices. Slash commands from SuperClaude do not work in this UI. ([7:59](https://youtu.be/6Rg5M69bMgQ?t=479))
- **Install is a global-or-project choice. Global install requires clearing the existing .claude folder first; project install needs .claude appended to the target folder path.** — The configuration files must sit inside a .claude directory for either install mode to work. ([10:19](https://youtu.be/6Rg5M69bMgQ?t=619))

## Techniques
- **Install SuperClaude from its GitHub repo** — Clone the repo with the command shown on the GitHub page (the exact command is not spelled out in the transcript), cd into the folder, and run the install script it contains. Global install: delete any existing ~/.claude folder first, then run the script. Project install: run the script with the target folder path, with .claude appended to the end of that path, so the config lands in <project>/.claude. *When:* Adopting the framework globally for every Claude Code session, or scoping it to one project.
- **Have an AI write a usage guide from the framework's own config** — Open the installed config folder in Cursor (or any model with file access). Ask it to read all configuration files and write a comprehensive guide covering which commands, flags and personas to use and when, plus where each MCP fits. Save the output as docs.md (about 450 words in the demo). Paste or attach that file to Claude Code as context. *When:* A framework has many commands and flags but thin docs, and you want the model to explain how to use it for your task.
- **Turn a phase into a runnable slash command plus prompt** — Ask the model to output, for each phase, the slash command with its flags and the accompanying prompt in a structured form. Paste the command into Claude Code's slash menu, then paste the prompt into the same message. The host says the prompt can be customized. *When:* Driving a multi-phase project plan (research, design, build, deploy) through Claude Code without memorizing flags.
- **Wire MCPs yourself, then reference them through flags** — Configure each MCP server in Claude Code directly. The framework only says where each one belongs in a workflow. In the demo, flags like --magic (Magic UI MCP) and --watch (continuous monitoring) were used alongside /build, with a --react flag and a front-end persona flag. Remove any MCP flags whose servers are not set up. *When:* A workflow expects MCP servers that are only partly configured.
- **Reach Claude Code from a phone on the same LAN** — Run the installed web UI executable. The default launch serves localhost:8080 only. Use the network-enabled launch command instead (the video does not name it; the host used ls to find the exact executable name, since the docs had an error). Find the host machine's LAN IP with a terminal command (the host used Warp; ChatGPT was suggested as an alternative). In a browser on any device on that network, open the IP with the same port. Create or pick a project directory and chat with Claude Code from there. *When:* Running Claude Code on a desktop and checking or prompting it from a phone or another machine on the same network.
