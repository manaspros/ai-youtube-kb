> A single-author head-to-head of Claude Code (Opus 4.7) vs Codex CLI (GPT 5.5) across usability, planning, greenfield builds, context, memory and sub-agents; Codex wins on cost and autonomy, Claude on UX, hooks and ecosystem.

## Summary
The creators compare Claude Code running Opus 4.7 against OpenAI's Codex CLI running GPT 5.5 across nine categories, each tested inside its own CLI. They report that Claude Code's UI and permission handling have degraded since version 2.1.0, with auto mode prompting even in bypass mode, while Codex's Rust-based UI, pre-installed skills and personality setting work more smoothly. On a single debugging task, Opus 4.7 used about 173k tokens against about 82k for GPT 5.5, which they measured with a custom script that parses both tools' session JSON files. On planning and greenfield builds, Codex was faster and built fallbacks, while Opus produced deeper plans and a more polished UI. Context management and memory favour Codex in the creators' view: it preserves a tail of recent context through compaction and builds cross-project memory, whereas Claude Code offers in-session context editing and project-scoped memory. Claude Code keeps the lead on hooks, effort control, worktree sub-agents, desktop and mobile surfaces, and a richer code review, though its strict sub-agent context isolation hurt the creators' research sub-agents. The evidence is one author's anecdotes on one project each, and the video includes a sponsored segment for Stream.

## Key ideas
- **Claude Code's permission model is blocking unattended work** — Claude Code replaced the dangerously-skip-permissions mode with auto mode by default, and it still prompts for writes even in bypass mode. In one run, a skill creation sat blocked on a prompt to write under the .claude folder for a long time while the author was in another session. Codex's YOLO mode asked for no permissions. ([1:02](https://youtu.be/8ImlAQOyVTs?t=62))
- **Codex ships more built-in skills** — Codex comes with pre-installed skills including an agent browser that verifies features automatically after implementation, so no browser MCP is needed. It also has a built-in skill creator that generates a full skill with reference files. In Claude Code, the skill creator must be installed separately, otherwise it just writes a Markdown file. ([2:30](https://youtu.be/8ImlAQOyVTs?t=150))
- **Token efficiency measured on one debugging task** — On the same app and a similar debugging task, Opus 4.7 used about 173k tokens and GPT 5.5 about 82k, which the author attributes to fewer retries. The count came from a custom script that reads both tools' session JSON files, since Claude Code's context command has no Codex equivalent. The result is one task, not a benchmark. ([3:41](https://youtu.be/8ImlAQOyVTs?t=221))
- **Planning depth versus speed** — On a frontend-for-existing-FastAPI task, Codex's plan mode was simple but clearly separated its assumptions, and the implementation took about 8 minutes. Claude Code took 24 minutes but produced a much deeper plan that pulled in ShadCN UI for better UX. ([5:08](https://youtu.be/8ImlAQOyVTs?t=308))
- **Fallbacks versus needing everything up front** — When no Gemini API key was present, GPT 5.5 implemented local fallback follow-up questions so the app did not crash. Opus 4.7 asked for the key before starting and built the app around it, so with no key the app just errored. The author sees GPT's behaviour as more production-like, while Opus's UI was stronger. ([7:41](https://youtu.be/8ImlAQOyVTs?t=461))
- **Debugging style differs: self-inspection versus asking the user** — Codex used the agent browser to debug autonomously. Claude Code instead asked the user questions, added UI indicators and console logs, and waited for the user to check states and report back. Claude eventually fixed the issue after several rounds. ([7:41](https://youtu.be/8ImlAQOyVTs?t=461))
- **Compaction keeps a raw tail in Codex** — Claude Code edits context in-session, removing stale tool calls and reasoning, and then compacts. Codex compacts the whole conversation but leaves the last ~20,000 tokens uncompacted. In the author's test, Codex performed better after compaction, though only one test is described. ([10:31](https://youtu.be/8ImlAQOyVTs?t=631))
- **Memory scope: project-level versus global** — Claude Code's memory stores persistent preferences per project, so the behaviour is lost when switching projects. Codex consolidates information across sessions into a global memory that spans projects. ([11:43](https://youtu.be/8ImlAQOyVTs?t=703))
- **Sub-agent context isolation versus inheritance** — Claude Code gives each sub-agent a fresh context, an explicit tool allow-list and only the parent's prompt plus system prompt and global rules. Codex forks the full parent history and inherits tools by default. The author found Claude's strict isolation hurt research sub-agents that lacked prior context. ([14:06](https://youtu.be/8ImlAQOyVTs?t=846))

## Techniques
- **Count tokens per session from the CLI's session files** — Claude Code and Codex both store sessions as JSON files, organized differently. Write a small script that parses each tool's session files and sums token usage per session, then compare sessions of similar scale. The video does not show the script's code or the exact file paths. *When:* When a CLI lacks a built-in token or context report, to compare cost across coding agents on comparable tasks.
- **Set a Codex personality to reduce sycophancy** — In Codex, change the personality setting to a direct, concise style. The author says this prevents GPT 5.5's default agreeableness. In Claude Code, the equivalent was done with instructions in CLAUDE.md. The video does not show the exact setting name. *When:* When the model keeps agreeing with every prompt and you want terse, direct responses.
- **Use Claude Code's expanded thinking to course-correct** — Press Ctrl+O in Claude Code to expand and view the model's thinking during a task, then correct the approach mid-task instead of after implementation. *When:* When a long task may be heading the wrong way and you want to intervene before it finishes.
- **Use Codex's attempt flag for best-of-n** — In Codex cloud, an attempt flag runs the same task n times, producing several implementations from which the best is selected. Claude Code can approximate this only through configuration and instructions, not a flag. The video does not show the flag's exact name. *When:* When a task is worth parallel attempts and you can pick the best result.
- **Keep AGENTS.md or CLAUDE.md lean** — The author found Claude Code's generated CLAUDE.md (about 90 lines) included architecture, app flow and commands, much of it redundant. Codex's AGENTS.md added commit, pull-request and security guidelines and kept the project-structure section brief. Keep only what helps the agent, and include the process rules the agent needs. *When:* When bootstrapping agent instruction files with a generator's init command.
- **Design sub-agents for isolation or inheritance deliberately** — Claude Code sub-agents get a fresh context with an explicit tool allow-list, which suits isolated work. Codex forks full history and inherits tools, which suits continuity-heavy work. Match the choice to the task, because the author's research sub-agents under strict isolation performed poorly. *When:* When designing sub-agents for research or analysis that depends on prior discussion.

## Hot takes
- Claude Code's UI and terminal quality has degraded since version 2.1.0, and the TUI now feels vibe-coded (the author's anecdote, no measurement).
- Codex is more usable and more cost-efficient than Claude Code per dollar, based on one debugging task and one greenfield app.
- GPT 5.5 is significantly more sycophantic than Opus 4.7 by default.
- Claude Code's strict sub-agent isolation hurt research sub-agents in the author's use.
- The video has a sponsored segment for Stream (Vision Agents) around 3:50 to 5:08. The sponsor is not the video's focus, so quality is not capped, but the comparison is single-author and anecdotal throughout.
