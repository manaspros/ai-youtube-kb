> Exa's forward-deployed engineer demos ExaSnapshot, point-in-time web search for backtesting agents without future leakage, plus a hands-on acquisition-prediction exercise. Mostly a vendor pitch, but the leakage and holdout-set points hold regardless of vendor.

## Summary
Ryan Ahern (Exa) pitches Exa as agentic web search and introduces ExaSnapshot, which lets you run a search or fetch a URL as it would have looked at a past date. The core argument is that live search silently leaks future information into backtests, so any predictive system that uses web features gives inflated results unless retrieval is constrained to a cutoff date. He describes two patterns: a traditional ML model whose features are gathered from historical web snapshots, and an agentic feature added to that model that is backtested one feature at a time. He also argues that freezing the snapshot before an outcome can isolate whether a coding model or agent actually improved. The second half is a 30-minute hands-on exercise where attendees find features that predict company acquisitions 1, 7 or 30 days ahead, scored +1, -1 or 0. The talk closes by showing that the winning features were overfit to the small public test set, and the speaker recommends keeping a holdout set. Most of the content is product demonstration and enterprise upsell, and no CLI, API calls or config were shown.

## Key ideas
- **Live search leaks the future into backtests** — A search done today returns the latest information, including the outcome you are trying to predict (e.g. an acquisition already announced). Backtesting against it gives a falsely perfect true-positive rate. Constraining retrieval to a snapshot date before the outcome removes that leak. ([10:29](https://youtu.be/L4dUFimVDKU?t=629))
- **Two version-control primitives: content versioning and version search** — Content versioning returns a URL as it was at a given date (or the nearest earlier version the index holds). Version search re-runs a whole query as it would have run on that date. The speaker says the index covers about 100 billion documents and trillions of URLs. ([5:48](https://youtu.be/L4dUFimVDKU?t=348))
- **Traditional models can be backtested with historical web snapshots** — If a model's features come from web pages that do not keep old versions, or from article publish dates that get edited (SEO refreshes), the features cannot be trusted or reconstructed. Pulling the page as it existed at the time gives a reliable feature store for backtesting. ([11:41](https://youtu.be/L4dUFimVDKU?t=701))
- **Backtest agentic features one at a time, then add them one at a time** — For a live system where an agent turns web search results into a structured yes/no signal that feeds a trained model, test each agentic feature against known positives and negatives at the snapshot date. Keep the feature only if it improves prediction. Tune the search approach, because non-deterministic systems move a lot with small search changes. ([13:24](https://youtu.be/L4dUFimVDKU?t=804))
- **Freeze the snapshot before a solved PR to evaluate a coding model** — To check whether a coding model improved, pin the search to the point just before an external repo's PR was resolved, then let the agent run. A success then reflects the model or harness change and not information from the future. ([15:45](https://youtu.be/L4dUFimVDKU?t=945))
- **Overfitting to the public test set is the main failure mode** — The winning features in the room were tuned to the 10 known companies. Two of the top features were specific enough to be overfit, and the speaker admits he removed the holdout set to keep the exercise simple. He argues for a holdout set, with the same backtest run against companies the tuning never saw. ([22:50](https://youtu.be/L4dUFimVDKU?t=1370))
- **Combining features with AND vs OR trades precision for recall** — Combining two yes/no features with OR flagged many false alarms. Requiring both with AND improved the score in the demo. Feature combination is treated as a tunable part of the backtest, not a fixed choice. ([21:18](https://youtu.be/L4dUFimVDKU?t=1278))

## Techniques
- **Point-in-time (as-of date) retrieval for backtests** — Set a snapshot date on every search or URL fetch in the pipeline. Choose a date just before the outcome is announced, and check that no retrieved document can reveal it. Run the full agent or feature pipeline at that date. Compare the results to live runs to measure leakage. *When:* Any system that uses web search or scraped pages as features and is backtested against events that happened later (acquisitions, earnings, hires, deals, PRs resolved).
- **Content versioning for trusted historical features** — For a known URL, request the content as of a target date. The result is the nearest earlier version in the index. Store the fetched content with its as-of date, and do not rely on the page's publish-date field, since articles get re-dated. *When:* Features come from specific sites or articles, and you need the feature value as it was seen at decision time.
- **Feature-by-feature backtest with a holdout set** — Write one yes/no feature as a natural-language question (e.g. did the company lose its CEO or CFO or appoint interim leadership in the last period). Run it at T-1, T-7 and T-30 days before each known event, plus control dates for companies that did not have the event. Score it. Keep the feature only if it improves the score on a holdout set it was not tuned on. Then add the next feature. *When:* Adding LLM-based or agentic signal extraction to a predictive model and needing evidence that each feature helps.
- **Scoring rubric for event prediction** — +1 when the feature flags a company as acquired at T-1, T-7 or T-30 days before the real event. -1 when it flags a company that was never acquired. 0 for misses and for correct non-flags. Use this to compare feature sets against each other. *When:* Binary event-prediction backtests where false alarms should cost more than misses are worth.
- **Pin the repo state for coding-model evals** — Pick a commit before a known fix or PR in an external repo. Give the agent the issue with the repo at that commit and the search snapshot at that date. Score whether the agent resolves the task. Repeat with the model or harness changed to see whether resolution rate changes. *When:* Measuring whether a coding agent or model improved on real-world issues without seeing the answer.

## Numbers
- Index covers about 100 billion documents and trillions of URLs (speaker's approximate figure), with versions kept per URL. ([5:48](https://youtu.be/L4dUFimVDKU?t=348))
- Search latency ranges from about 300 ms up to long-running research jobs; one example ran 20 minutes and found 3,212 video game publishers and their developers. ([4:26](https://youtu.be/L4dUFimVDKU?t=266))
- Workshop backtest: 10 companies per test run, with control companies that were not acquired. Scoring is +1 for a correct flag at T-1, T-7 or T-30 days, -1 for a false alarm, and 0 for misses and passes. The exercise had a 30-minute budget. ([18:55](https://youtu.be/L4dUFimVDKU?t=1135))
- Example news context used in the demo: reported OpenAI annualized revenue estimates around $70B versus $50B, with the gap attributed to gross vs net revenue accounting. ([6:59](https://youtu.be/L4dUFimVDKU?t=419))
- Example winning-style feature threshold: share price at least 60% below its five-year high, or an activist or large shareholder publicly calling for a sale within 12 months. The speaker notes this is overfit to the test set. ([24:25](https://youtu.be/L4dUFimVDKU?t=1465))

## Hot takes
- Vendor workshop: the talk is a product demo with an enterprise sales hook (email for the enterprise team). It also calls Exa 'perfect search for AI agents' with no supporting evidence. Quality capped at 2 under the sponsored-segment rule.
- The core idea is useful regardless of vendor. Any backtest that lets live search see post-cutoff information is inflated, and this is a common blind spot in agent evals.
- The speaker's own winner example shows the pitfall: features tuned to a small public set overfit, and he admits he removed the holdout set to keep the exercise simple.
- No commands, API calls, config keys or code were shown. The hands-on part happened in a web UI, so this is not reproducible as a how-to.
- Numbers such as index size and 300 ms latency are stated without methodology or source, so treat them as marketing claims until checked against Exa's docs.
