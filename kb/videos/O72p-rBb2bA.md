> SonderMind engineers describe the guardrail, eval and clinician-annotation loop behind Sonder, a clinically grounded mental health AI coach, and open-source 300 scenarios for it.

## Summary
Akele Reed and Dave Revere of SonderMind present how they built guardrails for Sonder, a conversational (voice and text) mental health AI coach. The system wraps a core model in separate input and output guardrails, each implemented as its own LLM-as-judge call, which is slower and costlier but harder to jailbreak and easier to evaluate in isolation. The speakers argue that over-triggering is also a harm, so the goal is "more correct triggers" rather than more triggers, with clinicians calibrating the behavior. Their learning loop traces conversations, has a licensed clinician annotate missed or wrong guardrail firings, and turns those annotations into typed evals that gate releases in CI. They also say they turned off the model providers' built-in safety filters on day one because they over-filtered their test sets. They open-sourced 200 input and 100 output clinically reviewed guardrail scenarios. The talk contains sensitive content, and the speakers are a vendor presenting their own product, so the evidence is a single product case study with no published benchmark numbers.

## Key ideas
- **Input and output guardrails sandwich the core agent model** — Input guardrails inspect each user message before the core model responds. Output guardrails inspect the AI response and the conversation as a whole for clinical safety risk and can steer the conversation back on track. ([2:25](https://youtu.be/O72p-rBb2bA?t=145))
- **Keep each guardrail as a separate LLM-as-judge call** — Separate judge calls are harder to prompt-engineer or jailbreak through continued conversation. The team accepts the added latency and cost because of the sensitivity of the use case. Modularity also lets them change the core model without compromising safety and makes each guardrail easier to evaluate. ([3:37](https://youtu.be/O72p-rBb2bA?t=217))
- **Optimize for correct triggers, not more triggers** — Over-triggering a guardrail can feel like a door slam to a vulnerable user and isolate them. The system should surface crisis resources and disengage only for active danger, respond normally to past-tense or ordinary distress, and pass ordinary messages straight through. ([6:03](https://youtu.be/O72p-rBb2bA?t=363))
- **A regex, long prompt, or generic moderation API misses the sentence under the sentence** — The speaker gives an indirect self-harm message about packing a box to feel what it would be like to be gone. Keyword rules, bloated prompt instructions, and broad moderation endpoints were argued not to catch the clinical implication, which a clinician recognizes. ([9:55](https://youtu.be/O72p-rBb2bA?t=595))
- **Clinician annotations become typed evals that gate CI** — Traces are captured at the moment of risk. A clinician annotates the expected behavior with a small rubric. The annotation fields map to an eval: input, expected result, expected observation as the assertion, turn index for replay, and category. An extraction script triages the flagged traces and commits them to the eval schema, so a single case can lift a whole category. ([12:22](https://youtu.be/O72p-rBb2bA?t=742))
- **The subject-matter expert defines correct and the team does not vibe-check** — Labeled scenarios ask concrete questions: did the expected observation fire, did the right category trigger, did it fire at the right turn, and did the output evaluator catch the issue. False positives, false negatives, category, and timing are all scored. ([13:49](https://youtu.be/O72p-rBb2bA?t=829))
- **Turn off built-in provider safety filters and manage calibration yourself** — In answer to a Q&A question, the speakers say they disabled the models' built-in guardrails on day one because those filtered out their whole dataset. They frame provider over-calibration as a compassionate choice that they try to shrink with their own, more precise guardrails. ([19:06](https://youtu.be/O72p-rBb2bA?t=1146))
- **Open-sourced a shared baseline dataset for mental health guardrails** — The release contains 200 input and 100 output guardrail scenarios, single and multi-turn, clinically reviewed and calibrated against real conversation patterns. The speakers present it as a baseline to supplement, not replace, your own learning loop. ([16:16](https://youtu.be/O72p-rBb2bA?t=976))

## Techniques
- **Pre- and post-LLM guardrail sandwich** — Run an input-judge LLM call on each user message before the core model responds, and an output-judge LLM call on the response plus the full conversation history. Keep the judges as separate calls so they can be tuned and evaluated independently of the core model. *When:* High-stakes conversational products where users may try to jailbreak the system through multi-turn pressure, and where the cost and latency of extra judge calls is acceptable.
- **Trace-to-typed-eval annotation loop** — Capture the conversation at the point of a guardrail miss or false trigger. A domain expert annotates it with a small rubric covering expected observation (the assertion), turn index (for replay up to the point where the guardrail should fire), category, and notes. An extraction script triages flagged traces into a report and converts annotations into typed evals in the project's eval schema. Commit the evals with the calibration changes so they run in CI on every prompt, model, or guardrail change. *When:* When correctness depends on expert judgment that automated rules cannot capture, and when you need regression protection for a whole failure category after fixing one example.
- **Multi-metric guardrail scoring** — Score each labeled scenario on four questions: did the expected observation fire, did the right category trigger, did it fire at the correct turn, and did the output evaluator catch the issue type. Track false positives and false negatives separately, and use them to gate releases. *When:* When you need to balance over-triggering against missed risk and to check that timing is correct in multi-turn conversations.

## Hot takes
- General-purpose LLMs are too over-calibrated for mental health use. The speakers disabled provider guardrails on day one because they filtered out their entire dataset.
- A simple eval gate does not make a mental health system safe. A learning loop that captures clinician judgment does.
- Over-triggering is a safety harm, not a safe default. The goal is correct triggers, not more triggers.
- Benchmark perfection can drift focus away from the human the benchmark is meant to protect.
