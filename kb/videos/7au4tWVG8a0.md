> Practical tips for getting better results and lower cost from Anthropic's Fable 5.1 in Claude Code: lower effort, prune old-model instructions, scope edits, and give whole-feature prompts. Mostly anecdotal.

## Summary
The host argues that Fable 5.1 (Anthropic) behaves differently from earlier models, so habits from older models can produce worse or more expensive results. On the host's own client projects, Fable 5.1 was better than Fable 5 only on the hardest task, but it finished more attempts and cost less, partly because of a 75% cut in cached-read pricing. The host also cites Artificial Analysis figures: about 1.7x more output tokens and roughly 20% higher cost per task versus Fable 5, and a higher hallucination rate on unknown answers. The main warning is that when a safety guardrail triggers, Claude Code silently switches to a weaker model for the rest of the session. The seven tips are: start at low effort, delete CLAUDE.md instructions written for older models (using a prompt-audit command), tell the model nobody is watching and that reversible steps can proceed, fence off what not to touch, edit small parts of files instead of rewriting them, remove mannered prose, and give whole features in one prompt instead of many small steps. Evidence is a single channel's anecdotes plus a sponsor read, so treat the numbers as directional.

## Techniques
- **Start at low effort and escalate only on evidence** — Set the effort setting to low for a task first. Raise it only if the output shows the extra effort is needed. The host says high effort caused a lot of back-and-forth on one part of a feature. *When:* Default for most Fable 5.1 coding tasks. Raise effort only for work that is clearly hard.
- **Ablation test to prune CLAUDE.md** — For each instruction in CLAUDE.md, remove it and rerun the same kind of task. If the output is the same, delete the instruction permanently. Use the prompt-audit command the host names (Claude API prompt audit) to list instructions written for older models, with proposed diffs. Review and approve each change yourself. *When:* After switching models, or whenever CLAUDE.md has accumulated workaround rules for older behaviour.
- **Unattended-run preamble** — State in the prompt that no one is watching. Tell the model to continue with any step already covered by the original request as long as it can be undone. Ask it not to stop for questions that do not need asking. *When:* Long agent runs the user will not monitor, where a permission pause would stall the job indefinitely.
- **Explicit scope fence** — Add an explicit list of what must stay unchanged, for example test files or specific modules. Tell the model to mention any other problems it notices at the end of its reply instead of fixing them. *When:* Any feature task on a codebase where extra edits could change behaviour the user wants preserved.
- **Minimal-diff editing instruction** — Tell the model that when a small change gives the same result, it should edit only that part of the file, not rewrite the whole file. The host says this cut output tokens on a large project. *When:* Multi-file edits where full-file rewrites drain the usage limit.
- **Remove mannered prose** — Add an instruction to remove all mannered prose, meaning metaphors and fancy phrasing in place of plain statements. The host used this on a research-writing task. *When:* Long research or report writing where the point gets buried in figurative language.
- **Whole-feature prompts instead of step-by-step prompts** — Describe the end result of the whole feature clearly in one prompt, and let the model work through the steps itself rather than sending one small step at a time. *When:* Large, well-specified tasks where the model's ability to finish without stopping matters.

## Hot takes
- Client comparisons (Fable 5 vs 5.1) rest on undisclosed projects and a handful of runs. Treat them as anecdotes, not a benchmark.
- The most important warning, that a guardrail silently switches the session to a weaker model, is backed only by one anecdote and an Anthropic claim about guardrail frequency. It needs independent verification before anyone relies on it.
- The cost figures conflict in the transcript: 'well under half as much' (1:14) versus '58% less' (10:59). The 47% figure is an estimate from a usage command, not billed cost.
- The channel promotes its paid community (AI Labs Pro) and includes a sponsor read (Porkbun, roughly 6:50-8:04). Weigh the tips with that in mind.
- The CLAUDE.md ablation method (remove an instruction, rerun, delete if unchanged) is sound practice regardless of model, and is the most reusable idea here.
- Tips about low effort and scope fencing are reasonable but generic. Most are standard prompt hygiene, not Fable-specific findings.
