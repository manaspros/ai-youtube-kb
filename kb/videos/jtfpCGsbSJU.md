> Better Stack commentary on Artcraft, a viral open-source Adobe clone, and a "reverse engineer anything" MCP; the host tests Opus 5.5 rebuilding a 1990s pinball game in Rust with sub-agents and verification passes.

## Summary
The host covers two viral GitHub projects. Artcraft is a set of open-source Adobe-style apps (Photocraft, Vectorcraft, Filmcraft) that its author says were clean-room rewrites built from public file specs and observed behavior. The host notes visible resemblance to Adobe screenshots, and a Hacker News tester found basic features broken, while the project's own roadmap admits real Photoshop parity is well below 50%. The second project is "Reverse Engineer Anything," an MCP that connects agents to reverse-engineering tools (Hopper, Ghidra, IDA) with skills on top. The host then tested the idea himself by asking Opus 5.5 to disassemble the Pinball Space Cadet EXE and port it to native Rust, which took about 2h25m, produced 31k lines with 174 tests and zero dependencies, and used 15 sub-agents. A fresh set of agents checking each function against the original found almost nothing to fix. The host estimates about $140 at API prices and says it barely dented his subscription usage. His conclusion is that agents make cloning cheap whenever they can observe and inspect the target and a test suite or reference can verify the result, pointing to a Next.js port and a claimed TypeScript-compiler-to-Rust port as examples. He argues that making tests private would be a weak defense.

## Techniques
- **Reference-driven port with source-address traceability** — Have the agent build its own disassembly/inspection tools, translate the target function by function, and tag every generated function with the address or location it came from. Split the work into sub-agents by domain (e.g. physics, controls, missions). Keep the original binary as the oracle. *When:* Porting or cloning a closed binary or app where a reference implementation is available to run and compare against.
- **Fresh-context verification pass after a fan-out** — After the build sub-agents finish, start a new set of agents with clean context. Have each check one function or unit against the original and report mismatches, instead of letting the builders review their own output. *When:* Any large agent-generated port or refactor, where the builder's own review is unlikely to catch what a fresh agent would.
- **Verifiable-goal loop (test suite as the spec)** — Give the agent a test suite or other mechanical check and let it keep iterating until the suite passes. The host's examples are the Next.js port and the TypeScript-compiler port. *When:* Migrations or rewrites where pass/fail can be defined mechanically. The host's claim is that this is the main reason agents succeed at large ports.
- **Clean-room rebuild from public specs and observed behavior** — Implement features from a public file-format spec (the Artcraft author cites the PSD spec) and test against real sample files, instead of reusing the original code, shaders or assets. *When:* Replicating a file format or app behavior where a public spec exists. The host notes this does not protect against copying screenshots or UI.

## Hot takes
- The 'open source Adobe' framing is oversold: basic features were reported broken, and the project's roadmap admits Photoshop parity below 50%.
- Clean-room claims are doubtful given visible Adobe screenshots in the project; the host implies this is a legal risk.
- With enough tokens, most closed software can be cloned to some extent, so software is becoming de facto open source.
- Keeping test suites private is a 'pretty useless' protection against capable agents.
- For personal software, code quality does not matter as long as it works for its owner.
