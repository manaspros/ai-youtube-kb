> Walkthrough of Routa, a free, local-first, open-source Kanban desktop app that runs AI coding agents through backlog, dev, and review lanes with evidence and gates instead of one chat thread.

## Summary
The presenter demos Routa, an open-source desktop app (also self-hostable via Docker Compose) that organizes AI coding work as a Kanban delivery pipeline. He attaches a real repo to a workspace, adds a small task, and watches it move automatically from backlog into development, with a different agent picking up each stage. The pitch is that chat-first tools like Cursor and Claude Code keep the conversation at the center, so plans, failed attempts, and checks get lost, while Routa makes the task state, handoffs, traces, and checks visible. He argues the core shift is from "does this look good?" prompts to explicit fitness functions, evidence, and review gates, similar to CI/CD thinking. He frames the problem as maintenance: agents forget what they tried, touch unrelated files, and leave the developer as a manager who has to review diffs and tests. He compares it to agent frameworks like CrewAI and LangGraph, where you build the workflow yourself, and says it is free, local-first, and needs no account. The video is a single short demo with no measurements, and he is explicit that it has a learning curve and fewer ready-made agents than commercial tools.

## Key ideas
- **Three failure modes of chat-first AI dev tools** — The presenter names chat hell (plans, failed attempts, and fixes buried in a conversation), no traceability (you cannot see what the AI tried or what evidence it used), and no real quality gates (you have to ask whether tests ran, the diff was checked, and acceptance criteria were met). ([0:00](https://youtu.be/_16PhraFYjQ?t=0))
- **Treat AI coding as a delivery pipeline, not a chat** — The core framing is tasks, agents, review stages, evidence, and gates, which he calls CI/CD-style thinking applied to AI-assisted software work. ([0:50](https://youtu.be/_16PhraFYjQ?t=50))
- **Tasks become board items that agents pick up automatically** — A task added to a workspace lands in the Kanban backlog, moves to development on its own, and the matching agent picks it up. The handoff is visible, and the user can chat with the agent while it runs. ([1:58](https://youtu.be/_16PhraFYjQ?t=118))
- **The Kanban board is the coordination layer** — Different agents can own different lanes, and a task moves lane to lane. Routa also supports MCP and ACP for agent connections. He describes it as infrastructure for coordinating software agents rather than another chat box. ([3:20](https://youtu.be/_16PhraFYjQ?t=200))
- **Gates and fitness functions instead of asking the LLM to approve** — He says Routa adds checks, fitness functions, evidence collection, and review gates, which changes the question from whether the model thinks the output is good to whether the work passed defined checks. ([3:20](https://youtu.be/_16PhraFYjQ?t=200))
- **The real cost is maintenance and managing the AI** — On a real codebase, context gets messy, the agent forgets earlier attempts, and it edits files it was not asked to touch. The developer then becomes the manager for the AI: tracking tasks, reviewing diffs, and checking tests. ([4:28](https://youtu.be/_16PhraFYjQ?t=268))
- **Positioning against chat tools and agent frameworks** — Cursor and Claude Code are chat-first and close to the code. CrewAI and LangGraph are flexible, but you must design the workflow yourself. Routa's pitch is a ready-made delivery structure that is free, local-first, and pluggable, with no mandatory account to try it. ([5:41](https://youtu.be/_16PhraFYjQ?t=341))
- **Honest limits: learning curve and a thinner agent ecosystem** — He says it is not a drop-in replacement, that the Kanban and protocol model has a learning curve, and that there are fewer ready-made agents than commercial closed tools. He still claims it speeds up the flow, but offers no measurement. ([6:55](https://youtu.be/_16PhraFYjQ?t=415))

## Techniques
- **Lane-per-stage agent pipeline** — Create a workspace, attach a git repo, and pick the Kanban view. Add a task, and it enters the backlog. Lanes run backlog, to-do, development, testing, and review. Map a different agent to each stage (planning, implementing, reviewing, testing). Agents are connected through your AI provider key. The presenter used OpenCode as the agent runtime and synced an Anthropic key for Claude. *When:* Multi-step tasks where you want explicit handoffs and a visible state for each step, instead of one long chat.
- **Evidence-backed review gates** — Require each stage to produce checkable artifacts before a task advances: tests run, the diff inspected, and the acceptance criteria verified. Keep the trace of what changed and what was checked with the task, and do not rely on a model's yes/no judgment. *When:* Reviewing agent-written changes before merge, or when you need an audit trail of what an agent did and why.
- **Per-task traceability** — Keep each task's plan, tool actions, changed files, and checks attached to the task card, so a reviewer can see the path to the result without scrolling a chat log. The demo shows this as a traces view per task. *When:* Longer or multi-agent work where you need to resume, hand off, or audit a task later.
- **Self-hosted setup** — Clone the repo and run docker compose up to self-host. The presenter chose the desktop app instead because he had sync problems with his git repo under the Docker setup. *When:* You want a local-first install with no account, or you need a self-hosted team deployment.

## Hot takes
- Chat-first AI coding tools have reached their limits, and the next step is better coordination and traces rather than smarter models (6:55).
- Managing AI agents is now a job in its own right, and a visible board is needed to do it well (4:28).
- Routa speeds up the flow, but the claim rests on one demo with no timing or quality measurements (5:41-6:55).
- Local-first and no-account operation matters because many developers are tired of AI tools with subscription models and unclear code boundaries (5:41).
