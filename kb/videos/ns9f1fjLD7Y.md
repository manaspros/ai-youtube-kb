> Google DeepMind's Paige and Guillaume, with Gemma's Ian Ballantyne, demo AI Studio, Gen Media models and local Gemma 4 agents. Mostly a live product tour, with some practical prompting and cost tips.

## Summary
Paige (Google DeepMind) opens with a tour of AI Studio: video analysis with Gemini 3.1 Flash-Lite, code execution for vision-checked counting, and Build, which turns a prompt into an app with Firestore and Google auth. She argues that many startup workarounds (vector DBs for small context windows, per-domain fine-tunes, agent frameworks, MCP servers) get absorbed by base models, and that skills (markdown files) are replacing MCP for many people. Guillaume then runs a Gen Media workshop that illustrates a public-domain book with Nano Banana 2, animates with Veo, scores with Lyria 3, and voices dialogue with multi-speaker TTS. He stresses per-character reference images for consistency and cheap-model prompt generation. Ian closes with Gemma 4 (E2B/E4B, 26B MoE, 31B dense) running on a phone, a Mac via LM Studio, and an OpenCode coding loop against a local OpenAI-compatible endpoint. Many live demos were slow or needed manual nudges, so the content is more "what is possible" than measured results.

## Key ideas
- **Many agent-era workarounds may be temporary because base models absorb them** — Paige's thesis: when everyone sprints to build the same thing (vector DBs for 8k-16k context windows, per-language fine-tunes, MedLM/MedPalm fine-tunes, agent frameworks), the model usually gains the capability later. Her check: if everyone is doing the same thing, it may be the wrong thing. ([3:32](https://youtu.be/ns9f1fjLD7Y?t=212))
- **Skills (markdown files) are replacing MCP servers for many people** — She says most people have moved away from MCP servers toward skills, which she calls fancy markdown files. A longer-term idea is a background listener that writes skills from what you do. ([5:16](https://youtu.be/ns9f1fjLD7Y?t=316))
- **AI Studio's Get Code turns a playground run into app code** — Whatever you configure in the playground (model, video URL and offset, prompt, tools like search grounding or code execution) can be exported as TypeScript or Python. The stated path is: if it works in AI Studio, you can ship it in an app with one click. ([16:52](https://youtu.be/ns9f1fjLD7Y?t=1012))
- **Code execution gives a sandboxed Python environment as a one-line tool** — With code execution on, the model writes and runs Python with preinstalled data libraries and returns results such as drawn bounding boxes. Gemini 3 Flash also checked its own boxes with a second pass, which cost more and needed more tool calls. ([17:54](https://youtu.be/ns9f1fjLD7Y?t=1074))
- **Build produces a full app with database and auth, and the model fixes its own permission errors** — From one prompt (bookshelf photo, search grounding for book details, Google login, Firestore storage), Build plans, writes Firestore rules, and when saves fail with insufficient permissions it finds the rule and the validation issue and fixes them. Its app gallery, version history and GitHub sync are also shown. ([22:40](https://youtu.be/ns9f1fjLD7Y?t=1360))
- **Use a cheap model to write prompts for expensive generative models** — Guillaume uses structured outputs and chat mode so that a model produces prompts, character lists and scene descriptions from the full book in context. Generative media training data is largely made with Gemini, so Gemini is good at writing prompts for these models. ([56:18](https://youtu.be/ns9f1fjLD7Y?t=3378))
- **For character consistency, send only the reference images for characters in the scene** — Chat history helps style consistency, but as the cast grows the model cannot track every character. Passing only the reference images for the characters in that scene is more reliable. For a real book with 40 characters, he would also make several views per character. ([1:01:20](https://youtu.be/ns9f1fjLD7Y?t=3680))
- **Multi-speaker TTS works by giving each character a style and reusing it** — Each character gets a style prompt and a voice, and repeat characters reuse their style so the voices stay consistent. The prompt must start with a read or tell verb or the model may ignore the text. Narrator and characters get different voices. ([1:08:18](https://youtu.be/ns9f1fjLD7Y?t=4098))
- **Gemma 4 small models use per-layer embeddings that page from flash** — E2B and E4B are called effective models because embeddings can stay on flash and be paged in. The core is about 2B or 4B effective parameters, but the RAM footprint is closer to 5B or 8B. The 26B MoE has 4B active parameters and the 31B is dense. Ian claims performance comparable to models about 10x larger. ([1:26:13](https://youtu.be/ns9f1fjLD7Y?t=5173))
- **A local OpenAI-compatible endpoint lets an existing coding harness run on local Gemma** — LM Studio serves the 26B model on port 1234. OpenCode is configured with only a provider name, schema, model list and base URL. The 31B model writes a spec and the local model implements it. The first run had a syntax error. Re-reading the file and editing with the built-in line-edit and rewrite tools fixed it. ([1:37:02](https://youtu.be/ns9f1fjLD7Y?t=5822))

## Techniques
- **Playground-to-code export** — Configure model, inputs, offsets, prompt and tools in AI Studio, then use Get Code to export working TypeScript or Python with the same settings. *When:* Prototyping a multimodal call (for example video analysis) before wiring it into an app.
- **Code execution for verified counting and drawing** — Turn on the sandboxed Python tool, ask for drawn boxes or masks, and let the model check its own output in a second pass. *When:* Vision tasks that need exact counts, coordinates or per-frame answers, where a few cents per run is acceptable.
- **Per-scene reference injection for character consistency** — Store one reference image per character, then give the image model only the references for characters in the current scene. Use chat history for style, not for every character. *When:* Generating a long series of images with recurring characters, where the cast is too large for the model to track in context.
- **Structured outputs as a prompt-writing stage** — Use a cheap Gemini model with a response schema to produce prompts, character lists or chapter objects, so the output parses cleanly into the next generation call. *When:* Chaining a text model into image, video or music generation at scale.
- **Prompt-level multi-voice TTS** — Describe each character's style in the prompt and reuse it when the character reappears. Assign voices per role (narrator vs character). Start the prompt with a read or tell verb. *When:* Producing dialogue or audio drama with more voices than the usual two-speaker setup.
- **Flex and priority service tiers** — Set the service tier on each request: Flex for cost-sensitive jobs that can wait minutes, priority for reliability at about twice the price. *When:* Batch-style runs where latency does not matter, or live runs that must finish in a demo.
- **Local orchestrator with parallel subagents on an OpenAI-compatible server** — Run a local model server, then fan out one orchestrator to several subagents, each in its own terminal, to draw or research in parallel. Turn thinking off for speed. *When:* Quick local prototyping or parallel subtasks that do not need the internet.
- **Vibe-coding guardrails: one file per feature, plus logging** — Ask the model to split code into one file per feature, so a change can be reviewed by file. Require logs in the code so the reason for a failure is visible without guessing. *When:* Generating apps with an AI coding tool where you need to review and debug the output.

## Hot takes
- Everybody sprinting to build the same thing is a sign it is the wrong thing, because the model will absorb it (Paige, 3:32).
- Most agent frameworks and MCP-server workarounds will probably be absorbed into the model; skills (markdown files) are replacing MCP for many people (Paige, 5:16).
- Open-weight image and video generation models are unlikely because safety gating is hard to enforce once weights are open (Guillaume, 1:23:27).
- Gemini is good at writing prompts for Gen Media models because much of their training data was made with Gemini (Guillaume, 1:07:14).
