## Summary
The video lists about a dozen Claude Code settings and flags that the speaker says are buried in config files and environment variables. The core claim is that defaults set when the context window was 200k are now too conservative for a 1M-token window, so caps on output, file reads, and auto-compaction should be raised. It covers session retention (default one month, configurable through a cleanup-days field in settings.json), path-scoped rules that load when matching files are read, and a 30,000-character cap on bash output. It then shows how to run a session as a named sub-agent with flags for skills, effort, background, worktree isolation, and permitted child agents. The read limit section explains the 2000-line hard limit and two workarounds: a CLAUDE.md instruction or a read hook that forces chunked reads. The middle of the video is a sponsored segment and a sponsor pitch for AI Labs Pro and Claude CTX, an open-source profile switcher. The last section covers disabling commit co-authoring, opting out of telemetry without disabling auto-updates, prompt stashing with Ctrl+S, and exit-code-2 hooks that feed errors back to the model. The examples are concrete, but the speaker gives few key names and no version numbers.

## Techniques
- **Extend session retention** — In settings.json, add the cleanup-days field (spoken as 'cleanup period days', key not shown on screen) with the number of days to keep. Use 365 for a year. Use 0 to store no conversations. *When:* When you want insights or resume to reach sessions older than the default one-month window, or when you need to avoid storing transcripts at all.
- **Path-scoped rules** — Put per-area instruction files in the project's .claude folder, each with a path pattern. They load when Claude reads a matching file, so the main CLAUDE.md stays short. *When:* When CLAUDE.md is long and mixes front-end, back-end, and test instructions, and the agent starts ignoring some of them.
- **Raise the bash output cap** — In settings.json, change the bash output character limit from the 30,000 default to around 150,000 (key name not shown in transcript). *When:* When test suites, build logs, or migrations print more than 30k characters and the agent is reasoning from truncated output.
- **Run a session as a sub-agent** — Start Claude with the agent flag and the sub-agent's name. Set skill, effort, background (true/false), and isolation (worktree) in the agent config, add hooks in the agent config, and list permitted child agent names in its tools section. *When:* When you want to hand a task directly to a specialized agent without the orchestrator step, to run it in the background, or to make risky changes in an isolated worktree that is discarded if nothing changed.
- **Raise the file read cap and enforce full reads** — Raise the per-read token cap in settings.json from 25k to 100k or more. For the 2000-line limit, add a CLAUDE.md rule to check line count on large files and read them with offset and limit. Or add a read-triggered hook that counts lines and, above 2000, forces the agent to read with head-based chunks. *When:* When the agent reads large files and reasons from only the first 2000 lines without noticing the rest was skipped.
- **Lower the auto-compact threshold** — In settings.json, set the auto-compact percentage override to 75 (default is 95). Key name not shown in transcript. *When:* When you do not need the full 1M window and want compaction before output quality degrades, which the speaker puts at around 70%.
- **Remove commit co-author lines** — In settings.json, add the attribution key and leave the commit and PR fields empty. Set them to a custom string to change the author shown. *When:* When Claude's co-author trailer on commits and PRs is unwanted, for example on repos where it inflates the contributor graph.
- **Opt out of telemetry without losing updates** — Add three variables to the main settings.json that disable telemetry, error reporting, and feedback display (names not given in the video). Do not use the CLI flag that disables non-essential traffic, because it also blocks auto-updates. *When:* When you want to stop analytics to Statsig and error reports to Sentry but keep auto-updates.
- **Prompt stash with Ctrl+S** — While typing a prompt, press Ctrl+S to stash it. Send a different prompt, and the stashed text returns to the input box. *When:* When you need to interrupt a half-written prompt with a more urgent task.
- **Exit-code-2 hook to block and steer** — Configure a pre-tool hook (the video uses one that runs before every Bash command) that checks the command against a disallowed pattern. On a match, print the redirect message and exit with code 2 so the message is fed back to Claude. Example: block pip installs and direct Claude to uv (transcribed as 'uvicorn'). *When:* When Claude keeps picking a library or command you have ruled out because of its training defaults, and an instruction in CLAUDE.md is not reliably followed.
- **Loop-until-done with exit-code hooks (Ralph-style)** — Use the same exit-code-2 mechanism to force Claude to keep iterating until a completion check passes. The video describes this only in outline and points to a separate video for detail. *When:* When tasks are often marked complete before they actually are, and you need a machine-checkable completion criterion.
- **Claude CTX profiles** — Install the open-source Claude CTX tool (brew install on Mac, clone the repo elsewhere). It keeps per-profile settings.json and CLAUDE.md files in a profiles folder under .claude. Check the active profile with its C flag and switch with claudectx followed by the profile name. Each switch backs up the previous working state. *When:* When one machine serves several clients or work types that need different permissions and CLAUDE.md contents, and you need them kept apart.
