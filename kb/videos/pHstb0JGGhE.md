> Seven-stage tutorial for building a non-generic landing page with the Codex app and GPT 5.6, using AGENTS.md, a design skill, a design.md brand file, generated images, and a deploy step. Main lesson: encode taste and brand in files, not in each prompt.

## Summary
AI LABS walks through building a waitlist landing page for a fictional podcast analytics app ("Beacon") in the Codex desktop app, using GPT 5.6. The workflow has seven stages: a scoped seed prompt, an AGENTS.md file generated with /init, a design skill (the GPT Taste skill) that replaces the default front-end skill, browser verification with the model's own computer use, a design.md brand file to break the model's default color palette, generated illustrations and avatars with plan mode on, and layout and component upgrades from references (Pinterest, awards directories, 21.dev). A final stage covers a performance pass, local git commits as checkpoints, and deployment through the Codex "site" skill. The speaker says the whole site took about 17 minutes of model work. The method is practical and reproducible, but most of the value is in the prompt and file conventions, and the evidence for quality is the presenter's own subjective judgment. A sponsor read sits mid-video.

## Key ideas
- **Put the landing page's purpose and conversion goal in the seed prompt. The presenter calls the 'function' line (here: get visitors to join a waitlist) the most important line, because it decides whether the CTA is a waitlist signup or a product sign-up.** — Seed prompt includes: build a landing page, use Next.js, what the product is (a podcast analytics platform called Beacon), and the page's single job (waitlist signup). Without the audience and action, the model guesses and can solve the wrong problem. ([2:38](https://youtu.be/pHstb0JGGhE?t=158))
- **Turn the seed prompt into a persistent AGENTS.md file so every later thread shares the same context. The presenter uses the built-in /init command.** — Threads in Codex are separate chats inside one project folder. Running /init creates AGENTS.md with project structure and the context from the first prompt, so later threads do not drift. ([3:53](https://youtu.be/pHstb0JGGhE?t=233))
- **Add a standing instruction that the agent should do anything it can do itself (start the dev server, verify the build) rather than asking the user to.** — The presenter says GPT Codex models often ask the human to run or check things. Putting this rule at the top of AGENTS.md is what let the browser verification run without manual prompting. Presenter says the behavior has improved in newer models. ([5:21](https://youtu.be/pHstb0JGGhE?t=321))
- **Replace the model's default visual taste with a design skill. The presenter argues that newer models already avoid the older generic AI design patterns and fall into a new, recognizable style, so the default Anthropic front-end skill is out of date for them.** — They use the GPT Taste skill from a set of 13 design skills. The OpenAI 'site' skill is explicitly excluded from design work; the presenter says it produces weak output and that the model will use it by default unless told not to. They also suggest writing the exclusion into AGENTS.md. ([6:27](https://youtu.be/pHstb0JGGhE?t=387))
- **Use browser verification as a built-in loop. The model opens the running site, inspects it, checks responsiveness at desktop and mobile widths, and fixes code issues it finds.** — Presenter says GPT models are the strongest at computer use and that this verification was more reliable than other coding agents in their testing (anecdotal, one project). The annotate tool was janky, so they recommend screenshots of problem areas. ([9:22](https://youtu.be/pHstb0JGGhE?t=562))
- **Break the model's default brand palette with a design.md file. The skill sets general taste, while design.md sets this brand's specific visual system. The presenter says the first build reused the same green and purple across the page.** — They downloaded a design.md from Aura Build's free library, attached it in Codex, and asked for a design.md in the project plus a revamp that changes colors and tokens while keeping structure, layout and animations unchanged. The result kept the layout and changed the palette. ([11:41](https://youtu.be/pHstb0JGGhE?t=701))
- **Generate brand-specific imagery with the GPT image model, and turn on plan mode first. The presenter notes that image generation can be limited on the 20-dollar plan.** — Codex is asked to create an assets folder, link it in AGENTS.md, generate illustrations that match both the design and the copy around them, and replace all stock images. Plan mode is toggled from the UI, not written into the prompt. The plan is approved before any code or image changes. ([16:04](https://youtu.be/pHstb0JGGhE?t=964))
- **Use screenshot references for layout. Good sources are Pinterest searches and award-winning site directories. Give the model a screenshot and ask it to recreate that composition.** — Presenter kept the generated SaaS hero because it looked good. Their method for a layout they don't like is to give the model a reference screenshot and ask for the same composition. ([18:48](https://youtu.be/pHstb0JGGhE?t=1128))
- **Upgrade individual components instead of redesigning the page. Pick one part (here, a shader background for the hero section) from a component library, copy its prompt, and tell the model to apply it to that section only, telling it not to use the optimization skill.** — Libraries named: 21.dev (free and paid), plus Godly and Fancy components. The hero background came from 21.dev's shaders category. After applying it, they asked for a small color tweak. ([20:16](https://youtu.be/pHstb0JGGhE?t=1216))
- **Run a separate performance pass after the visual work. The presenter says the heavy animations made navigation feel slow, and that asking the model to optimize the site fixed most of it. A custom skill for animation-heavy landing pages is available as a slash command.** — They show before-and-after latency metrics that the presenter says show a large speedup. No numbers are given in the transcript. The custom skill is part of their paid community resources. ([21:44](https://youtu.be/pHstb0JGGhE?t=1304))
- **Use local git commits as checkpoints, and ask Codex to create and name them. This allows reverting if a later change breaks the site.** — No account is needed for local commits. The presenter asks Codex to list commit names and go back to any checkpoint. They used these checkpoints to show each stage of the build. ([22:52](https://youtu.be/pHstb0JGGhE?t=1372))
- **Deploy from inside Codex with the site skill, then share the published link and optionally add a custom domain in Settings. The presenter compares this with the older manual process of creating a Vercel account and connecting GitHub.** — Steps: click the plus button, add the site skill, ask it to deploy, open the Sites section in the sidebar, click Share, change visibility from 'just me' to 'anyone on the internet', then publish and copy the link. The presenter says the site skill is poor for design, so use it only for publishing. ([24:20](https://youtu.be/pHstb0JGGhE?t=1460))

## Techniques
- **Scoped seed prompt** — In the first prompt, state the stack (Next.js), what the product does, who the page is for, and the one action the page must drive (for example, joining a waitlist). Do not leave the CTA implicit. *When:* Starting any landing page or marketing site with a coding agent.
- **AGENTS.md via /init, plus a self-verify rule** — Type / in Codex and select init, which writes AGENTS.md from the context already given. Add a top-level rule: 'Whenever you can perform an action yourself (start the app, run the build, verify in browser), do it. Do not ask me to.' Also list the icon library, the assets folder path and the 'never use the site skill for design' rule in the same file. *When:* Any multi-thread project where you do not want the agent to stop and wait for the human to run things.
- **Install a design skill and forbid the default one** — Copy the skill's install command from its repo and paste it into Codex, asking it to install the skill. Quit Codex and reopen the thread so the skill loads. Reference it by typing / and its name. In the prompt, say explicitly not to use the OpenAI site skill for design work. Optionally record this exclusion in AGENTS.md. *When:* Using GPT-family models for UI work, where the model's default style is recognizable as 'AI-generated'.
- **Browser verification loop** — Let Codex open the running localhost site in the built-in side-panel browser and inspect it. Drag the window narrow and wide to check responsiveness. For any broken element, take a screenshot and send it to the model with a description. *When:* Checking generated front-end work visually, instead of trusting that the code works because it builds.
- **design.md brand system** — Download a design.md file from a library (the presenter uses Aura Build's free library). Attach it to Codex with the attach button. Prompt: create a design.md file in the project, copy in this file's contents, and revamp the site to match. Add: 'Keep the structure, layout and animations unchanged.' *When:* When the site has the right layout and animations but the palette, spacing and type look like the model's defaults.
- **Plan-mode image generation into an assets folder** — Toggle plan mode from the UI first, not in the prompt. Ask Codex to create an assets folder (here, under the app's public folder), link it from AGENTS.md, and generate illustrations that match the design and the card copy. Replace all stock images. Approve the plan, then let it implement. Next time, drop new images into that folder and tell Codex where to use them. *When:* Replacing stock photos with on-brand illustrations or testimonial avatars, especially on a plan that limits image generation.
- **Screenshot-based layout cloning** — Find a reference hero or section on Pinterest or an award-winning site directory. Save a screenshot, attach it, and ask Codex to recreate that composition in the existing site. *When:* When the model's default layout is generic and you have a concrete visual target.
- **Single-section component swap** — Pick a component from a library such as 21.dev, copy its provided prompt, and paste it to Codex with 'apply this to the hero section only'. Tell it not to use the optimization skill, which would otherwise run. Ask for a color tweak afterward. *When:* Adding one polished effect (shader background, nav animation) without changing the rest of the design.
- **Performance pass** — After the design is done, ask the model to optimize the site for load speed. For a custom version, use a skill for animation-heavy pages, invoked as a slash command. Compare latency before and after. *When:* When the page feels slow because of heavy animation after design work.
- **Local commits as checkpoints** — Ask Codex to make a local git commit at each stage. It names the commits itself. Ask it to list commits and revert to one when a later change goes wrong. *When:* Working with an agent that edits many files, so you can roll back a bad change.
- **Deploy with the site skill** — Click the plus button, add the site skill, and ask Codex to deploy the project. Open the Sites section in the sidebar, click Share, change access from 'just me' to 'anyone on the internet', publish, and copy the link. For a custom domain, open Settings and follow the add-domain steps. *When:* Publishing a finished static or Next.js site without setting up Vercel and GitHub by hand.
