> Review of "Phonon 2," a 164 MB local speech-to-text model from Fermion Research. It is fast and includes an OpenAI-compatible server, but the speed and accuracy claims rest mostly on the vendor's own benchmarks.

## Summary
Josh from Better Stack tests Phonon 2, a 164 MB speech-to-text model derived from NVIDIA's Parakeet encoder, which Fermion Research retrained so each weight takes one of five learned values. He runs it locally on a MacBook Air and reports that an hour of audio transcribes in about 21 seconds at a claimed 174x real time, with the speed depending heavily on whether the default fast-path decoder is enabled. Fermion's word error rate table puts Phonon 2 ahead of Parakeet Redux and Whisper Large V3 Turbo, but every number comes from Fermion, and the presenter points out that Redux was run through a third-party Core ML port that likely slowed it down. An independent OpenASR leaderboard run favors Phonon 2 on average but shows Whisper winning several individual sets, including noisy speech. Developer-facing features include live microphone captions, hot words for technical vocabulary, and a local server on port 8000 with an OpenAI-compatible transcription endpoint and a WebSocket stream. Code is Apache 2.0 and weights are CC BY 4.0, so commercial use is allowed with attribution. The presenter's verdict is to experiment with it rather than switch yet, since the project is about six weeks old and has few real users outside Fermion's own dictation app.

## Techniques
- **Local transcription setup** — Use Python 3.10 or newer (macOS ships 3.9, so create a fresh venv). Install the Fermion Research package with its MLS extra (the exact package name is garbled in the captions, so check Fermion's docs). Run `phonon transcribe <audio file>` for offline transcription. *When:* Fast offline transcription of English audio on Apple Silicon with no cloud upload and no per-minute pricing.
- **Live captions and hot words** — Run `phonon listen` to transcribe the microphone in near-real time. Provide a list of names or technical terms as hot words so they are recognized correctly. The presenter compared output with and without hot words. *When:* Dictation or meeting capture where domain vocabulary is often misrecognized. Measure latency first, since the model is offline.
- **Drop-in OpenAI-compatible speech server** — Run `phonon serve`, which listens on port 8000 and exposes an OpenAI-compatible transcription endpoint plus a WebSocket stream. Point an existing OpenAI transcription client's base URL at http://localhost:8000. *When:* Replacing a hosted transcription API with a local one during development or for privacy-sensitive audio, without rewriting client code.
- **Checking speed claims for the runtime, not just the model** — When a benchmark compares models of different sizes, check whether the same runtime and port were used for both. Look for an unexpected result, such as a much larger model running several times faster through the same port, and treat that as a sign the runtime is the bottleneck. Confirm decoder settings such as fast-path versus exact decoding, since they change throughput by about 4x here. *When:* Evaluating vendor or leaderboard speed and accuracy claims before choosing a model.

## Hot takes
- Fermion's benchmarks are self-reported, and the six-times-faster claim against Redux is likely an artifact of a slow third-party Core ML port.
- The 'most accurate open English model under 900 MB' framing depends on the chosen size cutoff, and the presenter questions why that number was picked.
- Phonon 2 wins on average on OpenASR but loses several individual sets, so the overall accuracy lead is smaller than the headline suggests.
- Hype came from a Twitter post, not from community testing; the Hacker News post got a few points and no comments.
- Presenter's recommendation: experiment, do not switch from Whisper or Redux yet.
