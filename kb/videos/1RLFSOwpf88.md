> Step-by-step FastAPI logging tutorial: a configured Python logger, a per-request logging and timing middleware, and shipping logs to Better Stack, with the slow-request search as the payoff.

## Summary
Better Stack walks through adding logging to a small FastAPI app (served with Uvicorn). It builds a logger.py with a formatter, a stdout handler and a file handler at INFO level, then adds a Logtail handler that ships logs to a Better Stack source. It next adds an HTTP middleware that logs method and URL for every request, moves that middleware into its own module (switching to a BaseHTTPMiddleware-based registration to avoid a circular import), and passes the log dict through extra= so its keys become top-level searchable fields. Finally it times each request with time.time() around call_next, adds an artificial 1.5 s asyncio.sleep to one endpoint, and filters Better Stack for process_time greater than 1 s to find it. The content is beginner-level and the video ends by promoting the Better Stack UI; the reusable pattern is the timing middleware plus structured extra fields.

## Key ideas
- **Configure one logger module, not per-file print calls: a logging.Formatter with time, level and message fields, a stdout StreamHandler and a FileHandler (app.log), both given the formatter, then logger.setLevel(INFO).** — Logger lives in logger.py and is imported into main.py. Log output shows time, level name and message. Handlers decide where records go; any can be removed. ([3:32](https://youtu.be/1RLFSOwpf88?t=212))
- **Ship logs to a hosted platform by adding a Logtail handler built from the source token and appending it to logger.handlers alongside stdout and file.** — Create a Python source in the Better Stack UI, copy its token, install the Logtail Python package, and add the handler. The speaker hardcodes the token for demo purposes and warns against that in real code. ([10:46](https://youtu.be/1RLFSOwpf88?t=646))
- **Use an app-level middleware to log every request once instead of adding log calls to each endpoint handler.** — Middleware runs before each path operation and can process the response after it is produced. The speaker logs request.url.path and request.method, then awaits call_next(request) and returns the response. ([14:31](https://youtu.be/1RLFSOwpf88?t=871))
- **Moving middleware to its own module breaks the app.middleware decorator, so register it with app.add_middleware(BaseHTTPMiddleware, dispatch=...) instead.** — The decorator needs the app object, which causes a circular import. The fix is to import BaseHTTPMiddleware from starlette.middleware.base (the older starlette.middleware path from a 2019 GitHub answer fails) and pass the dispatch function. Starlette docs say to override dispatch. ([19:28](https://youtu.be/1RLFSOwpf88?t=1168))
- **Pass the log dict as extra= so its keys become top-level, indexed fields in Better Stack instead of text inside the message.** — logger.info(log_dict, extra=log_dict) keeps the message and adds url and method as searchable fields, so queries like method equals GET work. ([23:27](https://youtu.be/1RLFSOwpf88?t=1407))
- **Time each request in the middleware: record time.time() before call_next, subtract after it returns, and log the delta as a process_time field.** — Logging moves below the response so process_time can be included. The check: a near-zero value for fast routes and about 1.5 s for the endpoint with the artificial sleep. ([26:02](https://youtu.be/1RLFSOwpf88?t=1562))
- **Find slow endpoints by filtering the structured field: process_time greater than 1 returns the sleeping upload endpoint at 1.49 s.** — Better Stack infers the field is a float, offers numeric comparison and substring search, and the same method works for url. This is a demo of the query pattern, not a benchmark. ([28:26](https://youtu.be/1RLFSOwpf88?t=1706))

## Techniques
- **Central logger module with formatter and multiple handlers** — In logger.py: import logging and sys; logger = logging.getLogger(); formatter = logging.Formatter(<format string with time, levelname and message>); stream = logging.StreamHandler(sys.stdout); file = logging.FileHandler('app.log'); call setFormatter(formatter) on both; logger.handlers = [stream, file]; logger.setLevel(logging.INFO). Import logger from logger.py into main.py. The exact format string is not shown in full on screen; the speaker describes time, a dash, level name, a dash, then message. *When:* Any FastAPI or Python service that needs consistent log lines in more than one place (console, file, hosted platform).
- **Ship logs to Better Stack with the Logtail handler** — In the Better Stack UI, create a source named e.g. 'FastAPI Demo' with the Python platform and copy its token. pip install the Logtail Python package from Better Stack's docs. Import the Logtail handler, create it with the source token, and add it to logger.handlers. Load the token from an environment variable in real code (the video hardcodes it for demo purposes only). *When:* You want centralized, searchable logs with live tail, and the app already uses the standard logging module.
- **Request logging middleware** — Define an async function with the @app.middleware('http') decorator taking (request, call_next). Build a dict with request.url.path and request.method, then response = await call_next(request). Return the response. Remove per-handler logger.info calls once the middleware covers them. *When:* You need one log record per request for all endpoints rather than per-handler log calls.
- **Middleware in a separate module (class-based registration)** — Move the function to middleware.py without the decorator. In main.py: from starlette.middleware.base import BaseHTTPMiddleware (the speaker corrected the older starlette.middleware path); app.add_middleware(BaseHTTPMiddleware, dispatch=log_middleware). This avoids importing app into middleware.py. *When:* The middleware lives in its own file and would otherwise need the app object, which causes a circular import.
- **Structured log fields via extra=** — Build a dict log_dict with url, method and other keys. Call logger.info(log_dict, extra=log_dict). The dict appears in the message and each key becomes a top-level field in the log platform. *When:* You want to filter and aggregate logs by field (method, path, status, duration) rather than search raw message text.
- **Per-request latency via timing middleware** — In the middleware: start = time.time(); response = await call_next(request); process_time = time.time() - start; add log_dict['process_time'] = process_time; logger.info(log_dict, extra=log_dict). Use the field to filter slow requests, e.g. process_time > 1 in the log platform. *When:* You need to find slow endpoints in a FastAPI app without a full tracing setup.
