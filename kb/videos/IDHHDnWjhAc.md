## Summary
The presenter argues Bun has grown from a runtime and package manager into a full front-end toolchain and says they are moving some projects to it from Vite, React and Next.js. The demo starts with an interactive project template picker in Bun 1.2.3 that offers React with Tailwind or shadcn/ui, then runs bun dev on the generated app. The presenter walks through the generated Bun.serve entry file, where routes now replace the old static option, dynamic path parameters are built in, and a catch-all route serves index.html. Hot reload is shown working on save, and the presenter credits a module-based design where most assets are sent over WebSockets so changing one file does not rebuild everything. Two developer-experience features follow: a dependency-analysis step that finds imports missing from package.json and installs them, and bun create on a single TSX file that generates a full shadcn project. The presenter's attempt to open an incremental module-graph visualizer returned a 404 and has no docs yet, and an idea for importing code from a shared Anthropic chat link is noted as not yet possible. The video does not cover production builds, deployment, or a head-to-head comparison with Vite.

## Techniques
- **Scaffold a React + Tailwind + shadcn/ui app interactively** — Run `bun init` (spoken 'bun in it'), choose the React template, then pick the default, Tailwind CSS, or shadcn with Tailwind. Run `bun dev` to start the dev server. Packages come from the Bun cache. *When:* Starting a new React front end where you want shadcn and Tailwind wired up with no manual config.
- **Routes in Bun.serve with dynamic params** — In the entry file (index.tsx), call Bun.serve with a routes object instead of the old static option. Map a catch-all pattern to index.html, which imports the front-end entry. Define API routes with path parameters such as the hello/:name pattern shown, and read the value from request.params.name. The exact route syntax is not shown on screen. *When:* A small full-stack app where you want Bun to be the server, the API layer and the bundler, with no separate router library.
- **Turn a single LLM-generated component file into a project** — Save the component (for example subsite.tsx) in its own folder. Run `bun create ./subsite.tsx`. Bun reads the file, detects shadcn usage, writes the config, installs shadcn components such as button, and sets up the app. Then run `bun dev`. *When:* You have one component from a chat or copied snippet and want a runnable site in seconds.
- **Find and install missing imports across source files** — Run the Bun install analysis command (spoken as 'bun install analyze') with a glob that covers the source directory, such as all .tsx files. Bun finds imports that are not in package.json and installs them. The presenter's example added framer-motion. *When:* After an LLM or Cursor adds components with imports that are not yet in package.json, or when you copy in code from elsewhere.
