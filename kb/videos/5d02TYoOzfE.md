> Hermes Agent cost-reduction tutorial from AI LABS: where the tokens go, and which model, context, tool, and hard-limit settings cut the bill without hurting output.

## Summary
The speaker's team ran Hermes Agent on an OpenAI subscription, hit usage limits, moved to OpenRouter, and then found per-token billing exposed high costs, mostly from background tasks that were set up poorly. The video explains what consumes tokens (system prompt, conversation history, skill headers, MCP tool definitions, memory files, auto-evolving skills and memory, and always-on cron-style background runs) and how to inspect usage through Hermes's usage database and its insights command. The main levers are model choice (use an existing subscription where Hermes supports it, or the OpenRouter Pareto router), pointing auxiliary background tasks and sub-agents at cheaper models, and matching the effort level to the task. Context levers include compressing conversations early (lower compression threshold and target ratio), capping tool-result size, using ephemeral system prompts, and trimming memory and agent files, with auto memory optional. Tool and skill hygiene (disable unused tools, skills and MCP servers; set tool search to auto) and hard limits (lower max tokens, max turns 150 to 60, hard stop on, cron max-turns caps) finish the list. The speaker does not state a dollar savings figure, despite promising one.

## Key ideas
- **Hermes's per-token bill came mostly from background tasks that were set up incorrectly, not from active use, which is why OpenRouter's per-token billing made the cost visible.** — The team moved from an OpenAI subscription to OpenRouter to escape usage limits. They then saw costs far above expectations, and most of the spend came from poorly configured recurring tasks. ([0:00](https://youtu.be/5d02TYoOzfE?t=0))
- **Per-message input cost includes much more than the prompt: system prompt, full conversation history, every skill header, MCP tool definitions, and memory and user files.** — Hermes ships with about 90 skills, and the count grows because it turns reusable workflows into new skills. Self-evolving skills and auto-updating memory also consume tokens, since Hermes scans conversations to create skills and extract user details. ([1:06](https://youtu.be/5d02TYoOzfE?t=66))
- **An always-on agent burns tokens through background tasks, so cost grows with repetition and the number of scheduled jobs.** — Hermes runs 24/7 on a local server or a rented VPS. Each background run is cheap, but repeated and similar jobs pile up. Goals also cost money. Hermes stores token usage in a database in the root folder, and its insights command gives a 30-day cost breakdown by component, tool, and skill. ([2:33](https://youtu.be/5d02TYoOzfE?t=153))
- **The connected model drives most of the bill, so the first lever is which provider or subscription Hermes runs through.** — The speaker says the Codex subscription is the best option for Hermes. He says Anthropic and Gemini subscriptions are listed but not usable this way, and that Claude Code needs a separate API key. On OpenRouter, the Pareto router routes each task to one of 13 models across price tiers. ([3:44](https://youtu.be/5d02TYoOzfE?t=224))
- **Auxiliary background tasks default to the main model, so pointing them at a lighter model removes a large hidden cost.** — Auxiliary tasks include reading images, searching skills, loading MCP tools, and writing profile descriptions. Sub-agents are token-heavy because each runs its own session, so a cheaper sub-agent model saves on every spawn. Effort level should match the task, and thinking can be turned off for simple work. ([4:58](https://youtu.be/5d02TYoOzfE?t=298))
- **Context compression is the main way to shrink the per-turn payload, and the default threshold is high.** — Compress often to start a fresh session built on a summary. The default compression threshold is 50% of the context window, and the speaker recommends a lower value. A lower target ratio carries less of the old conversation forward. Tool-result size limits control how much tool output enters context. ([6:40](https://youtu.be/5d02TYoOzfE?t=400))
- **Ephemeral system prompts and trimmed memory or agent files keep one-off instructions and standing context from taxing every message.** — Use an ephemeral system prompt for a single-session instruction instead of writing it into the context files. Keep memory and agent files small, since they sit in context on every turn. Auto memory can be turned off, but the team keeps it on because it shares company context through Slack. ([7:59](https://youtu.be/5d02TYoOzfE?t=479))
- **Fix a bad turn with undo and a fresh, specific prompt rather than re-prompting on top of the mistake.** — Undo steps back exactly one message. It is not a full rewind. The speaker prefers it because the next prompt can say what went wrong and what to avoid. ([9:26](https://youtu.be/5d02TYoOzfE?t=566))
- **Unused tools, skills, and MCP servers are dead weight in every request, so the agent's surface area should be trimmed.** — Each enabled tool and MCP server adds to the context. The speaker split out a separate profile for code execution and disabled the unused tools. Set tool search to auto so tools load only when needed, as in Claude's tool search. ([10:29](https://youtu.be/5d02TYoOzfE?t=629))
- **Hard limits cap runaway cost: output max tokens, max turns, a hard stop on loops, and per-cron turn caps.** — The default max turns is 150 and the team lowered it to 60. The hard-stop setting changes from false to true to halt stuck loops. Cron jobs have no turn limit by default, so the speaker sets one for each. ([11:48](https://youtu.be/5d02TYoOzfE?t=708))

## Techniques
- **Audit token spend before tuning** — Ask an agent to read Hermes's usage database in the root folder and produce a breakdown of sessions, tokens, and cost since install. Or run Hermes's insights command for the last 30 days, which shows cost by component, most-used tools and skills, activity patterns, and longest sessions. *When:* Before changing any settings, to find which background jobs, skills, or sessions dominate the bill.
- **Route auxiliary and sub-agent work to a cheaper model** — In config.yaml, the auxiliary-task model defaults to auto, which falls back to the main model. Point auxiliary tasks (image reading, skill search, MCP tool loading, profile writing) at a lighter model, and set a cheaper model for sub-agents. The speaker did not name the exact config keys. *When:* When the main model is expensive and background or delegated work is simple and does not need heavy reasoning.
- **Use the OpenRouter Pareto router** — Set the OpenRouter provider and select the Pareto router, which picks a model per task across 13 models from cheap to powerful tiers. *When:* When you need many models under one API key and want per-task cost-quality routing for team-wide use.
- **Match effort level to task, and turn thinking off for simple work** — Lower the effort level from max for routine tasks, and disable thinking entirely for tasks that need little reasoning. *When:* For simple, mechanical, or repetitive tasks, where max effort burns tokens without better output.
- **Compress context early with a lower threshold and target ratio** — Run the compress command often to start a fresh session built on a summary. Lower the compression threshold from its 50% default, and lower the target ratio so less of the old conversation carries over. *When:* In long-running sessions where per-turn history resends dominate the cost.
- **Cap tool output in context** — Set the tool-result size limit lower than the high value used on the subscription setup. Higher limits avoid missed details, but cost more per turn. *When:* When tool outputs are large and the team has moved to per-token billing.
- **Use ephemeral system prompts for one-session instructions** — Pass a one-off instruction as an ephemeral system prompt, which applies to a single session only, rather than writing it into the Hermes context files. *When:* For instructions needed once, so they do not sit in the context window of every later session.
- **Keep knowledge in files the agent loads on demand** — Organize the local second-brain notes so the agent reads them piece by piece, rather than loading everything. Trim memory and agent files, since they sit in context on every message. Optionally turn off auto memory. *When:* When the agent holds a lot of reference material or the memory files keep growing.
- **Undo the last message and re-prompt with the failure described** — Use the undo command to step back one message. Then give a fresh prompt that states what went wrong and what to avoid, instead of stacking corrections. *When:* When the agent produces a wrong answer and the next prompt should correct it cleanly.
- **Trim tools, skills, and MCP servers to what is used** — Run the Hermes list command to see the more than 17 tools. Disable unused tools via the desktop app or the tool's disable command. Turn off unused skills, disconnect unused MCP servers, and set tool search to auto so tools load on demand. *When:* For a profile that does not need certain tools, such as a team profile with no code execution, or whenever the tool list is long.
- **Set hard limits on output, turns, and loops** — Set the model's max tokens to cap output length. Lower max turns from the 150 default (the speaker uses 60). Change the hard-stop setting from false to true to stop loops. Set a max-turns cap on each cron job, which has no limit by default. *When:* For always-on or scheduled agents that can get stuck and burn turns resending full context.
