> Michele Grant on earning trust in enterprise AI agents: define value, name an accountable owner, and grant autonomy in stages backed by audit evidence, using an M&A integration example.

## Summary
The talk argues that an agent earns trust in daily operations, not in a pilot, by proving it creates value inside leadership's risk controls. Using a hypothetical $15B acquisition with an IMO tracking 40 synergy workstreams, the speaker walks through a written value case, a three-lines-of-defense ownership model, and a per-agent "human work standard" that maps each decision to an authorized human role and escalation path. She says engineers supply the evidence for autonomy through three artifacts: an auditable decision log, a model inventory with regression triggers, and an autonomy scorecard. The scorecard moves an agent through four stages from shadow mode to exceptions-only review, and she warns that falling override rates can mean reviews have gotten shallower rather than that the agent improved. The core message is that deciding who owns and governs each agent is an executive mandate, not an engineering task.

## Key ideas
- **Go-live does not prove trust. Teams must rely on the agent in daily work, and trust has to be built before launch through change and risk management.** — She draws on M&A integrations, where trust was engineered before day one. A pilot tests whether software functions; daily operations tests whether it creates value within leadership's controls. ([0:02](https://youtu.be/-a2oTS9J67U?t=2))
- **Leadership must answer three questions for every agent: what value it creates, who is accountable for it, and what evidence permits more autonomy.** — Established AI risk frameworks give principles but not how to apply them per agent. For each agent, leadership decides what it may do, who owns it, what evidence it records, and what triggers escalation. She calls this an executive operating mandate, not an engineering task. ([1:13](https://youtu.be/-a2oTS9J67U?t=73))
- **Set a written value case with a pre-deployment baseline before the agent touches production data. If the baseline cannot be stated, do not deploy.** — Her three metrics are cycle time (e.g. 5 days down to 2), analyst capacity freed (net of compute, licensing and human review cost, and only counted when reassigned to lagging workstreams), and detection time from first data slip to steering committee visibility. Faster reports do not automatically mean faster detection. ([4:37](https://youtu.be/-a2oTS9J67U?t=277))
- **Apply the three-lines model to each agent. Management owns the controls, risk and compliance challenge depth based on exposure, and internal audit decides on material risk.** — Review depth should scale with exposure. An internal draft reviewed by a senior analyst needs far less scrutiny than an autonomous agent publishing to the board. ([6:17](https://youtu.be/-a2oTS9J67U?t=377))
- **Each agent needs one named human overseer with four capabilities: understand its boundaries, interpret its output in context, override or reverse it, and use a kill switch.** — A one-page human work standard maps each decision point in the process to the authorized human role, the required evidence, and the escalation path. The agent prepares analysis and stops there; the decision-maker owns the consequence. ([7:23](https://youtu.be/-a2oTS9J67U?t=443))
- **An agent with no assigned decision owner should not be deployed, because its flags would lead to no action.** — For example, if leadership has not agreed who declares an initiative off track, the agent's alerts go nowhere. Keeping decisions with named people does not slow the agent down. ([8:28](https://youtu.be/-a2oTS9J67U?t=508))
- **Autonomy should rest on three engineering artifacts: an auditable decision log, a model inventory record, and an autonomy scorecard.** — The decision log captures ingested data, tool calls, prompt, model versions, output and human sign-off. Core reconciliation math should run in deterministic, finance-approved code, and the model's written summary is treated as explanation, not proof. If reported savings do not match the general ledger, the agent flags the discrepancy and does not change the number. ([9:36](https://youtu.be/-a2oTS9J67U?t=576))
- **Define regression triggers in the model inventory. Any base-model or source-API change requires full revalidation before the agent returns to production.** — The inventory also lists the accountable executive, data lineage, cross-system dependencies, validation results, escalation path and kill-switch runbook. ([11:16](https://youtu.be/-a2oTS9J67U?t=676))
- **Grant autonomy in four stages: shadow mode, supervised draft, exception ensemble (lagging items plus a random sample), and exceptions-only review.** — In exceptions-only review, the biggest risk is what the agent failed to flag, so track material misses through independent sampling and watch error severity and override rate. ([11:50](https://youtu.be/-a2oTS9J67U?t=710))
- **A falling override rate may mean the agent improved, or that human review has become shallower. Independent sampling is the way to tell which.** — The scorecard shows control metrics next to value metrics (cycle time, analyst hours, detection time) so the steering committee can promote, hold, or step the agent back a stage. ([12:59](https://youtu.be/-a2oTS9J67U?t=779))

## Techniques
- **Pre-deployment value case with baselines** — Write down the value metrics and measure them before the agent touches production data. Net out compute, licensing and human review cost, and count capacity savings only when the freed time is reassigned to specific work. *When:* Before deploying any agent that a leadership group will fund or rely on.
- **Human work standard (one-page decision map)** — For each fork in a process, document the decision, the human role authorized to make it, the required evidence, and the escalation path. The agent prepares analysis; the named human decides. *When:* When an agent sits inside a multi-tier process with decisions at several levels.
- **Deterministic core for financial math** — Run reconciliation and variance calculations in approved code rather than in LLM-generated prose. Use the model only for explanation and summarization. *When:* When outputs must match a system of record such as a general ledger.
- **Telemetry as proof, not the model's summary** — Log the records pulled, the deterministic tools run, the prompt and model versions, and the reviewer sign-off. Judge the agent by these logs, not by its narrative. *When:* When building the evidence trail that justifies more autonomy.
- **Four-stage autonomy scorecard** — Move the agent from shadow mode to supervised draft to exception sampling to exceptions-only. Promote, hold, or step back based on error severity, override rate, and independent sampling results. *When:* When deciding how much review a running agent still needs.
- **Regression triggers in the model inventory** — List every base-model or source-API change that requires full revalidation before the agent runs in production again, along with lineage, dependencies, escalation path and kill-switch runbook. *When:* When an agent depends on upstream models or APIs that change over time.
