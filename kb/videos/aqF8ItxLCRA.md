> Walkthrough of Suna, a free open-source self-hosted alternative to Manus, with one head-to-head build test, its architecture, a local Docker setup, and its cost and bug downsides.

## Summary
The host compares Suna (captions say "Sooner"), an open-source self-hosted agent that builds websites and does research, against Manus on one prompt: a page listing the top 10 Vietnamese restaurants in London. Suna finished in 17 steps in just over seven minutes with a polished page, while Manus ran out of free credits partway through, took over an hour, and finished only after upgrading and resuming. The architecture uses a Next.js frontend, Supabase for auth, conversation history and file storage, a FastAPI backend that handles REST endpoints and LLM calls, Daytona for isolated Docker environments that run AI-generated code, and Redis for caching. The setup needs several accounts and keys (Supabase, Anthropic, Daytona, Firecrawl, Tavily) plus Docker, with Supabase migrations and a schema selection step before docker compose up. The host's main downsides are that the LLM and sandbox costs are not free, Daytona credits run out after a few runs, web search is slow for them, and several bugs show errors only in the Docker logs. This is a single anecdotal test by a vendor-neutral reviewer, with no benchmark.

## Techniques
- **Self-host an agent stack with Docker Compose after DB migrations** — 1) Clone the Suna repo. 2) Add Supabase credentials, leave Redis as-is, add the Anthropic API key. 3) Add the Tavily and Firecrawl API keys and the Daytona values; a Daytona API key is enough, no local install. 4) Run the Supabase migrations. 5) In the Supabase UI, select the basejump schema (personal accounts and subscription billing). 6) Run docker compose up at the project root. Config file name is not stated in the video. *When:* Use when you want a self-hosted general-purpose web/research agent and are willing to juggle several third-party accounts.
- **Isolate AI-generated code in per-run Docker environments via a sandbox provider** — The backend asks Daytona to create an isolated Docker environment for the code the model writes and runs. The app's own services (Next.js, FastAPI, Supabase, Redis) stay outside that sandbox. *When:* Use whenever an agent executes generated code, to keep it away from the host and the app's services.
- **Use container logs as the primary debug surface for agent runs** — Run docker compose logs while a task executes. The host says many errors (search failures, duplicate conversation writes) surface only there and not in the UI. *When:* Use when a self-hosted agent app shows little in its UI, or when a run reports a failure that appears to have succeeded.
- **Head-to-head test of agent products on one identical prompt** — Give the same prompt to both products at the same tier (standard). Compare step count, wall-clock time, output quality, and completion. Note the tier and any free-credit limits. The host used a website build task: top 10 Vietnamese restaurants in London. *When:* Use for a quick qualitative comparison of agent products. It is a single run, so treat results as anecdotal.

## Hot takes
- Suna matched or beat Manus on this one prompt, but it was a single run at the standard tier, so the result is anecdotal and not a benchmark.
- The Manus failure is partly a pricing and free-credit effect, not only a capability gap.
- Calling Suna free understates the cost: LLM API bills, Daytona credits, and Tavily and Firecrawl keys all add up, which the host concedes.
- The host calls the architecture simple on paper and says the value is in wiring many third-party services together, which also means many failure points.
