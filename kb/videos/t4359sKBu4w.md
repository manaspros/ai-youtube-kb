> An ad-agency AI director argues for "bounded autonomy": treat LLM context as a soft constraint, keep systems simple, store knowledge in several representations, and never automate work you cannot do yourself.

## Summary
Angus J. McLean, an AI director at the ad agency Oliver, gives a short, mostly conceptual talk on how to work with LLMs under their limits. He describes today's models as closed systems with weak data efficiency and no continual learning, so most tools are band-aids around them. Context is a soft constraint that shapes model behaviour, much like guardrails, and the real problem has shifted from getting context in to keeping noise out. He recommends self-imposed limits on context use, a simple working version before a complex one, and storing knowledge in several representations (markdown, graphs, clusters, folders, timelines). He ends with a warning to automate only work you could do yourself. Most of the evidence is anecdote from his agency work and personal experiments, with few measurements.

## Key ideas
- **LLMs are closed boxes that do not learn after training; many current tools are temporary band-aids that hide the underlying limits (data efficiency, no continual learning).** — The speaker calls the model a flexible database that does semantic math. He says new trends are a blind spot because the model does not know them, and that training methods themselves can be a band-aid. ([4:50](https://youtu.be/t4359sKBu4w?t=290))
- **Context is a soft constraint, not a hard one, and it shapes model behaviour as much as guardrails do.** — Giving the model curated, high-quality documentation works better than open web access. Models are weak at spotting promotional content and are easy to manipulate with SEO, so competitor research picks up what competitors wrote about themselves. ([6:17](https://youtu.be/t4359sKBu4w?t=377))
- **Long-running agents depend on large context windows because they must hold action history, tool output, goals and plans. Without that, they forget mid-task.** — He cites a widely reported case of an agent deleting many emails after its context ran out. He says context windows will never be big enough, because the amount of knowledge keeps growing. ([6:17](https://youtu.be/t4359sKBu4w?t=377))
- **The problem has flipped from too little context to too much, so the skill is deciding what to leave out.** — Context assembly is now dynamic. He suggests self-imposed constraints, asking how little of the context window you can use and still finish the task. He compares this to early computing, when limited compute forced creative solutions. ([8:50](https://youtu.be/t4359sKBu4w?t=530))
- **Simple versions beat complex ones. Models are verbose and push toward complicated solutions, so build the simplest working version and test it against reality early.** — His own CV tool, built with a complex setup, did worse than a plain HTML file, which he says was roughly a 10x to 100x improvement. He argues for shortening the feedback loop with real users instead of with the agent. ([11:34](https://youtu.be/t4359sKBu4w?t=694))
- **Structure is a property of the observer's chosen representation, not of the content itself, so one piece of knowledge should be kept in several forms.** — AI as translation (text to image, audio to video, structured to unstructured). He suggests using markdown for human-readable hierarchy, graphs for relationships, clusters for large unstructured text, folders for fast retrieval, and timelines where they fit the task. ([12:57](https://youtu.be/t4359sKBu4w?t=777))
- **Do not automate a job you cannot do yourself, and treat structured workflows as often more effective than fully free agents.** — He ties this to Adam Smith's pin factory: capitalism splits work into small repeatable chunks, and workflows often beat open-ended agents. His example is a social-listening report that an LLM built from about 50,000 clustered tweets. He describes it as an output he could judge because he had done the job before. ([15:20](https://youtu.be/t4359sKBu4w?t=920))

## Techniques
- **Self-imposed context budget** — Deliberately cap how much of the context window a task uses, then find the smallest budget that still finishes the task. Treat that minimum as a design goal, not a fixed setting. *When:* When designing long-running or multi-step agents, or when cost and noise are problems. Use it to find where extra context stops helping.
- **Curated documentation over open web access** — Give the model a vetted, high-quality document set instead of live internet search, which can surface SEO-optimised or self-promotional content. *When:* For research tasks where source quality matters, such as competitor or consumer analysis.
- **Simple-first prototype with fast reality checks** — Build the smallest version that works, put it in front of real users or data early, and skip extra scaffolding the model suggests. *When:* At the start of any product or agent build, before adding planning layers or complex prompts.
- **Multi-representation knowledge storage** — Store the same material in several forms: markdown for authoring, graph edges for relationships, clusters for large text bodies, folders for fast lookup, and timelines for time-ordered events. Convert between them as needed. *When:* When one knowledge base must serve different retrieval needs, or when a single structure hides relationships the task depends on.
- **Cluster-then-report pipeline** — Cluster a large text corpus (for example 50,000 social posts), then have an LLM write a report per cluster, with standout items pulled out for each. The older method of labelling clusters by their most frequent words is the baseline it replaces. *When:* For turning large volumes of unstructured text into strategy or insight summaries that a human then checks.
- **Teach yourself on older, smaller models and your own harness** — Use an older or smaller model, and build your own harness, memory and compaction, to understand how the model behaves. Do this for learning, not for production. *When:* When you want to build intuition about context limits before relying on a larger platform.
- **Automate only what you can do yourself** — Before automating a task, confirm you can do it well by hand. Use that to judge agent output and catch errors. *When:* When deciding which tasks to hand to an agent, especially in high-risk customer-facing work.

## Hot takes
- Abundant context makes you lazy; constraints create creativity, so ask how little context a task really needs.
- Simple HTML beat a complex setup for a CV task, so models push toward complexity and you should resist it.
- Context windows will never be large enough; the goal is keeping noise out, not getting more in.
- Do not automate a job you cannot do yourself.
- Structure belongs to the observer's chosen representation, so one piece of knowledge should be stored in several forms.
