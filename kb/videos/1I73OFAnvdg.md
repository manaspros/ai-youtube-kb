> Better Stack walkthrough of Task Master AI with Claude Code: a PRD is parsed into dependency-tracked tasks, scored for complexity, expanded into subtasks, then run one at a time. The demo app built in one pass, but the claims rest on one example.

## Summary
The presenter installs Task Master globally and initializes it in a Next.js project, which writes Claude Code slash commands, a PRD template, a config file, an mcp.json and a CLAUDE.md link. Models are set to Sonnet for generation, Opus for research and Sonnet as fallback. An AI writes a PRD for a recipe app that extracts ingredients and nutrition from photos with OpenAI and saves recipes to IndexedDB. Claude Code then parses the PRD into tasks.json, which holds priority, dependencies, status and subtasks. A complexity-analysis command scores each task, with task 10 highest at 7, and expanding it creates subtasks. The presenter marks tasks in progress one at a time and runs each agent in its own terminal tab instead of using sub-agents. The finished app works in the single demo shown: image upload, extraction, and editing of saved recipes. The video does not show the generated code, tests, failures or cost.

## Key ideas
- **Task Master turns a PRD into a persistent task graph that the coding agent works through** — The PRD is parsed into tasks.json with priority, dependencies, status and subtasks, plus one file per task with more detail. The presenter credits this structure for the agent building a complex app in one pass, but that rests on a single demo. ([0:00](https://youtu.be/1I73OFAnvdg?t=0))
- **Init scaffolds Claude Code integration files into the project** — Initialization creates a .claude directory with Task Master slash commands, a .taskmaster directory with the PRD template and config, an example env file for optional API keys, an mcp.json for the MCP server, and a CLAUDE.md that links to Task Master's own CLAUDE.md. ([1:23](https://youtu.be/1I73OFAnvdg?t=83))
- **The PRD is generated by an AI from a prompt and an example template** — The presenter keeps a prompt file describing the app and asks the model to write the PRD using an example PRD as the template, saved in the scripts directory. Claude Code is then asked to run that file. The resulting PRD has an overview, core features, personas and key user flows. ([1:23](https://youtu.be/1I73OFAnvdg?t=83))
- **Complexity analysis drives how tasks are split into subtasks** — After parsing, a complexity command adds a score to each task. The most complex task (task 10, score 7) is then expanded into subtasks, and the presenter notes these subtasks can run in parallel. The presenter says any task can be expanded, but the video does not give a threshold for when to do so. ([2:49](https://youtu.be/1I73OFAnvdg?t=169))
- **The execution loop is one task at a time, with one terminal tab per agent** — Work starts by moving the next task (task 2) from pending to in progress, then the agent runs. The presenter prefers separate tabs so each agent's progress stays visible, over sub-agents that run tasks by dependency. The loop repeats until all tasks are done. ([4:14](https://youtu.be/1I73OFAnvdg?t=254))
- **Hooks and project tooling are honored by Claude Code** — Because Claude Code runs under the project's hooks, lint hooks and package-manager choices such as bun instead of npm apply to the tasks it runs. ([7:01](https://youtu.be/1I73OFAnvdg?t=421))
- **The one-shot result is a single example, not a benchmark** — The demo app passes a manual check: photo upload, recipe extraction with name, ingredients, instructions and nutrition, and editing of saved recipes that survives a refresh. No tests, error cases or repeated runs are shown. ([5:39](https://youtu.be/1I73OFAnvdg?t=339))

## Techniques
- **Pick models per Task Master role** — Run the models setup during first use: generation = Claude Code Sonnet, research = Opus, fallback = Sonnet. Use the Task Master models command to show the selected models and API key status. The config file under the .taskmaster directory holds these choices and Claude Code options. *When:* Use when you want a stronger model for research or planning and a cheaper one for routine generation, and when keys or model choices need to be checked.
- **Have the model write the PRD from an example template** — Keep a prompt file that describes the app. Ask the model to write a PRD using the example PRD as the template and save it in a known directory such as scripts. Then ask Claude Code to run that file. *When:* Use at the start of a greenfield project to get a structured requirements document that Task Master can parse.
- **Parse the PRD into tasks, then score complexity and expand the hardest tasks** — Run the Claude Code command that parses the PRD into tasks.json, then view the table with the Task Master list command. Run the complexity-analysis command in Claude Code, then expand the highest-scoring task (the presenter passes 10 as the argument) into subtasks. Inspect with the Task Master show command for that task. *When:* Use when a PRD yields tasks with unclear scope, or when some tasks look big enough to need breaking into smaller pieces before the agent starts.
- **Drive the work loop by task status** — Use the Task Master command to set the next task (task 2 in the video) from pending to in progress, then let the agent run it. Repeat through the remaining tasks. Run each agent in its own terminal tab so progress stays visible. *When:* Use when you want a clear per-task status record and direct visibility into each agent rather than a single long session.
- **Keep project hooks in the loop** — Put lint and package-manager rules (for example, bun instead of npm) in Claude Code hooks. The presenter says Claude Code applies them to Task Master tasks, so no extra per-task instruction is needed. *When:* Use when the project has fixed tooling or lint steps that every generated change must pass.
