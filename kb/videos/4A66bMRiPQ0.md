> A walkthrough of Shotgun Code, which packs a whole Next.js repo into one prompt, gets a full diff from Gemini 2.5 Pro, and applies it in Cursor to overhaul a personal app.

## Summary
The presenter introduces Shotgun Code, a tool that bundles a project's files into one large prompt. That prompt is pasted into Google AI Studio's Gemini 2.5 Pro at temperature 0.1, which returns a complete diff. The diff is then applied in Cursor, where the presenter switched from Gemini to Claude 3.5 Sonnet because Gemini was slow there and kept stopping to ask questions. Setup needs Go, Node.js and the Wails CLI, plus one install command and one launch command from the repo root; the exact commands were on screen but not spoken. Opening the full project first hit a size limit, which was fixed by unchecking generated folders, docs and the cursor rules file. The demo is a three-change overhaul of a personal timetracking Next.js app: performance, a UI component swap (shadcn first, then Aceternity UI after the first result looked poor), and a reworked activity-entry flow. The presenter argues that one task plus whole-repo context beats agent edits file by file, but the evidence is one app judged visually, with no measurements.

## Techniques
- **Setup and launch from repo root** — Install Go, Node.js and the Wails CLI. Run the repo's one install command, then the launch command from the project root; the presenter says the launch command also installs the frontend dependencies. The exact command text was on screen but not spoken, so check the repo README or the video description. *When:* Before first use of Shotgun Code on a machine.
- **Curate the context before generating the prompt** — Select the project folder and generate context. Uncheck .next (build output), dependency folders, the cursor rules file and personal .md docs. Keep package.json for dependency info. Generate the prompt only after the size error is gone. *When:* When a Next.js project is too large to pack, or when the packed context includes build output and docs that add noise.
- **Write one task plus custom rules into the packed prompt** — Type a single concrete task in the task box (e.g. 'convert the custom React components to shadcn components'). Put project constraints such as banned libraries or style rules in the custom-rules section. Copy the finished prompt with copy-all. *When:* Any single cross-cutting change that must touch many files consistently.
- **Generate the diff in Google AI Studio** — Open Google AI Studio, choose Gemini 2.5 Pro (not Flash), set temperature to 0.1, paste the packed prompt with no additions and run. Keep the returned diff, which names the files and changes to make. *When:* When you want literal instruction following from a long-context model and can use the free daily prompt quota (25/day, per the presenter).
- **Apply the diff with a coding agent in chunks** — In a Cursor chat, type 'apply diff' and paste the diff prompt. Use Claude 3.5 Sonnet for execution if the Gemini chat in Cursor is slow or keeps asking questions. Start a fresh chat for each change area (performance, UI, flow) to keep the context clean. *When:* Applying a large multi-file diff produced outside the editor.
- **Control visual style through the task text** — Name the component library and the look in the task (e.g. 'use Aceternity UI components only, minimal'). Check the result visually. If it looks wrong, re-run the pack-diff-apply cycle with a revised task rather than hand-editing. *When:* When the first generated UI does not match the desired look.

## Hot takes
- One task plus whole-repo context in a single prompt replaces the need for documentation and implementation plans. This is claimed from one personal app, with no comparison to agent-driven editing.
- The 'FREE' title rests on Gemini's free daily prompt quota, which the presenter mentions in passing. The workflow also depends on manual copy-paste, because the apply-patch step was not yet built into the tool.
- Gemini is poorly suited to Cursor's agent role because it stops to ask questions, and the presenter swapped it for Claude 3.5 Sonnet. This is a single user's experience.
- The quality judgement is aesthetic and personal. The presenter disliked the first UI result, and the speed claim is a screen-recording impression, not a measurement.
