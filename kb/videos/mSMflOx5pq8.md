> Tutorial on shadcn's official registry MCP: add extra community component registries, then run a multi-subagent workflow (requirements, component research, implementation) to build UIs without unnecessary components.

## Summary
The presenter installs shadcn's official registry MCP server into Claude Code and says it can search, install and read components from any public registry, not just shadcn's own. Because many curated registry lists are stale or in the wrong format, he has Claude search the web for registries, test each one through the MCP, and keep a working list. Extra registries are added to components.json, which requires a React or Next.js app with shadcn initialized. Without a plan, a single agent builds a landing page with every animated component it can find and has layout problems, so he wrote a workflow of Claude Code subagent files: one turns requirements into requirements.md inside a per-task design docs folder, one writes a component research file, and one implements, with each stage continuing the same task by name. A lightweight "Express" agent skips the research stages for small changes. He closes by suggesting TweakCN for swapping themes by pasting its generated code into Claude. The video is a practical tutorial, but it is an early-stage, single-project demo with no measurements beyond a component count.

## Key ideas
- **The official shadcn registry MCP goes beyond the earlier community MCP, which only exposed shadcn's own component data. It can search, install and read docs for components from any public registry, so the agent can use third-party component libraries.** — The earlier MCP only gave information about shadcn components and limited builds to them. The official one connects to any registry that follows the public format. ([1:11](https://youtu.be/mSMflOx5pq8?t=71))
- **Adding registries is the main lever. Extra registries go into the registries option of components.json, comma-separated, and the MCP then pulls all their components.** — Requires shadcn to be initialized, so a React or Next.js app is needed first. The presenter's list is still small, and he plans to publish the formatted entries in the resources. ([2:30](https://youtu.be/mSMflOx5pq8?t=150))
- **Many curated registry lists are out of date or not real registries. Some (Neo Brutalism, RetroUI) failed because their format did not meet the public registry requirements.** — His fix was to have Claude search for repositories, add each to an MCP, and test whether it works, which produced a shorter list of registries that actually function. ([3:10](https://youtu.be/mSMflOx5pq8?t=190))
- **Components from a registry are not enough on their own. Without a plan, the agent added every animated component it could find to a landing page and produced layout issues, so he argues for a staged workflow.** — The MCP supplies per-component implementation details, but the agent still lacked a plan for choosing which components to use. ([5:21](https://youtu.be/mSMflOx5pq8?t=321))
- **Splitting the work into subagents keeps the context window clean. Requirements, component research and implementation each write a file that the next stage reads, so implementation does not carry all the earlier discussion.** — He checks the context usage between stages with the context command, and continues the same task by naming it, so the separate design docs folder per task keeps different tasks apart. ([6:46](https://youtu.be/mSMflOx5pq8?t=406))
- **A separate Express agent covers small changes such as adding a card or a retractable menu, where the full research and planning steps are not worth the overhead.** — He used it to add a menu toggle with a specific icon after the main build. ([7:48](https://youtu.be/mSMflOx5pq8?t=468))
- **Visual style comes from a theme layer. TweakCN generates theme code that can be pasted into the project for Claude to apply on top of an existing layout.** — He switched themes between recorded segments; the theme change is not part of the MCP. ([8:55](https://youtu.be/mSMflOx5pq8?t=535))

## Techniques
- **Install the shadcn registry MCP** — Run the quick-start install command from the shadcn docs in the project root (an npm option is shown; the command configures the MCP, installs dependencies and writes an mcp.json for Claude Code). Launch Claude Code without the --dangerously-skip-permissions flag the first time, because the presenter found it stopped the MCP from being detected. Confirm the 'MCP server being added' prompt appears, then check that the shadcn MCP is listed as connected with its tools. *When:* Start of any project that wants shadcn components driven by an agent. The MCP is free, and the same setup works in Cursor and VS Code.
- **Add third-party component registries** — Initialize shadcn in a React or Next.js app to create components.json. Add the registry URLs to the registries option of that file, comma-separating several. Use a registry only after checking it runs through the MCP, since some listed registries fail the public format. *When:* When the default shadcn components are too limited, for example to get animated effects from Aceternity UI or other libraries.
- **Preview a registry's visual style before using it** — Ask the agent to search a registry (the presenter used Origin UI as an example) and browse its components. Decide whether the look fits the target design before asking for an implementation. *When:* Choosing an aesthetic for a page before a build.
- **Three-stage subagent workflow for UI builds** — Four subagent command files go in the commands folder (the presenter says four in the commands folder; the workflow he describes uses three main stages plus Express). Stage 1 (requirements): take a screenshot, PRD or page-flow description and write requirements.md plus a per-task folder in design docs. Stage 2 (research): continue the named task and write a component research file listing the shadcn components to use. Stage 3 (implement): continue the same named task and build the UI from the research file. Check context usage between stages and keep the same chat when the project is small. *When:* Multi-page UI work where the agent otherwise adds unneeded components or loses structure, and when several tasks share one repository.
- **Express agent for small changes** — Use the lightweight variant that skips requirements and research and goes straight to the change, giving the specific element and icon wanted. *When:* Small edits such as a new card, a menu toggle or an icon change, where the full pipeline is overhead.
- **Port the commands to Cursor** — Change the .md agent files to .mdc and put them in the Cursor rules folder. *When:* Using Cursor instead of Claude Code.
- **Apply a TweakCN theme** — Pick a theme on TweakCN, copy its code, and give it to Claude to apply on top of the existing layout. *When:* Restyling a shadcn project without rebuilding its layout.
