## Summary
The speaker presents Claude Code's subagents as a successor to custom slash commands for building role-based agent teams (UI designer, PM, QA, and so on). He walks through creating a project-level agent with the /agents command, using Claude to generate the agent from a description, restricting its tools, and saving it as a markdown file in the project. The main claim is that each subagent runs in its own context window and returns only a concise summary, which keeps the main session clean. He demonstrates this with a ShadCN UI Builder agent that uses the ShadCN MCP server to build a Next.js app from a spec file, reporting 72k tokens consumed inside the subagent with the main context untouched. He then applies a TweakCN theme generated from a reference screenshot through the same agent. He explains the two invocation modes, automatic delegation driven by the agent's description field and explicit naming, and suggests chaining subagents inside one custom slash command. The video includes a sponsored TestSprite segment and admits the demo involved several iterations and an unfinished backend.

## Key ideas
- **Subagents are a native Claude Code feature that turns the role prompts of custom-command frameworks into dedicated, reusable agents.** — Frameworks like BMAD and SuperClaude used custom commands for roles. Subagents let those roles become separate agents with their own specialization, e.g. PM, scrum manager, developer, UI expert, QA. ([0:00](https://youtu.be/Ppu6pJ5yyD4?t=0))
- **The key difference from custom commands is context management. Each subagent starts with its own empty context window and returns only a concise summary to the main agent.** — The speaker's illustrative UI-design agent used one tool, about 30.7k tokens and about 2 minutes, with its context kept separate from the main conversation. ([4:59](https://youtu.be/Ppu6pJ5yyD4?t=299))
- **Subagents can be scoped by tool access, which the speaker says custom slash commands could not do.** — During creation you deselect tools the agent does not need (he removed MCP tools from the UI agent and web search from the ShadCN builder), which he frames as both a security and a focus benefit. ([11:03](https://youtu.be/Ppu6pJ5yyD4?t=663))
- **Automatic delegation depends on the agent's description, and the speaker treats that description as the most important field.** — If Claude Code fails to pick up an agent when needed, the description is probably too vague. The alternative is to name the agent explicitly in the prompt. ([12:12](https://youtu.be/Ppu6pJ5yyD4?t=732))
- **A subagent can execute a long spec-driven build while the main session stays small.** — The ShadCN builder read a file reference (integrationstore.md) that held the app spec and navigation, followed MCP rules that route all ShadCN components through the MCP server, and produced an implementation.md plus a working Next.js front end. The speaker says styling still needed refinement and no backend was built. ([8:28](https://youtu.be/Ppu6pJ5yyD4?t=508))
- **Theme changes can be delegated to the same specialist agent, using a theme generated from a reference image.** — He generated a TweakCN theme from a screenshot of a Gumroad landing page, copied the index.css (Tailwind v3 project), and pasted it into Claude Code, which routed the change to the ShadCN agent. He then removed emojis and checked dark mode. ([9:52](https://youtu.be/Ppu6pJ5yyD4?t=592))
- **Subagents can be chained inside one custom slash command, for example a code-analyzer agent that finds performance issues followed by an optimizer agent that fixes them.** — He presents this as the way to combine subagents with slash commands for repeatable, consistent workflows. ([12:12](https://youtu.be/Ppu6pJ5yyD4?t=732))

## Techniques
- **Create a project-scoped subagent with /agents** — Run /agents in Claude Code. With no agents present it offers Create new agent. Choose Project agent (limited to the current repo, shown under Project Agents) or Personal agent (global across sessions). Pick Generate with Claude, enter a description of the agent's purpose, then select tools (deselect anything unneeded), choose a name (Claude suggests one) and a color, review the preview, and press S to save. The result is a markdown file in the project's .claude folder that holds the full system prompt and spec. *When:* When you want a reusable specialist (UI designer, QA, mobile prototyper) whose context should stay out of the main session.
- **Write a specific description and scope tools tightly** — Make the description field specific about the task, since it drives auto-delegation. Enable only the tools the agent needs, such as Read and Edit plus the specific MCP server for a builder, and disable web search or unrelated MCP tools for focused agents. Generic agents such as 'UI agent' are weaker than specialized ones such as 'mobile prototype agent'. *When:* Any time you create a subagent. The speaker treats this as the main lever for reliable delegation and for security.
- **Spec file plus rules file handed to a builder subagent** — Put the app spec and page navigation in a file (he used integrationstore.md). Put workflow rules in the prompt, such as a rule that all ShadCN components must go through the ShadCN MCP server. Ask the main agent to call the builder with a reference to the spec. The builder then produces an intermediate doc (implementation.md) that records patterns and components. *When:* Multi-step UI builds where the main session should stay lean and the builder should run autonomously.
- **Theme swap through a subagent** — Generate a theme in TweakCN from a reference screenshot, copy the generated index.css (for Tailwind v3), and paste it into Claude Code with the instruction to replace the theme. Claude calls the ShadCN agent to apply it. Clean up leftover issues afterward, such as emojis that clash with the design. *When:* Restyling a shadcn/Tailwind app without manual CSS editing. He reports about 4 minutes and 46k tokens for one run.
- **Chain subagents in a custom slash command** — Write one custom command that first calls an analyzer subagent (e.g. to find performance issues) and then an optimizer subagent (to fix them). Running the command runs the sequence. He states this gives consistent results on each run but shows no code. *When:* Repeatable multi-stage workflows, such as analyze-then-fix or plan-then-implement.
- **Invoke a subagent explicitly** — Name the agent in the prompt (for example, asking Claude to use the ShadCN UI Builder) instead of relying on automatic selection. Use this when auto-delegation does not pick the agent. *When:* When the description is not enough, or when you need deterministic routing.
