## Techniques
- **Shared fixed-size latent for variable-view 3D reconstruction (Surflow)** — Encode all unposed input images into one global latent of fixed size (128 tokens in the paper as described), regardless of view count. Decode the surface from that latent with flow matching, and sample the decoder at any resolution without re-running the encoder. *When:* Multi-view 3D reconstruction where the number of views varies a lot and memory should not grow with view count. Use it as a comparison point against per-view point-map methods like VGGT or DUSt3R.
- **Reusable motion primitives with zero-shot composition (Motion Bricks)** — Represent each motion skill as a reusable primitive in one latent generative backbone. Stack primitives to build complex movement, and add a new primitive for a new scenario instead of fine-tuning the model or hand-authoring transitions. *When:* Real-time character animation in games or sims where the set of needed behaviours keeps changing and no animator is available to author transitions.
- **Report steps and cost per task next to success rate for computer-use agents (Fara-7B)** — Benchmark on web tasks and report average steps per task and estimated cost per task alongside the success score, then compare small open models against larger proprietary agents on all three. *When:* Choosing a cheap computer-use model for a fixed set of tasks, where per-task cost and step count matter as much as accuracy.
- **Canonical body topology as a pivot between body models (SOMA)** — Map each body representation (SMPL, SMPL-X, MHR and others) to one canonical topology and rig. Mix identity sources and pose data at inference time through that pivot instead of writing a custom adapter per pair. *When:* Reusing mocap or motion-generation datasets and models that were trained on different body representations.
- **Haptic torque feedback in teleoperation for robot data collection (UME)** — Capture the operator's arm pose and the force the robot feels, and send that force back to the operator's exoskeleton in real time. Record the resulting trajectories as training data so the policy learns force-sensitive behaviour. *When:* Collecting demonstrations for contact-rich manipulation where position-only teleoperation does not capture the forces the policy needs.

MiniMax M3: weights on Hugging Face, try via Minimax Code. Kimi K2.7 Code: weights on Hugging Face under an open license, try via KimiCode.
