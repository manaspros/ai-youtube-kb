## Key ideas
- **Kimi K3 is a 2.8T-parameter open MoE model, presented as the largest open model released** — Built on Kimi Delta Attention and attention residuals, with sparse MoE routing (16 of 896 experts per forward pass) and a 'stable latent MoE' framework. The speaker says these changes yield roughly 2.5x better scaling efficiency than Kimi K2. Native vision and a 1M-token context window are included. Weights were promised by July 27, 2026, with a technical report. ([1:21](https://youtu.be/sUamCGBjWkM?t=81))
- **K3 was used to do most of its own kernel optimization work during late development** — In a kernel-optimization eval, each model got up to 24 hours in a sandbox to profile, rewrite and benchmark four GPU kernel tasks on H200 and an alternative vendor GPU. The speaker reports K3 was competitive with Claude Fable 5 and beat Opus 4.8, GPT 5.6 Sol and GPT 5.5 on this task. The speaker notes the benchmarks are Kimi's own, except Fable 5 which was third-party evaluated. ([2:33](https://youtu.be/sUamCGBjWkM?t=153))
- **Inkling wrote and ran its own fine-tuning job to learn a constraint that prompting could not enforce** — Thinking Machines Lab's Inkling (975B total, 41B active, trained on 45T tokens across text, image, audio and video, Apache 2.0) ran inside OpenCode. The target was a lipogram model that never uses the letter E. Inkling planned the run, generated synthetic data, launched fine-tuning through the Tinker API, loaded the new weights and verified the result without human steps. The company says it is not the strongest open or closed model, and head-to-head numbers against Qwen 3.5 were not in the main post. ([4:53](https://youtu.be/sUamCGBjWkM?t=293))
- **Scaling diverse pre-training makes single-example post-training transfer to unseen environments** — ACT2 (Sunday AI, home robot Memo) reports 99.1% zero-shot laundry folding in homes it never trained in. The speaker summarizes the claim that past a certain pre-training scale, the in-domain vs out-of-domain generalization gap closes, and one fine-tuning example can teach a behavior that transfers to new homes. The proposed maintenance loop is: identify failure pattern, collect one example, post-train, generalize. Beta deployments into homes are planned for this year. ([6:15](https://youtu.be/sUamCGBjWkM?t=375))
- **A robot world model is positioned as a synthetic training-data generator, with its inference speed as the key enabler** — Xiaomi Robotics U0 is a 38B autoregressive model covering text-to-image, image editing, multi-view scene generation, embodied transfer (re-skinning a demo into a new environment) and video generation. Its Flash R Plus inference system is reported to cut 1024x1024 image latency from 450 s to 5.44 s with the same quality. Weights and code are released under an open license. ([7:36](https://youtu.be/sUamCGBjWkM?t=456))
- **A 5B video diffusion model runs fully on a phone after converting its attention to chunk-wise recurrence** — Qualcomm's MobileWan generates 5-second 480x832 video at 16 fps in about 20 seconds end-to-end on a commercial phone, with VBench 83.79 and an 80% user preference over NeoDragon in a user study. The team started from Wan 2.2 5B and converted attention to a chunk-wise autoregressive RNN with near-constant peak memory, added causal linear attention for cross-chunk coherence, pruned heads with learnable binary gates, and applied step distillation to cut denoising steps. ([9:02](https://youtu.be/sUamCGBjWkM?t=542))
- **Ovis OCR2 replaces multi-stage document pipelines with one 0.8B end-to-end model** — The model takes a page image and emits markdown covering text, formulas, tables, figures and captions in reading order in one pass. It scores 96.58 on OmniDocBench V1.6, which the speaker calls the first end-to-end model to top a leaderboard previously dominated by multi-step pipelines. It is post-trained from Qwen3.5-0.8B with SFT, RL and a step called OPD (not explained), on a data engine mixing real and synthetic documents. ([11:32](https://youtu.be/sUamCGBjWkM?t=692))
- **Tool calling is a retrieval-and-assembly task, so a 26M attention-only model can serve as an on-device router** — Needle (Cactus Compute) has no FFN layers, only attention and gating, on the argument that tool schemas are supplied in the input and so the model does not need to store facts in MLPs. It was pre-trained on 200B tokens and post-trained on 2B tokens of Gemini-synthesized function-calling data across 15 tool categories. It beats FunctionGemma 270M, Qwen 0.6B, Granite 350M and LFM 2.5 350M on single-shot calls, but is a specialist and not a general assistant. ([12:49](https://youtu.be/sUamCGBjWkM?t=769))

## Techniques
- **Self-driven fine-tuning loop for a behavioral constraint** — Have the model plan the target behavior, generate synthetic training data, launch a fine-tune through a training API (Tinker in the demo), load the resulting weights, and verify the behavior with an evaluation, all inside a coding harness (OpenCode). The example target was a lipogram that never uses the letter E, which prompting alone did not reliably achieve. *When:* When a behavior is hard to enforce through prompts and you want an agent to close the data-train-eval loop without manual steps.
- **Failure-driven single-example post-training loop** — Identify a failure pattern in deployment, collect one example of the correct behavior, post-train the model on it, and check generalization on new environments. The speaker says this works only after pre-training on diverse data reaches a sufficient scale. *When:* When a deployed model has a narrow failure mode and you need a fast, low-data maintenance cycle that transfers beyond the training environments.
- **Chunk-wise recurrent attention for constant-memory long generation** — Convert a pretrained video diffusion transformer so attention runs chunk by chunk with a recurrent state. Add causal linear attention between chunks for coherence, prune heads using learnable per-head binary gates, and apply step distillation to reduce denoising steps. *When:* When you need long-sequence generation on memory-limited devices, where peak memory must stay near constant instead of growing with output length.
- **Attention-only tiny router for tool selection** — Use a small model with only attention and gating layers (no FFN) trained on synthetic function-calling data generated by a larger model. Route single-shot tool calls on-device and hand anything needing reasoning or knowledge to a general model. *When:* When an agent needs a cheap, fast tool-selection layer on device, and tool schemas are passed in the prompt so the model does not need to memorize facts.
- **Long-horizon kernel-optimization evaluation** — Give each model a sandbox with a large time budget (up to 24 hours) to profile, rewrite and benchmark a set of real GPU kernel tasks, then compare results across models on the same hardware targets. *When:* When measuring agentic coding ability on hard, measurable engineering tasks that need sustained iteration rather than a single attempt.
