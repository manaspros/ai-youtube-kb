> Philip Kiely (Baseten) updates his inference book with post-February 2026 developments: why TurboQuant lost on data-center throughput, learned KV compaction, DFlash diffusion-style drafting, and continuous speculator retraining.

## Summary
Kiely frames inference engineering as two worlds: local inference (compress the model, then recover quality at batch size one) and data-center inference (get it running, then make it faster). He focuses on the data-center side and organizes the update around quantization, KV cache, and speculative decoding. TurboQuant (4-bit KV cache) halves KV memory but needs extra decode computation that cut throughput by more than half, so Baseten does not use it in production; it is more useful for memory-bound local setups. For KV cache, he presents learned compaction (the "Still" approach), where a fixed set of learned query vectors cross-attends to the full cache in one forward pass to produce a much shorter, differentiable memory. On speculation, DFlash (diffusion-based block drafting) beats EAGLE-3, which was the leading method as of February, with a reported 3x-plus gain on one benchmark. DSpark is new research with no production numbers yet. The most actionable production point is continuous speculator retraining on live traffic, which gave 20% to 2x acceptance-rate gains but needs storage, data permissions, compute, and a retrain whenever the base model changes. He closes with predictions: NVFP4 on Rubin, PD disaggregation, moving KV data across the system, and training for inference.

## Key ideas
- **Two inference worlds with opposite playbooks** — Local inference compresses a model to fit small hardware and then recovers quality at batch size one. Data-center inference gets the model running first and then makes it less slow using KV-aware routing, speculation, and disaggregation. The talk focuses on the data-center side. ([2:37](https://youtu.be/75ckHC2LU_0?t=157))
- **Training and inference are merging** — Many inference speedups now come from a dedicated training step, such as a trained draft model or a learned cache representation. He describes a flywheel: faster inference yields more data, which trains a better model, which is faster again. ([4:06](https://youtu.be/75ckHC2LU_0?t=246))
- **TurboQuant is a poor fit for data-center throughput** — It stores the KV cache in 4 bits instead of 8, halving its memory and effectively doubling bandwidth. The cost is extra computation during decode, which cut tokens per second by more than half, so Baseten does not use it in production. It remains useful for long-context local inference, where memory is the bottleneck. ([5:21](https://youtu.be/75ckHC2LU_0?t=321))
- **Learned KV compaction keeps more information than deterministic pruning** — Recent compaction methods (attention matching, cartridges) shrink the cache at inference time. The Still approach instead amortizes the work into training: fixed learned query vectors cross-attend to the full KV cache and produce compact keys and values in one forward pass, giving a differentiable compressed memory the model can attend to. ([8:43](https://youtu.be/75ckHC2LU_0?t=523))
- **DFlash drafts blocks of tokens with diffusion instead of one token at a time** — A diffusion language model proposes 8 or 16 tokens per window in parallel. Each DFlash pass is slower than one EAGLE draft step but produces more tokens, and the proposed tokens attend to each other, which raises acceptance rate. He says acceptance rate is the key metric. ([12:34](https://youtu.be/75ckHC2LU_0?t=754))
- **Bidirectional attention within a draft block, causal across blocks** — DFlash is trained with an attention mask that allows bidirectional attention inside each block of sampled clean tokens while keeping causal consistency. The target model supplies the context. This is what makes a diffusion-style drafter workable. ([14:43](https://youtu.be/75ckHC2LU_0?t=883))
- **Continuous speculator retraining on live traffic** — Speculation depends on the actual prompts and responses, so retraining the draft model on production data gave 20% to 2x higher acceptance rates. It needs storage, permission to use the data, compute, and a new speculator whenever the base model changes. ([16:03](https://youtu.be/75ckHC2LU_0?t=963))
- **Predictions focus on NVFP4, disaggregation, and KV movement** — He expects Rubin to perform well on NVFP4, so confidence in that format matters. He sees PD disaggregation and moving KV cache around the system as increasingly important, with training for inference continuing to have a large effect. ([17:03](https://youtu.be/75ckHC2LU_0?t=1023))

## Techniques
- **Continuous speculator retraining** — Log live prompts and responses (with data-use permission), periodically retrain the draft model on them, and redeploy the speculator. Retrain again whenever the target model changes. *When:* Large-scale production serving where the traffic distribution is stable and the acceptance rate is a bottleneck.
- **DFlash block drafting** — Use a diffusion language model as the draft model to propose a whole block of 8 or 16 tokens in one pass. Train it with an attention mask that is bidirectional within each block and causally consistent across blocks, conditioned on the target model's context. *When:* Speculative decoding where acceptance rate limits speed-up and the drafter's extra per-step cost is acceptable. He reports it in production at Baseten.
- **Learned KV compaction (Still)** — Train a perceiver-style module with a fixed set of learned query vectors that cross-attend to the full KV cache, producing a compact set of keys and values in a single forward pass. The output is differentiable and can be attended to as if it were context. *When:* Long-context workloads where the KV cache is the memory bottleneck and near-lossless retention matters more than the cost of a training step.
- **Stay on NVFP4 weight quantization for production** — Quantize the weights to NVFP4 and watch for distribution distortion in the quantized weights. Do not compress the KV cache with TurboQuant on the serving path. Handle KV pressure with KV-aware routing, offloading to CPU memory, and sharing. *When:* Data-center serving where throughput per GPU matters more than fitting long sequences on limited memory.
- **Local-first versus data-center-first sequencing** — Start from the most constrained target and then recover quality or speed. Local work first squeezes the model down and then restores quality; data-center work first gets the stack running and then optimizes. *When:* Deciding which optimization to tackle first when serving a new model.

## Numbers
- Book published 2026-02-23; over 11,000 paper copies sold and nearing 30,000 digital copies (self-reported) ([0:12](https://youtu.be/75ckHC2LU_0?t=12))
- TurboQuant: 4-bit KV cache instead of 8-bit, halving KV memory and effectively doubling bandwidth, but cuts tokens per second by more than half ([5:21](https://youtu.be/75ckHC2LU_0?t=321))
- DFlash: more than 3x improvement in the wild over EAGLE on a single B200 with an 8B-class Qwen model, in both acceptance rate and tokens per second (speaker's measurement) ([13:41](https://youtu.be/75ckHC2LU_0?t=821))
- DFlash drafts 8 or 16 tokens per window; a DFlash model can be 2-4x slower per forward pass than an EAGLE draft step, but one DFlash pass is faster than the whole EAGLE draft phase ([13:41](https://youtu.be/75ckHC2LU_0?t=821))
- Continuous speculator retraining on production data: 20% to 2x improvement in token acceptance rate (DFlash, production) ([16:03](https://youtu.be/75ckHC2LU_0?t=963))

## Hot takes
- Acceptance rate is everything for speculative decoding.
- TurboQuant is a great paper but is not suited to data-center inference because its decode-time compute cost outweighs the memory savings.
- Training for inference is the theme that will have the biggest impact on the industry.
- Continuous speculator retraining is worth it at very large scale despite the cost.
