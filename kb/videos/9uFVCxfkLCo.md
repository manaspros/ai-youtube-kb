> Walkthrough of capturing a website component with the Web2 MCP Chrome extension, cloning it one-to-one with a Claude Code/Cursor agent using a modified CLAUDE.md, and generating variants with SuperDesign. Mixed results, with a Rocket.new sponsor segment.

## Summary
The host presents a UI-design workflow built from two tools. Web2 MCP is a paid Chrome extension that lets you capture any on-page element and send it to Cursor or Claude Code via an MCP server and a reference ID. SuperDesign is an editor extension whose rule files set the agent's design behavior. The host reports that SuperDesign's default system prompt, which pushes a color scheme and a CSS library, prevented a one-to-one clone, and that removing it produced an exact clone. He edited the generated CLAUDE.md to force one-to-one cloning, excluding app logos but keeping ordinary icons, with the agent outputting an HTML reference plus a screenshot. He then opens a new chat and asks for variants of the captured component (dropdowns with animations, a navigation bar, a dashboard), noting that output inherits the uniqueness of the inspiration. An open-source alternative, MCP Pointer, was judged clearly weaker. The video opens with a roughly 1.5-minute sponsor read for Rocket.new. The results shown still have off-style icons rendered as emojis, and the host admits the title's "perfect" claim is aspirational.

([0:00](https://youtu.be/9uFVCxfkLCo?t=0))

## Techniques
- **Capture an element with Web2 MCP and reference it by ID** — 1) Install the paid Web2 MCP Chrome extension (the host used Arc) and log in. 2) Copy the account-specific MCP config token. For Cursor, use the provided config; for Claude Code, run the provided one-line command in the terminal, which installs the MCP for that project. 3) Open the extension, click 'capture element', hover to highlight, click the target element. 4) Paste the menu's reference ID into the agent prompt. *When:* When you have a specific live website component you want reproduced in your own project, not generic UI from a description.
- **Initialize SuperDesign rule files and edit CLAUDE.md for one-to-one cloning** — 1) Install the SuperDesign extension from the editor marketplace. 2) Open the command palette (Cmd+Shift+P on macOS) and run the SuperDesign initialize command. 3) Delete the rule files you will not use. 4) Edit the CLAUDE.md: remove the colour-scheme and CSS-library directives that broke fidelity; add rules to clone the UI one-to-one, excluding app logos/brand icons while keeping arrows and common icons as-is; require the agent to output an HTML reference and a screenshot together. *When:* When you want faithful clones rather than SuperDesign's restyled outputs, and visual verification of every clone.
- **Two-session workflow: clone first, then generate variants** — 1) In session one, capture a component and have the agent clone it one-to-one. 2) Open a new chat. 3) Tell the agent the component already exists and reference it by name or path, specifying either a single component or a full page. 4) Ask for new designs based on that reference (e.g., dropdown menus, a navigation bar, a dashboard). *When:* When you want new UI in the style of an inspiration site, not a copy of it.
- **Use SuperDesign's canvas view to inspect how a design was produced** — Open the generated designs in SuperDesign's canvas view to see how each design was made, rather than reading the code alone. *When:* When reviewing or iterating on agent-generated UI and you need to understand the generation trail.

## Hot takes
- A sponsored read for Rocket.new (about 1.5 minutes) and a hype title ('The PERFECT Design Workflow') on thin, single-tool evidence, so quality is capped at 2.
