> Walkthrough of the open-sourced Apollo 11 Guidance Computer code: 1960s hardware limits, a priority job scheduler that raised alarm 1202 under overload, restart checkpoints, and how to run it in an emulator.

## Summary
The video is a retro-computing walkthrough of the Apollo 11 Apollo Guidance Computer source code, which is public on GitHub (transcribed by volunteers from scans of printouts). The presenter covers the hardware limits (about 1 MHz, 2048 words of RAM, roughly 70 KB of core rope read-only memory that could not be patched after weaving) and the verb/noun command language forced by a 19-key keypad and digit-only display. The most technically useful part is the executive scheduler: fixed slots for priority jobs, with overflow raising alarm 1202 instead of queueing. It then explains restart protection through checkpoints and an interpreter VM that trades speed for code size. The landing story ties these together: a rendezvous radar fault consumed about 13 to 15 percent of CPU, the navigation job missed its 2-second cycle, and the computer restarted five times on descent. The video closes by running the code in the Virtual AGC emulator and walking through the verb/noun commands used for lamp test, clock, alarm display and the pre-liftoff countdown. Most of the content is history and humor, with the scheduler and restart design as the real engineering substance.

## Key ideas
- **The Apollo 11 source is public (on GitHub since 2016, about 72k stars per the presenter), but the original survived only as two printouts; the GitHub version was transcribed by volunteers from scans.** — Presenter says more than 400 people worked on Apollo software and Margaret Hamilton led the command module software team; the code is annotated with sign-off pages and comments. ([0:00](https://youtu.be/ACAd_w3D-io?t=0))
- **Hardware constraints shaped everything: about 1 MHz clock, 2048 words (about 3840 bytes) of RAM, and roughly 70 KB of core rope read-only memory.** — Core rope was woven by hand with wire through magnetic rings (wire through ring = 1, around = 0), so the program could not be patched and had to be locked months before launch. ([1:20](https://youtu.be/ACAd_w3D-io?t=80))
- **A tiny verb/noun command language replaced words because the keypad had 19 keys and the display only showed digits.** — Verb = action (display, load), noun = the data it applies to (clock, position); the mapping lived in a document of assembly and operational information, and astronauts likely carried a checklist. ([3:53](https://youtu.be/ACAd_w3D-io?t=233))
- **The executive scheduler runs jobs by priority in fixed slots, and overflow is treated as a fatal alarm rather than being queued.** — The lunar module had 8 job slots of 12 words each; when a new job arrived with all slots full, the computer raised alarm 1202. A code comment was out of date (it said 7 sets of 11 registers, the code scanned 8 sets of 12). ([3:53](https://youtu.be/ACAd_w3D-io?t=233))
- **Restart protection uses checkpoints: on restart, protected jobs resume from their last checkpoint and unprotected work is dropped.** — The landing software re-enabled the descent engine if it had been running. Heavy math ran in an interpreter VM packing two instructions per word, about 19 times slower than native assembly but much smaller. ([4:56](https://youtu.be/ACAd_w3D-io?t=296))
- **A rendezvous radar wiring fault forced the landing into overload, causing repeated restarts.** — The radar fired up to 12,800 pulses per second, using 13 to 15 percent of the CPU. Landing already used about 90 percent, so the 2-second navigation job never finished, copies kept being scheduled until 1202 fired, and the computer restarted five times during descent. ([6:01](https://youtu.be/ACAd_w3D-io?t=361))
- **Pre-launch and liftoff were handled by the command module computer itself, with a manual backup.** — The computer sat in program 2 keeping its gyros aligned; the checklist had the crew pre-type verb 75 without Enter. A liftoff signal from the rocket switches it to program 11 and resets the clock; Enter on verb 75 is the fallback if that signal never arrives. ([7:02](https://youtu.be/ACAd_w3D-io?t=422))

## Techniques
- **Fixed-slot priority job scheduler with overflow alarm** — Keep a fixed array of job slots with priorities; the highest-priority runnable job always runs. When no slot is free, raise an explicit alarm (Apollo used 1202) instead of queueing unboundedly. Each job record has a fixed size (12 words in the LM). *When:* Memory-constrained or hard real-time systems where dynamic allocation is unacceptable and overload must be visible, not silently absorbed. Relevant as prior art for priority schedulers with preemption (e.g. a 4-class scheduler on one GPU).
- **Checkpoint-based restart protection** — Place checkpoints through critical sequences. On restart, resume each protected job from its last checkpoint and drop anything not marked protected. Restore hardware state explicitly (the landing software re-enables the descent engine if it was on). *When:* Any long-running, restartable process where some steps must survive a crash and others must be discarded. Maps to checkpoint/resume design for long agent runs.
- **Interpreter VM to trade speed for code size** — Write bulky, infrequent math as bytecode for a small interpreter that packs two instructions per memory word, rather than in native assembly. *When:* When code size is the binding constraint and the routine is not on the critical path (Apollo accepted about 19x slowdown).
- **Verb/noun command language for constrained input** — Map a small key set to two-number commands: verb selects the action, noun selects the data, and Enter executes. Keep the full mapping in a reference document the operator carries. *When:* Input devices with few keys and limited display output, such as embedded panels or emergency consoles.
- **Reproducing Apollo 11 in the Virtual AGC emulator** — The presenter used the Virtual AGC project, ran a script he wrote that builds the emulator and assembles the Apollo 11 source (the output matches the original memory byte for byte, per the presenter), and opens the DSKY keypad. Commands shown: verb 35, Enter (lamp test); verb 16, noun 36 (ticking clock); verb 5, noun 9 (alarm-code display used during landing). Before liftoff, type verb 75 without Enter; the liftoff signal switches to program 11. *When:* Learning the Apollo code or verifying a retro emulator against the original binary. The presenter does not show the build script itself, so exact commands are not in the transcript.
