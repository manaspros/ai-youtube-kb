## Techniques
- **Install the Claude Code GitHub app into a repo** — Run the Claude Code slash command for GitHub setup inside the repo (command name not stated in the transcript). Follow the guided workflow, which installs the app. Then prompt Claude with the automation you want and it generates the GitHub workflow. *When:* Once per repo, before any scheduled or issue-triggered Claude Code automation.
- **Scheduled news monitor on GitHub Actions** — Workflow runs on a twice-daily schedule and can also be started by hand from the Actions tab. It asks Claude to check the model-provider sites and post the result to Slack. If nothing is new, the agent posts a 'no news' message rather than staying silent. *When:* Recurring watch tasks that need notifications without a terminal session.
- **Whitelist all tools for headless runs (Rule 1)** — List every tool the workflow needs and pass them through the allowed-tools flag. The speaker did not name the flag in the transcript. Check the first run's logs for denied tools before assuming the workflow works. *When:* Any unattended Claude Code run in CI or a scheduled job. This is the most common failure he hit.
- **Verify MCP servers before automation (Rule 2)** — Connect each MCP server in a manual test and confirm its tools are callable and have the needed permissions (read-write, not read-only) before adding it to a workflow. Do not trust Claude's claims about how a third-party service's API works. *When:* Before adding any external MCP server to an automated run.
- **Post to Slack via incoming webhook with curl** — From a workflow step, send the message to the Slack webhook URL with curl. The speaker found that Claude's suggested direct webhook approach failed, and that a full Slack app was needed for it. He used curl for the working path. Exact payload format is not shown in the transcript. *When:* Lightweight notifications from an agent workflow where a full Slack app is unnecessary.
- **Hand off a background coding task via a GitHub issue** — Open a new issue with a title and a brief describing the task. Tag Claude in the issue. Wait for its reaction emoji, which means it has seen the request and started. Review the resulting branch and PR. *When:* Longer tasks you want to delegate and check later, including from a phone.
- **Paste SDK documentation into the task** — Open the Agent SDK documentation (TypeScript or Python), use the copy-page button, and paste it into the issue or prompt so Claude has the API context it lacks. *When:* When the agent is building on an SDK it may not know well, or when setup keeps failing for lack of API knowledge.
- **Verify auth end to end on a branch** — After Claude says auth is done, ask it to create a test user, switch to the feature branch, run the app and log in as that user to confirm. *When:* Accepting an agent's claim that a feature works.
