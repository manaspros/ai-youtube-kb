> Karthik Rao (Perpetual CTO) on building reliable, regulated wealth-management workflows: an LLM planner emits a typed graph, a deterministic compiler fails closed, and models make only small typed judgments.

## Summary
Karthik Rao, CTO of Perpetual (a wealth-management roll-up), argues that regulated workflows need a deliberate boundary between deterministic control and model judgment, not more or less agency. He uses a real W9 task (one advisor sentence that triggers lookups, ambiguity, client waits, approvals and follow-ups) to show why fixed flowcharts and free-running agents both fail compliance. His engine has an LLM planner that only translates the request into a typed semantic graph, then a compiler with no model call that checks it against a closed grammar of 42 action contracts and fails closed on anything it cannot verify. Compiled plans are hash-pinned and approved by a person, with external side effects gated per payload hash. Model calls are small typed decisions, mostly sent to a cheap "flash" tier, with frontier-model decisions logged as future training data. Because each call has a schema, moving to a privately hosted model is a configuration change. The talk is short and grounded, with few hard benchmarks, and its main numbers come from one illustrative run.

## Key ideas
- **The reliability boundary is the design** — Reliability and intelligence are not opposites. Decide per step where deterministic control ends and model judgment begins. Determinism governs control flow, evidence and side effects. Intelligence handles interpretation and judgment. ([0:00](https://youtu.be/8g0g1ncwzG0?t=0))
- **A one-line task hides a long, branching process** — Filling a W9 looks like data entry, but each answer changes the next question (taxpayer type, tax box, which name, which TIN, exemptions, signer). The speaker's example also needs a lookup, a human clarification, a multi-day client wait, e-signature and follow-ups. ([2:53](https://youtu.be/8g0g1ncwzG0?t=173))
- **Use a planner for translation only, and compile the plan without a model** — The LLM planner emits a typed graph of intents, entities, facts, artifacts, events and constraints, each linked to the words it came from. A model-free compiler runs 11 stages and returns one of three verdicts: valid, needs clarification (asks, e.g. 'which Harper?'), or refused. Invalid plans fail closed. ([8:07](https://youtu.be/8g0g1ncwzG0?t=487))
- **A closed action grammar limits what the model can ask for** — The firm defines 42 typed action contracts across forms, documents, email, e-signature, calendar and human steps. The compiler rejects unknown or mis-wired actions, with about 40 fail-closed paths. One contract digest is pinned across engine, backend and UI so all three agree on what an action means. ([9:18](https://youtu.be/8g0g1ncwzG0?t=558))
- **Waits, approvals and follow-ups are plan nodes, not prompts** — Reply waits default to 72 hours, with deadlines from a minute to 30 days. One approval covers the plan, and each external send has its own gate bound to a hash of the exact payload, rechecked just before sending. A partial client reply is provisional until a person confirms it. Follow-ups run as new child plans, capped at five rounds, so the approved parent is never changed. ([10:45](https://youtu.be/8g0g1ncwzG0?t=645))
- **The state machine drives, the model steers** — After approval, a state machine runs every step and logs every result. When judgment is needed, it makes one fixed-schema call (compose, judge a reply, spot missing values, extract fields, verify a document). Side effects have their own lifecycle (prepare, dispatching, succeeded, outcome unknown, manual review). There are no automatic retries. Chat can approve a step but cannot change an approved plan. ([12:15](https://youtu.be/8g0g1ncwzG0?t=735))
- **Most judgments go to a small model, and frontier decisions become training data** — In one illustrative run of 20 decisions, 19 went to a flash-tier model and 1 to a frontier model. The design target is about 95% of decisions on small models. Every judgment is typed and logged, and frontier outputs with human-confirmed provisional results can later train the small tier. The speaker says logging and evals exist, and the training loop is next. ([13:17](https://youtu.be/8g0g1ncwzG0?t=797))
- **Private hosting is a config change because each call is typed** — Each model call has a small, schema-checked output shape, so moving a call to a privately hosted model means changing one line while the same typed answer comes back. The speaker presents this as the route to running most sensitive workflows on infrastructure the firm controls. ([14:22](https://youtu.be/8g0g1ncwzG0?t=862))

## Techniques
- **Planner emits typed semantic graph, compiler verifies with no model** — Have the LLM translate a request into a typed graph of intents, entities, facts, artifacts, events and constraints, each tied back to source words. Compile it deterministically against a closed grammar. Return valid, needs-clarification or refused, and fail closed on anything else. Pin the compiled plan by hash. *When:* When outputs must be auditable and a wrong action is costly, such as regulated or financial workflows, or any agent that writes to external systems.
- **Closed action grammar with typed contracts** — Define a fixed set of typed action contracts. The planner may only request actions that match one, and the compiler adds required steps (such as rendering or attaching a document) that the contracts require. Pin one contract digest across backend, engine and UI. *When:* When the set of safe actions is known in advance and must be shared consistently across services.
- **Payload-hash-bound approval gates** — Attach an approval to a hash of the exact outbound payload (email, signature request). Recheck the hash immediately before sending. Keep the approved parent plan immutable, and run any follow-up as a new child plan with a round limit. *When:* When a human must approve the exact content that leaves the system, and approvals must not be reused for changed content.
- **Provisional judgments awaiting human confirmation** — When a model judgment is uncertain (e.g., a partial reply), mark it provisional and block the step until a person confirms or rejects it. Only then continue. *When:* When a wrong automatic decision would be costly and human review is cheap enough to sit in the loop.
- **Side-effect lifecycle with no automatic retry** — Give every external side effect explicit states (prepare, dispatching, succeeded, outcome unknown, manual review). Send unclear outcomes to manual review instead of retrying. *When:* When duplicate side effects (double-sent emails, double-filed forms) are unacceptable.
- **Rule-based timeouts instead of model decisions** — Set explicit waits and deadlines as plan nodes (default 72 hours, configurable from one minute to 30 days). When a deadline passes, a fixed rule decides the next step. *When:* When long-running workflows wait on external people and the timeout policy must be auditable.
- **Route judgments to a small tier and log frontier calls as training data** — Use one fixed-schema call per judgment, send most to a cheap model, and send only hard cases to a frontier model. Log every typed decision and human outcome so frontier results can later be used to train the small model. *When:* When model cost and data sensitivity both matter and the workflow produces many repeated, narrow judgments.

## Hot takes
- In regulated industries, token maxing is the wrong goal.
- Both 'more agency and better models' and 'less agency, more rules' are the wrong axis; the question is where the deterministic/intelligent boundary sits.
- Most model decisions in a workflow should never need a frontier model.
