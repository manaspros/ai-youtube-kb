> Live workshop from Google DeepMind's Guillaume Vernade building an illustrated children's book with Gemini, Nano Banana, Veo, Lyria and TTS, plus API tips on retries, service tiers and stateful chats.

## Summary
Guillaume Vernade, a developer advocate at Google DeepMind, runs a hands-on Colab workshop that turns an open-source book (The Wind in the Willows) into character portraits, chapter illustrations, short video clips, songs and a multi-voice audio reading. He uses Gemini to write structured prompts and then feeds them to the GenMedia models (Nano Banana for images, Veo for video, Lyria for music, Gemini TTS for speech). The talk is mostly a demo, with practical tips on overloaded-model retries, Flex vs Priority pricing, and using chat history versus the newer stateful Interactions API. A recurring point is that long, specific prompts work much better than one-liners, and that Gemini-written prompts suit these models because they were partly trained on them. He also covers Lyria's prompt-only controls (duration, BPM, structure, timed lyrics) and the Lyria RealTime model. Speaker-stated costs are roughly $1 per notebook run, mostly from video. A Q&A answer says EU customers will not get preview models soon, since preview models only run on global endpoints. Some transcript lines are garbled, so exact wording is uncertain in places.

## Key ideas
- **DeepMind's stated goal is one multimodal world model, but releases ship as separate specialized models (image, video, music, speech) because updating one big model risks breaking others.** — Speaker says the long-term aim is one model that takes and produces many modalities. For now each GenMedia modality ships as its own model to limit release risk. He also notes Gemini 1.5 still had leftover training that made it refuse images at times. ([3:41](https://youtu.be/BcWFc3H7Khg?t=221))
- **Use Gemini to write the prompts for the media models, because the media models were partly trained on Gemini-written prompts.** — Speaker says a large share of the GenMedia training data was written with Gemini's help, so Gemini tends to write prompts they follow well. Longer, more specific prompts also tend to beat one-liners, since the models rewrite prompts internally anyway. ([40:04](https://youtu.be/BcWFc3H7Khg?t=2404))
- **Chat mode resends the whole history on every call, so a full book in context gets slow; the stateful Interactions API reuses a server-side ID instead.** — With chat, every turn re-sends the earlier messages, including the whole book. The newer Interactions API returns an ID you can pass to later calls to recover context on the server. It also makes forking a conversation easy (e.g. lyrics from one model, images from another), and implicit caching makes repeat context cheaper. It was in preview at the time. ([25:47](https://youtu.be/BcWFc3H7Khg?t=1547))
- **For consistent characters across scenes, pick the reference images per scene and pass only those, instead of relying on chat history.** — Speaker asks the model for a structured output per chapter that lists which characters appear. A script then pulls only those saved character images and sends them as references to a one-shot generate_content call. He says this is the approach to use at scale, and that one portrait plus a full-body or side view per character would likely help more. ([29:50](https://youtu.be/BcWFc3H7Khg?t=1790))
- **For video, pass the image as the first frame and generate a separate motion prompt from that frame, otherwise the wrong character can end up speaking.** — Reusing the image prompt for video produced the wrong character speaking, because the video prompt lacked details about what happens next. Asking Gemini for a short action prompt that starts from the last frame fixed it. He also notes video training relies heavily on image generation, since the first frame sets up the rest. ([35:50](https://youtu.be/BcWFc3H7Khg?t=2150))
- **Lyria is controlled entirely through the prompt: duration, key, BPM, and section structure all go in text, and timed lyrics come back with timestamps.** — There are no API parameters for these. Section labels like intro, verse, chorus and outro can be given in the prompt, and a fast or slow tempo can be set in BPM or with accelerando wording. Lyrics can be supplied or invented, and the output carries timing data that could drive a karaoke view. Streaming returns the lyrics before the audio, so you can act on them early. ([43:27](https://youtu.be/BcWFc3H7Khg?t=2607))
- **A single TTS voice can sound like several characters if the script adds a style note per speaker, but the request must begin with an explicit read-this instruction.** — Gemini writes a play-format transcript where each line has a style in parentheses (e.g. whispering, breathless, stutter). Each character then gets a different style instead of a different voice. Without an opening instruction such as read this text, the model did not read the input aloud. He says a real system should keep a proper transcript with names and a separate prompt per character. ([47:17](https://youtu.be/BcWFc3H7Khg?t=2837))
- **Gemini API file upload and chat mode hide the bucket and ACL setup that Vertex AI requires, and the Gemini API and Vertex share one SDK, so you can switch later.** — Speaker frames AI Studio and the Gemini Developer API as the easy entry point, with Vertex AI as the enterprise option with data-center and access control. Uploading a file through the Gemini API avoids managing buckets. The same SDK works with both backends. ([18:03](https://youtu.be/BcWFc3H7Khg?t=1083))

## Techniques
- **Retry wrapper around the media client** — Configure the GenAI client to retry automatically (speaker uses 5 retries, 2 seconds apart) because the newest image models are often overloaded, especially in US evening hours. *When:* Any batch or demo pipeline calling preview or newly released image/video models at peak times.
- **Service tier choice per request** — Use Flex (about 50% cheaper, may be delayed by minutes) for batch work, and Priority (about 2x price, faster) for interactive demos. The speaker switched Priority on for the live demo, which made character generation noticeably faster. *When:* Batch jobs where cost matters more than time (Flex), or live steps where latency matters more than cost (Priority).
- **Iterate cheap, then upscale** — Test prompts on the cheapest video model (Veo 3.1 Lite), then re-run the chosen prompt on the full model. *When:* Video generation, where each run is expensive and prompt iteration needs many attempts.
- **Structured output as a scene manifest** — Ask Gemini for JSON with a name, a prompt and a list of characters per chapter; use the list to choose which reference images to send to the image model. *When:* Multi-entity image or document generation where per-scene context must stay small and precise.
- **Style and composition system instructions** — Put standing instructions in the system prompt (for example, no title or cover layout, no multi-panel layouts, always describe clothing) to keep the output style consistent across calls. *When:* Generating a series of images that must share one look or avoid unwanted layouts.
- **Streamed Lyria output** — Use streaming generate_content with audio and text modalities: the lyrics arrive first, so you can create a title or image while the audio is still being generated. *When:* Music apps that need lyrics or timing data before the full audio is ready.
- **Lyria RealTime as a live, steerable stream** — Send new text prompts into an open session to shift the music (the speaker describes it as a DJ mix, with about 2 seconds of latency). Sessions are capped at about 10 minutes. *When:* Interactive experiences where music should respond to game state or user actions.

## Numbers
- Veo 3.1 Lite is the cheapest video model at about $0.05 per second, so about $0.40 for one video (speaker's figures). ([7:40](https://youtu.be/BcWFc3H7Khg?t=460))
- Lyria clip (30-second songs) costs about $0.04 per song; the full-song model (up to 3 minutes) costs about twice that, $0.08 (speaker's figures). ([40:04](https://youtu.be/BcWFc3H7Khg?t=2404))
- Running the whole notebook costs roughly $1, and most of that is the video generation. ([10:19](https://youtu.be/BcWFc3H7Khg?t=619))
- Flex service tier is about 50% cheaper and can be delayed by a few minutes; Priority costs about 2x and is faster. ([20:46](https://youtu.be/BcWFc3H7Khg?t=1246))
- The client retries automatically 5 times, 2 seconds apart, when a model is overloaded. ([14:16](https://youtu.be/BcWFc3H7Khg?t=856))
- Nano Banana 2 supports aspect ratios from 520 pixels up to 4K, plus search and image grounding. ([6:21](https://youtu.be/BcWFc3H7Khg?t=381))
- DeepMind ships things about every five days on average across the org, and GenMedia alone ships at least monthly (the speaker's wording in the transcript is garbled, so exact figure is uncertain). ([6:21](https://youtu.be/BcWFc3H7Khg?t=381))
- Lyria RealTime responds to prompt changes in about 2 seconds, and its sessions end after about 10 minutes. ([8:57](https://youtu.be/BcWFc3H7Khg?t=537))
- Gemini 1.0 shipped without image understanding; Gemini 1.5 was the first widely multimodal input version the speaker used. ([3:41](https://youtu.be/BcWFc3H7Khg?t=221))
- Preview models are available only on Google Cloud global endpoints, which is why EU customers cannot use new models yet. The speaker says this is unlikely to change soon. ([59:25](https://youtu.be/BcWFc3H7Khg?t=3565))

## Hot takes
- Video generation is expensive, so do not try a prompt 100 times. Iterate on the cheap model first.
- One-line prompts give boring results on these models; longer prompts work better.
- Gemini-written prompts suit the GenMedia models because those models were partly trained on Gemini-written prompts.
- Preview-only model availability on global endpoints is a real blocker for EU customers, and the team is fighting it internally.
