> A walkthrough of skills, plugins and slash commands the Claude Code team reportedly uses, including batch worktree fan-out, a verify skill and an end-of-session tech debt skill. Several are internal and unverified, and a sponsor segment is included.

## Summary
The host goes through skills, plugins and slash commands that they say the Claude Code team uses daily, sourced from posts, open-source repos, the official plugin marketplace and what they call leaked source code. Public items include the frontend-design plugin, the batch command, the Code Simplifier plugin, the built-in Simplify command, the built-in security scan, a commit command, and the Remotion skill. Several others are described as internal-only: verify, Skillify, tech debt and dedupe, and the host reverse-engineers their likely behaviour and suggests building your own versions with the skill creator. The most reusable ideas are the batch flow (plan, approve, one agent per unit in its own git worktree, then merge) and project-specific verify and tech-debt skills. Most of the content is high-level, with few exact commands or configs, and the sponsor segment and a plug for a paid tier take up part of the runtime.

## Key ideas
- **The batch command fans parallelizable work out to several agents, each in its own git worktree, so they cannot clobber each other.** — Batch first enters plan mode. The plan covers the current app state, the division into units, the list of additions, and how end-to-end verification should run. After approval it spawns one agent per unit, each in a separate worktree. The main agent merges the worktrees into main and can open a PR if a remote is configured. The host suggests this is different from ordinary subagent parallelism because of the worktree isolation. ([1:24](https://youtu.be/AhXfI1rSUPc?t=84))
- **A project-specific verify skill gives the agent a way to prove its own changes work.** — The host says the internal verify skill runs the app, tests changes from several angles and fixes failures. It scans the codebase to generate a tailored version, using Playwright, MCP checks, tests or other methods. Good setup includes test cases and visual checks, for example through the Claude Chrome extension. A CLI reference file lists the available tools, linters, exit codes and npm test files. ([4:15](https://youtu.be/AhXfI1rSUPc?t=255))
- **Skillify turns a session that refined a workflow into a reusable SKILL.md draft.** — Per the host, Skillify (internal, behind an environment flag, with its system prompt in the leaked source) analyses the session for repeatable processes, tools, permissions and agents. It asks clarifying questions, produces a skill file for review, and saves it to the project once confirmed. The host suggests recreating it with the skill creator. ([5:34](https://youtu.be/AhXfI1rSUPc?t=334))
- **The team uses slash commands for every repetitive inner-loop task, such as commit, push and open a PR.** — The host cites a commit-push-PR command and the official commit command, which builds commits from staged and unstaged changes. Both are in the official plugin marketplace. ([8:00](https://youtu.be/AhXfI1rSUPc?t=480))
- **A tech-debt skill run at the end of every session finds duplicated code and consolidates it into a shared library.** — The internal skill runs multiple agents across the codebase, reports redundant duplication, creates a shared library, and updates components to use it. The host advises writing the skill instructions as a step-by-step workflow: identify session changes, detect duplicates, define the file-structure rules, and finish with npm test and the linter. ([8:58](https://youtu.be/AhXfI1rSUPc?t=538))
- **The built-in security scan checks several vulnerability classes, then Claude can fix what it finds.** — The host lists input validation, authentication, secret management, injection and code execution, and endpoint exposure. The scan is a released feature that the team used internally first. The suggested flow is to run the scan over the repo, then prompt Claude to fix the findings. ([6:53](https://youtu.be/AhXfI1rSUPc?t=413))
- **The frontend-design plugin steers UI generation away from generic AI aesthetics.** — It is an official plugin that improves UI and UX from simple prompts. It can be invoked by slash command or triggered by Claude when it judges it useful. ([0:00](https://youtu.be/AhXfI1rSUPc?t=0))
- **Built-in Simplify is a heavier version of the Code Simplifier plugin.** — Code Simplifier runs a single agent that removes duplicates and unnecessary files, then returns a summary. The built-in Simplify spawns three agents and checks code against several metrics. The host says the team uses both. ([2:48](https://youtu.be/AhXfI1rSUPc?t=168))
- **A dedupe skill flags likely duplicate GitHub issues and comments with the reasons, but still needs a human to verify.** — The internal skill (reverse-engineered from a linked issue) parses the issue, searches for similar issues with the gh CLI, and comments on the match once it reaches roughly 70% certainty. The comment explains the match. The host notes that a human still has to verify. ([10:25](https://youtu.be/AhXfI1rSUPc?t=625))
- **The Remotion skill generates motion graphics and videos from prompts inside Claude Code.** — The host says the Claude marketing team uses it across product-announcement and marketing videos. This is a claim the host makes without evidence. ([11:34](https://youtu.be/AhXfI1rSUPc?t=694))

## Techniques
- **Batch fan-out with worktrees** — Run the batch command with an instruction. Review the plan it produces in plan mode: current state, work units, additions, and end-to-end verification steps. Approve it; one agent starts per unit in its own worktree. The main agent merges the worktrees into main and can open a PR if a remote is set. Exact flags and settings were not shown. *When:* Parallelizable changes such as migrating from one library to another, where each unit can be worked on separately.
- **Project-specific verify skill** — Generate it with the skill creator or start from the repo template, letting it scan the codebase. Give it step-by-step rules for handling changes and reporting results. Add a CLI reference file listing linters, exit codes and npm test files. Add test cases and visual checks (Playwright, or the Claude Chrome extension). *When:* Any project where the agent needs its own check that a change works before reporting done.
- **Skillify-style session capture** — After a session that refined a workflow, run a skill that analyses it for repeatable steps, tools, permissions and agents. Answer its clarifying questions, review the generated SKILL.md, then save it to the project. *When:* A workflow was worked out over several conversations and should be reused.
- **End-of-session tech-debt pass** — Create a tech-debt skill, named as the host suggests, with instructions for: identifying the session's changes, detecting duplicates, the file-structure rules, and verification with npm test and the linter. Run it at the end of each session. It fans out agents across the codebase, then creates a shared library and updates the callers. *When:* To stop duplication building up across sessions.
- **Inner-loop slash commands** — Wrap each repetitive step in a slash command, for example commit, push and open PR. Install existing ones from the plugin marketplace by searching (e.g. commit). *When:* Any workflow repeated many times a day.
- **Issue dedupe with a confidence threshold** — Parse the incoming issue, search for similar issues with the gh CLI, and set a threshold (about 70%). Above it, comment on the older issue with the reasons for the match. A human checks before closing. *When:* Busy repos where the same bug gets reported repeatedly.
- **Security scan, then fix** — Run the built-in security scan across the repo, read the findings, then prompt Claude to implement fixes. *When:* Before shipping, especially on large codebases where issues are easy to miss.
